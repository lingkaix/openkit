# OpenKit Skills

OpenKit distributes one independently installable [openkit-ops Skill](openkit-ops/SKILL.md) for installation, configuration, upgrade, diagnosis, recovery and the generated administrator CLI under [Agent Operator Skill](../docs/specs/20260910-agent_operator_skill.md). Ordinary product work uses [remote MCP](../docs/specs/20261002-remote_mcp_interface.md) guide, search, describe and call or Web. The former user-facing package is absent; no fallback, alias or separate CLI package is shipped.

## Administrator CLI

The authoring sources remain openkit-cli.mjs, openkit-operations.mjs and openkit-secrets.mjs. Online entries derive from the full composed operation definitions through strictShared and invoke the public Core Client; no second catalog or server implementation is copied. Local credential storage, named one-time-secret sinks, actorless bootstrap delivery and the three bounded local-file archive transfers retain their owned safety rules. Rebuild scripts/openkit in the operations tree with `pnpm build:openkit`; never hand-edit generated bytes.

The generator embeds the root `package.json` metadata imported by the CLI. Rebuild the bundle after root manifest changes, including repository command changes.

Use `openkit --help`, `openkit help [command]`, or a command's `--help` for local JSON guidance. Help shows the supported commands, strict flat stdin examples, and the update discovery sequence. Help, search and describe require no endpoint or credential and make no network request.

`openkit ops search <query>` returns only operation ids and one-line summaries. Bounded discovery terms such as `update`, `upgrade`, `preflight`, `connection`, and `version` select existing definitions. `openkit ops describe <operation-id>` adds mutation, sensitivity and required-access metadata plus a compact input contract with required fields, value kinds and scalar constraints. Flat input alternatives retain their own fields and requiredness; nested product structures stay compact. Add `--schema` to search for full shared JSON input/output schemas, or to describe for the full shared JSON input schema. Defaulted input fields remain optional. Discovery aliases never change an operation id or create a call path; invoke the canonical id with `openkit ops call <operation-id> --input -` and one strict flat JSON object on stdin.

Use a currently usable administrator credential for online administration. Append `--credential <name>` to doctor or authenticated calls for an explicitly selected named Token. Clear a non-empty `OPENKIT_NANOCORE_TOKEN` first. The selector binds the exact endpoint, fails without fallback, and does not change endpoint administration storage. Use `caller.read` to verify the selected identity before a scoped member call. NanoCore owns authority, private audience, restricted Material delivery, human decisions, workflow, audit and durable state. Credentials remain in endpoint/named keychain or explicitly permitted encrypted fallback storage; retirement changes no storage identity or retained data. Stable network audit labels remain openkit-cli and agent-skill. Ordinary session-only bearer refusals and administrator eligibility follow credential owners. No cookie jar, arbitrary route, SSH, generic shell, daemon or host control is part of this CLI.

`openkit ops call administration.cleanup-read --input -` accepts `{}` and reads bounded observations from six current canonical cleanup sources. It requires current administrator authority. Source coverage and explicit unknown evidence remain visible; the read performs no cleanup and grants no mutation authority. Discover its shared response with `openkit ops search cleanup --schema`.

Use `openkit ops search whoami` to discover `caller.read`. Call it with `{}` for non-secret caller identity, or `{"workspaceId":"<owned-workspace-id>"}` for current counts in that exact owned Workspace. Counts follow current source audiences and do not prove content equality across updates. Administrator access remains separate from actual ownership and membership; this read does not provision a default Workspace.

## Maintenance And Packaging

Keep one maintained source per topic in the existing six references. docs/manual provides discovery pointers. The complete operations tree, executable mode and license ship under one tag with SHA256SUMS. The release verifier checks extracted references and runs local discovery under Node.js 24 outside the checkout. Install or replace the complete package as one unit; installation starts no service and grants no authority. Host-only recovery remains usable when NanoCore is unavailable and explicitly acquires source/image prerequisites where needed.

Run `pnpm build:openkit` and `node --test tests/openkit-skill-interface.test.mjs tests/openkit-public-redaction.test.mjs` for generated bytes, whole-public mapping/exclusions, schema refinements, typed envelopes/exits, redaction, credential preflight, local abort truth and standalone execution. Release tests verify exact composition and outside-checkout usability. Remote MCP tests independently check the six excluded definitions, all eligible discovery/description/native dispatch and the delivered guide. These local checks make no live acceptance or release-publication claim.

Worker-side MCP, product Skill Catalog/version/candidate operations, Agent Plugins and AEP supply remain separate owners. The removed user-facing stdio and setup/loop/developer variants remain absent. Worker publication uses selected vendor MCP through its Gateway; the administrator CLI gains no worker tunnel or bearer.

Doctor reports service availability separately from product-work readiness, update qualification and content-free maintenance safety. Unknown evidence stays unknown. The operations archive includes reviewed App-update helper bytes outside the Skill tree, and the operator verifies and replaces them before preparation. See the operations reference for checksum, atomic installation, status identity, refusal and recovery steps.
