# Retrieval Kernel

This app implements the kernel portion of the accepted [Retrieval Kernel specification](../../docs/specs/20261014-retrieval_kernel.md). One Rust executable owns scope-local BM25, canonical literal and line-regex scans, segmentation, immutable identity sidecars, publication, and recovery. NanoCore supervises this kernel and enforces whole-RPC and store reservations. Image notice qualification for both candidate platforms remains [#249](https://github.com/lingkaix/openkit/issues/249). The Rust library is the executable's implementation and test boundary; NanoCore consumes the service face.

## Build and checks

The app-local `mise.toml` pins the compiler. NanoHost pins its own compiler. Run bare Cargo from this directory with mise shims on PATH. The root Cargo workspace contains this app and excludes the independent NanoHost crate and lockfile. Package scripts expose the repository's build, test, lint, and format tasks. The test command first fetches locked Cargo dependencies so the notice tests can inspect complete metadata offline in a cold CI shard. A failed fetch stops before test collection. The pnpm workspace includes this app with an empty lockfile importer generated by `pnpm install --lockfile-only --offline --ignore-scripts`.

```bash
export PATH="$HOME/.local/share/mise/shims:$PATH"
export LINDERA_BUILD_DICTIONARY_CACHE_DIR=/tmp/openkit-lindera-cache
cargo fmt --check
cargo clippy --all-targets --all-features -- -D warnings
cargo test
cargo build --release
cargo build --release --target aarch64-unknown-linux-gnu
```

The Linux arm64 build needs its Rust standard library and a target C compiler/linker, including a `CARGO_TARGET_AARCH64_UNKNOWN_LINUX_GNU_LINKER` selection where the host requires one. The source uses Unix descriptor confinement and file locks. Platform image qualification remains [#249](https://github.com/lingkaix/openkit/issues/249).

### Dictionary supply

Package `Cargo.toml` and `Cargo.lock` own the tokenizer pins. OpenKit maps the Lindera Segmenter directly to Tantivy tokens and retains its lowercase and word filters; lindera-tantivy, lindera-analysis, and kanaria are removed. Jieba and IPADIC are embedded in the executable. Runtime does not fetch dictionaries, read an ambient Lindera configuration, or call inference. The index identity binds the full Cargo lockfile digest, explicit schema/chunk/scoring/normalization settings, processor identity, and the dictionary source digest.

The Lindera build fetches one dictionary archive. `scripts/retrieval-dictionary.py` and the App image build verify the vendored copy before use. This guide does not copy that digest.

Set `LINDERA_BUILD_DICTIONARY_CACHE_DIR` outside the repository. The pinned build retains the archive and the built dictionary in the cache directory and reuses them. CI and the App image build verify the vendored archive before populating that cache. `cargo --offline` controls Cargo registry access; a cold Lindera cache still causes its build script to use the network. The verified archive and exact COPYING notice are under `vendor/`. The expanded dictionary remains a build artifact.

The app keeps omitted upstream notices and elected license texts with byte provenance under `notices/`. OpenKit elects Apache-2.0 for htmlescape; `notices/ELECTIONS.json` retains the exact canonical license source and manifest/archive/revision evidence. Package tests discover `tests/*_test.py` before Cargo tests, including the real collector checks and the image verifier self-checks. Packaging ships the archive's full `COPYING` notice, including the 2000–2003 Nara Institute of Science and Technology copyright and the ICOT redistribution and no-warranty conditions, with the executable. Packaging retains the Jieba and Rust dependency notices and exact SPDX metadata. `notices/GAPS.json` records unresolved source notice supply and is empty after the #249 source corrections. Closure still requires exact packaged license/provenance bytes in both built Linux App images; local builds do not constitute that proof. The prepared `verify-image-notices.py` checks both loaded App images without starting them; [notice verification instructions](notices/README.md#prepared-image-notice-check) describe its prerequisites, exact-byte predicate, and evidence limits. Real-image verification runs on the merge train or release CI that builds the images.

## Directory CLI and MCP

```bash
retrieval-kernel index
retrieval-kernel index /selected/directory
retrieval-kernel search lexical '测试 修复'
retrieval-kernel search exact 'literal text' /selected/directory --limit 20
retrieval-kernel search regex '^pattern' /selected/directory
retrieval-kernel mcp /selected/directory
retrieval-kernel --version
```

`index` reconciles the current inventory and any unavailable-entry count and publishes a replacement scope generation. Repeating an identical healthy inventory is a no-op. Updates, removals, and repair use this same operation. A search requires a prepared index. The directory defaults to the current directory; the derived store defaults to `<directory>/.retrieval-kernel`. `--store PATH` selects a separate caller-owned derived directory. This local default assigns no product storage path.

The directory adapter includes dotfiles and ignores no Git rules. It visits regular files through held directory descriptors, refuses symlinks, skips its own derived store, and computes SHA-256 incrementally. Full-stream UTF-8 validity and NUL detection select direct text or an identity-only sidecar; no format parser runs. It checks file metadata during reads and reconciles again after a query. Changed hits are withheld and coverage becomes incomplete. `complete` describes the enumerated units and observed fixed reads; it does not claim a filesystem snapshot.

Failure to open the startup root fails before generation access. An entry that fails stat, open, or canonical identity verification has no name-searchable Document, sidecar, or fabricated digest. It appears only as an aggregate unavailable count with the fixed reason `source-unavailable`; no failed path, name, or underlying OS error is returned. Other files remain searchable. An inaccessible directory counts as one observed unavailable entry; its unseen descendants cannot be counted. The inventory remains incomplete. Publication commits this count with the readable records, so restart or a no-op index does not erase the coverage gap. Known-identity unavailable sources remain supported by the service and recorded as failed text.

MCP uses newline-delimited JSON-RPC 2.0 over stdio. It negotiates 2024-11-05, 2025-03-26, or 2025-06-18, exposes only `retrieval_search`, the supplied name for canonical `retrieval.search`, and has no write or index tool. Arguments are exactly `{mode,query,limit}`; additional arguments fail. The root and derived store are fixed at launch, so a model cannot supply a path or scope. CLI and MCP use the same directory query operation. Prepare or rebuild with `index` outside the MCP tool. No Sandbox face is installed by R1.

## Trusted local service contract, version 1

Launch `retrieval-kernel service --sources ROOT --store STORE`. ROOT is a trusted startup admission boundary for canonical regular files; STORE is the storage owner's private derived boundary. Requests cannot use absolute paths, parent traversal, or symlink components. The service is sequential, listens on no socket, and reads one JSON request per LF-delimited stdin frame. Stdout contains one JSON reply per frame. Errors are bounded and contain no query or source text. R2 must admit complete scope generations under current source and destination authorization before sending requests; the kernel cannot detect an authorization grant in a scope name.

The envelope requires `version:1`, a numeric or bounded string `id`, and one closed `op`. Unknown additive members are ignored. Unknown operations, versions, modes, language categories, content kinds, or persisted text statuses fail closed. The wire has no independent compatibility promise. An output-changing mechanism change updates its index identity and requires a rebuild; canonical bytes remain with their owners.

| Operation | Exact request members | Success `result` |
| --- | --- | --- |
| `publish` | `{version:1,id,op:"publish",view,expected_generation:null|string}` | `{generation:string}` |
| `search` | `{version:1,id,op:"search",request:{mode,query,scopes:[view],limit}}` | Search result below |
| `inspect` | `{version:1,id,op:"inspect",scope:string}` | `{generation:null|string}` |
| `digest-windows` | `{version:1,id,op:"digest-windows",request:{path,source_bytes,start,end,patterns:[{window_bytes,encoding,digests}],bounds:{max_bytes,max_matches,timeout_ms}}}` | `{start,end,bytes,range_digest,matches:[{start,end}]}` |
| `analyze` | `{version:1,id,op:"analyze",query,title,body,language?:"zh"|"ja"|"unicode"}` | `{language,query_terms,title_terms,body_terms}` |

`view` is `{scope:string,documents:[Document],unavailable_objects?:usize}`. `unavailable_objects` defaults to zero and counts observed entries whose canonical digest could not be verified. It carries no identities and creates no searchable records. The combined Document and unavailable-entry count must not exceed the object ceiling declared in `src/text.rs`. Publication commits the count; search uses the greater of the current and committed unavailable counts, reports `source-unavailable`, and sets `inventory_complete=false`. Recovery requires a fresh inventory and publication; a current zero count alone does not erase a committed gap. Each scope is an exact opaque eligibility partition, not a grant. There is no global registry or search-all default. `scopes:[]` reads no generation or canonical content. A missing scope set fails. A missing `expected_generation` fails; initial publication uses explicit null. An update must name the inspected current generation. One writer holds the scope lock through publication. A changed pointer, active writer, or contradictory canonical identity at the same revision returns `conflict`. Transport paths or byte ranges can move without changing the logical source identity. A scope move remains two independent scope publications.

Document core fields are `{key:{namespace,id},revision,digest,size,name,media_type,content}`. `digest` is a verified lowercase canonical SHA-256 over the complete admitted canonical unit, supplied by the adapter. `size` is that complete unit's byte count. Optional fields are `title` (default empty), `text_ranges` (absent or an array of `{start:u64,end:u64}`), `language` (absent or `zh|ja|unicode`), `metadata` (string-to-string map, default empty), and `locator` (opaque original coordinate or null). A revision includes canonical metadata and `text_ranges` changes. Transport form and availability can change without changing that canonical revision. Two adapters retain distinct keys for identical bytes.

`text_ranges` declares which canonical UTF-8 bytes are searchable. Absence selects the complete unit. An explicit empty array selects no body bytes and leaves the title searchable. The range ceiling in `src/store.rs` applies; each range is nonempty, half-open, byte-bounded by `size`, sorted, disjoint, and aligned to UTF-8 boundaries. The kernel verifies digest and size against the complete unit, then indexes and scans each declared range independently. It does not join adjacent ranges. Text locators retain offsets in the original canonical unit. `text_ranges` is invalid for `unreadable` and `unavailable` content, whose identity sidecar behavior is unchanged.

| Content | Input meaning |
| --- | --- |
| `{kind:"text",path:string,range?:{start:u64,end:u64}}` | One admitted canonical UTF-8 unit. Path is root-relative. An optional range is half-open, must match `size`, and confines all hashing, indexing, and scans to that unit. This supports one Item inside a canonical JSONL log without copying or joining Items. Returned text offsets are relative to the unit. |
| `{kind:"inline-text",text:string}` | Bounded canonical UTF-8 supplied by the trusted adapter, including decoded text from an Item JSON field. Required in publish and every current search view. Its bytes and metadata must fit the frame and inventory ceiling in `src/text.rs`. The payload is request-local and is omitted from the committed manifest; exact and regex scan the supplied current text. Text offsets refer to that UTF-8 unit, with `locator` identifying its original source coordinate. Large retained files use the file-stream form. |
| `{kind:"representation",path:string,digest:string,size:u64,processor:string,fragments:[{start:u64,end:u64,locator:string}],complete:bool}` | Source-owned immutable extracted UTF-8 beneath the admitted source root. The representation has its own SHA-256 and byte length, within the representation and fragment ceilings in `src/model.rs` and `src/store.rs`. Fragment offsets are half-open representation UTF-8 bytes; each opaque locator names its original page or source coordinate. Empty fragments preserve empty-page metadata without searchable bytes. The processor string binds its version and output-changing configuration. The kernel verifies the representation and uses existing chunks and scans without making another text copy. |
| `{kind:"unreadable"}` | Identity metadata only. The kernel leaves the body unopened and creates a sidecar from the supplied verified identity. Missing digest fails admission. |
| `{kind:"unavailable"}` | The adapter knows the fixed canonical identity, but its representation is unavailable. The generation records failed text and queries are incomplete. |
| `{kind:"resource-limited"}` | The adapter stopped at a named processing budget. The body stays unopened, its canonical identity remains in the inventory, and existing `TextStatus.ResourceLimited` makes queries incomplete without removing healthy neighbors. |

For `representation`, Document `digest` and `size` remain the original canonical identity. The source adapter verifies that original and current authorization before calling the kernel; the kernel opens only the admitted representation path. Existing `text_ranges` apply only to direct canonical text; extracted text uses its fragments. Hits retain the original digest, report the separate representation digest and processor, and use `representation:"sidecar"` with `Locator::Text.original` for the fragment's source locator. Incomplete processor coverage adds `partial` and makes `representations_complete` false while verified hits remain eligible. Empty extracted text does not prove that the original body has no content. Missing, invalid UTF-8 or changed representations withhold their own matches and preserve healthy neighbors with truthful incomplete coverage. Source-owned representations stay in the existing source snapshot/cache lifecycle; the kernel adds no parser, durable owner or second representation cache. Derived schema identity 5 requires an ordinary rebuild for earlier generations.

Without a hint, kana in declared searchable ranges or the canonical title selects Japanese, Han without kana selects Chinese, and other text selects Unicode words. Excluded canonical bytes do not select an analyzer. Title, admitted body ranges, sidecar, and query use matching analyzers and lowercase Latin normalization. Each Document uses one dictionary tokenizer. One shared word filter excludes punctuation-only tokens, retains identifiers with internal punctuation, and bounds normalized tokens at the declaration in `src/text.rs` for indexing and analysis. The gram field nominates missed CJK candidates; a source-unit literal check is required before a gram score is admitted. There is no lexical query parser. BM25 uses one scope's tombstone-free statistics, the maximum chunk score, and the title and verified-fallback boosts declared in `src/query.rs`. Each gram candidate is checked against that Document's selected query settings. Combined lexical order is descending score, source key, chunk ordinal, then scope as a final deterministic tie.

`exact` preserves bytes, Unicode, whitespace, case, and line endings and emits overlapping literal occurrences inside each declared searchable range. A match cannot cross a range boundary. `regex` uses Rust regex syntax through the grep crates and scans each range independently. Each LF-delimited line excludes LF and retains CR. BOM sniffing and transcoding are disabled. Backreferences, lookaround, explicit LF literals even in classes, zero-length matches, and oversized regex programs fail before source access. Scan order is source key, representation, metadata field, offset, then scope. Limits are applied after scope merge. A scan stop preserves hits found before that stop and marks representations and matches incomplete with the stopping reason. Regex feeds one bounded LF line at a time to grep, so read-ahead cannot lose earlier matches when a later line exceeds the ceiling. Canonical identity is verified before scanning and checked again after a scan stop while the request budget permits; detected stale identities, changed range identity, and malformed current text are withheld. If cancellation, the wall budget, or an I/O failure prevents that last check, earlier verified hits remain explicitly incomplete.

Success replies are `{version:1,id,result}`. Failure replies are `{version:1,id,error:{code,message}}`. Codes are `invalid-request`, `conflict`, `unavailable`, `resource-limited`, and `io`. A process terminated during publication yields no acknowledgement; R2 must restart, inspect the pointer, and re-enumerate current truth before a new request. It must not replay a canonical write. EOF exits cleanly. Cancellation by process termination releases OS reader/writer locks; the next successful scoped operation removes abandoned staging.

A search result is `{generations:{scope:generation},mode,hits:[Hit],coverage,complete}`. A Hit has `{key,scope,revision,digest,representation,representation_digest,processor,locator,chunk,score,snippet,provenance}`. Representation is `text` or `sidecar`; processor is null or `identity-markdown-v1`; score is null for scans. Locators are `{kind:"text",start,end,original}`, `{kind:"title",start,end,original}`, or `{kind:"metadata",field,start,end}`. Title offsets refer to the supplied canonical title, text offsets to the canonical unit, and metadata offsets to the committed Markdown representation. Metadata offsets never claim binary-body coordinates.

Coverage has `admitted_objects`, `searched_representations`, `stale_revisions`, `stopped_work`, `unsupported_bodies`, `inventory_complete`, `representations_complete`, `matches_complete`, `reasons`, `omitted_matches`, `matching_documents`, and `enumeration_complete`. Counts come only from named scopes. `admitted_objects` sums the greater of each current and committed total inventory count, including unavailable entries; unavailable reason counts use the greater current or committed gap rather than adding it twice. Reasons aggregate stopped work without private identities. `complete` is the conjunction of the three completeness flags. Binary bodies remain explicitly unsearched while valid sidecar search can be complete. Changed canonical identities are withheld. A complete empty sidecar result says nothing about the binary body.

Lexical `matches_complete` certifies the requested top-k, not all matching Documents. `matching_documents` reports verified matches before the response limit; `enumeration_complete` is true only for a fresh lexical result that returns every match. **R2's governed adapter must require both `complete` and `enumeration_complete` before dispositioning a full selection.** It can request up to 1000 matches and must use its owning typed failure if enumeration exceeds that bound. R1 adds no durable cursor or second selection engine.

`analyze` returns distinct terms using the same selected Document analyzer and bounded chunk stream as indexing. Without a hint, title and body select the language by the same kana/Han rule. Query, title, body, and the returned term set stay within the ceilings in `src/text.rs`. Knowledge Manager consumes this evidence for its existing two-term page or one-term title sufficiency rule; there is no TypeScript tokenizer replacement inside NanoCore.

NanoCore uses the existing `@openkit/storage` byte owner to stream decoded inline text through the confined `text` file form when its product-owned store is beneath the admitted source root. Direct-inline, transport, and buffer ceilings are owned by `apps/nanocore/src/retrieval-service.ts`. Exceeded text budgets produce `resource-limited` documents, not a failed whole inventory. Files stay under the private derived store, are removed after each RPC, and carry no retained text cache; the empty instance namespace is removed at close. Original source keys, revisions, digests and byte coordinates are unchanged. The first-party adapters still own canonical acquisition, eligibility and final rechecks; this transport does not grant new source access. The frame ceiling stays with the kernel.

NanoCore's `retrieval-service.ts` owns whole-RPC deadlines, child health and restart, shutdown and derived-store admission. It checks health with empty scopes, admits only complete current adapter views, and never replays an unacknowledged publication. Each storage-owned service reserves its temporary-generation ceiling inside its store budget before a publish. `apps/nanocore/src/retrieval-service.ts` owns those defaults. These are derived-store implementation limits, not upload admission or deployment minima. Source and audience admission remain outside this executable.

The additive `digest-windows` operation compares generic SHA-256 windows through the same startup source boundary without opening a generation. Encodings are `bytes`, `base64url-text` (unchanged alphabet bytes) and `base64url-decoded` (canonical unpadded decoding). It returns positions only, with no source text or comparison identity. The exact range digest proves only the named range. Core owns proof selection, complete-original checks and product admission. The operation refuses source drift, hardlinks and non-regular sources. Its ceilings are owned by the kernel scan implementation; caller limits can only tighten them. Limit exhaustion fails instead of returning a partial clean result. Existing operations retain their current limits and semantics. Run `cargo test` for both the generic scan regressions and the unchanged retrieval suites.

## Publication, sidecars, and bounds

A scope uses `STORE/SHA256(scope)/CURRENT`, immutable generation directories named by manifest digest, and private scope/reader locks. The Tantivy commit payload pins the manifest generation hash, so foreign valid engine files cannot be mixed with that tuple. The manifest binds canonical inventory, statuses, selected languages, source and representation identities, and sidecar references. Canonical text is indexed but is not stored as another scan-text body. Adapter text is stripped from the stored Document identity; it must be supplied again from current canonical truth for search. Sidecar files live inside the same immutable generation tuple. Their cache identity binds source key, source digest, metadata revision, processor, and exact Markdown digest. Fields have sorted escaped headings and fenced JSON string values; each value is a separate searchable unit. Optional canonical titles and supplied metadata are retained.

Scope and reader locks explicitly unlock on every exit path before their descriptors close; a child that inherits a descriptor cannot prolong a completed or failed operation. Publication builds a fresh index, disables merges to avoid duplicate temporary segment growth, flushes all tuple members, then atomically replaces and synchronizes CURRENT. It acknowledges only after pointer durability. It creates no tombstones. Queries pin a generation with a reader lock; writer cleanup cannot remove a pinned generation. Valid sidecars are hard-linked into a new generation without processing again. Metadata or digest changes create replacement identities. Missing or corrupt sidecars are rebuilt or reported incomplete; wrong machinery requires a rebuild. Query completion and publication remove unreferenced retired generations. Stopped work retains an unchanged verified identity sidecar with incomplete coverage.

A crash before pointer publication leaves the old tuple authoritative. A crash after publication leaves the new tuple authoritative. Staging is never queried. A corrupt or unreadable pointer fails explicitly; recovery does not guess a current generation from directory names. Dispose such derived storage only under its storage owner's existing authority, then rebuild from canonical input.

Native admission limits are declared in `src/text.rs`, `src/query.rs`, `src/store.rs`, and `src/main.rs`. The specification owns the contract. This guide does not copy those limits.

Bounds preserve canonical bytes. Cooperative stops yield partial or resource-limited coverage; malformed declared UTF-8 fails without replacement characters or a fabricated sidecar. The executable ignores SIGXFSZ so the file-growth ceiling returns EFBIG instead of terminating it with a core dump. EFBIG, ENOSPC and EDQUOT publication failures return resource-limited and preserve the last committed generation. Other OS exhaustion can terminate this separate executable. NanoCore already supervises this executable and bounds store volume and whole-RPC time. Unqualified platform and image cases remain [#249](https://github.com/lingkaix/openkit/issues/249). These ceilings are implementation limits, not a deployment minimum. Fixture qualification is not a hostile-filesystem, power-loss, or maximum-upload certification.

## Verification and remaining qualification

Tests use actual Tantivy generations, packaged tokenizers, exhaustive independent scan oracles, source-open observations, real SIGKILL checkpoints, reader locks, real stdio faces, OS resource observations, and an OS file-growth failure. Run `cargo test` for the library and the real executable faces. Product adapters still own decoding, eligibility, revisions, and final response validation. Entries without verified digests have coverage only and no name-searchable record. Image notice proof for both platforms remains [#249](https://github.com/lingkaix/openkit/issues/249).
