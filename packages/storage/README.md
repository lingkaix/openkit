# Storage (`@openkit/storage`)

Storage locates bytes and enforces the caller's current admitted access. It does not own Sources, Artifact versions, Knowledge, Policy, publication, retrieval or media processing. The accepted owner is [File Storage And Knowledge Packages](../../docs/specs/20261018-file_storage_and_knowledge_packages.md).

## Contract

`StorageService` uses asynchronous JSON requests and responses. Byte chunks use base64; temporary staging uses opaque handles. No native file handle, callback or shared mutable object crosses the service contract. `ContentReference` comes from `@openkit/protocol`; do not create another descriptor or URI codec.

`LocalStorage` accepts configured mount roots and a staging root. The trusted NanoCore caller supplies a fresh `StorageAccess` on every operation. Its `basis` distinguishes an explicit current `lease` (actual grant ID, expiry and revocation), request-local `knowledge` authority and native `work-capture` admission (both without grant ID or expiry). Knowledge authority is restricted to a declared managed raw root and its exact `sources/` prefix; external/host mounts and Worker exposure require leases. Native Knowledge admission owns current membership and publisher checks; Storage cannot turn metadata into permission. This projection is not a new grant, grant issuer or retained lease store. Do not expose the backend directly to an untrusted client. Roots, grants and owner publication remain outside this package. Configure physical roots without symlink components. The local backend pins directory traversal through an OS descriptor namespace; platforms without that primitive return unavailable/unsupported instead of falling back to mutable pathname traversal.

`work-capture` uses explicit `knowledgeBaseId: null` only for a configured Server or Workspace `backend-evidence` mount. The native owner supplies the existing scope's `evidence/backend/` root, authorizes current record access before each operation and confines digest objects to `sha256/<digest>`. This basis cannot borrow Knowledge, User, external or host mounts. Native references support whole-source or byte ranges; scans are confined to the digest directory. Equal digests grant no read permission. The shared Knowledge case still requires its exact real Knowledge Base ID.

`stat` observes original identity and sniffed media. `read` verifies the entire original against captured digest and size with bounded memory before returning a bounded requested byte chunk; it does not retain an original for replay. Missing or changed originals return unavailable. Only whole-source and byte-coordinate references support raw reads; page conversion belongs to Derivation; time and frame references are deferred.

`scan` examines at most the requested number of directory entries per call. A name filter can therefore return an empty page with a continuation. A changed directory or unusable cursor requires a new scan. Stateless continuation seeks at most 65,536 prior entries; a cursor beyond that capacity explicitly requires a rescan and cannot establish complete discovery of a larger directory. This is shallow metadata discovery, not a recursive index or durable change feed.

Staging uses `beginStage`, repeated bounded `writeStage` calls and `finishStage`. The owner consumes sealed bytes through `readStage`, performs its own Source or Artifact publication, then calls `discardStage`. Storage never writes the destination original. Handles are temporary and bound to their admitted basis and exact owner/mount/prefix. Lease handles expire with that lease; Knowledge and work-capture handles have no invented expiry and are closed by their owning native request. A process restart invalidates them. The caller owns cleanup of its dedicated staging directory after restart, when no live process uses it. `close` removes this instance's remaining temporary stages.

## Commands

Trusted Node owners can use `createDirectoryExclusive` for a synchronous single-directory create with caller-selected mode. It creates no parents and preserves `EEXIST`; the caller owns current admission, directory identity and any cleanup. This primitive alone makes no durable-publication claim. They can use `copyVerifiedFile` for bounded independent copies or digest verification, and `publishDurableFile` for create-only private metadata publication. Both pin directory traversal, reject links and source changes, and synchronize output bytes before acknowledgement. Publication also synchronizes its parent entry. `removeDurableFile` retires one caller-owned regular-file entry through the same pinned parent and acknowledges only after parent synchronization; an absent-entry retry still synchronizes that parent. It does not select content, revoke publication authority or remove a directory. `copyFileForCut` uses the same confined independent-copy mechanics but returns explicitly unverified private bytes without a digest or payload sync. It preserves inode, link, size and binding checks. Its caller must verify and synchronize durable destination objects before publishing any seal; a completed cut copy alone is not durable publication. NanoCore's snapshot owner selects paths, reserves capacity, protects source lifetimes and decides when a seal can become visible; these helpers add no Storage service request or retained authority.
