# Worker Shim

`@openkit/worker-shim` provides the generic sandbox-local OpenKit worker supervisor. Its single zero-argument binary, `openkit-worker-shim`, runs the shared Harness used by NanoHost. The Harness executes the six private operations of [Worker Control Protocol](../../docs/specs/20260703-worker_control_protocol.md) (`session.open`, `session.inspect`, `turn.start`, `turn.interrupt`, `session.close`, `harness.drain`) for resident AgentSession bindings ([AgentSession](../../docs/core/agent-session.md)) and keeps one shared worker-control, transcript, workspace-publication, and lineage lifecycle for each Turn.

## Sandbox Integration

Before any native work, the shim accepts the stock Supervisor connection only on its image-owned `127.0.0.1:17891` binding and establishes one standard HTTP/2 client session. That session exposes only `/worker-control/*`, `/inference/*`, and `/capabilities/*`; the Harness itself uses only the credential-free `/worker-control/harness/poll` and `/worker-control/harness/result`. The worker receives no NanoCore, Gateway, upstream MCP, or caller-selected transport address.

A separate loopback-only HTTP/1 listener at `127.0.0.1:17892` serves the resident runtimes at the fixed URLs `http://127.0.0.1:17892/inference/v1` and `http://127.0.0.1:17892/capabilities`, and admits only exact authenticated `POST /inference/*` and `POST /capabilities/mcp/*` after the H2 session is ready. [Worker Agent Capability](../../docs/specs/20260703-worker_agent_capability.md) owns the credential rule. `session.open` delivers two distinct session loopback credentials, one per family, which the Harness registers for that AgentSession and hands to the runtime. `turn.start` delivers the three upstream route tokens of that Turn, which the Harness binds to the AgentSession for the Turn. A native request is attributed to its AgentSession by its loopback credential and forwarded with the bound Turn's upstream token, streaming without retry. An unknown credential gets 401. A known credential with no bound Turn, or one whose Turn reached its barrier, gets 403. At the Turn barrier the Integration refuses new requests, waits at most 10 s for in-flight ones, then cuts the rest; `session.close` destroys the credentials and cuts any request. No route token or loopback credential enters native argv or the resident environment except the loopback credential the runtime itself presents.

The no-argument Harness writes the fixed value-free `OPENKIT_WORKER_SHIM_ENTRY_V1\n` marker exactly once after its loopback listener is installed and before it waits for the stock bridge connection. NanoHost consumes that marker only as bootstrap-entry evidence; it is not authentication, native-child start, terminal, transcript, or product state.

## Resident Bindings

One poll loop routes each command to the Harness instance its `harnessInstanceId` names and requires that instance's exact next `sequence`. A Harness instance serves one adapter, fixed by its first `session.open`, admits at most eight open AgentSessions, and runs at most one active Turn. Every body is validated against its closed schema before any effect; a malformed, extra, or retired field is `unsupported`. A refusal carries only its reason, except that a pre-native `turn.start` `dependency_failed` refusal also carries the closed `startupFailure` stage and reason described below. The Worker Control Protocol permits this diagnostic only for `turn.start` with `reasonCode="dependency_failed"`; its normalized fields are validated before use.

`session.open` refuses a live Thread (another current binding for the same Thread in any Harness instance of this shim process), a duplicate binding or AgentSession, a non-canonical AgentSession id, an unknown or different adapter, and a runtime environment that names a Harness-owned variable. It then registers the loopback credentials, creates disposable control below the private root, and opens the adapter's resident binding with the retained per-Thread native root `/sandbox/openkit/native/<adapter>/threads/<sha256(threadId)>`, the fixed loopback URLs and credentials, and the resident environment. That environment is the image allowlist (including `HOME`), `TEMP`, `TMP`, and `TMPDIR` fixed to the non-retained `/tmp/openkit-bootstrap`, `NODE_EXTRA_CA_CERTS` copied from an allowlisted `SSL_CERT_FILE`, `npm_config_nodedir` and `NPM_CONFIG_NODEDIR` when the bundled Node prefix contains `include/node/node.h`, `NO_PROXY` and `no_proxy` extended with `127.0.0.1`, and the session-static runtime environment. A failed open destroys the loopback credentials. It releases the Thread only when native cleanup is proved; otherwise it keeps the Thread reserved and drains the Harness.

A resume carries the predecessor AgentSession id as its locator and the accepted handle digest. The Harness stores the first ready reference an adapter reports under `/sandbox/openkit/native/agent-session-references/<agentSessionId>`, privately and atomically, and the digest is the SHA-256 of those bytes. A resume whose locator has no stored reference is `missing`; one whose stored bytes do not match the digest, or whose runtime does not prove that exact ready handle after opening, is `conflict`. The adapter decides when its conversation carries ready authority; a later different reference is reported as `unknown` and never replaces the stored one.

`turn.start` accepts only the exact AEP and Context references of its AgentSession and the binding's Workspace and Thread (otherwise `stale`), and answers once the runtime accepted the Turn. A binding is established when its handle was ready at open, whether resumed from a proved predecessor or created by the runtime, or when one of its Turns completed; a binding whose handle was pending at open and whose first Turn did not complete, or whose resident host ended on its own, only closes (`conflict`). A host that ends during a Turn fails that Turn; it is not reported as an interrupt. `turn.interrupt` acts only on the exact active Turn and lease before its barrier (otherwise `stale`) and answers after the Turn settled. `session.inspect` reports the handle, host liveness, and cleanup without starting work. `session.close` of an idle binding closes the resident binding, destroys the loopback credentials, removes the AgentSession's input and control directories, and releases the Thread; retained native data and the stored reference stay. `harness.drain` refuses new sessions and Turns and reports the remaining counts. An unproved native stop marks the binding failed with unknown cleanup, retains its Turn occupancy, and drains the Harness. A subsequent interrupt or close that cannot prove cleanup returns `cleanup_required`. A rejected `startTurn` whose native acceptance is unknown fences the same way and keeps that Turn occupied.

Pre-native `turn.start` failures return `dependency_failed` with a closed `startupFailure` stage and reason. Raw exceptions, filesystem paths, child output and route credentials are never included. Stages distinguish package validation, runtime supply, workspace materialization, Integration readiness, worker-control readiness and native start. An empty Git slot first fetches the exact commit with depth 1 using HTTP/1.1. Any completed nonzero fetch then fetches advertised branch tips and tags once, also with HTTP/1.1, including when the refusal text is not a known missing-ref message. A fetch that times out, is signaled, or fails to start does not try that fallback and is `git_fetch_transport_failed`. Checkout proceeds only when `git cat-file -t` reports that the object is a commit. A completed object check whose private result says the object is absent is `git_fetch_commit_unavailable`. A terminal fetch whose private result matches a certificate failure is `git_fetch_tls_failed`. A terminal fetch whose private result matches a proxy, connection, or HTTP/2 framing failure is `git_fetch_transport_failed`. A completed terminal fetch with Git’s HTTP 401/403 refusal phrase is `git_fetch_http_refused`, with observed status and unavailable enforcement attribution. A failed fallback that matches none of these, and every other object-check failure, stay `git_fetch_failed`. When the sandbox provides `SSL_CERT_FILE`, Git receives that same path as both `GIT_SSL_CAINFO` and `CURL_CA_BUNDLE`; ambient CA paths do not win. These reasons do not rewrite host repository diagnostics, and the incomplete slot is left in place. Terminal fetch failures carry a closed normalized explanation through the startup refusal, including producer time, subprocess category, evidence completeness and private stderr truncation. Neither raw stderr nor repository URLs enter that explanation. HTTP refusal is not proof of a sandbox deny or Vault failure; local object checks retain their existing reasons.

## Adapters

`src/adapter-registry.ts` defines the resident adapter contract: `openSession` returns a binding with `startTurn`, `nativeHandle`, `childState`, `close`, and `exited`, and each started Turn has `settled` and `interrupt`. Every Gateway package contains one or more allowed LLM routes and one preferred logical model; the shared shim selects the unique route for that model and passes it with the Turn's MCP server ids, Skill targets, working directory, and input. The production registry is empty until the resident Codex App Server v2, Pi SDK host, OpenCode V2, and DeepSeek adapters land ([Codex Worker Adapter](../../docs/specs/20260716-codex_worker_adapter.md), [Pi Worker Adapter](../../docs/specs/20260716-pi_worker_adapter.md), [OpenCode Worker Adapter](../../docs/specs/20260716-opencode_worker_adapter.md), [DeepSeek Worker Adapter](../../docs/specs/20260930-deepseek_worker_adapter.md)); the slices are tracked in `docs/changes/202609300021100000-agent_communication_redesign/plan.md`. The package does not materialize upstream MCP commands, endpoints, or credentials, and declared Skill metadata remains inert package metadata.

## Vault Runtime Environment

`session.open.runtimeEnvironment` supplies the Core-resolved values of the AgentSession's runtime-env declarations; they are session-static inside the resident binding, as [Worker Runtime Communication](../../docs/specs/20260629-worker_runtime_communication_model.md) states. The Harness rejects names it owns, including the image allowlist, `NODE_EXTRA_CA_CERTS`, `NODE_OPTIONS`, `TEMP`, `TMP`, `TMPDIR`, every `OPENKIT_` name, and every casing of `npm_config_nodedir`. Each Turn's AEP must declare exactly the delivered names, or the Turn fails at package validation. The Harness never falls back to its parent environment for these values. The values and both loopback credentials join the exact-value diagnostic, assistant-output and Git-publication redaction checks; an assistant message containing one fails the Turn.

## Workspace Publication

For one read-write Git workspace input, the shared supervisor validates the closed AEP source projection, rejects credential-bearing or non-HTTPS URLs before contact, and initializes only an absent or empty plain-directory target below the declared Workspace root. A retained target must keep the exact requested origin and `HEAD` baseline; tracked, untracked, ignored, and incomplete bytes are never reset, cleaned, or overwritten. Source conflicts and incomplete first initialization fail while preserving the target for explicit reconciliation. After the Turn settles and the loopback drains, the supervisor captures worker changes through an isolated index and publishes `workspace.patch` followed by `workspace-changes.json`. Before publication, it inspects every non-deleted changed path's exact stage-zero blob bytes from that index and rejects any blob containing an exact non-empty credential value of the binding. This is literal-value protection, not generic DLP or encoded-secret detection. It also rejects ambiguous inputs, hidden index state, Git filters, unsupported file modes, and incomplete publication.

The accepted design removes this in-Sandbox publisher; collection is the outside read-only snapshot chain, and the literal credential-value check runs in the NanoHost scan over staged blob bytes ([NanoHost Workspace Data Boundary](../../docs/specs/20260801-nanohost_workspace_data_boundary.md), [Workspace Synchronization](../../docs/specs/20260703-workspace_synchronization.md)).

## Codex Runtime Provenance And Work Capture

`src/codex-runtime-provenance.ts` and `src/codex-runtime-capture.ts` interpret the stable Codex 0.153.4 rollout forest for opt-in runtime provenance (`control.transcript.runtimeProvenance`) and incremental work capture; `src/runtime-capture.ts` supplies bounded source framing, exact admitted body selection and opaque references. They await the resident Codex adapter, which replaces primary `codex exec --json` with the Codex App Server v2 event stream; [Worker Runtime Subagent Provenance](../../docs/specs/20260711-worker_runtime_subagent_provenance.md) owns capture and [Codex Worker Adapter](../../docs/specs/20260716-codex_worker_adapter.md) owns the stream.

Missing root evidence is `failed`; missing, contradictory, or changing reachable evidence is `unstable`; and partial or limit-bounded evidence is `truncated`. Malformed physical frames remain explicitly indexed instead of being silently attributed. The AEP supplies immutable capture coverage; off preserves required facts, while on permits complete admitted bodies. Restricted chunks bypass ordinary local transcript payloads and are sent with backpressure through the existing control client. Explicit source/version/parse gaps do not imply zero children or complete coverage. When a semantic unit fails credential or size admission after expected metadata was emitted, the shim emits an unavailability fact for each expected observation ID without forwarding rejected body bytes. The shim validates the AEP capture pair with the shared Worker protocol schema when it reads the package, then passes that typed pair to adapters without resolving policy again.

## File Map

- `src/harness.ts`: the poll loop, one Harness per instance id, the six operations over resident bindings, resume references, and the resident environment.
- `src/turn.ts`: one Turn on a resident binding: AEP validation, supply and workspace materialization, route binding, worker-control readiness, native start, the Turn barrier, publication, and final status.
- `src/integration-client.ts`: fixed loopback listeners, standard HTTP/2 client, credential-free private Harness carriage, session loopback credentials, and Turn-bound upstream routes.
- `src/adapter-registry.ts`: the resident adapter contract and the production registry.
- `src/control-client.ts`, `src/transcript.ts`: worker-control envelopes and the Turn transcript.
- `src/workspace-git.ts`: Git workspace materialization and publication.
- `snapshots/codex-0.153.4/`: minimized primary-exec and rollout JSONL fixtures pinned to Codex `rust-v0.153.4`.
