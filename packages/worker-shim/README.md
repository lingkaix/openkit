# Worker Shim

`@openkit/worker-shim` provides the generic sandbox-local OpenKit worker supervisor. Its single zero-argument binary, `openkit-worker-shim`, runs the shared Harness used by NanoHost. The Harness executes the six private operations of [Worker Control Protocol](../../docs/specs/20260703-worker_control_protocol.md) (`session.open`, `session.inspect`, `turn.start`, `turn.interrupt`, `session.close`, `harness.drain`) for resident AgentSession bindings ([AgentSession](../../docs/core/agent-session.md)) and keeps one shared worker-control, transcript, workspace-publication, and lineage lifecycle for each Turn.

## Sandbox Integration

Before any native work, the shim accepts the stock Supervisor connection only on its image-owned `127.0.0.1:17891` binding and establishes one standard HTTP/2 client session. That session exposes only `/worker-control/*`, `/inference/*`, and `/capabilities/*`; the Harness itself uses only the credential-free `/worker-control/harness/poll` and `/worker-control/harness/result`. The worker receives no NanoCore, Gateway, upstream MCP, or caller-selected transport address.

A separate loopback-only HTTP/1 listener at `127.0.0.1:17892` serves the resident runtimes at the fixed URLs `http://127.0.0.1:17892/inference/v1` and `http://127.0.0.1:17892/capabilities`, and admits only exact authenticated `POST /inference/*` and `POST /capabilities/mcp/*` after the H2 session is ready. [Worker Agent Capability](../../docs/specs/20260703-worker_agent_capability.md) owns the credential rule. `session.open` delivers two distinct session loopback credentials, one per family, which the Harness registers for that AgentSession and hands to the runtime. `turn.start` delivers the three upstream route tokens of that Turn, which the Harness binds to the AgentSession for the Turn. A native request is attributed to its AgentSession by its loopback credential and forwarded with the bound Turn's upstream token, streaming without retry. An unknown credential gets 401. A known credential with no bound Turn, or one whose Turn reached its barrier, gets 403. At the Turn barrier the Integration refuses new requests, waits at most 10 s for in-flight ones, then cuts the rest; `session.close` destroys the credentials and cuts any request. No route token or loopback credential enters native argv or the resident environment except the loopback credential the runtime itself presents.

The no-argument Harness writes the fixed value-free `OPENKIT_WORKER_SHIM_ENTRY_V1\n` marker exactly once after its loopback listener is installed and before it waits for the stock bridge connection. NanoHost consumes that marker only as bootstrap-entry evidence; it is not authentication, native-child start, terminal, transcript, or product state.

## Resident Bindings

One poll loop routes each command to the Harness instance its `harnessInstanceId` names and requires that instance's exact next `sequence`. A Harness instance serves one adapter, fixed by its first `session.open`, admits at most eight open AgentSessions, and runs at most one active Turn. Every body is validated against its closed schema before any effect; a malformed, extra, or retired field is `unsupported`. A refusal carries only its reason, except that a pre-native `turn.start` `dependency_failed` refusal also carries the closed `startupFailure` stage and reason described below. The Worker Control Protocol permits this diagnostic only for `turn.start` with `reasonCode="dependency_failed"`; its normalized fields are validated before use.

`session.open` refuses a live Thread (another current binding for the same Thread in any Harness instance of this shim process), a duplicate binding or AgentSession, a non-canonical AgentSession id, an unknown or different adapter, and a runtime environment that names a Harness-owned variable. It then registers the loopback credentials, creates disposable control below the private root, and opens the adapter's resident binding with the retained per-Thread native root `/sandbox/openkit/native/<adapter>/threads/<sha256(threadId)>`, the fixed loopback URLs and credentials, and the resident environment. That environment contains trusted protected bootstrap settings (including `HOME`) for environment-aware sessions, `TEMP`, `TMP`, and `TMPDIR` fixed to the non-retained `/tmp/openkit-bootstrap`, `NODE_EXTRA_CA_CERTS` copied from an allowlisted `SSL_CERT_FILE`, `npm_config_nodedir` and `NPM_CONFIG_NODEDIR` when the bundled Node prefix contains `include/node/node.h`, `NO_PROXY` and `no_proxy` extended with the fixed `127.0.0.1` bypass, and the session-static runtime environment. A failed open destroys the loopback credentials. It releases the Thread only when native cleanup is proved; otherwise it keeps the Thread reserved and drains the Harness.

A resume carries the predecessor AgentSession id as its locator and the accepted handle digest. The Harness stores the first ready reference an adapter reports under `/sandbox/openkit/native/agent-session-references/<agentSessionId>`, privately and atomically, and the digest is the SHA-256 of those bytes. A resume whose locator has no stored reference is `missing`; one whose stored bytes do not match the digest, or whose runtime does not prove that exact ready handle after opening, is `conflict`. The adapter decides when its conversation carries ready authority; a later different reference is reported as `unknown` and never replaces the stored one.

`turn.start` accepts only the exact AEP and Context references of its AgentSession and the binding's Workspace and Thread (otherwise `stale`), and answers once the runtime accepted the Turn. A binding is established when its handle was ready at open, whether resumed from a proved predecessor or created by the runtime, or when one of its Turns completed; a binding whose handle was pending at open and whose first Turn did not complete, or whose resident host ended on its own, only closes (`conflict`). A host that ends during a Turn fails that Turn; it is not reported as an interrupt. `turn.interrupt` acts only on the exact active Turn and lease before its barrier (otherwise `stale`) and answers after the Turn settled. `session.inspect` reports the handle, host liveness, and cleanup without starting work. `session.close` of an idle binding closes the resident binding, destroys the loopback credentials, removes the AgentSession's input and control directories, and releases the Thread; retained native data and the stored reference stay. `harness.drain` refuses new sessions and Turns and reports the remaining counts. An unproved native stop marks the binding failed with unknown cleanup, retains its Turn occupancy, and drains the Harness. A subsequent interrupt or close that cannot prove cleanup returns `cleanup_required`. A rejected `startTurn` guarantees no live native Turn and returns a typed `dependency_failed` refusal with the closed `native_spawn/failed` startup diagnostic. Unproved Turn input cleanup also invokes that failure/drain fence and retains the occupied cleanup owner, whether the Turn was refused or settled normally. After proved Turn-local route and input cleanup, an established binding remains usable with its original supply and closable for exact successor resume; a pending binding whose first Turn was refused remains non-reusable and only closes. Unproved native acceptance must be returned as a cleanup attempt with rejecting settlement and follows the same bounded stop/fence path.

Pre-native `turn.start` failures return `dependency_failed` with a closed `startupFailure` stage and reason. Raw exceptions, filesystem paths, child output and route credentials are never included in that closed refusal. When worker-control readiness completed, the failed Turn separately preserves the original setup or execution error in the existing final-status `diagnostics.native` summary, redacted for session, Vault and current Turn credentials and common secret patterns, then limited to 1000 characters (within the 16 KiB diagnostic byte bound). When native cleanup is unproved, this summary retains the original cause and the Harness retains its cleanup fence. Stages distinguish package validation, runtime supply, workspace materialization, Integration readiness, worker-control readiness and native start. An empty Git slot first fetches the exact commit with depth 1 using HTTP/1.1. Any completed nonzero fetch then fetches advertised branch tips and tags once, also with HTTP/1.1, including when the refusal text is not a known missing-ref message. A fetch that times out, is signaled, or fails to start does not try that fallback and is `git_fetch_transport_failed`. Checkout proceeds only when `git cat-file -t` reports that the object is a commit. A completed object check whose private result says the object is absent is `git_fetch_commit_unavailable`. A terminal fetch whose private result matches a certificate failure is `git_fetch_tls_failed`. A terminal fetch whose private result matches a proxy, connection, or HTTP/2 framing failure is `git_fetch_transport_failed`. A completed terminal fetch with Git’s HTTP 401/403 refusal phrase is `git_fetch_http_refused`, with observed status and unavailable enforcement attribution. A failed fallback that matches none of these, and every other object-check failure, stay `git_fetch_failed`. When the sandbox provides `SSL_CERT_FILE`, Git receives that same path as both `GIT_SSL_CAINFO` and `CURL_CA_BUNDLE`; ambient CA paths do not win. These reasons do not rewrite host repository diagnostics, and the incomplete slot is left in place. Terminal fetch failures carry a closed normalized explanation through the startup refusal, including producer time, subprocess category, evidence completeness and private stderr truncation. Neither raw stderr nor repository URLs enter that explanation. HTTP refusal is not proof of a sandbox deny or Vault failure; local object checks retain their existing reasons.

## Adapters

`src/adapter-registry.ts` defines the resident adapter contract: `openSession` returns a binding with `startTurn`, `nativeHandle`, `childState`, `close`, and `exited`, and each started Turn has `settled` and `interrupt`. Every Gateway package contains one or more allowed LLM routes and one preferred logical model; the shared shim validates and passes the exact allowed route set with the unique preferred route for this Turn, plus its MCP server ids, Skill targets, working directory, and input. The admitted set is fixed for a binding, while the preferred route may change by Turn; an adapter uses the preferred route for the current Turn and refuses a model outside the admitted set. The shim observes exceptional settlement immediately before asynchronous transcript work, validates every route’s identities, routing-mode authority and complete present model parameters, and drops safe additive fields. A rejected native settlement triggers bounded stop confirmation, and unproved stop retains capacity and Thread ownership through the Harness cleanup fence. The production registry contains the resident Codex App Server v2 adapter `codex`, pinned to `@openai/codex@0.159.2`, the resident DeepSeek adapter `deepseek`, the resident Pi SDK host, and the OpenCode V2 adapter, id `opencode` ([Codex Worker Adapter](../../docs/specs/20260716-codex_worker_adapter.md), [Pi Worker Adapter](../../docs/specs/20260716-pi_worker_adapter.md), [OpenCode Worker Adapter](../../docs/specs/20260716-opencode_worker_adapter.md), [DeepSeek Worker Adapter](../../docs/specs/20260930-deepseek_worker_adapter.md)); the slices were tracked in `docs/changes/202609300021100000-agent_communication_redesign/plan.md`. ## Vault Runtime Environment

`session.open.runtimeEnvironment` supplies the Core-resolved values of the AgentSession's runtime-env declarations; they are session-static inside the resident binding, as [Worker Runtime Communication](../../docs/specs/20260629-worker_runtime_communication_model.md) states. The Harness rejects names it owns, including trusted home/control bindings, `NODE_EXTRA_CA_CERTS`, `NODE_OPTIONS`, `TEMP`, `TMP`, `TMPDIR`, every `OPENKIT_` name, and every casing of `npm_config_nodedir`. Each Turn's AEP must declare exactly the delivered names, or the Turn fails at package validation. The Harness never falls back to its parent environment for these values. The values and both loopback credentials join the exact-value diagnostic, assistant-output and outside workspace-collection credential checks; an assistant message containing one fails the Turn.

## Workspace Initialization And Collection

The Harness reads the imported initial AEP and verifies session scope, root, layout, and static runtime supply inside `session.open`, before native adapter startup. It initializes each new source-less writable worktree as an empty directory. A Git source uses its exact admitted commit; a retained target keeps its original origin and a valid worker HEAD, preserving tracked, untracked, ignored, and worker-committed changes. Core verifies retained source identity against the initial accepted package rather than resetting worker commits. Unsafe paths, incomplete materialization, source conflicts, and unavailable supply return a closed `workspace_materialization` startup refusal without native startup.

NanoCore accepts the outside NanoHost baseline before the first Turn. NanoHost owns read-only snapshot capture and the literal credential check over staged blob bytes; NanoCore owns durable capture pairs, cumulative candidates, and review handoff ([NanoHost Workspace Data Boundary](../../docs/specs/20260801-nanohost_workspace_data_boundary.md), [Workspace Synchronization](../../docs/specs/20260703-workspace_synchronization.md)). The shim has no workspace publisher, patch generator, manifest writer, or compatibility reader.

## Public Native Environment

`session.open.nativeEnvironment` captures the exact admitted public map separately from private credential settings. Every Turn checks its AEP values against that immutable capture; missing, changed or sibling delivery fails before native work. The Harness rejects protected names and credential collisions, excludes ambient ordinary settings from environment-aware children, and merges fixed bindings and private credentials only into the addressed native child. The launcher retains `env -i` and fixed native executable selection. Benign vendor names and native `PATH` remain settings. Public values are not secret-redaction inputs or Vault injection receipts. `native-child-environment.test.ts` samples benign settings inside real Pi/OpenCode processes through the Harness and checks a sibling and the parent separately.

Codex admission and launch share the worker-protocol protected-name predicate. The launch check uses its Codex-specific projection because the Harness supplies trusted shared bootstrap bindings such as `HOME` and `TMPDIR`. Unused selectors (`CODEX_ARGS`, `CODEX_BIN`, `CODEX_EXECUTABLE`) and harmless `OPENAI_` names such as `OPENAI_LOG` pass through to the fixed binary. DeepSeek keeps its four existing managed names; its pinned ACP profile and explicit loopback overlay establish the protected routing and home boundary.

Pi and DeepSeek project only `text` and `image` from complete route modality metadata and report omitted `audio`, `video` or `pdf` in bounded result diagnostics. A native model subset without `text` is refused before inference; Codex and OpenCode preserve their complete modality contract.

The package reader validates `llm.reasoningEffort` and each present route's `reasoningEffortLevels` with `@openkit/protocol`, retaining absence and empty lists. Presence of levels declares a reasoning route; the advertised subset never limits native delivery. Unknown values fail before native Turn effects. Codex sends the exact recorded string in `turn/start.effort`. Pi sends it over the existing private host channel and maps `none` to native `off` before prompting. OpenCode declares all seven variants and waits for the selected model/variant to be proved. DeepSeek declares all seven `llm-pi-ai` levels and verifies ACP `reasoning_effort` selection, mapping `none` to `off`. Pi and DeepSeek declare `off: "none"` and identity mappings for the other six, with native Chat effort compatibility enabled.

An omitted effort invokes no effort setter. A model change follows native model selection without reapplying a previous effort. Result diagnostics report the effective native selection or `unknown` when it cannot be proved, and report `not-delivered: model has no reasoning` for routes without levels. This is Turn-local evidence, never a durable adapter effort cache or global native default. Native selection failures retain each adapter's existing stop, cleanup and fencing path.
