# LLM

This directory owns LLM Gateway behavior, provider dispatch, upstream clients and adapters, provider-subscription accounts, public OpenAI-compatible projection, and usage observation.

NanoCore pins pi-ai `0.99.2` and consumes the vendored models.dev `2026-10-01` snapshot. The adapter supplies `Context` to the stock `Models` entry points; provider callbacks receive normalized `TranscriptContext`, with prompts and tools carried by system messages. Conformance fixtures inspect those declarations through the stock transcript accessors.

## Boundaries

- Keep Gateway routes, dispatch, direct public-format mapping and native admission, upstream error normalization, provider-subscription account state, and prompt-cache behavior here.
- Family `llm` CapabilityCall rows opened at public Gateway and worker-inference entry (`capabilityId` `llm.chat_completions` or `llm.responses`) carry a pre-adapter system-prompt digest of the prompt Core intended, including an absent prompt, before any stock mapping is selected. Knowledge, MCP, git-push, worker-checkpoint, administration, workspace-transfer, Goal propose-tool, and other family-llm usage rows such as Quick Chat have no system prompt at this boundary and do not carry this digest. Public Gateway requests with no workspace database or no lineage open no CapabilityCall and therefore carry no digest.
- Publish logical model IDs only. Private Provider profile and native model route members remain Gateway-owned. The pinned models.dev inventory supplies optional metadata, not model-ID admission. Provider-scoped `modelMetadata` overlays share one effective resolver between logical-model selection and adapter construction, with explicit false/zero precedence and no shared stock-model mutation. Mixed or unknown families permit multiple authored members; their shared family is null unless every member with known metadata names the same family. Discovery lists a logical model while at least one member is available; configured IDs remain valid when supply disappears.
- Explicit Codex and xAI subscription model IDs newer than the stock adapter inventory use request-local models built from effective Provider metadata and the selected account pair's existing transport. The adapter strips only the matching `openai-codex/` or `xai/` namespace before sending the API model ID; it neither aliases to another model nor mutates the pair catalog. Missing context or an undeclared model remains a configuration error. Unknown prices omit observed USD cost rather than inheriting another model's rates.
- `gateway-execution.ts` owns request-local selection and execution shared by public Gateway, worker inference and internal roles. Unavailable or pinned-capability-ineligible members are excluded before Provider attempts; `routing.autoFailover: false` keeps backups dormant. No request changes durable routing or the next request's primary.
- `../providers/` is the single owner of configured provider instances, profiles, credential references, and readiness projection.
- `../capability/` owns durable capability-call and usage ledger operations; LLM code records observations through that owner.
- Consume resolved credentials without serializing secret-bearing configuration or creating a second provider vocabulary.
- Provider-native payloads remain private while public responses preserve the documented OpenAI-compatible contract and redaction rules.
- Carry request cancellation through the dispatcher, upstream clients, stream converters, usage observers, route responses, and durable capability-call termination without allowing a late disconnect to rewrite an independent provider failure.
- Preserve the known `provider_stream_truncated` and `provider_stream_failed` diagnostics on failed capability calls. Public Gateway JSON and SSE retain their fixed redacted error classes; these diagnostics neither prove an upstream root cause nor make an incomplete stream successful.
- Preserve typed pre-response `unsupported_gateway_feature` failures in the capability ledger. Gateway JSON uses a fixed message without bridge feature text. Failed Worker closeout projects this known category from the latest exact Turn, AgentSession and package call into the existing Turn error for Web, remote MCP and the administrator CLI, with guidance to choose a compatible model route and start a new Task. Cancellation keeps its own category; a later successful inference call supersedes an earlier unsupported failure, and arbitrary error-code lookalikes remain generic.
- Preserve `x-codex-turn-state` only through the pi-ai native Responses transport and the internal worker response boundary. Ordinary pi-ai providers never receive or publish this Codex-private state.
- Preserve the optional canonical `at_` UUIDv5 identity on the Codex Responses Lite additional-tools prefix and admit local custom or function tools at the root or inside one namespace level; malformed identities, deeper namespaces, provider-executed tools, unknown fields, and duplicate callable keys fail before provider access.
- Normalize native default tool namespace identity, reject alias collisions, and wait for completed tool identity when a streamed item omits its namespace.
- Preserve admitted Codex native input through pi-ai's payload callback, lower exact client tool search through the reserved provider-private function, activate validated discovered definitions immediately after the matching result, and reconstruct the public search, function, custom, and namespace shapes without granting execution authority.
- Internal worker inference accepts only its distinct inference-family live token plus the narrow transport contract; the authenticated AEP owns logical-model admission, admitted context/output minimums, and durable lineage; current members below those known minimums are excluded before Provider attempts. Privileged request fields remain server-owned, and worker-control or sandbox-binding values cannot authenticate inference. After closed-vocabulary validation, Worker Responses retain their admitted top-level local tools; the Pi boundary selects native local-tool admission from the resolved upstream API and member capability. Cross-protocol mappings retain standard function definitions without wrapping or clearing them.
- `worker-inference-runtime-hint.ts` validates the existing normalized `WorkerInferenceRuntimeHint` contract against the authenticated AEP runtime. The bound worker adapter owns native parsing; Integration removes its consumed native fields and carries only `openkit_runtime_hint`, which Core consumes and strips before provider dispatch. Raw native ids and cache lineage are neither forwarded nor persisted.
- `provider-subscription-accounts.ts` owns the internal strict account metadata, exact Core and encrypted-Vault classification, pair-scoped credential store and stock pi-ai runtime, mutation fence, reconciliation, and redacted lifecycle audit boundary for `openai-codex` and `xai`.
- `codex-quota.ts` projects positive reported window durations as optional `limitWindowSeconds` and implements the current strict direct Codex quota reader, distinguishing HTTP 401 rejection of the still-selected credential from transient failures without refresh or account mutation; `xai-quota.ts` implements the strict xAI account/credits reader and independent lazy auto-top-up read; [Provider Subscription Accounts](../../../../docs/specs/20260721-provider_subscription_accounts.md) owns their behavior.
- `provider-subscription-operation-implementations.ts` exposes the deployment-admin App API for both supported provider families, and every production Gateway path dispatches through `PiAiGatewayClient`.

`model-capture.ts` verifies the Store-admitted Turn and persisted coverage before internal model work, owns the scoped Workspace database lifetime, and sends admitted semantic request/response content to the shared work-observation writer. The dispatcher captures the admitted semantic request in its caller public format before cache-key injection and stock Context/options mapping, so retained sampling describes the admitted request even when full I/O capture is off; the [First-Release Capture Matrix](../../../../docs/specs/20260921-work_data_retention_format.md#first-release-capture-matrix) owns this boundary. Quick Chat, Goal planning, and Administration pass its trusted context through their existing provider calls. Public and Worker Gateway calls derive their capture context from authenticated CapabilityCall and Worker lineage instead of a Store entry; both paths verify the persisted Turn binding through `ModelCapture`. `model-semantic-content.ts` selects outward text and tool events before public conversion can defer or discard partial results. Capture failure is distinct from provider failure and must not trigger fallback; CapabilityCall and usage remain their existing owners.

`withTurnModelCapture` accepts optional `environment: { systemPrompt, tools }` from internal Chat and Administration entry owners. After verifying the admitted Turn, it commits one Core `env.bound` observation before invoking the model effect, even with full I/O capture off. It retains the NanoCore package version, Workspace identity, the existing prompt digest over the supplied instructions, and ordered Tool names plus lowercase SHA-256 hex digests of serialized input schemas. It writes no prompt, schema, description or body. Exact Turn re-entry uses the persisted admission timestamp and the existing writer's duplicate/conflict rules; a missing timestamp or required retention failure is `ModelCaptureError`. Callers without environment input, including Goal planning, keep their existing behavior.

Requested sampling retains only fields supplied at the dispatcher-to-Pi boundary, as required by [Environment Binding And Cause](../../../../docs/specs/20260921-work_data_retention_format.md#environment-binding-and-cause). Undefined values stay omitted; explicit zero and null values remain unchanged. The canonical sampling schema accepts both omitted fields and retained null slots, so existing observations stay readable without rewriting their bytes or filling adapter defaults.

## Verification

Run the focused Gateway, dispatcher, upstream client, provider-subscription, usage, mapping, and prompt-cache tests affected by the change, followed by the package gates in the [NanoCore source guide](../README.md).

The chat-native Responses bridge reuses pi-ai context and event projection for standard and message-anchored function tools, including one-level namespaces. A request-local inverse preserves native identity across provider-safe names, history and streamed/non-streamed output; namespace descriptions prefix member descriptions. It preserves complete function-call/result history and developer instructions; collisions, undeclared output, custom tools, deferred declarations and tool search fail closed.

Native Responses text preserves the stock parser's message identity and optional `commentary`/`final_answer` phase through streamed completion and subsequent tool-result replay. Because the pinned parser publishes that metadata at `text_end`, native text items wait for that event before emitting their consistent item and content frames; chat-provider text keeps incremental delivery. Post-start Responses errors use `response.failed` with the existing fixed redacted error envelope so worker clients receive a terminal cause instead of an unexplained EOF.

`pi-ai-failure.ts` classifies original thrown adapter evidence and terminal assistant errors into the Gateway's closed failure value. Provider refusal requires a refusal stop reason or a recognized filter/safety code; transport wording such as `connection refused` stays transient. Terminal categories precede stock `isRetryableAssistantError` so its broad numeric and timeout patterns cannot override their evidence. The executor reads the non-enumerable `failure` property on the error thrown by non-streaming calls or rejected by stream reads; the dispatcher preserves it. `status`, `providerCode`, and raw `retryAfter` are included only when exposed by the adapter. The adapter never manufactures upstream HTTP status. The public envelope projects stable codes, fixed messages and closed-kind exhaustion causes; local subscription and credential resolution retain their exact Error Contract mappings. Stock pi-ai can flatten provider throws into text-only terminal messages, so unavailable metadata stays absent. Length finishes and readable refusal results stay protocol results. Provider retries and vendor fallback remain unset. The `settled` boolean authorizes replay only with an exposed Provider HTTP status, a retained recognized Provider rejection code (including inline codes in a stock terminal result), explicit Provider refusal evidence, or proven pre-send failure (connection refused, DNS failure or connect timeout). Rejection codes come from the classifier’s existing Provider vocabulary; a kind inferred from plain wording alone is not replay evidence. A stock terminal assistant-error wrapper supplies no delivery proof and defaults to unsettled. Stock retryable transport wording, including network, connection, upstream-connect, socket, timeout, WebSocket and premature-stream families, preserves its kind with `settled: false` unless affirmative Provider response/rejection evidence or a proven pre-send branch applies. Generic load/server wording and numeric status text alone also supply no settlement proof. No-output is never replay evidence.

`gateway-execution.ts` retries settled `rate_limited` and `provider_unavailable` failures at most three times (1, 2 and 4 seconds), independently of failover. Settled authentication and quota failures advance only when failover is enabled; other closed kinds terminate. A valid Retry-After replaces a computed delay only when at most 10 seconds and strictly within the remaining deadline; longer waits are never shortened. One absolute 120-second pre-commit deadline bounds attempts and waits, with a 32 KiB lifecycle buffer. Live deadline or cap expiry commits without killing the Provider; known held failures fail privately. Lifecycle events and worker heartbeats become public only when text, reasoning, tool output or a validated terminal protocol result commits, or a live cap/deadline commits. A committed attempt never retries or advances, and the deadline never cuts its stream. Caller cancellation reaches active adapter work and retry waits. The pi-ai client classifies a terminal failure before publishing terminal usage or invoking terminal semantic observers. Its non-stream abort race keeps an already observed Provider failure if a callback aborts afterward; cancellation before that observation retains the caller’s exact reason. An aborted request never retries or advances in either ordering. Terminal error results fail before non-stream release; length/incomplete and readable refusal results retain their protocol meaning. Enabled failover exhaustion exposes the terminating attempt’s closed OpenKit kind as `error.cause` beside the fixed message, type and code. Selection without an available member omits `cause`; disabled failover and request-terminal failures retain their own classified errors without a public cause. Provider text and identity never enter the cause. Attributed consumers open one logical CapabilityCall before planning and retain private route lineage through the shared dispatcher; same-member retries and failover append to that call. Public caller request IDs already present in the ledger are refused before Provider access. Unattributed requests retain only request-local selection. The optional absolute transport deadline uses the executor wall clock and is passed to inference clients without imposing a stream timeout. Missing terminal stream evidence retains an unknown attempt result and the existing truncation diagnostic.

`reasoning-attribution.ts` owns a shared process-local, payload-free association with a fixed 4,096-entry ceiling and LRU eviction. Only returned Responses reasoning identities create entries, keyed by Provider profile id and native model id rather than logical route id. Matching history retains its opaque payload; another profile/model, an external or conflicting identity, eviction, and restart receive ordinary assistant reasoning text with ciphertext/signature and paired `fc_` ids omitted. Empty or redacted reasoning is omitted. Native payload restoration and pi-ai context use the same handoff, and outward Responses items gain no field. Multiple clients and logical routes share the process association; restart loses it.

Synthetic text and reasoning item ids use one UUID namespace per response, shared by every stream frame and its terminal payload. Content indices alone collide across requests and can replace earlier conversation items, causing native clients to select an intermediate message as the final answer. Native ids and tool-call identities remain unchanged.

Deployment extension metadata reaches the shared resolver through loaded Provider metadata. Snapshot → extension → profile leaf precedence applies equally to Gateway contracts and request-local adapter models. Missing context still fails closed; the resolver does not impose a second context cap.

The logical-model resolver preserves every ordered authored member with current availability and a fixed reason. Mixed or unknown families resolve with a shared-or-null family; the coherent contract uses minimum known context/output limits, intersected capabilities and input modalities, and reasoning only when every member with known metadata declares it. Absent profiles and delisted models constrain none of these fields; when no metadata is known, capabilities are empty and parameters are absent. Complete `modelParameters` reach admitted worker supply when required values are known. Missing required values omit that projection. Known limits constrain compaction even on unavailable members; absent profiles and delisted models contribute no metadata. Discovery hides models without available members, while their configured IDs remain valid. `routing.autoFailover` defaults to true; false selects only the primary. Subscription availability reuses the account manager's non-secret pair inspection and non-resolving Vault health; it never resolves a secret or writes a Vault-use record. Unverifiable accounts become unavailable only on their own members, while account-owner reads retain integrity errors. Before the account owner exists, resolution reports only configuration facts and does not warn about missing subscription supply. Gateway discovery, dispatch, deployment diagnostics and reload also inspect required API-key presence through the provider credential owner: unresolved references and absent or revoked Core Vault references make the member unavailable with `provider_api_key_missing`. The check shares dispatch fallback resolution, never resolves Vault material or records use, and keeps an active reference configured even while Vault is locked. Internal-role callers pass both live availability dependencies; Agent setup omits them and Worker inference recomputes availability before dispatch.

The xAI observation preserves missing usage, explicit zero, actual current periods, and optional signed USD-cent balances. Successful same-call user discovery may remain visible when billing fails. Auto-top-up requires its own bounded discovery and rule request, never a payment-method inference or billing mutation. All reads remain deployment-admin and pair-scoped; remote MCP, the administrator CLI and Web use the same public schemas.

`logical-models.ts` reads toggle and effort `reasoning_options` from the pinned snapshot beneath extension and profile replacement arrays; token-budget entries do not contribute effort levels. `reasoningEffortLevels` uses the Core protocol order and intersects all currently available members. A reasoning member without options contributes an empty set, so one such available member empties the intersection. Without reasoning on every available member, the control is absent. Availability changes recompute the projection on the next resolver call without retained level state. Public discovery projects that current list, including empty options and absent non-reasoning control, on every request; safe route activation and restart use the active resolver snapshot.

Account deletion does not consult Provider bindings. It marks pending login as settling under the pair fence, invokes the existing cancellation path outside that fence and awaits settlement, then revokes the latest backend credential, commits the exact Core cascade and removes account metadata under the fence. Existing partial-removal and repeat-delete integrity predicates remain binding; referencing profiles and routes remain unchanged.

The private `openkit.gateway/routeLineage` extension records plan exclusions, pre-dispatch checks and reached callbacks through the Workspace ledger. Usage references cite retained equivalent measurements; call Provider references stay null while measurements retain the measured member. Entries contain no account-slot identity or raw Provider error. The Workspace audit reader exposes only the authorized redacted route explanation; export and import preserve canonical lineage and the gateway-entry system-prompt digest.

The shared public/Worker stream normalizer carries a released failed terminal frame’s fixed Gateway code into logical closeout. EOF does not turn that failure into success, and no committed stream replays or fails over; legal incomplete protocol finishes keep their existing meaning. Terminal codes are restricted to the existing Gateway vocabulary and inner diagnostics, with an existing fixed fallback for unknown code text.

Pair handles retain one process-local inference observation for their exact current Vault reference and material version, separate from durable account status. The inference client resolves stock auth once inside the stock stream setup boundary, passes it directly to the selected Provider, and passes classified outcomes back to that existing owner. Stock auth or refresh failure terminates the attempt; optional attribution failure leaves its resolved auth in control. Credential reads and refresh writes carry their exact fenced material version through stock OAuth derivation as private request-local metadata, so refreshed failures remain observable while identical-byte replacements are suppressed. A replaced version, logout or deletion discards the observation; accepted uncancelled inference or quota reads clear access rejection, while only an available same-version quota read clears quota exhaustion. Account list and detail expose the optional `inferenceObservation` member with independent timestamps for `accessRejected` and `quotaExhausted`, without an upstream request. The quota union continues to describe its live result with no observation overlay. Missing observation remains unknown. Codex and xAI rejection proofs take the original absolute request deadline and suppress changed, unreadable or late credentials. The Codex quota reader shares its equality proof; the xAI reader requires a pair-owned version callback to admit a same-bearer rejection. Public, Worker, internal-agent and Quick Chat inference forward the executor's original absolute deadline to the account rejection proof, without adding a stream timeout. Calls without a deadline cannot record access rejection. See [Inference And Same-Credential Observations](../../../../docs/specs/20260721-provider_subscription_accounts.md#inference-and-same-credential-observations).

Gateway request admission validates Responses `reasoning.effort` and Chat Completions `reasoning_effort` with the Protocol enum before Provider effects, including Worker inference. Explicit native request effort precedes the immutable bound Turn value: Worker inference reads its authenticated AEP projection, and public Turn-bound inference reads the exact persisted admission through the existing observation binding reader. Unbound requests use only their submitted value. Current Agent defaults never supply a bound inference fallback. Omission preserves the native request's existing shape and does not reset a runtime's retained conversation selection. The pi-ai adapter uses the same Protocol schema for native Responses admission. Effort-bearing attempts select the stock native entry with `reasoningEffort` for the serializer-proven APIs `openai-completions`, `openai-responses` and `openai-codex-responses`, preserving the caller's output cap; every other API uses the stock simple entry with canonical `reasoning`, across ordinary, subscription and tool-aware paths. Native `openai-completions` represents canonical `none` by omitting `reasoningEffort` before handoff and, only when its selected model leaves `thinkingLevelMap.off` undefined, handing stock an attempt-local model copy with `off: "none"`; existing string/null off mappings and registered catalogs remain unchanged. Stock owns the resulting disabled wire form; native Responses and Codex retain literal `none`, and the handed effective fact remains canonical `none`. Azure OpenAI Responses and Mistral Conversations remain on the simple fallback pending stock-serializer regression coverage. For Anthropic thinking the simple entry can raise the request's output cap by the thinking budget, bounded by the model maximum, and omits temperature. An attempt without effort keeps the native options and entry unchanged.

The shared dispatcher fits each reached member against the existing resolver's member levels in Core order, unchanged when supported, otherwise upward first and highest-supported when no higher level exists. Non-reasoning members drop effort; reasoning members with no declared levels use their Provider default. This request-local fitting leaves routing, admission and retry/commit rules unchanged. Effective facts describe the control OpenKit handed to stock pi-ai after its own admission, validation and option construction; OpenKit pre-handoff refusals carry none, while stock-internal failures, including auth or refresh failures, retain the handed control. Attempt facts distinguish the effort actually carried by the native request from the effective control handed to the stock adapter after fitting; a Turn fallback does not fabricate a requested value, and unavailable entries have no effort facts. The dispatcher supplies descriptive absent-value reasons `model_without_reasoning`, `provider_default_no_options` and `provider_default_no_effort` to the existing lineage writer. The recognized Gateway namespace validates both effort facts with the Protocol enum and the three absent-value reasons with a closed implementation enum; each fact remains optional. The `audit.read` projection retains its owner-listed route explanation fields and omits all three effort facts.

Native Codex public inference accepts object-valued `metadata` for Gateway attribution and retains its CapabilityCall and private lineage. The shared Responses admission entry validates this field for both dispatcher preflight and client admission, then excludes it from native field checks; native Provider options and payloads omit it. Both direct public formats reuse this validation before Provider access. Malformed metadata keeps the existing unsupported-feature diagnostic at adapter admission, while public authority may reject unscoped metadata before that boundary.

`PiAiGatewayClient` maps each Chat or Responses request directly to stock Context and options and projects stock results or events directly to the requested public format, with or without tools. Chat carries readable non-redacted thinking as `reasoning_content`; completion reconciles already published reasoning and function arguments without duplicate bytes, and conflicting completions or duplicate call identities fail. Responses preserves native reasoning boundaries and attributed opaque replay through stock thinking signatures; other producers and formats receive readable content only. One attempt-local native envelope supplies admitted native input, declarations and missing controls through `onPayload`, and supplements only unrepresented native reasoning/search output and native identity and index metadata through `onProviderStreamEvent`. Stock blocks do not retain wire output indices; the same envelope supplies those indices so terminal-only reasoning can precede an already published native message without renumbering it. Admission uses the selected model API and member capability, never a Provider or subscription name. Length remains `length` in Chat and `incomplete` in Responses. Cancellation, terminal failure classification, usage exactly once, private capture, executor commitment and Codex transport continuity retain their existing owners. The convergence and stock-parser tests exercise these paths without credentialed Provider effects.

`provider-subscription-operation-implementations.ts` exports the dependency-built exact map for eleven canonical subscription operations. The existing account manager retains pair-scoped metadata, Vault, login, quota and credential ownership; the family projects only sanitized account bindings and safe known errors. Account deletion returns logical `null`, projected as bodyless HTTP 204.

Both public mappings share the request-local payload overlay for caller controls omitted by the resolved stock serializer: Codex Responses receives an explicit output cap and parallel-call selection, while Anthropic Messages receives its native parallel-tool flag without replacing the selected tool choice. Other APIs receive the admitted parallel-call selection through generic options; a stock serializer that omits the handed control is an [accepted external limitation](../../../../docs/decisions/20261002-external_provider_behavior_accepted.md), including Google Generative AI, so acceptance does not promise remote enforcement of `false`. Stock serializers retain ownership of caps and parallel controls they already carry. Streamed Responses text items admit the projector's empty `annotations` and `logprobs` arrays on continuation; populated or malformed metadata and unknown text-content fields remain unsupported.
