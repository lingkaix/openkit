# LLM

This directory owns LLM Gateway behavior, provider dispatch, upstream clients and adapters, provider-subscription accounts, public OpenAI-compatible projection, and usage observation.

NanoCore pins pi-ai `0.99.2` and consumes the vendored models.dev `2026-10-01` snapshot. The adapter supplies `Context` to the stock `Models` entry points; provider callbacks receive normalized `TranscriptContext`, with prompts and tools carried by system messages. Conformance fixtures inspect those declarations through the stock transcript accessors.

## Boundaries

- Keep Gateway routes, dispatch, native and bridged request handling, upstream error normalization, provider-subscription account state, and prompt-cache behavior here.
- Family `llm` CapabilityCall rows opened at public Gateway and worker-inference entry (`capabilityId` `llm.chat_completions` or `llm.responses`) carry a pre-adapter system-prompt digest of the prompt Core intended, including an absent prompt, before any client or converter is selected. Knowledge, MCP, git-push, worker-checkpoint, administration, workspace-transfer, Goal propose-tool, and other family-llm usage rows such as Quick Chat have no system prompt at this boundary and do not carry this digest. Public Gateway requests with no workspace database or no lineage open no CapabilityCall and therefore carry no digest.
- Publish logical model IDs only. Private Provider profile and native model route members remain Gateway-owned. The pinned models.dev inventory supplies optional metadata, not model-ID admission. Provider-scoped `modelMetadata` overlays share one effective resolver between logical-model selection and adapter construction, with explicit false/zero precedence and no shared stock-model mutation. Mixed or unknown families permit multiple authored members; their shared family is null unless every member with known metadata names the same family. Discovery lists a logical model while at least one member is available; configured IDs remain valid when supply disappears.
- Explicit Codex and xAI subscription model IDs newer than the stock adapter inventory use request-local models built from effective Provider metadata and the selected account pair's existing transport. The adapter strips only the matching `openai-codex/` or `xai/` namespace before sending the API model ID; it neither aliases to another model nor mutates the pair catalog. Missing context or an undeclared model remains a configuration error. Unknown prices omit observed USD cost rather than inheriting another model's rates.
- `gateway-execution.ts` owns request-local selection and execution shared by public Gateway, worker inference and internal roles. Unavailable or pinned-capability-ineligible members are excluded before Provider attempts; `routing.autoFailover: false` keeps backups dormant. No request changes durable routing or the next request's primary.
- `../providers/` is the single owner of configured provider instances, profiles, credential references, and readiness projection.
- `../capability/` owns durable capability-call and usage ledger operations; LLM code records observations through that owner.
- Consume resolved credentials without serializing secret-bearing configuration or creating a second provider vocabulary.
- Provider-native payloads remain private while public responses preserve the documented OpenAI-compatible contract and redaction rules.
- Carry request cancellation through the dispatcher, upstream clients, stream converters, usage observers, route responses, and durable capability-call termination without allowing a late disconnect to rewrite an independent provider failure.
- Preserve the known `provider_stream_truncated` and `provider_stream_failed` diagnostics on failed capability calls. Public Gateway JSON and SSE retain their fixed redacted error classes; these diagnostics neither prove an upstream root cause nor make an incomplete stream successful.
- Preserve typed pre-response `unsupported_gateway_feature` failures in the capability ledger. Gateway JSON uses a fixed message without bridge feature text. Failed Worker closeout projects this known category from the latest exact Turn, AgentSession and package call into the existing Turn error for Web and Skill, with guidance to choose a compatible model route and start a new Task. Cancellation keeps its own category; a later successful inference call supersedes an earlier unsupported failure, and arbitrary error-code lookalikes remain generic.
- Preserve `x-codex-turn-state` only through the pi-ai native Responses transport and the internal worker response boundary. Ordinary pi-ai providers never receive or publish this Codex-private state.
- Preserve the optional canonical `at_` UUIDv5 identity on the Codex Responses Lite additional-tools prefix and admit local custom or function tools at the root or inside one namespace level; malformed identities, deeper namespaces, provider-executed tools, unknown fields, and duplicate callable keys fail before provider access.
- Normalize native default tool namespace identity, reject alias collisions, and wait for completed tool identity when a streamed item omits its namespace.
- Preserve admitted Codex native input through pi-ai's payload callback, lower exact client tool search through the reserved provider-private function, activate validated discovered definitions immediately after the matching result, and reconstruct the public search, function, custom, and namespace shapes without granting execution authority.
- Internal worker inference accepts only its distinct inference-family live token plus the narrow transport contract; the authenticated AEP still owns provider/model selection and durable lineage, privileged request fields remain server-owned, and worker-control or sandbox-binding values cannot authenticate inference. After closed-vocabulary validation, Worker Responses local tools use the exact message-anchored prefix only for the resolved `openai-codex` family; other providers retain admitted standard top-level tool definitions without wrapping or clearing them.
- `worker-inference-runtime-hint.ts` validates the pinned Codex 0.153.4 canonical turn metadata, cross-checks its request-body and header projections, normalizes sub-agent kind, and strips native ids and cache lineage instead of forwarding or persisting them.
- `provider-subscription-accounts.ts` owns the internal strict account metadata, exact Core and encrypted-Vault classification, pair-scoped credential store and stock pi-ai runtime, mutation fence, reconciliation, and redacted lifecycle audit boundary for `openai-codex` and `xai`.
- `codex-quota.ts` projects positive reported window durations as optional `limitWindowSeconds` and implements the current strict direct Codex quota reader, distinguishing HTTP 401 rejection of the still-selected credential from transient failures without refresh or account mutation; `xai-quota.ts` implements the strict xAI account/credits reader and independent lazy auto-top-up read; [Provider Subscription Accounts](../../../../docs/specs/20260721-provider_subscription_accounts.md) owns their behavior.
- `provider-subscription-routes.ts` exposes the deployment-admin App API for both supported provider families, and every production Gateway path dispatches through `PiAiGatewayClient`.

`model-capture.ts` verifies the Store-admitted Turn and persisted coverage before internal model work, owns the scoped Workspace database lifetime, and sends admitted semantic request/response content to the shared work-observation writer. The dispatcher captures its converted request before cache-key injection and Pi adaptation, so retained sampling describes the same request passed to Pi even when full I/O capture is off; the [First-Release Capture Matrix](../../../../docs/specs/20260921-work_data_retention_format.md#first-release-capture-matrix) owns this boundary. Quick Chat, Goal planning, and Administration pass its trusted context through their existing provider calls. Public and Worker Gateway calls derive their capture context from authenticated CapabilityCall and Worker lineage instead of a Store entry; both paths verify the persisted Turn binding through `ModelCapture`. `model-semantic-content.ts` selects outward text and tool events before public conversion can defer or discard partial results. Capture failure is distinct from provider failure and must not trigger fallback; CapabilityCall and usage remain their existing owners.

`withTurnModelCapture` accepts optional `environment: { systemPrompt, tools }` from internal Chat and Administration entry owners. After verifying the admitted Turn, it commits one Core `env.bound` observation before invoking the model effect, even with full I/O capture off. It retains the NanoCore package version, Workspace identity, the existing prompt digest over the supplied instructions, and ordered Tool names plus lowercase SHA-256 hex digests of serialized input schemas. It writes no prompt, schema, description or body. Exact Turn re-entry uses the persisted admission timestamp and the existing writer's duplicate/conflict rules; a missing timestamp or required retention failure is `ModelCaptureError`. Callers without environment input, including Goal planning, keep their existing behavior.

Requested sampling retains only fields supplied at the dispatcher-to-Pi boundary, as required by [Environment Binding And Cause](../../../../docs/specs/20260921-work_data_retention_format.md#environment-binding-and-cause). Undefined values stay omitted; explicit zero and null values remain unchanged. The canonical sampling schema accepts both omitted fields and retained null slots, so existing observations stay readable without rewriting their bytes or filling adapter defaults.

## Verification

Run the focused Gateway, dispatcher, upstream client, provider-subscription, usage, converter, and prompt-cache tests affected by the change, followed by the package gates in the [NanoCore source guide](../README.md).

The chat-native Responses bridge reuses pi-ai context and event projection for standard and message-anchored function tools, including one-level namespaces. A request-local inverse preserves native identity across provider-safe names, history and streamed/non-streamed output; namespace descriptions prefix member descriptions. It preserves complete function-call/result history and developer instructions; collisions, undeclared output, custom tools, deferred declarations and tool search fail closed.

Native Responses text preserves the stock parser's message identity and optional `commentary`/`final_answer` phase through streamed completion and subsequent tool-result replay. Because the pinned parser publishes that metadata at `text_end`, native text items wait for that event before emitting their consistent item and content frames; chat-provider text keeps incremental delivery. Post-start Responses errors use `response.failed` with the existing fixed redacted error envelope so worker clients receive a terminal cause instead of an unexplained EOF.

`pi-ai-failure.ts` classifies original thrown adapter evidence and terminal assistant errors into the Gateway's closed failure value. Provider refusal requires a refusal stop reason or a recognized filter/safety code; transport wording such as `connection refused` stays transient. Terminal categories precede stock `isRetryableAssistantError` so its broad numeric and timeout patterns cannot override their evidence. The executor reads the non-enumerable `failure` property on the error thrown by non-streaming calls or rejected by stream reads; the dispatcher preserves it. `status`, `providerCode`, and raw `retryAfter` are included only when exposed by the adapter. The adapter never manufactures upstream HTTP status. The public envelope projects stable codes, fixed messages and closed-kind exhaustion causes; local subscription and credential resolution retain their exact Error Contract mappings. Stock pi-ai can flatten provider throws into text-only terminal messages, so unavailable metadata stays absent. Length finishes and readable refusal results stay protocol results. Provider retries and vendor fallback remain unset. The `settled` boolean authorizes replay only with an exposed Provider HTTP status, a retained recognized Provider rejection code (including inline codes in a stock terminal result), explicit Provider refusal evidence, or proven pre-send failure (connection refused, DNS failure or connect timeout). Rejection codes come from the classifier’s existing Provider vocabulary; a kind inferred from plain wording alone is not replay evidence. A stock terminal assistant-error wrapper supplies no delivery proof and defaults to unsettled. Stock retryable transport wording, including network, connection, upstream-connect, socket, timeout, WebSocket and premature-stream families, preserves its kind with `settled: false` unless affirmative Provider response/rejection evidence or a proven pre-send branch applies. Generic load/server wording and numeric status text alone also supply no settlement proof. No-output is never replay evidence.

`gateway-execution.ts` retries settled `rate_limited` and `provider_unavailable` failures at most three times (1, 2 and 4 seconds), independently of failover. Settled authentication and quota failures advance only when failover is enabled; other closed kinds terminate. A valid Retry-After replaces a computed delay only when at most 10 seconds and strictly within the remaining deadline; longer waits are never shortened. One absolute 120-second pre-commit deadline bounds attempts and waits, with a 32 KiB lifecycle buffer. Live deadline or cap expiry commits without killing the Provider; known held failures fail privately. Lifecycle events and worker heartbeats become public only when text, reasoning, tool output or a validated terminal protocol result commits, or a live cap/deadline commits. A committed attempt never retries or advances, and the deadline never cuts its stream. Caller cancellation reaches active adapter work and retry waits. The pi-ai client classifies a terminal failure before publishing terminal usage or invoking terminal semantic observers. Its non-stream abort race keeps an already observed Provider failure if a callback aborts afterward; cancellation before that observation retains the caller’s exact reason. An aborted request never retries or advances in either ordering. Terminal error results fail before non-stream release; length/incomplete and readable refusal results retain their protocol meaning. Enabled failover exhaustion exposes the terminating attempt’s closed OpenKit kind as `error.cause` beside the fixed message, type and code. Selection without an available member omits `cause`; disabled failover and request-terminal failures retain their own classified errors without a public cause. Provider text and identity never enter the cause. Attributed consumers open one logical CapabilityCall before planning and retain private route lineage through the shared dispatcher; same-member retries and failover append to that call. Public caller request IDs already present in the ledger are refused before Provider access. Unattributed requests retain only request-local selection. The optional absolute transport deadline uses the executor wall clock and is passed to inference clients without imposing a stream timeout. Missing terminal stream evidence retains an unknown attempt result and the existing truncation diagnostic.

`reasoning-attribution.ts` owns a shared process-local, payload-free association with a fixed 4,096-entry ceiling and LRU eviction. Only returned Responses reasoning identities create entries, keyed by Provider profile id and native model id rather than logical route id. Matching history retains its opaque payload; another profile/model, an external or conflicting identity, eviction, and restart receive ordinary assistant reasoning text with ciphertext/signature and paired `fc_` ids omitted. Empty or redacted reasoning is omitted. Native payload restoration and pi-ai context use the same handoff, and outward Responses items gain no field. Multiple clients and logical routes share the process association; restart loses it.

Synthetic text and reasoning item ids use one UUID namespace per response, shared by every stream frame and its terminal payload. Content indices alone collide across requests and can replace earlier conversation items, causing native clients to select an intermediate message as the final answer. Native ids and tool-call identities remain unchanged.

Deployment extension metadata reaches the shared resolver through loaded Provider metadata. Snapshot → extension → profile leaf precedence applies equally to Gateway contracts and request-local adapter models. Missing context still fails closed; the resolver does not impose a second context cap.

The logical-model resolver preserves every ordered authored member with current availability and a fixed reason. Mixed or unknown families resolve with a shared-or-null family; the coherent contract uses minimum known context/output limits, intersected capabilities and input modalities, and reasoning only when every member with known metadata declares it. Absent profiles and delisted models constrain none of these fields; when no metadata is known, capabilities are empty and parameters are absent. Complete `modelParameters` reach admitted worker supply when required values are known. Missing required values omit that projection. Known limits constrain compaction even on unavailable members; absent profiles and delisted models contribute no metadata. Discovery hides models without available members, while their configured IDs remain valid. `routing.autoFailover` defaults to true; false selects only the primary. Subscription availability reuses the account manager's non-secret pair inspection and non-resolving Vault health; it never resolves a secret or writes a Vault-use record. Unverifiable accounts become unavailable only on their own members, while account-owner reads retain integrity errors. Before the account owner exists, resolution reports only configuration facts and does not warn about missing subscription supply.

The xAI observation preserves missing usage, explicit zero, actual current periods, and optional signed USD-cent balances. Successful same-call user discovery may remain visible when billing fails. Auto-top-up requires its own bounded discovery and rule request, never a payment-method inference or billing mutation. All reads remain deployment-admin and pair-scoped; the Skill and Web use the same public schemas.

`logical-models.ts` reads toggle and effort `reasoning_options` from the pinned snapshot beneath extension and profile replacement arrays; token-budget entries do not contribute effort levels. `reasoningEffortLevels` uses the Core protocol order and intersects all currently available members. A reasoning member without options contributes an empty set, so one such available member empties the intersection. Without reasoning on every available member, the control is absent. Availability changes recompute the projection on the next resolver call without retained level state. Public Gateway advertisement and request fitting are separate integration work.

Account deletion does not consult Provider bindings. It marks pending login as settling under the pair fence, invokes the existing cancellation path outside that fence and awaits settlement, then revokes the latest backend credential, commits the exact Core cascade and removes account metadata under the fence. Existing partial-removal and repeat-delete integrity predicates remain binding; referencing profiles and routes remain unchanged.

The private `openkit.gateway/routeLineage` extension records plan exclusions, pre-dispatch checks and reached callbacks through the Workspace ledger. Usage references cite retained equivalent measurements; call Provider references stay null while measurements retain the measured member. Entries contain no account-slot identity or raw Provider error. The Workspace audit reader exposes only the authorized redacted route explanation; export and import preserve canonical lineage and the gateway-entry system-prompt digest.

The shared public/Worker stream normalizer carries a released failed terminal frame’s fixed Gateway code into logical closeout. EOF does not turn that failure into success, and no committed stream replays or fails over; legal incomplete protocol finishes keep their existing meaning. Terminal codes are restricted to the existing Gateway vocabulary and inner diagnostics, with an existing fixed fallback for unknown code text.
