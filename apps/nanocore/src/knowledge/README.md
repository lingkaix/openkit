# Knowledge Format

This directory owns the portable OKF v0.2 Markdown parser, OpenKit knowledge-profile validation and the immutable notebook content boundary.

## Boundaries

- `okf.ts` parses one YAML frontmatter mapping with bounded aliases, retains nested metadata, derives concept identity, validates reserved Markdown structure and conformance levels, and rejects secret-shaped fields recursively.
- The v4 profile requires a complete `scope` owner mapping and both `openkit.knowledge-owner-scope.v1` and `openkit.knowledge-git-notebook.v1` in `requiredFeatures`. Governed validation rejects unsupported required semantics, parallel `owner_scope` and `openkit_revision` fields; generic external OKF parsing remains permissive. `validateKnowledgePageCandidate` accepts `scopeSchemaText` and `expectedOwnerScope`, and successful schema validation reports `scope-schema-valid` with `scopeSchemaVersion`. The expected owner comes from trusted admission; page metadata grants no permission.
- `notebook-validation.ts` owns structural final-tree validation in the coordinated notebook cutover. Current source disclosure, authorization and publication remain native publisher duties.
- `notebook-publication.ts` joins fixed-base human Workspace edits to the existing Audit and command receipt owners. It retains admission before the Git CAS and completion before success, reconstructs exact old results from their commits, and refuses missing completion evidence. Its native current-authority callback is mandatory. Native Review decisions use the exact retained candidate and preserve original producer attribution separately from the current human actor. Confirmed removals and bounded reversals use the same publisher, create new commits, and retain historical bytes. These joins implement Workspace Git publication; other scoped notebook features remain separate joins.
- Saved Proposal Markdown names its owner scope and exact base/candidate commits; its body is the human-readable rationale. Page bytes resolve from the existing `refs/proposals/<proposalId>` commit. Review input binds that tuple and the exact Proposal document digest. Stale Review returns conflict before a terminal decision or publication. Removal confirmation binds the fixed base, selected path and exact content digest; this is ordinary removal, not the stronger forget/suppression flow.
- `notebook-history.ts` exposes currently authorized published history and exact selected text diffs. A denied revision remains visibly unavailable without its summary, producer or paths. Restore names `baseRevision`, `fromRevision` and `pageIds`, appends a new validated commit through the common publisher, and requires explicit confirmation when the complete selected diff removes published content. Ordinary diff returns at most 256 paths and 64 KiB of UTF-8 text, with `truncated` marking partial display; retained Git bytes stay exact. Diff with `forRestore: true` uses the same human attribution normalization as publication. Oversized restore previews and restores refuse before publication; callers can select fewer paths for complete confirmation. Current Source/audience checks apply to both sides and are repeated before restoration. There is no raw Git endpoint or fallback to materialized files.
- `notebook-entry-publication.ts` projects retained create/update commands into that same publisher, with an explicit fixed base and stable concept path. Their receipts retain the original command identity and immutable commit, without nested notebook receipts. Service timestamps come from the exact admitted candidate on explicit retry; a missing completion receipt remains recovery_required. Native callers retain current admission and exact source disclosure.
- `updateOkfFrontmatter` is the shared YAML edit boundary for changing managed fields while retaining unknown metadata and the selected exact Markdown body.
- Parsed computation, executor, attester, provenance, generation, and verification metadata remains inert data; this directory does not execute code, access networks, attest runs, or grant authority.
- Knowledge routes, ledgers, retrieval, indexes, and portable file storage remain with their existing feature and storage owners.
- `notebook-workspace-portability.ts` joins the existing Workspace archive to one published Git tree. Export checks the complete selected page set under current source authority. Clone/remint changes owned scope/source fields, propagates changed exact page digests through dependent page pins, and initializes a fresh target Notebook under the actual import command. Current-tree retrieval traces bind to that actual target commit only after initialization; original commits remain source provenance. Reserved navigation, unknown metadata and authored bodies remain retained; no live `knowledge/pages/` tree is written. Source commit identity is inert archive provenance, not a target revision or permission. Historical trace closure remains subject to the existing explicit refusal when unavailable.
- Page `source_refs` validation and source-reference indexes share `resolveRegisteredKnowledgeSourceReference`: bare ids require an owning-scope registry target and pins additionally require its matching digest. Registry resolution preserves citation bytes and supplies no review, captured-byte integrity, or retrieval authorization proof.
- `notebook.ts` uses a bare local Git repository for exact immutable page trees, unpublished candidates, published-ref compare-and-set and retained history. Git messages preserve strict historical admission facts; these facts grant no current permission. No working tree, hooks, network or model-supplied Git arguments are exposed. Ordinary Git object publication and expected-old-value ref updates use the supported Git durability configuration, with no custom recursive directory flushing. Git owns its repository internals; product calls do not recursively inspect configuration and object directories or defend against an administrator redirecting them.
- Workspace page commands, reviewed candidates, canonical reads and public history/diff/restore select the same Git notebook authority. Landing the public and Web joins enables these Workspace paths. User and Server Memory, scoped virtual Agent editing and full required-review invocation, forget suppression, and full historical trace and archive disclosure closure remain unfinished; complete Notebook and Memory acceptance is separate.
- Profile/schema v4 is a cutover component, not an independent activation path. All live callers must use the Scope schema API and `schema/scope-schema.yaml` with fresh Git notebook initialization; pre-stable data uses the approved reset boundary without offline conversion. There is no v2 fallback. Notebook Git commits own revisions; pages carry no revision counter.
- Keep parsing deterministic and independent of database, provider, and HTTP concerns.

## Verification

Run `pnpm --filter @openkit/nanocore exec vitest run src/knowledge` and the affected Knowledge Store tests.

See [Research Cookbook](../../../../docs/cookbooks/research.md).

Fresh Workspace Notebook initialization adds the OKF root version and initial navigation before its first Git publication. A valid authored root stays byte exact; a valid body-only initial root receives only the version block. Current Notebook edits keep that version, and Thread storage never repairs materialized page bytes.

Retained trace reads keep their exact Notebook commit and also check current recursive Knowledge source sensitivity and audience. Later source restrictions cannot be bypassed with an older trace. Trace refusals use the existing redacted trace error; no source identity or content appears in the refusal.

Workspace direct-read and dashboard Knowledge counts use the current published Notebook entry projection, so a native publication is visible before restart. Canonical page bytes remain Git-owned; cached Workspace counts do not own this projection.
