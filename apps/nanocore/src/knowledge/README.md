# Knowledge Format

This directory owns the portable OKF v0.2 Markdown parser, OpenKit knowledge-profile validation and the immutable notebook content boundary.

## Boundaries

- `user-memory-agent-maintenance.ts` binds explicit User information and current User Sources to the same bounded KM runner, virtual editor, fixed-base publisher and User command receipts. One private Thread in the existing personal Workspace records fresh runs and required approvals; Workspace Threads are not learning inputs. `user-memory-proposals.ts` retains exact candidates and append-only human Review in the existing User families. Model delivery cannot approve them. `user-memory-schedule.ts` uses the existing daily scan and default-off User setting; missing current authority is a visible failure, not a borrowed stored credential.

- `knowledge-agent.ts` runs a bounded query with the configured Knowledge Manager model, separate role usage and current source checks. Workspace and admitted Server selections keep independent rankings and scope-qualified page IDs. Query Tools cannot select a new scope. The asking capability call retains the delivered answer bytes.
- `knowledge-agent-maintenance.ts` retains fresh Workspace maintenance inputs in existing Turns and uses the virtual editor, fixed-base publisher and real multi-page Proposal/Review. A native Status Item records publication before model continuation. `knowledge-maintenance-command.ts` replays that outcome through existing command receipts without restarting a model or repeating publication. The daily callback reuses the recurring scan; its separate enablement switch defaults off.
- `notebook-proposal-preview.ts` reads the saved candidate inventory and bounded exact before/after parts, with the Proposal digest and fixed commits on every response. It rechecks the full current Source closure of both versions and publishes nothing. Web acceptance requires complete page inspection. Unpublished candidates stay outside generic published history.
- `server-knowledge-owner.ts` reads and captures explicit literal document Sources in the existing Server Source family, using current deployment authority, Core receipts and Audit. Workspace membership alone grants no Server access. Server retrieval uses the existing `page/server` Kernel source and the Server index root. Traces remain in the asking Workspace Thread/Turn. User Memory execution remains a separate join.

- `okf.ts` parses one YAML frontmatter mapping with bounded aliases, retains nested metadata, derives concept identity, validates reserved Markdown structure and conformance levels, and rejects secret-shaped fields recursively.
- The v4 profile requires a complete `scope` owner mapping and both `openkit.knowledge-owner-scope.v1` and `openkit.knowledge-git-notebook.v1` in `requiredFeatures`. Governed validation rejects unsupported required semantics, parallel `owner_scope` and `openkit_revision` fields; generic external OKF parsing remains permissive. `validateKnowledgePageCandidate` accepts `scopeSchemaText` and `expectedOwnerScope`, and successful schema validation reports `scope-schema-valid` with `scopeSchemaVersion`. The expected owner comes from trusted admission; page metadata grants no permission.
- The default ScopeSchema admits Rule, Effect and business Objective domain pages with nonempty `applies_to` identifier lists; Effect also requires descriptive `basis` and an offset timestamp in `last_checked_at`. These fields retain the common governance and grant no authority. ScopeSchema/page validation refuses `Procedure` even when an authored schema tries to allow it, because Skills own reusable procedures. External OKF parsing, descriptive Topic context and exact Skill references remain available. Run `pnpm --filter @openkit/nanocore exec vitest run src/knowledge/typed-knowledge-pages.test.ts src/knowledge/okf.test.ts src/knowledge/okf-scoped-profile.test.ts src/knowledge/notebook-validation.test.ts` for the publication and validation regressions. KM type/applicability selection is a separate consumer join.
- `notebook-validation.ts` owns structural final-tree validation in the coordinated notebook cutover. Current source disclosure, authorization and publication remain native publisher duties.
- `notebook-agent-editing.ts` supplies two Turn-scoped KM operations over one immutable admitted snapshot. `workspaceUpdate` interprets only fixed just-bash file/text/JSON/YAML commands in memory under `/notebook`; selected `/sources` and omitted base members are read-only. It enforces the owner limits, cancellation and shared deadline, keeps failed-script edits volatile, and submits exact fixed-base changes through a native publisher-or-Proposal callback. The runtime owns canonical Tool IDs and Gateway name projection. No host filesystem, process, network, plugin, Python or JavaScript runtime is supplied.
- `notebook-publication.ts` joins fixed-base human and delegated Agent Workspace edits to the existing Audit and command receipt owners. It retains admission before the Git CAS and completion before success, reconstructs exact old results from their commits, and refuses missing completion evidence. Its native current-authority callback is mandatory. An Agent producer requires current native instruction/delegation facts and its responsible human actor; changed generated pages receive `review_state: delegated`, while exact reviewed candidates and unchanged files retain their bytes. Native Review decisions use the exact retained candidate and preserve original producer attribution separately from the current human actor. Confirmed removals and bounded reversals use the same publisher, create new commits, and retain historical bytes. These joins implement Workspace Git publication; other scoped notebook features remain separate joins.
- `memory-lifecycle.ts` joins explicit personally authored self save/list/read/edit to the current scoped publisher, with or without current self literal document Sources. `memory-history.ts` applies current self/schema/sensitivity/suppression and Source-version admission to published ancestry, hides unavailable metadata and bodies, bounds selected diffs and restores admitted content through the common publisher. `memory-forget.ts` uses an actual private-Timeline Item and the existing person command-intent approval: grant alone executes nothing; apply claims once, suppresses before exact removal and replays the original receipt. Preparation, approval detail, grant and apply recheck the actual Source versions. Resolved approval detail is unavailable after suppression. Protected content still needs the existing exact Proposal/Review, and this authored-page slice refuses it before suppression. `memory-maintenance.ts` stores full canonical, content-free suppression rows in the existing monthly observations family under its narrow S31 exception. Its sorted, unique `source:<sourceId>@sha256:<digest>` fingerprints identify actual admitted Source versions without Source text or forgotten prose. The User page id stays reserved; independently retained Source/Git/evidence/backup bytes are not erased. Explicit human saves may use a new page id at the current base. Public `memory.*` management is wired by `memory-operations.ts`; Generated pages with current Sources use the separate bounded KM ask/tell and fixed-base User Proposal/Review joins; recent-Thread learning remains unjoined.
- The public `memory.search` join in `../memory-operations.ts` derives current self and an existing private Timeline from `workspaceId`, retaining any existing Thread/Turn lineage. It creates no Timeline and cannot replace a shared Thread with a private one. Its request accepts query, independent limit 1 through 20 with default 5, qualified pins and explicit inspection states; it accepts no owner, source scope or role selector. The native primitive reuses the existing governed selection and Retrieval Kernel owners, checks current Source bytes and exact Page-id suppression, and returns source-labelled Memory facts with actual User references, notebook commit and page digest. References use `page/user/<userId>` and the stable page path without `.md`; commit and digest identify the observed bytes. The existing private Thread/Turn trace retains references and selection metadata without query text, bodies, snippets or scores. Search selects saved Pages, not raw Sources: a new explicit human save under a new Page id stays eligible while raw Source model suppression remains. The separate KM ask loop uses this selection without changing its budget or source owner; automatic extraction and AI assessment are not added.
- `scoped-knowledge-sources.ts` registers, lists and reads explicit literal documents for the current User through `memory.source.*`. It reuses current self admission and the sibling `users/<userId>/sources/` root with `registry/<sourceId>.json` and `materials/<sourceId>/content.txt`. Registration creates no Memory notebook. Each registry JSON uses the [canonical record envelope](../../../../docs/specs/20260703-schema_evolution_record_envelope.md) once: identity, User/request lineage, timestamps and exact content digest stay in the header. The payload holds document kind, title and null URI, Thread, Turn and file provenance. This literal producer uses its actual creation event as the capture time; it does not infer import provenance. Reads verify exact UTF-8 bytes and their SHA-256 digest before disclosure. User command receipts retain the original Source on replay, changed input conflicts, and User Audit records the actual actor without source text. Lost established storage or missing completion evidence returns `recovery_required`; registration does not infer success or allocate a replacement Source. Conversation capture and recent-Thread learning remain unjoined; explicit supplied information reaches the bounded User KM maintenance path.
- Source read/list admission accepts a trusted `human` or `model` delivery context. Remote MCP fixes `model`, and native operation handlers forward that context rather than accept a request field. For model delivery, the reader compares exact `source:<sourceId>@<contentDigest>` fingerprints against current canonical Memory suppression. A matching read returns null before reading its body; list omits the complete metadata row, including title. Authorized human inspection retains the stored bytes. A lost established Memory root returns `recovery_required` for model Source inspection; it cannot stand in for empty suppression. First literal intake needs no Memory notebook. No Source deletion or automatic model pipeline is added.
- `admitUserMemorySources` uses the shared `resolveRegisteredKnowledgeSourceReference` for authored page `source_refs`. `source:<sourceId>` resolves a current owning-scope registry member; `source:<sourceId>@<contentDigest>` also requires its exact digest. It rereads exact literal Source bytes before page disclosure, publisher revalidation, first-save initialization and page publication receipt replay. It returns admitted registry digests and sorted canonical fingerprints. It starts no automatic recall, extraction or internal semantic maintenance and grants no inspection of another User's Sources. Source-free pages need no Source store. Generated-page admission keeps the same current Source-version and suppression checks, with exact required human Review through the User candidate family.
- Saved Proposal Markdown names its owner scope and exact base/candidate commits; a native multi-page candidate stores the actual sorted `changes` set, and its digest covers that complete set. Multi-page Review/application projections name all changed page IDs instead of a representative page. Single-page proposal drafting retains its existing shape; its body is the human-readable rationale. Page bytes resolve from the existing `refs/proposals/<proposalId>` commit. Review input binds that tuple and the exact Proposal document digest. Stale Review returns conflict before a terminal decision or publication. Removal confirmation binds the fixed base, selected path and exact content digest; this is ordinary removal, not the stronger forget/suppression flow.
- `notebook-history.ts` exposes currently authorized published history and exact selected text diffs. A denied revision remains visibly unavailable without its summary, producer or paths. Restore names `baseRevision`, `fromRevision` and `pageIds`, appends a new validated commit through the common publisher, and requires explicit confirmation when the complete selected diff removes published content. Ordinary diff returns at most 256 paths and 64 KiB of UTF-8 text, with `truncated` marking partial display; retained Git bytes stay exact. Diff with `forRestore: true` uses the same human attribution normalization as publication. Oversized restore previews and restores refuse before publication; callers can select fewer paths for complete confirmation. Current Source/audience checks apply to both sides and are repeated before restoration. There is no raw Git endpoint or fallback to materialized files.
- `notebook-entry-publication.ts` projects retained create/update commands into that same publisher, with an explicit fixed base and stable concept path. Their receipts retain the original command identity and immutable commit, without nested notebook receipts. Service timestamps come from the exact admitted candidate on explicit retry; a missing completion receipt remains recovery_required. Native callers retain current admission and exact source disclosure.
- `updateOkfFrontmatter` is the shared YAML edit boundary for changing managed fields while retaining unknown metadata and the selected exact Markdown body.
- Parsed computation, executor, attester, provenance, generation, and verification metadata remains inert data; this directory does not execute code, access networks, attest runs, or grant authority.
- Knowledge routes, ledgers, retrieval, indexes, and portable file storage remain with their existing feature and storage owners.
- `notebook-workspace-portability.ts` joins the existing Workspace archive to one published Git tree. Export checks the complete selected page set under current source authority. Clone/remint changes owned scope/source fields, propagates changed exact page digests through dependent page pins, and initializes a fresh target Notebook under the actual import command. Current-tree retrieval traces bind to that actual target commit only after initialization; original commits remain source provenance. Reserved navigation, unknown metadata and authored bodies remain retained; no live `knowledge/pages/` tree is written. Source commit identity is inert archive provenance, not a target revision or permission. Historical trace closure remains subject to the existing explicit refusal when unavailable.
- Page `source_refs` validation and source-reference indexes share `resolveRegisteredKnowledgeSourceReference`: bare ids require an owning-scope registry target and pins additionally require its matching digest. Registry resolution preserves citation bytes and supplies no review, captured-byte integrity, or retrieval authorization proof.
- `notebook.ts` uses a bare local Git repository for exact immutable page trees, unpublished candidates, published-ref compare-and-set and retained history. Git messages preserve strict historical admission facts; these facts grant no current permission. No working tree, hooks, network or model-supplied Git arguments are exposed. Ordinary Git object publication and expected-old-value ref updates use the supported Git durability configuration, with no custom recursive directory flushing. Git owns its repository internals; product calls do not recursively inspect configuration and object directories or defend against an administrator redirecting them.
- Workspace page commands, reviewed candidates, canonical reads and public history/diff/restore select the same Git notebook authority. Workspace, User Memory and Server Knowledge maintenance use their admitted notebook scope and human Review owners. Full historical trace and archive disclosure closure remain unfinished; complete Notebook and Memory acceptance is separate.
- Profile/schema v4 is a cutover component, not an independent activation path. All live callers must use the Scope schema API and `schema/scope-schema.yaml` with fresh Git notebook initialization; pre-stable data uses the approved reset boundary without offline conversion. There is no v2 fallback. Notebook Git commits own revisions; pages carry no revision counter.
- Keep parsing deterministic and independent of database, provider, and HTTP concerns.

## Verification

Run `pnpm --filter @openkit/nanocore exec vitest run src/knowledge` and the affected Knowledge Store tests.

See [Research Cookbook](../../../../docs/cookbooks/research.md).

Fresh Workspace Notebook initialization adds the OKF root version and initial navigation before its first Git publication. A valid authored root stays byte exact; a valid body-only initial root receives only the version block. Current Notebook edits keep that version, and Thread storage never repairs materialized page bytes.

Retained trace reads keep their exact Notebook commit and also check current recursive Knowledge source sensitivity and audience. Later source restrictions cannot be bypassed with an older trace. Trace refusals use the existing redacted trace error; no source identity or content appears in the refusal.

Workspace collection, direct-read and dashboard Knowledge counts use the current authorized published Notebook entry projection, so a native publication is visible before restart and revoked Source audiences do not disclose a page count. Canonical page bytes remain Git-owned; cached Workspace counts do not own this projection.

Knowledge Manager final output is submitted through the private, schema-validated `knowledge.result` Tool. Query results retain the existing answer, citation and uncertainty fields. Maintenance first obtains the existing notebook publication, proposal or no-change outcome; result submission grants no authority and repeats no notebook effect. One invalid output permits one bounded repair turn within the original call and deadline budgets. It may read missing evidence or submit a missing native outcome, but cannot repeat an edit script or an attempted submission. Zero citations with zero retrieval calls trigger repair mechanically; an overview alone cannot establish absence. The existing retrieval owner reconciles the pinned canonical notebook inventory and publishes its rebuildable index before search; publication needs no eager index writer. Failed asks return `knowledge_query_failed` with retained Thread and Turn references through the existing typed operation error boundary.

KM query guards batch overview and citation pages by their pinned notebook. The compaction provider checks complete sources at dispatch and after inference; the trace reader applies its own source checks and current caller admission. Repeating the complete notebook/proof read inside each nested trace check caused thousands of Git subprocesses per answer. Source authority and exact bytes are revalidated at the effect and disclosure boundaries without an authorization cache.

`server-knowledge-maintenance.ts` joins the general Server Thread to the existing bounded KM runner, daily scanner, fixed-base editor/publisher and native command receipts. Explicit tell bytes use the existing Server Source family; Server inputs exclude Workspace/User Threads and prior KM run output. `server-notebook-proposals.ts` carries the existing Proposal/Review families at their Server owner. Current Server administration authority is checked before content reads and effects. Server history, usage, observations and capture use the same scoped families without a hidden Workspace. Run the complete Knowledge directory plus the internal-agent, capability, LLM, Store and storage suites for this increment.

`server-knowledge-maintenance.ts` joins requested and fixed daily Server runs to general Server Threads, current administrator authority, explicit Server Sources, fresh captured context and the existing editor/publisher and exact Proposal/Review. It never learns from Workspace or User Threads. The default-off timer uses actual local authority or retains a visible failed/skipped outcome; a stored administrator credential cannot supply timer authority. `server-notebook-proposals.ts` rechecks current Server authority and exact fixed-base candidates. It freezes accepted page state in the unpublished candidate before its digest is shown, then publishes those exact bytes only after human Review. Agent attribution and decision replay remain unchanged. Model delivery cannot decide a required human Review, including through Remote MCP.
