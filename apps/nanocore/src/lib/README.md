# Library

This directory contains NanoCore's existing app-local product-state aggregate and deterministic simulator. It is not a general utility directory.

## Boundaries

C2-B2 product writes use the native database worker and return Promises. Callers must await Workspace, Thread, Turn, Item, AgentSession and Server product writes before exposing their results. Reads use actual read-only/query-only SQLite connections and verified immutable Storage bodies, never mutable cached truth or product file fallback. Other SQL and file-owned families retain their accepted owners. The [control-store specification](../../../../docs/specs/20261019-durable_execution_and_control_store.md) owns this boundary.

- `store.ts` presents one request-facing API over workspace, thread, turn, item, artifact, session, knowledge, and event state while canonical record placement and validation remain under `../storage/`. The accepted terminal categories remain already-decided publication and named field-limited display-projection refresh. `completeTurn` composes the decided Turn, supplied Items and one completion event through the complete native terminal transport. That same transaction owns Task/Goal facts, ordinary reap and supplied evidence, original receipt and actual execution settlement. Generic product guards still refuse split terminal writes. Service calls create no execution or physical release; producers supply existing execution facts when applicable. Completion returns only after acknowledgement and leaves synchronous notification to its caller. Imported Artifact introduction and manual version publication use that same born-terminal owner, with the exact reference Item and an idle Thread check in native SQL. Version bytes precede SQL; only a proved native non-commit permits removal of the new version. File-head publication follows acknowledgement, and an uncertain SQL result or failed head publication retains the existing Workspace recovery refusal. The original Artifact-family receipt remains with its existing command owner.
- New Workspace publication uses the storage owner's staged-tree publisher. Complete file bytes and child directory entries are synchronized before rename; the Workspace parent and distinct staging parent are synchronized before acknowledgement. A failed acknowledgement can leave a complete visible Workspace for inspection; filesystem publication and Core SQLite commit remain separate effects.
- General and personal Workspace creation retain a fresh default Knowledge Base ID in the staged configuration before Notebook initialization. Import supplies its already-reminted target ID; the exact qualified page scope admits initial page pins. Both paths initialize and migrate `workspace.sqlite` and initialize the Git notebook inside that staging root before publication. Public creation and imports retain their actual native User attribution; only the exact service-owned empty notebook seed may use the system actor. The Notebook database closes before the import callback. After that callback, the initializer synchronizes every initial immutable Item/event body and inserts Workspace, Thread, AgentSession, Turn and ordered entry rows into the genuinely unpublished, empty staging database. It validates the retained graph, closes the database and then publishes the tree. An importing request can supply file admission to separate synchronous preparation and final publication sections; no capacity scope spans immutable-content awaits. The private initializer accepts no live root or nonempty native product scope. Initialization failure publishes no Workspace; maintenance keeps its existing-only database open and missing-database refusal.
- The Git notebook owns durable Knowledge page bytes. File-backed human page commands use the governed Notebook publisher. The Store projects canonical full pages; createKnowledgePage supports in-memory fixtures only and refuses file-backed mutation. Unrelated Store persistence must not rewrite the notebook from cached page projections. Imports receive exact admitted current-format notebook bytes, with no retained-data conversion or materialized-page fallback. See the [Notebook owner](../../../../docs/specs/20260909-knowledge_notebook_editing.md).
- `DISPLAY_PROJECTION_REFRESH_FIELDS` names the existing Item level, title and summary admission; failed-start recovery reuses that list while comparing every other decided snapshot field. Missing-publication equality remains separate.
- `store.ts` is still a broad aggregate; do not add a new record family or workflow here by default. New behavior belongs with its concrete route, runtime, policy, provider, Vault, or storage owner.
- Native Turn admission and Thread preview changes share one worker transition. Original file inputs are verified and synchronized by the separate existing original-file owner before SQL can reference them; a failed SQL result can leave retained unreferenced originals for inspection, not automatic repair. Aggregate file persistence cannot rewrite or prune product metadata or histories. Export reads native Turn metadata, every immutable Item revision in first-seen logical order, and complete ordered transcript history. Recurring acceptance never authorizes automatic initial publication again.
- Process-local event listeners and timers are projections. `persistTurnEvent` and `persistServerTurnEvent` await immutable publication and native acknowledgement without notifying. The synchronous `emitTurnEvent` and `emitServerTurnEvent` methods accept only the complete acknowledged envelope and notify without an await. Producers must finish awaited persistence and cleanup preparation before their pure notification tail; adding an await to that tail can let an observer overtake interrupted cleanup.
- Native metadata and entry candidates use the same revision-conditional worker tuple. Returned objects cannot change authorization through mutation. Native readers discover rows admitted by Goal or maintenance owners without requiring a Store cache entry. `store-native-products.test.ts` covers native reopen, revision order, external admissions, immutable corruption, notification ordering, Server history, sessions and private import closure.
- Event envelopes project non-UUID App command ids to stable Workspace/Thread-scoped protocol UUIDs using the existing UUID helper; command receipts, checkpoints, and Worker packages retain the original command identity. The exported `projectTurnEventRequestId` supplies the same projection to recovery proofs so matching events must also agree with their command owner.
- `store.ts` does not own a Knowledge context materialization path; S61 owns retrieval traces and S39 owns worker Context Package files under `../storage/`.
- Split an existing family only when the new owner receives direct callers and removes a complete responsibility. Do not hide the same aggregate behind a pass-through repository or single-implementation interface.
- `simulator.ts` owns deterministic demo execution only and must use the same public store invariants as production paths. Product-backed questions use the existing Worker MCP `work_input_request` dispatcher and Pending Request owner before the raising Turn completes; answers arrive through frozen input on a later Turn of the same Task, never by reopening the raising Turn. Its modeled native start proves delivery only after accepting that exact input and its ordinary verified S39 trace, including for an outcome Turn without a Task checkpoint. That Turn retains its exact input under the existing Pending Request system actor for trace verification. Carried outcomes preserve the independently admitted command Item and exact replay regardless of checkpoint presence. Standalone protocol fixtures without Core storage cannot exercise durable answers.

## Verification

Run the nearest store, reload, canonical-file, event-stream, and simulator tests affected by a change, followed by the package gates in the [NanoCore source guide](../README.md).

The canonical Turn record preserves optional `reasoningEffort` at creation and reload. `updateTurn` refuses changes to this immutable admission field. Existing command receipts hash explicit submission content, so identical replay preserves the original choice even after an Agent default changes.

`FsStore.getApprovalProjectionLineage` returns only Workspace and Thread selectors from the existing Approval map under the selected Workspace for opaque-child admission. The Pending Request command owner still decides missing or contradictory canonical-record outcomes.

`AutomationStore.getAutomationLineage` selects only Workspace and user ownership from the existing durable Core definition for opaque-child admission. `listAuthorizedAutomations` applies admitted Workspace candidates and current administrator eligibility. `FsStore.getTurnLineage` discovers only indexed native Workspace and Thread selectors before addressed-Turn content access. Opaque lookup checks the existing scope databases and detects cross-scope identity conflicts; it reads no Item or event bodies and adds no registry. Scope-local APIs use their admitted Workspace directly. Native feedback still loads Turn content only after Workspace and Thread admission.

`StoreRecordNotFoundError`, `AutomationRecordNotFoundError`, and `KnowledgeProposalAuthorityError` distinguish known native refusals from unexpected exceptions without changing record data or messages. Families translate these errors into the neutral operation contract; storage does not frame transport responses.

`getKnowledgeSource` and `listKnowledgeSources` project current canonical SourceSummary pointers from Notebook Git. Capture uses the shared asynchronous Source publisher and current native Knowledge admission; `FsStore` owns no parallel Source registry, original byte reader or generated text view. The Knowledge operation preserves its definite lineage refusals before capture; unrelated storage and implementation exceptions remain unclassified.

`FsStore.updateAgentSession` admits the materializer's private `retainedStorage` association and slot once and refuses any later replacement or erasure. It remains historical provenance after terminalization and does not enter the public AgentSession projection or grant attachment authority.

The simulator Material fixtures invoke the canonical definition-derived JSON operations and retain their queue, projection and worker-delivery assertions.

The simulator publishes its two deterministic Material candidates through the shared exact-byte Artifact validator and existing Artifact/Review owners, with the process-private no-injection evidence constructor. It emits no Artifact declaration payload and cannot provide that proof to Worker MCP capture. Ordinary Worker submission requires the original Worker evidence set.

The deterministic self-check executor uses the same configured file admission owner as App uploads and NanoHost transfer staging. Material candidate staging, canonical publication and compensation must not create a second reserve or bypass that owner; a missing owner refuses file publication. Complete staging cleanup releases its reservation, while unproved cleanup retains it.

`recurring-cadence.ts` owns exact nominal successor and missed-prefix arithmetic for the two admitted timing shapes: fixed `intervalSeconds` and bounded `monthlyUtc`. Monthly calculations use integer Gregorian month indices and construct valid UTC dates; they do not approximate a month with elapsed days or convert local time. The same functions serve Store cursor/range calculations and the connection-local SQL live-frontier ordering before candidate limiting. Each `AutomationStore` registers the deterministic frontier function on its actual Core connection; constructing another Store on that connection safely replaces the same pure function. `validateRecurringRangeCoverage` also checks portable range timing and snapshot consistency without granting live actor authority.

Independent Workspace, Thread and Turn creation calls the shared Protocol UUIDv7 allocator once at the existing creation seam. The personal Workspace derives its identity from the recorded User id through the accepted UUIDv5 name. Private Thread creation requires the explicit canonical audience; no local-user constant or owner namespace is inferred. Receiving-Thread creation records its immutable parent. Demo history belongs to the explicit test-support fixture.

Knowledge Proposal page sources use the canonical Protocol URI codec and the actual retained Workspace Knowledge Base binding. Validation reads the exact cited page and digest at the Proposal base commit; direct edits use the current published Notebook revision. A foreign owner, base or mismatched pin refuses without allocating an identity or accepting the retired page form.


`FsStore.setWorkspaceResourcePolicyProjection` binds the application's current loaded Workspace configuration without a second Policy store. `getWorkspaceResourceAccess` reads that projection on each authorization. A newly imported managed Workspace remains inaccessible until its configuration joins the validated runtime snapshot. Standalone file-backed stores use their authored Workspace configuration; they do not reconstruct assignments from historical requests or decisions.

`FsStore` retains Server-owned Thread, Turn, Item and transcript history through explicit `*Server*` methods. These methods do not accept a Workspace selector. Their callers must enforce current Server administration authority. Server metadata uses `server/db/core.sqlite`, and its immutable Item/event bodies use the real Server private content mount and default Knowledge Base. Both owners use the same Protocol Thread, Turn and Item types with an immutable explicit owner union. Workspace methods require Workspace ownership and preserve their existing audiences; Server runs do not inherit Workspace membership. Reopen restores pending and running Turns as recorded; the bounded runtime owner reports recovery_required and never replays a Provider call. Server Turn capture coverage comes from native metadata, including after reopen. Server transcript listeners are process-local projections; complete events come from ordered native descriptors and exact immutable bodies.

`store.ts` retains one exact Artifact snapshot per version and only actual producing actor and publication Thread/Turn beside it. Version list, detail and commit results derive their existing public summary fields, including parent, mutation request and accepted time, from that snapshot. Restart and import still verify exact originals and producing Item lineage.

`createArtifact` returns workspace-only imported origins synchronously through its common validation and version publisher. Turn output returns a Promise that acknowledges its native reference Item. The import command retains request capacity through receipt publication and uses the existing Store rollback owner inside synchronous file admission only after a definite SQL constraint refusal and inspection proves no original receipt. Unknown outcomes and failures after receipt insertion retain Artifact authority. Unproved compensation retains capacity and reports cleanup failure.

Claim and reusable Observation/conflict analysis now use the existing Git Notebook publisher and reader. `conflicts.ts` interprets current draft/active unresolved subject references for Proposal acceptance and active retrieval; supporting Sources are not subjects, and an exact pin applies only to its observed version. Ordinary writes validate local targets and exact pins. Portable Notebook remint updates subject identities and digests together. The standalone fact DTO operations and monthly JSONL families are retired; operational WorkObservation, Audit, actual decisions and User suppression are unchanged.

A failed directory synchronization after canonical rename leaves the visible publication unacknowledged. FsStore keeps its prior candidate cache and refuses reads and writes for that Workspace with `recovery_required` until the ordinary Store reopen loads canonical records. Other scoped Workspaces stay usable; aggregate cache reads refuse rather than publish stale content. Later writes do not clear the process-local refusal. Failures confined to unpublished staging do not require reopen.

Native Thread counts and product getters reread committed SQL authority. Disposable startup projections do not authorize writes or override native rows. No result or cache is published before worker acknowledgement. A missing acknowledgement remains an unknown result for original-request inspection, not non-commit or permission to replay.

New Workspace Threads update the parent's activity timestamp from its current native row in the same worker transaction. Independent Thread creations do not carry an incidental Main-side Workspace revision; explicit parent mutations and same-record revisions retain their conditional checks.

Native terminal creation and update use the complete terminal owner, including the actual completion event. Explicit already-decided Item/event completion and the named status-display refresh use the closed native publication body, which cannot change Turn outcome, journal, evidence or Task authority. The generic product writer still refuses sealed Turns. Durable acknowledgement precedes Store projection and notification. Native Artifact counts exclude submissions whose acknowledgement has not arrived.

Turn admission carries the original turn.start, task.start or selected Worker conversation.submit receipt into the native product transition. Ready Pending input is prepared through the existing admission hooks and frozen in that same transaction. Conversation source and receiving Threads must share the actual Workspace; its original response metadata retains the downstream Task and receiving Thread identities. Completed Core-local conversation outcomes carry their original receipt through completeTurn. The separate User receipt owner is unchanged.

Workspace counts are an enumerable derived projection evaluated only when accessed or serialized. Metadata-only reads do not load unrelated Notebook bodies. Each count access reads actual committed products and retains the existing exact Knowledge body, digest and OKF checks; no count or authority cache is added.

Turn interruption carries its original receipt and authenticated command Audit explicitly to the execution owner. Simulator and queued cancellation publish them in their first native terminal tuple. A live Worker accepts the current Turn snapshot and command before external cancellation contact; acceptance does not prove physical stop or release. Main never backfills the receipt or Audit.

Native identity discovery scans only admitted scopes, as startup readers do. A quarantined Workspace cannot block reads or writes in a healthy sibling, and it never supplies fallback authority. Explicit access to the refused Workspace still follows the existing recovery diagnostic.

An unscoped Turn lookup searches admitted native owners only. If it finds no owner while a Workspace is quarantined, it cannot prove absence and returns the existing scope-admission `recovery_required` refusal without opening that Workspace. Known healthy Turns remain readable, and an absent Turn remains not found when the entire search domain is admitted. No cached body or replacement owner is used.

Workspace and Server Turn DTOs, and current Server event DTOs, project through the fixed retained decoder before current Protocol validation, leaving descriptive canonical additions unchanged.
