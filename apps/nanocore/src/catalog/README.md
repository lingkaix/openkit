# Resource Catalog

`resource-catalog.ts` is the single reader, immutable-content owner and compare-and-set publisher for scope-owned Skill, MCP and plugin catalogs. Server and Workspace use the same document layout and writer. Skill and plugin import remain Workspace operations in this feature; their retained arrays are preserved in both document scopes.

Trusted `ResourceCatalogOwner` arguments select Server or exact Workspace storage. `loadResourceCatalog` validates that scope agrees with its path and returns known fields. Catalog mutation reads preserve retained descriptive additions; public projections select known fields. Both scopes require an explicit matching `scope`; missing or unknown values fail schema validation. The reader and writer do not convert missing scope. Before `v0.1.0`, a release may require an authorized reset under [Pre-Stable Data Continuity](../../../../docs/decisions/20261014-pre_stable_data_continuity.md). Catalog path lookup never creates or revives a Workspace. Reads preserve bytes; immutable tree/configuration identity and Workspace effective MCP identity stay unchanged.

MCP create, stage, select and binding mutations take an explicit owner. Server administration remains in `../administration/server-mcp-operations.ts`; this module owns no user authorization or Vault effects. Server management never creates mutable Server process-data directories. Bindings retain their stable data key; the Gateway materializes shared mutable data inside each consuming Workspace.

`composeWorkspaceMcpCatalog` projects current Server supply without copying it into a Workspace. Any local entry, including inactive/removed entries, suppresses a same-id shared entry. Exact `mcp.disabledServerIds` belongs to the consuming Workspace. Only canonical shared projections add Server origin to effective digest identity. Callers must still recheck current selection, grant and audience at effect boundaries.

Run the focused catalog and shared flow tests with `pnpm --filter @openkit/nanocore exec vitest run src/catalog/resource-catalog.test.ts src/catalog/server-scope.test.ts src/server-shared-mcp.test.ts --maxWorkers=1`. Follow the parent [NanoCore guide](../../README.md) for checks and toolchain rules.

This directory owns the existing scoped catalog records and immutable installed Skill, MCP and Agent Plugin snapshots. It does not own Worker execution, permissions, Vault secrets or a learning runner.

## Boundaries

- `resource-catalog.ts` validates retained catalog authority, admits complete bounded trees and publishes one revision-protected catalog document. Exact version digests identify installed bytes; producer and source provenance explain their origin without granting current access.
- `validateCatalogTree` normalizes physical ancestor directories and applies the existing bounded tree validator and hash without filesystem effects. Direct Skill admission and Artifact admission use this same boundary.
- `catalog-tree.ts` holds that stateless transport preparation separately from catalog storage, so caller-side local uploads use the same validation without importing database or publication code.
- New Skill admission requires a UTF-8 root `SKILL.md` with valid Agent Skills metadata. The shared ecosystem header parser accepts descriptive names and metadata without requiring a directory-name match. Metadata validation changes no bytes and grants no tool authority. Historical content inspection continues to use retained exact bytes.
- Skill admission records the original package digest, member key and source subpath, or the exact base digest for an independent candidate. Reusing identical content in one entry returns its existing immutable version facts; later imports do not rewrite those facts or the original PluginVersion membership. Retained descriptive annotations remain in storage and do not enter public results.
- Ecosystem acquisition records the sanitized source locator and exact resolved Git commit in the existing version provenance. Uploads and direct downloads do not invent a Git commit. Same-entry identical-byte admission retains its first provenance.
- `catalog-operations.ts` joins the shared Operation Definitions to these native owners. Current read, write and configuration authority, command receipts and Audit retain their existing owners.
- `skill-inspection.ts` reads exact metadata and file bytes and compares verified inventories. Binary differences retain path, size and digest. Reads use retained snapshots without upstream lookup.
- Candidate submission publishes content lineage and the request in one catalog revision. Promotion retains exact actor, Audit reference and decision time. Public default and pin mutations name their expected prior digest. Removal clears the default and blocks later activation while retaining history and pins.
- Native pin publication retains `pinAuditRef` to its preceding command admission Audit. Fresh identical pins get new attribution; replay preserves the winner, and unrecorded attribution stays unknown. `catalog.read` exposes the reference without granting permission. Historical AEP selection keeps its own observed lineage rather than resolving the current pin.
- Decision Audit and external retention evidence enter through `CatalogOperationHooks`. Missing decision evidence fails before mutation. Purge reports exact catalog references and refuses missing external retention authority. `skill-retention.ts` joins existing retained AEP snapshots and unexpired evidence or legal holds; their owners alone decide when those references end. The existing receipt owner must retain partial purge admission for inspection.
- Each version records `retained` or `purged` payload availability separately from immutable provenance. Export carries purged metadata without a payload, and refuses missing retained content. Explicit identical-byte admission can restore a purged payload without changing original version facts.
- `catalog-portability.ts` preserves installed bytes and historical lineage through the existing Workspace portability boundary. Imported historical selection or review evidence grants no target authority.
- `turn.start` may select exact versions of Skills already in the composed setup through optional `skillSelections`. The canonical Turn retains this work input. AEP resolution uses run, composed exact version, pin, then current default, and records `selectionSource: run` without moving a shared pointer.
- Runtime setup and AEP resolve exact versions before materialization. Catalog mutation does not change files in an admitted AgentSession or prove real Worker consumption.
- Native Skill mutations join the existing receipt and Audit owners, Artifact-origin submission checks retained source authority, and purge checks existing external retention references. Complete physical Worker delivery and real Worker consumption remain open. The general candidate-loop regression uses a minimal test-only producer, with no shipped generic author or BWM acceptance claim. Server catalog scope is an additive shared-owner integration with L-GA; it does not create a second catalog.

## Verification

Run the affected `resource-catalog`, durable-write, catalog-operation and portability tests with one Vitest worker, then the package checks in the parent guide. Use the machine-wide CPU slot for heavy commands. A real Worker consumption claim also needs exact AEP/materialization and output evidence from the authorized runtime environment.

The [Skill owner](../../../../docs/specs/20260711-skill_catalog_versioning_pinning.md), [Plugin owner](../../../../docs/specs/20260907-agent_plugin_packaging_and_worker_supply.md) and [MCP owner](../../../../docs/specs/20260907-mcp_catalog_management.md) define the contracts.

The ecosystem import conventions follow the pinned MIT source documented in THIRD-PARTY-NOTICES.md. skill-source.ts parses locators and YAML without network, process execution or authority. Native import stages Git or bounded download supply only inside a fresh authorized command, then rechecks current authority and revision before publication. A completed receipt replays retained metadata without upstream access. No upstream CLI or telemetry runs.

Source acquisition components stage a complete bounded package before catalog admission. `skill-local-source.ts` belongs to the explicitly authorized caller filesystem boundary and must never accept a remote caller's Core host path. `skill-git-source.ts` reads an exact resolved commit with ordinary Git plumbing, no checkout, hooks or ambient Git credentials; its temporary repository is removed after staging. `catalog.skill-update-check` uses retained source provenance and reports changed, unchanged or unavailable without importing, activating or moving a pin. The bundled CLI stages local uploads and sends one public import. Physical Worker delivery of directory and executable entries remains incomplete.

Reusable Light App definitions share this catalog's `lightApps` entries, immutable inline versions and pins. `light-app-catalog.ts` admits the existing strict declarative schema, bounded to 256 KiB of canonical UTF-8 JSON, and uses the existing stable catalog JSON codec and SHA-256 content identity. The native reader and publisher verify definition content and closed parent, default and pin references. Same-entry identical bytes retain their first parent, actor and time; producer history grants no authority. Reads, history import/export, default selection, pin rollback and exact resolution operate on templates only. A default or pin applies to an explicit future create or activation and never changes an existing app database. Workspace portability carries complete definition history and source selection as historical facts, then clears target defaults and pins. Run the focused `light-app-catalog.test.ts` for the native lifecycle and verified Workspace export/import proof.

Workspace MCP create, select and binding mutations and Plugin import write the existing Workspace Audit after their native catalog publication, before reporting success. They open Audit storage before mutation and retain the actual caller, non-secret authentication summary, request, selected resource/version and resulting revision. Audit excludes declarations, endpoint locators, binding values and uploaded source bytes. File publication and SQLite Audit remain separate effect domains; an Audit write failure is an error and does not roll back a published catalog.
