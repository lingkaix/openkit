# LLM Context Projection

Retained Context Package manifests and traces admit descriptive annotations while verifying the original canonical representation and byte digests. A direct Task trace retains the complete scope-qualified retrieval trace reference that selected its Knowledge bytes. The trace reader returns known fields with its original immutable representation retained for same-identity serialization. Inventories and structured instructions remain exact; portable import remints only owned references and recalculates target digests. See [Worker Context Package](../../../../docs/specs/20260703-worker_context_package.md).

This directory owns deterministic projection of durable OpenKit items into provider-visible LLM context.

## Boundaries

- `projection-policy.ts` classifies item types and records versioned inclusion or exclusion decisions.
- `model-request-admission.ts` supplies the shared local text estimate for internal Agent rolling-window preparation and final serialized Provider admission by internal Agents and Worker inference. It includes native overlays, continuity, and the existing output reserve under [Bounded Model Projection](../../../../docs/specs/20260703-worker_context_package.md#bounded-model-projection). It selects no route, contacts no count endpoint, and mutates no history or durable accounting.
- `llm-projection.ts` creates provider messages, deterministic context-package digests, and attachment records.
- `worker-context-package.ts` builds, publishes, and verifies the immutable S39 worker-Turn package and delivery trace without owning a lifecycle. Knowledge selections carry the supplying Notebook commit separately from their exact page digest, matching the digest-addressed source snapshot projection.
- `worker-context-authorities.ts` maps the existing Core, Workspace, and product-store owners into the shared S39 verifier without retaining state.
- `worker-context-projection.ts` fully verifies present traces before deriving S16 Material, Goal steering, and exact Worker request objective read fields without storing them.
- Projection must not dispatch providers, mutate thread history, or become a second persistence owner.
- Every excluded item keeps a stable policy reason; provider-visible content must follow the selected projection policy.

S39 recognizes the existing frozen Pending Request input envelope as worker request context. Outcome-initiated Turns use scheduler request lineage without inventing a Task checkpoint; their exact input bytes enter the existing immutable package and trace before native launch. The Material projection still refuses a genuinely missing accepted trace.

The S39 authority reader locates the trace's exact AEP snapshot filename under retained Workspace AgentSession owners, independently of a session's mutable current-package pointer. It requires one strictly validated match for both package and backend-handoff reads, so unrelated malformed historical snapshots cannot prevent new delivery. Missing, malformed, or conflicting selected snapshots remain unavailable; workspace export still validates the full retained AEP inventory.

## Verification

Run `pnpm --filter @openkit/nanocore exec vitest run src/context` and the workflows that materialize context packages.

See [Work Model](../../../../docs/core/work-model.md).

Revalidating a parsed Context Package trace with its retained original requires equality of their normalized known core; a changed supplied core fails closed before serialization.

`bounded-source-view.ts` verifies one immutable UTF-8 representation with bounded source reads, pins its separate original and representation identities, and serves exact preview/read ranges with continuation and full serialized envelope limits. Its caller owns current authorization, source acquisition, file handles and disposal.

S39 keeps `contentDigest` as the original Material or Knowledge digest. An explicit `projection` binds the immutable source revision, complete representation digest and size, exact delivered digest and half-open representation ranges, delivery kind, availability, and truncation. A raw UTF-8 excerpt can share its complete representation digest with the original while its delivered digest differs. New inline deliveries are limited independently to 51,200 bytes and 2,000 lines. Retained whole-body selections with no projection still verify against their historical bytes. The helper forwards only explicit caller-supplied token accounting; its absence proves no model token fit. The caller owns complete request admission.

The additive `sourceFiles` inventory names qualified Artifact versions, Material revisions, or immutable Turn input ordinals. Each entry separates `originalSnapshotPath` and its original digest/size from the delivered `packagePath` and projection proof. Private stream callbacks never enter JSON. `writeWorkerContextPackageFiles` is asynchronous and requires the shared `FileStorageAdmission`; callers must await it before trace acceptance or launch. The writer checks pinned originals before and after copying, hashes actual chunks no larger than 64 KiB, publishes without overwriting, and writes the completed manifest last. Replay hashes existing files without reopening the source. Failed private copies release capacity only after proved cleanup. Package verification hashes held no-follow regular files in bounded memory, including binary originals larger than the metadata reader ceiling.

Each new serialized manifest has a caller-supplied `maxMetadataBytes` ceiling, capped at the existing 16 MiB metadata read ceiling, and includes JSON escape expansion. This metadata limit does not limit original file size or replace the model request budget. Before first trace publication, the authority map verifies exact present source metadata and bytes. A later current source head is never substituted. Accepted historical packages instead verify their original snapshot inventory, manifest, trace, WIS, and materialization evidence; missing or corrupt historical bytes fail closed and are never rebuilt. Current authorization and destination disclosure remain caller responsibilities. Portable import must remint qualified source references and owned paths, retain original and delivered digests separately, copy exact original snapshots through bounded streams, and recalculate the existing manifest/root/trace proofs.

`turn-source-files.ts` prepares only originals owned by the receiving Turn. It uses the current admission and audience callback to produce bounded 2,048-byte/50-line UTF-8 previews or explicit unavailable descriptors, with private original suppliers that read at most 64 KiB and pin exact canonical identity. The snapshot writer owns full original SHA verification and publication. No host paths or callbacks enter retained metadata. Runtime source authorization uses the exact current scheduler admission and Thread visibility, with a final recheck after publication. Native carriage uses the private bounded source factory.

A bound Material original can share the existing `workspace/materials/<id>/<revision>.md` or `.txt` delivered path. Source inventory and Material selection must agree on identity, revision, media type, original digest, and projection, and the existing body bytes must match exactly. The inventory retains one original entry and one delivered body entry. Artifact and Turn input delivery paths remain under `sources/`.

`artifact-source-files.ts` captures explicitly selected exact Artifact versions before caller mutation and prepares bounded 2,048-byte/50-line UTF-8 previews or truthful unavailable descriptors. It uses the existing canonical payload path and pins unique no-follow originals while streaming at most 64 KiB per chunk into S39. Retained inline text uses the existing 16 MiB processor; larger inline originals retain exact streamed bytes with a resource-limited view. The caller rechecks exact current metadata, source visibility, and receiving audience through a private synchronous authority callback. Preview and iteration descriptors close after use; no source callbacks, host paths, or access grants enter retained JSON. The snapshot writer owns full original SHA verification and publication.

`material-source-files.ts` captures an exact original immutable Material revision through its existing owner. It emits a bounded 2,048-byte/50-line preview with separate original, complete representation, and delivered-byte proofs, shares the existing Material delivered path, and streams the original in chunks no larger than 64 KiB into S39. Its private current-authority callback remains a caller responsibility. Complete provider-request accounting is separate from this bounded projection.

`projectWorkerContextRequest` preserves explicit Artifact selectors separately from prior Item ids. Structured delegation Artifact refs may carry a positive `artifactVersion`; other reference kinds cannot. A Review follow-up supplies its exact Artifact id and version, while pending outcomes supply no Artifact selectors. Resource display strings are not parsed as source authority. Current source/actor access, receiving audience, comparison of a supplied version, and exact snapshot publication remain caller responsibilities; this request projection grants no access and delivers no bytes.

A conversation-to-Task receiving Thread retains the entry owner's existing frozen Knowledge selection choice. Direct Task entry still requires its single selection; a Chat handoff with no selection still needs its exact persisted handoff lineage to admit null. The identifier cutover changes neither query triggers nor accepted selection bytes.

Context Package manifests and traces reuse the Protocol kind validators for Workspace, Thread, Turn, Item, logical AgentSession, Material and Material revision references. Package digests, authored Goal/Task selectors, native snapshots and request correlation keep their existing codecs.

The frozen Pending Request input schema reads its existing S59 delivery bound at parse time. Notebook portability links Store and context imports, so module initialization must not capture that bound before S59 initializes it. No second delivery limit or envelope is introduced.

`pdf-text-layer.ts` processes explicitly selected PDF Artifacts through packaged PDF.js in one short-lived Node child. The host and container use the same path. Defaults remain 64 MiB input, 2 MiB extracted UTF-8, 64 pages and 20 seconds total wall time, with a 512 MiB V8 old-generation heap ceiling. The heap ceiling is not a total process-memory limit. The child receives an explicit environment without inherited secrets, `isEvalSupported: false`, and Node's `--disallow-code-generation-from-strings`. It streams PDF.js text items in their declared order and preserves end-of-line markers. PDF.js and Node versions, effective limits, output options and actual launch configuration define its resource profile. The digest is not binary or App-image attestation. Missing dependencies, encrypted/invalid input and resource exhaustion return a bounded unavailable descriptor with no representation path. Parent cancellation or deadline kills the child and waits for exit before staging cleanup. See [Work Resource Interaction](../../../../docs/specs/20260713-work_resource_interaction_model.md#bounded-media-processors).

Successful PDF delivery retains its exact original through `originalSnapshotPath`, complete extracted text through the projection's `representationSnapshotPath`, and only the 2,048-byte/50-line preview through `packagePath`. The existing inventory and shared-admission writer verify all three identities independently. The projection retains processor configuration, exact page locators and text-layer coverage; partial or scanned pages never prove complete body absence. Historical verification compares preview ranges with retained representation bytes and never reruns a processor to repair history. This retained input supports bounded source reads and PDF text search; it is not automatic model input. The Artifact adapter rechecks current source and destination authority throughout staging and snapshot publication.

`worker-source-read.ts` resolves only an exact `sourceFiles[].packagePath` in the accepted current Turn package. It checks current scheduler credentials, the live Turn and package binding, source visibility, Material sensitivity and receiving audience before acquisition and disclosure. Its private roots and callbacks are operation inputs, never grants. `readWorkerSourceSnapshot` opens the retained original UTF-8 or complete PDF representation through unique no-follow regular files, uses at most 64 KiB per read and reuses the bounded preview/read cursor owner. The complete source projection is at most 65,536 serialized UTF-8 bytes. EOF describes the named representation; incomplete PDF extraction remains incomplete. Missing, corrupt, revoked and descriptor sources return value-free unavailable results with no body or cursor. Strict S39 verification checks the retained package on every operation; no cache or source registry is added.

`pdf-source-representation.ts` supplies the domain-free Kernel only retained extracted UTF-8, its digest/size, the separate original digest/size, processor identity, page ranges and coverage. The derived index stays in the receiving Thread home, outside immutable package bytes. `work_search_source` uses lexical, exact or line-regex matching over one selected PDF representation, with at most twenty bounded snippets and a 48 KiB complete projection. Current authority is checked before index access and again before disclosure. Partial PDF text coverage cannot prove absence in images or unprocessed pages. No parser runs in the adapter or Kernel. Run the complete source-read, PDF source-representation, retrieval-service, Work MCP and affected Kernel suites after building the actual Kernel.
