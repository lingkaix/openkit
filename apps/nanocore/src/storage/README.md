# Storage

This directory owns NanoCore's physical data-root layout, ownership-scoped SQLite databases, canonical workspace file records, migrations, integrity validation, derived indexes, backup, export, and import mechanics.

## Source Of Truth

| Scope or record family | Durable owner |
| --- | --- |
| Server control state, authentication, scheduler records | `server/db/core.sqlite` |
| User-scoped command idempotency and AuditEvent records | `users/<userId>/db/user.sqlite` |
| Workspace-scoped ledgers and transactional recovery | `workspaces/<workspaceId>/db/workspace.sqlite` |
| Workspace, thread, turn, item, artifact, knowledge, source, session, and runtime transcript history | Canonical files under the owning workspace tree |
| Search, readiness, and dashboard indexes | Rebuildable files under `indexes/` or derived SQLite tables |

One record family must have one durable authority. Do not add aggregate workspace snapshots, dual file-and-SQLite payload ownership, newest-file recovery, or runtime resource serialization.

## Boundaries

- `fs-layout.ts` owns safe paths and accepted directory placement. `ensureLayout` verifies the ownership tree, database placement, canonical envelopes, and layout marker at boot and during stopped-process migration. Request paths use directory preparation without tree verification; `ensureWorkspaceLayout` creates only the root and Workspace directories needed by its caller.

- Notebook publication retains typed content-free admission in the existing owning User, Workspace or Server AuditEvent table before the Git ref changes. User Audit shares `user.sqlite` and its native journal; it creates no notebook database or journal. An app-local Audit table cannot own a notebook admission.
- Authoritative SQLite integrity failure stops boot and leaves the original database file unchanged; only derived indexes may rebuild automatically.
- `workspace-file-records.ts` owns canonical workspace record serialization and boot loading. Predecessor Threads validate the shared Thread fields and original envelope digest before the existing audience classifier runs. The final classified record must pass all current Thread constraints; validation never supplies a placeholder User. Store Review verification, observation Turn bindings and retained Audit attribution reuse its descriptive readers.
- `workspace-file-records.ts` also ensures the OKF v0.2 bundle-root `knowledge/pages/index.md` once, preserves valid authored index bytes, and writes the same final Knowledge Page candidate bytes that direct-edit validation accepted.
- `command-request-records.ts` owns scope-homed SQLite command idempotency; process-local duplicate collapse remains in `../runtime/idempotent-command.ts`. Named Server Vault receipt pointers use the Protocol reference/grant validators; authored catalog MCP selectors remain opaque.
- `../workspace-materials.ts` owns exactly the three app-local Material tables and their same-transaction command mutations; worker delivery, Artifact Review, and portable graph rewriting remain with their later S16 stages.
- `workspace-export.ts` owns the V3 export tree, manifest, exact-byte inventory, and offline verification.
- `workspace-archive.ts` owns strict USTAR path representability shared by export creation, offline verification, and archive production, plus bounded one-shot extraction into private request-local staging.
- `workspace-import.ts` parses only verified bytes, validates and remints the import graph, and reconstructs importable records. It remints `env.bound.payload.workspaceId` to the imported Workspace identity while `importedFrom` preserves source provenance. The captured build revision, prompt and Tool digests, and `turn.reap` correlation remain unchanged. When a runtime row lacks header correlation, import preserves its source call reference in `corr` before reminting the fact identity, keeping recovery joins inside the reminted group.
- `workspace-portable-file-state.ts` owns portable Knowledge maintenance ledgers, workspace config and schema, native OKF pages, query-owned S61 retrieval files, and retained S39 worker Context Package files. Context Package text projections stay separate from originals. Export copies each retained `sourceFiles` original from the source Workspace into the verified private payload-path flow; import remints its qualified owner and owned paths, preserves the original bytes and excerpt/descriptor proof, and restores read-only original snapshots before final S39 verification. Original copies reserve their exact byte length through the existing canonical write admission scope; the App and transfer entry points supply that scope. Failed destination cleanup retains its reservation. No original is decoded into a text map or reconstructed from a current source. Complete PDF text representations remain bounded by the processor limit and use the existing UTF-8 map; import verifies their separate digest, remints their owned path, and preserves the bounded delivered preview and coverage. It has no Knowledge retrieval ledger reader or writer. Ordinary portable trace projections contain only normalized owned fields; ignored local annotations remain in immutable source bytes and are not forwarded into exports or target effects. `retrieval-traces.ts` alone publishes live immutable trace files by same-directory temporary file and rename, preserving an existing target as a conflict.
- Native Knowledge Page import remints scope and string-only `source_refs` through the Knowledge-owned helper, preserving authored bodies and unknown nested metadata. The existing Workspace import initializes one new Git Notebook with exact admitted bytes, its imported `scope-schema.yaml` and actual importer attribution. Staging writes no live page directory. The manifest retains the original published commit as provenance only.
- Standalone Knowledge context traces and materializations are unsupported; worker delivery belongs only to the S39 Context Package owner.
- `workspace-transfer-routes.ts` coordinates public requests, staged workspace publication, the Core database transaction, and synchronous compensation when Core replay fails. Archive download streams every inventoried original in 64 KiB chunks with exact size and digest checks. Response cancellation closes the original through the same stream pipeline.
- `index-rebuild.ts` rebuilds the three non-lexical files `knowledge-links.json`, `knowledge-validation.json`, and `knowledge-source-refs.json`. All three projections name one canonical Notebook commit; boot retains structurally valid files and rebuilds missing or invalid sets from Git-owned page bytes. Rebuild preserves the separately owned `indexes/retrieval/` directory and never migrates old lexical index data. The old mixed `search.json`, JSON term postings and TypeScript scorer are removed.
- Governed Knowledge retrieval uses the supervised kernel through `retrieval-knowledge-adapter.ts`. Current source and output audiences precede generation access; complete lexical enumeration precedes disposition and budgeting. Exact current page bytes and metadata are checked before returning results or writing one trace. Changed bytes or eligibility fail the request. The current Notebook commit and separate exact page digest remain bound through selection, query traces and S39 input. Historical selected bytes use that commit under current source and output authority. User Memory selection and trace reads verify the introducing Agent publication for delegated pages. Current User Source admission supplies exact reference proofs, so bounded maintenance output can be recalled through the same governed selection.
- Knowledge Page enumeration excludes `index.md` and `log.md` at every bundle depth while native portability keeps every Markdown file byte-for-byte.
- Secret material belongs to `../vault/` backends and credential consumers; storage may retain only explicitly allowed non-secret metadata and redacted evidence.
- The NanoHost-private attempt projection is the narrow exception for worker route authentication: it retains exactly three nullable lowercase SHA-256 projections for the control, inference, and capability families, never a raw token or a derived sandbox-binding credential.

`work-observations.ts` is the entry point for Turn observation append, validated reads and safe timeline projection using the shared App API presentation bounds. It validates immutable capture admission and separates expected facts from successful evidence publication. `../evidence-bundles.ts` owns restricted body staging, retention and expiry; callers never construct content paths or store bodies in control receipts. Portable consumers reuse the observation parser and existing exact reference maps.

`AssistantSkillAdmissionSchema` and `AssistantSkillAdmission` in `work-observations.ts` define the minimal canonical `env.bound.payload.assistantSkillAdmission` for trusted #144 producers. Retained rows may omit it; omission does not mean an empty selection. Strict identity tuples carry the source catalog revision and sorted unique Skill IDs with equal version/content digests, without Skill text or paths. Export and repeated import preserve these historical source values while reminting owned lineage; they never resolve or activate target resources. The existing whole-row conflict rule prevents later enrichment or replacement, and Timeline does not expose the tuple. The [Work Data Retention Format](../../../../docs/specs/20260921-work_data_retention_format.md#environment-binding-and-cause) owns this evidence contract; the model-capture owner commits the complete environment before dispatch.

Observation appends reuse a database-lifetime, process-local identity/sequence projection of the validated ledger. File replacement, size or nanosecond modification/change-time differences reopen it with full validation; reads always validate canonical bytes. State advances only after file and directory synchronization succeeds and keeps emitted bytes independent of producer-owned objects. Fresh-line fsync also commits any recovered truncation; exact replays still synchronize before acknowledgement. Complete canonical append logs check only their final byte, while incomplete tails retain full recovery validation. No cache is a durable authority or tamper-proofing mechanism.

Timeline coverage remains partial when a collection gap follows observed runtime activity; unsupported or unavailable collection without observed activity remains unavailable.

`work-observation-recovery.ts` appends `turn.reap` after restart recovery terminalizes a Turn it owns. It uses the historical capture binding and durable completion timestamp, pairs gateway attempts through their request parentage and runtime tool phases through observed opaque call references, and preserves the first committed snapshot on retry. Never-recorded Turns are skipped; ledger read or append failures propagate through the existing scheduler recovery retry loop. The observation records the Core recovery decision without concluding that an unresolved external effect did not happen.

## File Record Rules

- Writers store DATA_ROOT-relative path references. User and authored content may mention an absolute data root; layout verification does not scan text for that substring.
- Replace JSON records through a same-directory temporary file and rename.
- `writeFileAtomic` synchronizes replacement bytes and any caller-selected mode before rename, then synchronizes the parent directory. Callers retain their existing default modes. Vault keeps its separate no-follow writer and redacted errors with the same commit order.
- Existing Thread records skip file publication only when their complete projected canonical bytes match the current file. Changed bytes retain the durable writer; canonical validation, annotations and directory synchronization still run, including retries after a failed rename acknowledgement.
- Directory preparation commits each parent entry before creating a child. Retries synchronize existing components left visible by failed creation. Vault initialization also completes the store-directory commit after authenticating a visible header.
- `publishCanonicalPath` and its asynchronous counterpart synchronize complete staged file or tree contents, with child directories before parents, before rename. They synchronize the destination parent and any distinct staging parent before success. Snapshot, Workspace, rollback and runtime evidence publishers use this shared boundary; exact evidence replay retries synchronization after an interrupted acknowledgement.
- Bounded filesystem faults verify prior readable authority before publication, explicit failure after rename, and exact replay. These checks do not simulate a physical power loss or prove hardware cache behavior.
- Append item and event revisions to JSONL; readers select the latest item revision by id and preserve event sequence.
- Fail closed on malformed canonical records, invalid lineage, unsupported required features, path escapes, and legacy authority files.
- Descriptive history readers normalize root and nested annotations before returning known fields. Normal canonical rewrites preserve owned annotations, immutable Knowledge Proposal bytes and append-only Item/Review history; Knowledge ledger source annotations remain non-enumerable beside their normalized read model. Observation ingress persists its parsed payload, and unchanged receipt rewrites retain the original metadata JSON. Shared producer and instruction assertions remain exact.
- Export V3 preserves complete canonical history and exact portable file bytes; predecessor formats are rejected.
- Portable evidence keeps admitted restricted originals as verified binary bytes under their EvidenceBundle, separate from canonical UTF-8 records. Import remints owner references, preserves body digests and retention, and stages bytes before publishing the Workspace. Unpublished observation chunks and expired body bytes stay excluded.
- Current Goal portability retains intent history, card revisions, exact immutable Plan bytes and pointers, Task admission citations and Task terminal facts in `records/goal-state.json`. Import remints Workspace, Thread and Turn owners, keeps immutable Plan identities and bytes, binds responsibility to the importing actor and imports no grants. Retired Goal-owned rows are absent; shared historical Goal ids remain opaque lineage.
- Import writes the complete workspace tree and workspace database under `.staging`, publishes with one same-filesystem rename inside the Core transaction, and removes the published workspace when synchronous Core replay fails; this is coordinated rollback, not crash-atomic filesystem and SQLite commit.
- Fresh general and Quick Chat Workspaces initialize the complete scoped migration journal in their staged database before publication. Scoped discovery excludes `.staging`; a published Workspace with a missing database remains discoverable. Its boot scan and existing-only open fail without creating a replacement; database creation stays on the Workspace-create path.
- Deletion removes the canonical file or directory so restart cannot resurrect stale state.

## Verification

The accepted [Knowledge retrieval contract](../../../../docs/specs/20260703-knowledge_store_implementation.md#retrieval-pipeline) separates Memory and Knowledge, uses Core Protocol's path-qualified references and publishes one immutable trace file under its querying Thread/Turn. Threadless direct User App calls publish no trace. The governed path uses qualified pins and query-owned files; no Workspace JSONL trace remains. The retrieval publisher alone writes query-owned trace files; no manifest array, compatibility reader, second writer or private Memory union is permitted. Ordinary portable export applies current containing-record and source access. The deletion lifecycle instead uses its exact verified deletion request authority after ordinary Workspace authority closes; its recovery export preserves normalized trace evidence through the same portable file owner.

Run focused layout, migration, database, canonical reload, index rebuild, export, import, integrity failure, and backup tests for the changed owner, followed by the package gates in the [NanoCore source guide](../README.md).
