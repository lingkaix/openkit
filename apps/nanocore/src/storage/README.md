- Writers store DATA_ROOT-relative path references. User and authored content may mention an absolute data root; layout verification does not scan text for that substring.
- Replace JSON records through a same-directory temporary file and rename.
- The stopped-process Workspace layout move validates an existing current `config/workspace.jsonc` and preserves its exact bytes, including the established Knowledge Base binding. Invalid current configuration refuses the move; only an absent configuration uses the existing predecessor metadata split. Migration never allocates a replacement base. Before publication, migration reads the exact native Workspace identity from its migrated private staged database. Missing or invalid native metadata refuses the move while predecessor roots and the layout marker remain unchanged.
- `writeFileAtomic` synchronizes complete bytes and any caller-selected mode before publication, then synchronizes the parent directory. Its default rename replaces a record; create mode links or fails without clobbering an immutable winner and removes the temporary link before acknowledgement. Callers retain their existing default modes. Vault keeps its separate no-follow writer and redacted errors with the same commit order.
- Existing Thread records skip file publication only when their complete projected canonical bytes match the current file. Changed bytes retain the durable writer; canonical validation, annotations and directory synchronization still run, including ordinary reopen after a failed rename acknowledgement.
- Directory preparation commits each parent entry before creating a child. Retries synchronize existing components left visible by failed creation. Vault initialization also completes the store-directory commit after authenticating a visible header.
- `publishCanonicalPath` and its asynchronous counterpart synchronize complete staged file or tree contents, with child directories before parents, before rename. They synchronize the destination parent and any distinct staging parent before success. Snapshot, Workspace, rollback and runtime evidence publishers use this shared boundary; exact evidence replay retries synchronization after an interrupted acknowledgement.
- Bounded filesystem faults verify prior readable authority before publication, explicit failure after rename, and exact replay. These checks do not simulate a physical power loss or prove hardware cache behavior.
- Append item and event revisions to JSONL; readers select the latest item revision by id and preserve event sequence.
- Fail closed on malformed canonical records, invalid lineage, unsupported required features, path escapes, and legacy authority files.
- Descriptive history readers normalize root and nested annotations before returning known fields. Normal canonical rewrites preserve owned annotations, immutable Knowledge Proposal bytes and append-only Item/Review history. Observation ingress persists its parsed payload, and unchanged receipt rewrites retain the original metadata JSON. Shared producer and instruction assertions remain exact.
- Export V3 preserves complete canonical history and exact portable file bytes; predecessor formats are rejected.
- Portable evidence keeps admitted restricted originals as verified binary bytes under their EvidenceBundle, separate from canonical UTF-8 records. Import remints owner references, preserves body digests and retention, and stages bytes before publishing the Workspace. Unpublished observation chunks and expired body bytes stay excluded.
- Current Goal portability retains intent history, card revisions, exact immutable Plan bytes and pointers, Task admission citations and Task terminal facts in `records/goal-state.json`. Import remints Workspace, Thread and Turn owners, keeps immutable Plan identities and bytes, binds responsibility to the importing actor and imports no grants. Retired Goal-owned rows are absent; shared historical Goal ids remain opaque lineage.
- Import writes the complete workspace tree and workspace database under `.staging`, publishes with one same-filesystem rename inside the Core transaction, and removes the published workspace when synchronous Core replay fails; this is coordinated rollback, not crash-atomic filesystem and SQLite commit.
- Native import initialization establishes the reminted default Knowledge Base before Notebook validation. The portable writer then preserves the exact admitted configuration bytes only when their default base matches that initialized binding. A missing or different binding refuses; other portable file collisions remain errors.
- Fresh general and Quick Chat Workspaces initialize the complete scoped migration journal in their staged database before publication. Scoped discovery excludes `.staging`; a published Workspace with a missing database remains discoverable. Its boot scan and existing-only open fail without creating a replacement; database creation stays on the Workspace-create path.
- Deletion removes the canonical file or directory so restart cannot resurrect stale state.
