# Knowledge Package Format

This module owns the directory form of Knowledge package v1: a shared retained-v1 manifest, exact byte inventory, fresh private writer and integrity validator. The [file-storage owner](../../../../../docs/specs/20261018-file_storage_and_knowledge_packages.md#knowledge-package-format) owns its meaning. This is separate from Workspace export V3 and deployment backup.

`format.ts` uses Protocol scope, Knowledge Base, digest and retained-format codecs. `schemaVersion: 1` is the sole version marker, and `format: openkit.knowledge-package` identifies the family. Each mount declaration belongs to the single manifest Knowledge Base; live mount records keep their owning base identity. Derivative entries and `derived/` payloads are deferred until a real exporter registers their semantics through `requiredFeatures`. Source pointers keep their canonical paths without a duplicate registry. `format.ts` keeps package admission and uses the internal Storage `verifyPrivateFileCopy` for already-admitted local regular files in 64 KiB chunks, preserving captured lengths, digests and stable file metadata. Manifest parsing is limited to 1 MiB. Caller-supplied positive safe-integer byte and entry limits include the manifest and directories; only the package root is excluded from the entry count.

`writeKnowledgePackageFormat({directory, metadata, files, limits})` requires a nonexistent directory below a trusted private parent. Each file supplies a private `sourcePath` and its expected package path, digest and byte length. Source parent directories must already be admitted and stable. The writer exclusively creates its own staging, preserves authored bytes, writes canonical manifest JSON, verifies the result and removes only its new directory on failure. It never overwrites an existing output or publishes a live Knowledge Base. A process interruption can leave private staging for its caller to discard.

`verifyKnowledgePackageFormat({directory, limits})` requires private immutable staging. It validates the shared version marker before interpreting family data, then mount bindings, confined unique paths, quotas and the complete regular-file inventory. It refuses links, special files, undeclared or missing files and incorrect byte identities. It does not execute files or contact external mount roots. Additional mount namespaces are reserved even when a conflicting folder is empty.

A successful format check establishes container integrity only. `operations.ts` captures one currently admitted Workspace Notebook revision and Source tree, exact schema bytes and available managed originals; available files that fail verification refuse export. External mount declarations and unavailable originals retain references without fetching bytes. `archive.ts` streams an uncompressed POSIX tar carrier (`application/x-tar`), limits the complete package to 8 GiB and 10,000 entries, and uses the existing 1,000,000,000-byte per-file bound. Metadata reads retain the Notebook's 2 MiB member and 32 MiB complete editing bounds. The sole retained package shape remains the directory manifest, independent of tar framing.

`routes.ts` admits parsed Workspace selectors through the native operation resolver before receiving or disclosing a stream. `POST /api/app/operations/knowledge.package.export?workspaceId=...` needs current `knowledge.read`. `POST /api/app/operations/knowledge.package.import?workspaceId=...` needs current `knowledge.write`, the tar body and `X-OpenKit-Request-Id`. Import returns the target Workspace, fixed Knowledge Base and actual Notebook revision. These streaming bindings do not enter model or MCP JSON tools. Completed exact import requests replay the same immutable publication through the existing input-hash, Audit and command receipt checks; they do not remint again or require the destination to remain a seed. Current source and page disclosure is checked during export streaming and before replay.

Import verifies every inventory member before target effects, reuses Source and page reminting, and rewrites parsed inline, image and reference-definition destinations before calculating dependent page pins. Markdown prose, code, labels and original line endings stay unchanged. It accepts only a system seed with no authored retained history, Source pointers, proposals, raw originals or nondefault mounts. Schema validation, current protected-page rules and the existing human Notebook publisher remain authoritative. Imported Review labels cannot supply a target human decision. The publisher writes pages and Source pointers in one new commit whose parent is the target seed; raw digests stay unchanged. The existing Audit and command receipt supply publication evidence; no package receipt or store is added. Validation and staging failures preserve the target; a published or unknown result remains subject to the existing explicit recovery outcome. Private request staging uses the existing boot-cleaned archive-request namespace and is removed on completion, failure or response cancellation. Request-tree allocation, member-directory creation and caller-owned removal use the existing Storage primitives; tar validation, file streaming and reservation accounting stay in this module.

The minimal public round trip is Workspace-to-Workspace and does not select historical content, activate remote mounts, export derivatives or import deployment authority. Those exclusions add no compatibility reader or converter.

Run the complete module regression directory with `pnpm --filter @openkit/nanocore exec vitest run src/storage/knowledge-package`, then NanoCore typecheck and lint through the repository gate. Fixtures freeze page/schema bytes, binary originals and canonical manifest output independently of the implementation.

Bootstrap import accepts only the exact historical built-in default or the exact fresh built-in default at its recorded creation instant, in addition to the existing untouched system-seed predicates. Merely valid or custom-maintained schema text is not an empty-default proof. Imported schema metadata and authored bytes remain unchanged; import does not replace their timestamps or implement a general reviewed schema migration (#508). The existing import command alone can replace the proved bootstrap schema in the native Notebook head/Audit/receipt tuple. Publication rechecks the observed destination head and schema, while current destination authority and protected-page requirements still decide admission.

Export metadata capture uses the internal Storage `createPrivateMetadataDirectory` and `writePrivateMetadataText` helpers. Knowledge selects each path and exact text in the original page, schema and Source order, records an inventory entry only after its write, and retains admission, accounting and reservation release. The physical move keeps exclusive creation, original modes and failure residue; it adds no retained authority, retry or cleanup stage.

Manifest staging sends exact serialized text to Storage's exclusive private text writer. Knowledge retains manifest selection and limits, member copying, complete verification and whole-tree cleanup; a failed physical write keeps its original native error and cleanup precedence.

Import installation and selected copied-file/directory compensation use the existing Storage physical owner. This module retains the exact unchanged-head and schema proof before compensation, original schema/config restoration, later graph verification and unconditional reservation release. Unknown or changed publication preserves evidence. A failed native partial copy can leave an unrecorded prefix and cause the original directory cleanup to fail; this move preserves that existing limitation, without claiming general rollback safety. Export metadata staging retains its existing Storage helpers and separate caller-owned lifetime.
