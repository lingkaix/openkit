# Private Administration Entry

Administration waits for the native terminal acknowledgement before it accepts Stop. Its original conversation receipt and Audit join the waiting Stop receipt and Audit in that transaction; a refusal commits neither command tuple and returns recovery_required.

This directory owns the private administration conversation entry and its fixed model-visible Tool assembly. It reuses the shared Internal Agent Loop and existing Core operation owners; it does not own configuration, Worker environment, approval, authentication, or storage effects.

## Boundaries

- Admit only the current user's `administration` Thread in that user's owner-only Quick Chat Workspace.
- Exact admission and partial-state probes use current scoped Thread and Turn reads rather than listing unrelated history. Turn probes still validate the current parent and selected retained history; only definite selected absence is normalized, while the outer recovery classifier remains best effort.
- Recheck current deployment-administrator authority at entry and before every Tool closure. The model never receives token material.
- Keep the exact Tool order in `administration-tools.ts`. Configuration read and schema Tools expose the registered Server Agent family and editable Provider/Gateway catalog fields. Agent discovery returns exact file identities and revisions for image preparation. Catalog discovery returns target identities and source revisions; proposals publish an immutable, non-secret before/after Artifact through `../config/administration-configuration.ts`.
- Agent configuration detail reads its allowlisted fields and `sandbox.network` from the same current validated registered source as `expectedRevision`. The loaded snapshot version and hash remain separate observations. Network inspection excludes filesystem grants, credential declarations, permissions, extensions and raw source text. It supports [Git-read diagnosis](../../../../docs/specs/20260922-delegated_worker_policy_maintenance.md#first-registered-target-and-action), grants no effect authority; delegated application has its separate finite Policy check.
- Assemble the fixed administration role text from `../internal-agents/builtin-prompts.ts` with current server-authored private Workspace and Thread identifiers for each run. Tool definitions remain the exact entry-owned set and are passed separately to the shared loop.
- Pass that same assembled prompt and ordered Tool set to `withTurnModelCapture` before the loop. Its Core `env.bound` observation retains the exact injected NanoCore build revision (or `unknown`), Workspace identity, prompt digest and Tool name/input-schema digests even with full I/O capture off; prompt text, schemas and descriptions stay out of the row. Required retention failure stops the run through the existing administration failure path.
- Environment Tools are injected from their operation owner and remain list, status, prepare, and recover only. Preparation uses the actual current administration Turn and the shared immutable Agent configuration candidate service; it validates the exact file revision and publishes authored/resolved Artifacts without applying them. Activation and purge stay on human-confirmed public commands. Catalog application uses `POST /api/app/operations/administration.configuration-apply` after human review of the exact candidate digest; Provider/Gateway application is never a model Tool.
- `nanohost.runtime-target` is the ninth fixed Tool. It reuses `readConfiguredNanoHostRuntimeTargetStatus` with the definition-derived public JSON operation, selects that exact definition even when the administration table grows, accepts only an empty object, and never infers unreadiness from Provider catalog or Worker environment absence. The result is Core's stored projection at `observedAt`, not a live host probe. NanoHost is the execution host, not an LLM Provider.
- Persist ordinary Turn and Item records. Do not introduce a private run ledger, Worker lease, shell, Docker socket, or arbitrary MCP/Skill surface.
- After admission, keep the model run independent of the submitting Request signal. `administration-operations.ts` owns only live interruption handles; the existing Turn and command receipt remain durable authority. The existing `turn.interrupt` operation stops the exact run and waits for its retained interrupted outcome. No handle resumes work after restart. Assistant profiles and profile-free admission use the shared 600-second default; explicit limits remain binding. Ordinary answer deadlines use `internal_agent_deadline_limit`; context preparation retains its context-specific failure. The [Administration owner](../../../../docs/specs/20260704-chat_mode_assistant.md#administration-entry-path) defines this boundary.

The configured RuntimeTarget Tool derives its descriptor from the shared administration operation table and executes through `../operation-invocation.ts`. Invocation rechecks current deployment-administrator authority on every call; the other eight Tools retain their existing closure check. The actual assembly supplies authenticated actor and private Workspace/Thread/Turn lineage, returned in non-secret Tool details. `operation-invocation.test.ts` proves that provenance and next-call revocation through the ninth assembled Tool.

## Verification

Run the focused administration tests together with `internal-agent-loop.test.ts` and `gateway-provider.test.ts`, then the NanoCore package checks described in the [source guide](../README.md). `administration-lifetime.test.ts` composes the real entry, loop, configuration candidate owner and interrupt operation. It checks disconnect survival, exact candidate/replay effects, explicit interruption, late-result refusal and ordinary answer deadline diagnostics.

The fourth fixed configuration Tool, `administration.configuration.dispatch`, accepts only request identity and exact candidate reference. Assembly binds its current actor, private Thread/Turn and cancellation signal; the Artifact origin cannot replace this invocation. The configuration owner refuses Provider/Gateway candidates in that projection and evaluates finite loaded Server Policy for Worker Git-read corrections. The complete private set has nine Tools in stable order; the ordinary Assistant receives none of this delegation.

`server-mcp-operations.ts` implements current-administrator Server MCP configuration, version selection, binding and restricted Vault lifecycle through the existing native operation table. It uses the catalog owner and Core command ledger, with a pre-effect Audit fence and current-resource replay. File/backend effects, Core evidence and session cleanup remain separate. Canonical Server publication governs shared admission without reloading unrelated authored configuration. Narrowing and its linked original/replacement Audit share the existing Core transaction. The exact reference identity is audited before material storage so authorized recovery can inspect a partial backend publication. This family grants the private administration model no general catalog or secret Tool. Ordinary Workspace projection list/disable operations use existing Workspace admission.

The private apply Tool preserves the existing unknown-effect boundary after CAS or publication failure. Untyped application failures and typed recovery results return `configuration_recovery_required` with receipt, start status Item, outcome Artifact, source revision and loaded-state inspection. Read/proposal refusal text cannot claim that an uncertain application was rejected or advise another proposal. The real-owner regression in `../config/delegated-worker-git-read.test.ts` injects outcome and receipt publication faults after the actual write and exercises the fourth Tool, including same-request fencing.

Administration environment Tools use their `worker-environment.*` operation IDs. The fixed assembly retains the current administrator check on every call; a name match does not remove that authority check.

Server MCP binding authoring controls selected allowedTools supply only. Per-Tool prohibit and require_approval use the existing human full Policy candidate and confirmation, with exact Workspace selectors; no second MCP permission writer exists.

Administration acknowledges the original `turn.interrupt` receipt and authenticated Audit with the live Turn before it signals cancellation. Acceptance proves no terminal outcome; the existing interruption path still waits for the retained interrupted result. The original `conversation.submit` receipt, response metadata and Audit commit with that conversation's own terminal tuple, including refusal and interruption, so replay does not write a receipt from Main.

Server MCP reference revocation awaits the existing native credential revocation composition as well as Gateway session closure after its Core fence. This also covers valid retained direct Server runtime-env grants. Server grant revocation and narrowing remain restricted to their exact Gateway-only family.
