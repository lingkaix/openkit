Harness result acknowledgement retries retain the exact prior receipt while a successor operation is queued. Settled-state replay uses the recorded operation. For queued predecessors, every operation reader that accepts the fingerprint-verified retained body must also accept the incoming body and find the same normalized known core between retained and incoming. No matching reader, any incoming reader refusal or any core difference conflicts without mutation. Shared refusal grammar can therefore replay without a unique operation name, while inert additions cannot hide a change seen by any plausible reader. An admitted identical replay only returns the acknowledgement; it neither mutates the successor nor notifies its producer. Dispatching the successor clears the prior receipt, after which stale or changed results remain conflicts. The record and HTTP/2 replay regressions compare complete serialized SQLite snapshots with `Buffer.equals`, preserving the no-mutation oracle without object deep equality traversing each byte index. Run both `nanohost-harness-records.test.ts` and `nanohost-session-dispatch.test.ts` with `--maxWorkers=2` for this seam.

Successful Harness `session.close` proves the binding closed and its disposable private state absent. Host liveness is not the close proof: a shared host may remain running for siblings. The same transaction deletes the binding and releases that binding's open-session occupancy and, if it still names a current Turn, one active-Turn slot. Closing an idle sibling preserves another binding's active occupancy; a refused close other than `cleanup_required`, and an unknown close, release nothing. `cleanup_required` drains the Harness and, while the cleanup owner is still live, issues the first `bridge.close` and `sandbox.delete` when neither was dispatched; those successes release the binding's capacity, and a failure keeps the admission fence. A settled refused idle predecessor close with an exact effect-free successor attempt defers the same queued admission and pending Turn through the scheduler's existing capacity signal. The next read-only preparation recognizes whole-Sandbox retirement before acquiring a new attempt; deletion still requires exact admitted lineage. A failed wider retirement propagates as a real preparation failure and preserves the Sandbox/storage fence rather than deferring repeatedly. Result-only recovery stays limited to a genuinely uncertain earlier dispatch. A binding whose terminal inspection reported `failed` without clean state keeps its Turn slot until that close, under the [shared-Sandbox lifecycle owner](../../../../docs/specs/20260802-nanohost_runtime_and_transport.md#shared-sandbox-harness-topology). Definite no-effect incoming failures preserve the shared resident and finish the existing failed Turn publication without cancelling queued siblings. Pre-dispatch cleanup errors preserve residency; uncertain dispatched cleanup fences only its exact Sandbox and origin Epoch. Accepted-final maintenance continues wider fenced cleanup for a cleaned backend anchor without restoring the obsolete binding; same-Epoch release remains incomplete, and fresh replacement proof releases storage and removes the resident before attempt closure.

NanoCore refuses non-empty values during AEP resolution before Sandbox effects; empty and absent values resolve normally. See [Agent Manifest And AEP Resolution](../../../../docs/specs/20260703-agent_manifest_aep_resolution.md).
