# Retired Specs

This directory keeps `Status: Retired` specs whose contracts, modules, capabilities, or product directions ended without successor contracts, including deliberate resets.

Retired specs are not current guidance. Each spec must use `Implementation: N/A` and include the lifecycle date, `Current Guidance: None`, decision evidence, a substantive lifecycle reason, and a distinct retention reason required by the parent [specification guide](../README.md).

Only an auditor may add a spec to this directory, and the non-authorizing terminal-archive audit record must land in the same change. That record captures the accepted decision, exact source and archive paths, final SHA-256 of every archived file, complete authority-criterion receiver inventory, and every inbound current-guidance link disposition.

Files already archived here are immutable. Do not edit metadata, prose, links, spelling, formatting, or paths, and do not delete a file; record later observations in a new audit record and put any renewed contract in a new root-level specification, linking the terminal-archive audit only when one exists.

Do not backfill terminal-archive audits for files that predate the auditor-owned rule. Evidence corrections already included in the rule-adoption change may land with it; the resulting committed bytes are the frozen archive.

Use root-level specs and stable core documents as current entry points. Link to files in this directory only when historical evidence is explicitly needed.
