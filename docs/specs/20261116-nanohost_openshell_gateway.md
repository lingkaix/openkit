# NanoHost OpenShell Gateway

This specification owns the NanoHost-to-OpenShell-Gateway and Sandbox-to-Gateway boundaries within one NanoHost Runtime Epoch: the epoch-local loopback mTLS Gateway client, fixed unary worker bootstrap and single-file helper RPCs, the stock `ForwardTcp`/`RelayOpen`/`ConnectSupervisor`/`RelayStream` Sandbox transport bridge, epoch-private Linux network and mount namespace containment, and stock OpenShell release selection and integration qualification.

## Scope

### Owns

- The single epoch-local authenticated loopback mTLS client channel from the NanoHost service to the stock OpenShell Gateway, and the rule that NanoHost is the sole OpenKit caller of Gateway management and forwarding APIs.
- The fixed `ExecSandboxInteractive` single-file helper realization and the fixed unary `ExecSandbox` worker bootstrap (`OPENKIT_WORKER_SHIM_ENTRY_V1\n`) and Integration-lifetime response monitor.
- The Sandbox transport requirement and its stock `ForwardTcp`/`RelayOpen`/`ConnectSupervisor`/`RelayStream` realization carrying one nested standard HTTP/2 session per active Sandbox between Sandbox Integration (`127.0.0.1:17891`) and NanoHost, plus the native Agent loopback HTTP/1 projection (`127.0.0.1:17892`).
- Host-to-Sandbox process, credential, and Linux network/mount namespace containment (`containerd`, `dockerd`, stock Gateway, and host-namespace `slirp4netns`) keeping the system Docker daemon and host network untouched.
- The qualified stock OpenShell release boundary (`apps/nanohost/openshell/release.json` and `transport-assumptions.json`), envelope measurement boundary, fast deterministic foundation checks, and opt-in real-stock upgrade qualification.
- Stock OpenShell and standard HTTP/2 are consumed without an OpenShell fork, patch, replacement Gateway, private Supervisor, custom multiplexer, arbitrary proxy, arbitrary tunnel, private OpenShell protocol, operator-managed or externally exposed Gateway forward, direct worker endpoint, or direct Sandbox-to-NanoCore path; the NanoHost-owned loopback `ForwardTcp` stream and the one pinned opaque Gateway-internal SSH relay beneath the fixed single-file `ExecSandboxInteractive` helper are stock Gateway implementation closure only, not selectable SSH transport or an alternate execution topology.

### Does Not Own

- Runtime Epoch topology, Sandbox incarnation placement and residency, on-demand idle Sandbox retirement, Image Store, distribution archives, operator replacement and live inspection, and forensic Epoch Invalidation Reports in [NanoHost Runtime And Transport](20260802-nanohost_runtime_and_transport.md).
- The outer NanoHost-to-NanoCore HTTP/2 session, `nanohost-transport` Token lifecycle, server TLS trust, 12 fixed effect envelopes, carrier transport, stream/window reservations, and liveness/outage timers in [NanoHost Transport](20261116-nanohost_transport.md).
- Worker-control protocol schemas and adapter liveness in [Worker Control Protocol](20260703-worker_control_protocol.md) and [Worker Runtime Communication Model](20260629-worker_runtime_communication_model.md), workspace file/collection boundaries in [NanoHost Workspace Data Boundary](20260801-nanohost_workspace_data_boundary.md), and OpenShell policy/provider mechanisms in [OpenShell Mechanism Internalization](20260703-openshell_mechanism_internalization.md).

## Parties

Within the topology defined by [NanoHost Runtime And Transport](20260802-nanohost_runtime_and_transport.md), five runtime participants interact across the Gateway and Sandbox boundaries:

- **NanoHost service (`apps/nanohost`)**: the trusted execution-host process and sole OpenKit holder of epoch-local Gateway client and `ForwardTcp` credentials, acting as the gRPC/HTTP/2 client to the stock Gateway and the standard HTTP/2 server for each active Sandbox's nested session before projecting accepted streams onto [NanoHost Transport](20261116-nanohost_transport.md).
- **Stock OpenShell Gateway (`openshell-gateway`)**: the unmodified checksum-verified foreground process at the qualified pin running inside the epoch-private network and mount namespaces, bound only to namespace loopback and pairing NanoHost `ForwardTcp` streams with Supervisor `RelayStream` connections.
- **Stock OpenShell Supervisor (`/openshell-sandbox`)**: the exact release-pinned static-musl sandbox supervisor extracted by the stock Docker driver's explicit-image Tier 2 path, maintaining the authenticated `ConnectSupervisor` stream to the Gateway and dialing Sandbox Integration's loopback bridge listener.
- **Configured container backend (`dockerd` and `containerd`, with `slirp4netns`)**: the single host-local V1 Docker effect domain (`dockerd` and `containerd`) sharing the epoch-private network and mount namespaces with the Gateway, connected to the host network only through the supervised host-network `slirp4netns` helper (which runs in the host network namespace and its own private helper mount namespace attached through the retained namespace descriptor).
- **Sandbox Integration (`packages/worker-shim`)**: the sandbox-local supervisor launched by unary `ExecSandbox`, binding the Supervisor-only HTTP/2 bridge listener (`127.0.0.1:17891`) as the nested HTTP/2 client and the native Agent HTTP/1 listener (`127.0.0.1:17892`) for Session-scoped inference and capability projections.

## Service-To-Gateway Operations

- **One epoch-local Gateway mTLS client**: the NanoHost service is the only OpenKit process that may authenticate to the stock Gateway or invoke its management and forwarding APIs (`apps/nanohost/src/openshell_client.rs`). At steady state it maintains one current epoch-local authenticated mTLS logical client channel to the loopback-only Gateway, shared across stock lifecycle RPCs, the `ForwardTcp` stream for each active Sandbox, one fixed `ExecSandboxInteractive` single-file helper, and one fixed unary `ExecSandbox` worker bootstrap/monitor inside `bridge.open`. NanoCore supplies authorized work and immutable package inputs, but cannot select a Gateway address, method, socket, target host, target port, service ID, authorization token, arbitrary OpenShell operation, executable, environment, working directory, or timeout; the Sandbox Integration target is an image-owned fixed loopback binding resolved by NanoHost, and CLI listeners, operator-managed local forwards, public Gateway ports, NanoCore-to-Gateway connections, and second data channels are prohibited.
- **Short-lived namespace connector**: the stock Gateway binds its fixed loopback endpoint inside the epoch-private network namespace (`apps/nanohost/src/epoch_coordinator.rs`). NanoHost owns one fixed connector for the initial Gateway channel and every permitted physical reconnect: one short-lived thread enters only the retained network-namespace file descriptor, connects the fixed loopback endpoint, returns only the connected socket to the Tonic channel owner, and exits. It creates no proxy, listener, second logical channel, member relaunch, reconnect authority, or alternate endpoint.
- **SDK-only normal operations vs diagnostic CLI**: NanoHost may invoke the optional OpenShell CLI (subject to [Supported Release Set And Metadata](#supported-release-set-and-metadata)) only for installation-time version inspection or explicitly authorized diagnostics; Sandbox create, inspect, readiness, delete, provider or policy setup, session authorization, and forwarding during normal execution MUST use the compiled SDK client and the single current Gateway channel, and a subprocess exit code or parsed CLI text output is never lifecycle settlement evidence.
- **Epoch-local `ForwardTcp` authorization**: NanoHost obtains stock `ForwardTcp` authorization material through the supported-release Gateway API. That material is sandbox-bound, short-lived, epoch-local OpenShell authentication state (not runtime SSH transport even when the upstream API names the issuing record as an SSH session), MUST remain inside the NanoHost and Gateway boundary without entering the AEP or Sandbox, and MUST be revoked or discarded when the bridge closes.
- **Fixed `ExecSandboxInteractive` single-file helper**: for `reference.import` and `file.export`, NanoHost invokes the supported-release typed `ExecSandboxInteractive` RPC on that same retained mTLS client for the exact current ready Sandbox and one NanoHost-owned fixed helper command (with fixed command, arguments, environment, working directory, timeout, SSH fields, and endpoint, bound to an exact AgentSession and Turn slot under [NanoHost Workspace Data Boundary](20260801-nanohost_workspace_data_boundary.md) with no Sandbox-global package or Context destination). The one pinned opaque internal SSH relay beneath `ExecSandboxInteractive` is allowed solely as implementation closure of the fixed single-file helper, using the Gateway's authenticated ready-Sandbox authorization and one stock single-use Gateway-internal loopback listener that disappears after the call and is neither OpenKit-managed nor reachable from the Sandbox or public network; all OpenKit-managed, exposed, configured, or caller-selected SSH, direct SSH credentials/endpoints, SSH tunnels/lifecycle/control/settlement/fallbacks, stock CLI upload/download, and second connections remain prohibited.
- **Worker Shim bootstrap.** Within keep present, start one shim on the exact provider-scoped incarnation before opening its carrier. Refuse a second start. Use the fixed image-owned entry, working directory, no TTY and empty input. Configure no execution timeout. Omit it using the qualified release's encoding. Retain the shim-lifetime observation. A lost or ambiguous start leaves the incarnation held for recycle.

## Sandbox Transport

- **Durable Sandbox transport requirement**: for each active Sandbox, the runtime MUST provide one current authenticated bidirectional byte stream between Sandbox Integration and the NanoHost service established entirely inside the execution-host loopback boundary toward a NanoHost-fixed Integration target (never from caller input, and without exposing the Gateway, container-runtime socket, Supervisor interface, or any Sandbox port or using an operator forward, public listener, or direct Sandbox-to-NanoCore path). The stream carries one standard HTTP/2 session with Sandbox Integration as the HTTP/2 client and NanoHost as the HTTP/2 server, with no OpenKit frame envelope, channel identifier, byte multiplexer, replay buffer, or private reconnect layer, providing bidirectional streaming, definite closure, cancellation propagation, and end-to-end backpressure sufficient for the transport envelope in [NanoHost Transport](20261116-nanohost_transport.md), proving predecessor closure or fencing before a successor carries route traffic, and exposing only the three declared route namespaces (`/worker-control/*`, `/inference/*`, `/capabilities/*`).
- **Stock `ForwardTcp`/`RelayStream` realization and byte adapter**: each active Sandbox uses one current stock `ForwardTcp`/`RelayStream` pair and one nested HTTP/2 session at steady state—or two pairs only when the bounded conditional worker-control fallback in [NanoHost Transport](20261116-nanohost_transport.md) is authorized by recorded measurement evidence (`apps/nanohost/src/sandbox_bridge.rs`). NanoHost's per-Sandbox byte adapter translates only stock `TcpForwardFrame` bytes, closure, cancellation, and backpressure (with local bounded frame-channel capacity `4`, current default) into one asynchronous byte stream serving the nested standard HTTP/2 server while Sandbox Integration remains the HTTP/2 client despite the Supervisor dialing its loopback listener; worker-control, inference, and capability requests open standard HTTP/2 streams on that long-lived session rather than new Gateway forwards or `RelayStream`s, the stock Supervisor control stream remains an OpenShell lifecycle channel rather than a fourth OpenKit route family, and no OpenKit frame, channel ID, replay buffer, request retry, dynamic target, or second connection is added.
- **Entry marker stream validation (`OPENKIT_WORKER_SHIM_ENTRY_V1\n`)**: immediately before entering the Worker Shim poll loop, the image-owned entry module writes the exact ASCII bytes `OPENKIT_WORKER_SHIM_ENTRY_V1\n` to unary `ExecSandbox` stdout once (a fixed implementation token with no interpolation, path, identity, token, or timestamp, proving only entry load alone. Listener and session readiness, Worker start, Turn settlement and absence each require their own evidence). `exec_sandbox_worker_bootstrap` consumes stdout as a byte stream allowing arbitrary byte-boundary splitting across stdout events while ignoring empty stdout/stderr events; every non-empty stdout chunk before completion must extend the exact marker prefix, while missing, incomplete, or duplicate marker bytes, Exit or stream completion before the complete marker, any other non-empty stdout before or after the marker, any non-empty stderr, or response failure fails bootstrap for that incarnation, and the marker is consumed in NanoHost memory only (never logged or persisted) before handing the still-live response monitor to the bridge path.
- **Ordered stock bridge establishment and poll admission**: for one active Sandbox, bridge establishment executes in exact order before admitting Worker work:
  1. The stock Supervisor establishes its authenticated `ConnectSupervisor` stream to the loopback Gateway for the current Sandbox principal correlated by NanoHost within the current epoch.
  2. NanoHost sends the qualified release's fixed Start with no execution timeout, accepts the entry marker, and retains the live monitor while the Worker Shim binds its fixed listener.
  3. NanoHost opens one stock `ForwardTcp` bidirectional stream naming the current Sandbox, fixed Integration loopback target (`127.0.0.1:17891`), bounded service identifier, and stock target authorization, never opening an overlapping second `ForwardTcp` for the same Sandbox while a slot is pending.
  4. The Gateway validates the request and sends one `RelayOpen` carrying a Gateway-allocated channel ID and fixed target on the Sandbox's `ConnectSupervisor` stream.
  5. Within NanoHost's bridge-establishment and recovery budgets (treating an unclaimed, rejected, closed, or locally timed-out slot as a definite bridge failure for that Sandbox and recording the stage and elapsed interval in private qualification results without depending on Gateway internal reaper cadence), the stock Supervisor dials `127.0.0.1:17891`, initiates one `RelayStream` with the matching channel ID, and reports definite open success or failure.
  6. The Gateway pairs the pending `ForwardTcp` and `RelayStream` by channel ID and bridges raw bytes in both directions without parsing OpenKit routes.
  7. Sandbox Integration sends the standard HTTP/2 client preface on the paired byte stream to the NanoHost HTTP/2 server, exposing only `/worker-control/*`, `/inference/*`, and `/capabilities/*`.
  8. The Worker Shim sends its first poll over the bound relay. NanoHost refuses a client-supplied binding and supplies the exact current Sandbox incarnation association from the authoritative outer connection. NanoCore verifies current lineage, authentication and release before accepting the poll. See [Worker Control Protocol](20260703-worker_control_protocol.md#worker-shim-poll).
  9. Current poll admission proves the shim carrier is ready for this incarnation. It grants no Turn authority and establishes no Worker start.
  10. Keep present can report the incarnation ready after the correlated Start, request EOF, live monitor, bridge, nested HTTP/2 session and admitted first poll. Bind readiness to the enrolled Host, deployment, current connection generation and origin Host epoch. Include the realized attachment and envelope under the [environment provider contract](20261020-compute_neutrality_target.md#environment-provider-contract).
- **Fixed loopback listeners (`127.0.0.1:17891` and `127.0.0.1:17892`) and native HTTP/1 projection**: Sandbox Integration binds both fixed loopback listeners before emitting the entry marker (`packages/worker-shim/src/integration-client.ts`): `127.0.0.1:17891` remains exclusive to initial and successor stock Supervisor bridges, while `127.0.0.1:17892` is the native Agent HTTP/1 listener whose admission stays disabled until the nested HTTP/2 client is ready (`http://127.0.0.1:17892/inference/v1` and adapter-owned fixed capability URLs, with both `NO_PROXY` and `no_proxy` in the native child including exact `127.0.0.1`). The native listener accepts only `POST /inference/*` with that AgentSession's inference loopback credential or `POST /capabilities/*` with its capability loopback credential, plus the exact existing `POST /worker-control/credential-helper` exception (`packages/worker-shim/src/credential-helper-client.ts`) bound to the current AgentSession and Turn under [Worker Credential Access Declarations](20260703-vault_secret_injection.md#on-demand-credential-channels), rejecting all other `/worker-control/*`, cross-family bearer, disabled-capability, absolute-form URL, unauthenticated, or non-`POST` traffic before opening an outer stream. It enforces each semantic owner's encoded request aggregate (including the independent fixed `512 KiB` capability per-request collection limit) plus the separate `2 MiB` inference or `1 MiB` capability in-flight `DATA` ceiling (current derived defaults from [NanoHost Transport](20261116-nanohost_transport.md)) and common `64 KiB` write bound (current default), translates authentication from the session loopback credential to the bound Turn's upstream route token ([Worker Agent Capability](20260703-worker_agent_capability.md)), applies the adapter-owned native-inference normalization (`normalizeNativeInference` in `packages/worker-shim/src/integration-client.ts` under [Worker Runtime Subagent Provenance](20260711-worker_runtime_subagent_provenance.md) when decoding registered native representations, consuming native hint fields, supplying the admitted runtime hint, and adjusting encoding/length headers when rewritten), and streams unchanged origin-form paths and all bytes, end-to-end headers, content encodings, and SSE responses left unchanged by that normalization with backpressure, single-stream cancellation propagation, and no local retry or replay.

## Containment

The containment rules below enforce **security and adjudication isolation** between the execution host and its Sandboxes; co-resident AgentSessions inside one shared Sandbox remain one compromise domain receiving conversation-context and Workspace-write isolation ([NanoHost Runtime And Transport](20260802-nanohost_runtime_and_transport.md)):

- **Epoch-private network and mount namespaces (`apps/nanohost/src/epoch_coordinator.rs`)**:
  - In the V1 Docker backend, dedicated `containerd`, dedicated `dockerd`, and the stock Gateway share one fresh Linux network namespace owned by the current Runtime Epoch (whose device and inode MUST differ from the NanoHost host namespace and any still-observable prior-epoch namespace), while the NanoHost parent and one exact `/usr/bin/slirp4netns` cgroup member remain in the host network namespace so no backend member or Gateway process shares the host network or mutates the system Docker daemon's links, routes, nftables tables, `docker0` bridge, or business containers.
  - Epoch creation starts `containerd` in a new network namespace, retains a close-on-exec descriptor (`fd`) proved by device and inode before starting other members, and starts `/usr/bin/slirp4netns` as a direct foreground service-cgroup member configuring that retained namespace via an inherited duplicate at fixed descriptor `4` (`--netns-type=path`, `/proc/self/fd/4`, never by PID) with `--configure`, `--disable-host-loopback`, `--disable-dns`, `--enable-sandbox`, `--enable-seccomp`, `--ready-fd=3`, and fixed `tap0` under systemd `PrivateMounts=yes` with `/run/docker.sock` masked (proving helper readiness by the bounded ready-fd `3` signal plus expected namespace inode, `tap0`, and default route).
  - Before creating the namespace or starting a member, NanoHost reads `/run/systemd/resolve/resolv.conf` once, extracts `1..3` unique plain unicast IPv4 `nameserver` literals in file order (failing before effects on a missing file, `0` or `> 3` resolvers, duplicate or malformed lines, or unspecified/loopback/multicast/broadcast addresses, and ignoring search domains, options, host aliases, and proxies), renders an epoch-owned resolver file, and has `containerd` create one shared recursively private mount namespace (retained via a close-on-exec mount-namespace `fd` verified distinct from the parent mount namespace) with the epoch resolver bound read-only over `/etc/resolv.conf` before `exec`. Dedicated `dockerd` and the stock Gateway join that same retained mount namespace before `exec` (with verified matching device/inode and no host mount propagation or fallback), and NanoHost passes the same accepted IPv4 resolvers as fixed DNS arguments to `dockerd` while `slirp4netns` DNS stays disabled.
  - The retained network and mount namespace descriptors and `slirp4netns` child are Runtime Epoch members: any resolver rejection, namespace mismatch, `slirp4netns` timeout/exit, missing private route, Gateway bind failure, or partial start invalidates the complete epoch; controlled teardown terminates and reaps `slirp4netns` and all namespace holders before releasing the retained descriptors; NanoHost `SIGKILL` closes its descriptors immediately while systemd terminates the service cgroup; and every fresh start creates and proves fresh network and mount namespaces.
- **Gateway, credential, and host-surface confinement**:
  - Gateway authentication material is epoch-local and discarded with the epoch generation, never entering Core, AEPs, Sandbox Integration, Workers, or cross-class credential use.
  - The stock Gateway, container-runtime sockets, Supervisor interfaces, cgroups, host roots, process IDs, and OpenShell credentials remain private to the execution host (`RelayStream` is the sole Sandbox-to-Gateway route; Sandbox Integration never authenticates to the Gateway, calls `ForwardTcp`, receives Gateway credentials, opens direct NanoCore connections, or uses operator forwards or host-network exceptions, and `RelayStream` failure is transport failure rather than proof of Turn cancellation, worker termination, Sandbox deletion, or sibling security isolation).
  - The raw `nanohost-transport` Token stays in its one-time issuance path and execution-host sink (`0600` file mode and service/root ownership outside the Epoch; slot opening verifies regular-file service ownership and refuses symbolic links before reading) over server-authenticated TLS or exact same-host loopback HTTP/2 ([NanoHost Transport](20261116-nanohost_transport.md)), and NanoHost, worker-control, inference, capability, OpenShell, provider, and Vault credentials remain distinctly bound and fail closed at their exact boundaries.
  - NanoHost accepts no NanoCore-supplied shell command, unit name, root path, port, socket, binary path, environment, working directory, timeout, SSH field, or arbitrary OpenShell RPC selector: build definitions are consumed only as backend build data under backend containment (with no host mount, host network namespace, or Token/Gateway/socket/store-write access, and `{docker.io:443, ghcr.io:443}` OCI bootstrap kept separate from exact AEP `{host, port}` `RUN` grants), the Image Store remains inert and private, Epoch Invalidation Reports are secret-scanned and redacted, and normal execution exposes no SSH surface outside the pinned opaque `ExecSandboxInteractive` single-file helper relay.

### Envelope Measurement Boundary And Calibration

- **Compositional memory proof and `transport-assumptions.json`**: because one inference response traverses the nested HTTP/2 session, Supervisor relay stream, Gateway pairing buffer, NanoHost forward stream, and outer HTTP/2 session, real-stock qualification MUST prove bounded intermediate buffering by combining live external observations with exact-release source-evidenced finite stock holding points in `apps/nanohost/openshell/transport-assumptions.json` (retaining only release commit, source path/SHA-256, queue multiplicity, per-frame or per-direction bound, and load-bearing reason for `forward-response-queue`, `relay-queues`, and `gateway-pairing-buffer`, rebound and reviewed on every candidate release and deleted if later observed directly, with no protobuf copy or RPC inventory; source hashes or finite load tests alone cannot prove the hard memory bound).
- **Four named byte boundaries and composed ceiling**: the closed measurement vocabulary has four direction-specific (`current` and `peak`) byte counts—`outer-session` (admitted to outer H2 and not yet consumed), `relay-composite` (held at the NanoHost `ForwardTcp`/`RelayStream` adapter boundary), `worker-control` (in-flight `DATA`), and `inference` (in-flight `DATA`)—never substituting serialized sizes, file sizes, process RSS, or constants. A family's composed ceiling is the sum of its per-session in-flight ceilings across spanned sessions plus the admitted finite stock contributions (when only application endpoints are observable, `outer-session` and `relay-composite` may be conservatively bounded together as direction-specific produced-minus-consumed bytes against the composed ceiling while keeping separate per-session/per-family ceilings enforced; missing observability fails the gate, and any production observation seam requires a separate accepted specification amendment and implementation package).
- **Saturation, liveness predicates, and measurement lifecycle**: `Saturating inference load` holds the inference family continuously at both its stream ceiling and in-flight `DATA` ceiling for at least `60 s` on each spanned session, recording stream count, in-flight byte total, interrupt-delivery intervals (from committed interrupt admission to observation of its correlated settlement, beyond poll delivery alone), and consecutive accepted-heartbeat gaps (satisfying `margin = deadline - interval - B >= interval` and `gap <= interval + B` in [NanoHost Transport](20261116-nanohost_transport.md) without worker-emission instrumentation). Each bridge attempt creates one non-inherited measurement generation finalized exactly once at definite bridge close, attempt failure, epoch invalidation, or process termination (never resumed, repaired, or reused across successor or later gate attempts). The finalized snapshot contains only the four byte-boundary rows (`current`, `peak`, `direction`), saturation duration, stream count, in-flight byte total, interrupt-delivery intervals, accepted-heartbeat gaps, status (`complete | incomplete | invalid`), and one evidence-local opaque attempt binding generated once for that attempt (the verifier retains the binding-to-lineage association privately—and a strict-risk real-use verifier may privately correlate the attempt with the stock Gateway channel ID—while MUST NOT serialize raw epoch, attempt, request, Sandbox, Gateway channel, token, path, header, payload, transcript, provider output, or credential values). Arithmetic or correlation faults—including overflow, underflow, unmatched release, duplicate finalization, or conflicting attempt binding—yield `invalid`, while a missing boundary, missing liveness observation, insufficient saturation interval, or loss before a complete snapshot yields `incomplete`; both `invalid` and `incomplete` fail the gate and neither may clamp a value, fail product traffic, or alter runtime state. The measurement is private non-authoritative evidence: it MUST NOT enter a Core record, public API, protocol field, product diagnostic payload, Audit payload, transcript, Artifact, `RuntimeTarget`, or Epoch Invalidation Report, MUST NOT decide runtime readiness, capacity, scheduling, recovery, attempt/terminal outcome, or retry state, and creates no durable record, retention rule, or pruning owner.
- **Capability calibration and blocking vs calibration disposition**: capability-family calibration includes concurrent native MCP discovery of the qualified selected supply (including all built-ins) completing within the current capability ceiling without HTTP `429` or client retries ([Shared Capability Capacity Acceptance](../decisions/20261003-shared_capability_capacity_acceptance.md); larger supply or workload requires renewed qualification). The qualification gate (never the measurement producer) classifies any target miss as either a **blocking mechanism failure** (cannot satisfy liveness, bounded buffering, definite predecessor closure, or an admissibility ceiling at any permitted setting) or a **non-blocking calibration** (within admissibility ceilings, recorded with conditions and applied by an independent amendment that recomputes all derived values).

### Fast Foundation And Real-Stock Upgrade Adoption

- **Fast OpenShell Integration Foundation**: ordinary local deterministic tests compile the Cargo-selected SDK, verify that Cargo, `Cargo.lock`, `release.json`, packaging inputs, and readiness identities match one release, and exercise the real NanoHost byte adapter across arbitrary input lengths and frame boundaries, exact byte preservation, full send-queue backpressure and recovery, EOF/error/cancellation/closure accounting release without replay, and a reversible negative check (foundation checks do not run stock processes or qualify a release, and foundation failure blocks the candidate).
- **Real-Stock OpenShell Upgrade Qualification (`apps/nanohost/tests/openshell-upgrade-peer.mjs`, `docs/cookbooks/openshell-upgrade.md`) and adoption gate**: a newer official OpenShell release becomes selectable only when all five conditions hold: (1) Cargo, `Cargo.lock`, `release.json`, external artifacts, and `transport-assumptions.json` identify the same immutable release; (2) Fast Foundation passes; (3) opt-in live-host qualification against real candidate SDK, Gateway, and Supervisor processes (never mocks, compile probes, or saved prior runs) passes all five scenarios—slow consumption + recovery proving that backpressure reaches the producer, outstanding bytes stay within composed bounds, and exact byte sequences settle without loss or duplication; `>= 60 s` continuous saturating inference at both stream and in-flight `DATA` ceilings meeting interrupt and heartbeat liveness bounds; active-transfer cancellation proving prompt capacity release, no logical request replay, and the owning `interrupted` or `unknown` outcome; bridge loss + successor establishment proving predecessor fencing, no late-byte acceptance, no replay, and the bridge recovery bound; and fixed bootstrap monitor + `ExecSandboxInteractive` helper behaviors—recording candidate tag/commit, Gateway/Supervisor digests, transport values, host/load conditions, attempt identity, expected predicate, observed value, failure stage, and closed failure class (running the prior release only to isolate an environment/instrument fault, and changing one parameter at a time without runner relaxation); (4) packaging and readiness consume the exact recorded external artifacts; and (5) the diff and evidence receive independent governance acceptance (failure leaves the current release selected without auto-downgrade, mixed versions, or waiver of the separate A1 noninterference gate).

## Errors And Failure

- **Cold Gateway startup allowance**: Gateway connection and health during cold supervisor preparation consume the remaining absolute startup readiness or rebuild deadline (`apps/nanohost/src/epoch_coordinator.rs`, `apps/nanohost/src/main.rs`) and MUST NOT be cut off by a separate `10 s` Gateway health timeout, without extending the overall startup bound, advertising readiness before verified health and Core acknowledgement, or weakening partial-start invalidation and fencing.
- **`ExecSandboxInteractive` helper failures**: after RPC admission, the single-file helper completes from the exact declared request length under `<= 64 KiB` frames and the operation-specific aggregate ceiling (`<= 256 MiB` for terminal export and build input, or up to `1,000,000,000` bytes plus `1` sentinel byte for ordinary file/import/active-Artifact bounds in `apps/nanohost/src/file_transfer.rs` and `openshell_client.rs`), keeping the request sender open until one Exit event and clean response completion. Exit `0` is the sole present-file success, exit `2` with empty stdout and stderr is the sole optional-absence success, and on an active Artifact submission with optional presence ([NanoHost Workspace Data Boundary](20260801-nanohost_workspace_data_boundary.md)), exact exit `3` with empty stdout and stderr is the proved ordinary `artifact_file_not_regular` refusal (admitting no Artifact result while preserving the healthy Sandbox, neither a present-file/optional-absence success nor an unknown effect); any other nonzero, missing or duplicate exit, stderr, output accompanying exit `2` or `3`, oversized/extra data, digest or length mismatch, gRPC error, timeout, cancellation, relay loss, or unclean completion fails or leaves the effect `unknown` without replay (uncertain import prevents worker launch, uncertain export admits no result, reachable partial staging is removed, and incarnation absence follows the provider proof and original-deadline escalation).
- **Bootstrap monitor and termination ambiguity.** Keep the unary monitor for the shim lifetime. A correlated Exit and clean completion is evidence about that shim. A missing or duplicate Exit, unexpected output or monitor loss leaves the evidence uncertain. Carrier loss, request EOF and Turn interrupt each leave Worker process absence unproved. The same surviving shim may reconnect within its outage budget. Recycle the incarnation after shim exit or when the same shim cannot return in time. Prove Sandbox absence through the provider before release.
- **Sandbox listener and native HTTP/1 projection failures**: failure to bind `127.0.0.1:17891` or `127.0.0.1:17892`, a non-HTTP/2 Supervisor bridge, protocol-role confusion, unexpected listener or nested-session closure, an unsupported declared adapter, or inability to preserve the `127.0.0.1` proxy bypass fails the Integration and Sandbox lifecycle, whereas an individual native HTTP/1 request socket failure cancels only its one outer stream unless the shared listener or nested session also failed; definite Integration close stops both listeners, aborts active native requests, and closes the nested session.
- **Gateway channel and bridge loss.** Loss of a Gateway channel, `ForwardTcp`, `RelayStream`, Supervisor session or nested HTTP/2 session makes the affected carrier non-ready. Keep original in-flight obligations. Reconnect only after the predecessor carrier closes or is fenced and the successor matches the Host epoch, Sandbox incarnation, current supervisor and same shim lineage. A reconnect never bootstraps a second shim. A failure of the Host's own effect infrastructure or containment follows the Host epoch recovery rule.
- **Host-to-Sandbox containment loss**: confirmed containment escape or inability to exclude escape at the host-to-Sandbox boundary invalidates the complete Runtime Epoch, revokes route access, interrupts all hosted AgentSessions independently, withholds unaccepted output publication, exports one bounded `containment-loss` Epoch Invalidation Report before the cgroup fence, and invokes existing Vault revocation or rotation owners ([Vault](../core/vault.md)) without claiming recall of already exposed material.

## Acceptance

- **Containment, supervision, and namespace isolation**: verify that the single `EpochCoordinator` member/fence seam monitors child exit across all local effects, keeps the OpenShell client private, exports before the complete-group fence, and kills and reaps every child once on failure or drop; that dedicated `containerd`, `dockerd`, and stock Gateway share one fresh non-host network namespace and shared private mount namespace while NanoHost and `slirp4netns` remain in the host network namespace with bounded ready-fd `3`, fixed IPv4 resolvers, and the short-lived namespace-entering Gateway connector; that a private-namespace probe has policy-governed public Git DNS/HTTPS egress while host NanoCore listener, host-loopback sentinel, and `/run/docker.sock` access are denied; and that start, stop, member failure, and NanoHost `SIGKILL` leave the system Docker default bridge, kernel `docker0`, canonical Docker-owned nftables structure (excluding dynamic counters, handles, and formatting), business containers, and system-Docker build network unchanged while all epoch-private namespaces, TAP interfaces, routes, sockets, and members disappear.
- **Gateway client, single-file helper, first authenticated poll and one shim start per incarnation, and native loopback projection**: verify one Rust binary crate (`apps/nanohost`) linking the qualified official OpenShell SDK with a separate foreground checksum-verified Gateway process, one epoch-local mTLS Gateway channel, fixed `ExecSandboxInteractive` single-file import/export (`<= 64 KiB` chunks, declared-length completion without early request EOF, per-Turn AEP-before-supply-before-Context ordering, `final_status` vs active-Turn export barriers, and provider proof and scoped escalation under [NanoHost Workspace Data Boundary](20260801-nanohost_workspace_data_boundary.md)), and one fixed provider bootstrap with absent execution timeout (`OPENKIT_WORKER_SHIM_ENTRY_V1\n` across arbitrary stdout splits, retained lifetime monitor, `127.0.0.1:17891` H2 bridge and `127.0.0.1:17892` native H1 listener bound before marker, client-header rejection and admission of the first current authenticated shim poll before launching one native Agent child per AgentSession with session loopback credentials and built-in MCP capability enabled even when external MCP selection is empty), with zero Cell/configurable-SSH/operator-forward/direct-endpoint paths and zero extra relaunch effects on reconnect. Qualify the shipping pin through [Real-Stock Upgrade Adoption](#fast-foundation-and-real-stock-upgrade-adoption).
