# Work Data Retention Format

This specification is the single owner of the work-data observation record format (`control_work_observations` and portable `observations.jsonl`), the four observation boundaries (`llm-gateway`, `nanohost`, `worker-shim`, `nanocore`), Turn capture-coverage binding (`captureCoverage`), lossless native model and runtime content capture, observation reference closure (`refs`), retention-basis `B′` and observation `ret` assignments, reserved reader fields (`Thread.segment`, `Thread.segmentation`, and `config.model`), and content-before-publication durability.

## Scope

Owns:
- The admission judgement and completeness contract for retained work data: retain all admitted observed inputs, outputs, context, actions, decisions, and judgments at capture time without gating on anticipated use (filtering, normalization, and anonymization happen at authorized use time).
- The separation between the user-visible protocol `Item` narrative stream and the append-only observation ledger (`v: 1`, `openkit.work-observations.v1`), the four observer boundaries, the split-envelope header, reference closure (`refs`, `parent`, `corr`), retention basis `B′`, and uncertainty expressions (`cert` and observation `outcome`).
- Effective capture-coverage resolution (`server -> workspace -> task`, default `on`), immutable admission binding (`captureCoverage`), first-release mandatory metadata cells, reserved reader fields, and content-before-publication durability.
- Export purpose and closure: analytical export serves external analysis, evaluation, and audit without requiring lossless OpenKit re-import, while operational backup, restore, and MOVE belong to [Workspace Backup, Export, Import, And Data-Root Migration](20260704-workspace_backup_export_import.md).

Does not own:
- Physical `DATA_ROOT` directory trees, SQLite versus file source-of-truth placement, local SQL transaction boundaries, or storage migrations ([Storage Layout And Record Ownership](20260703-storage_layout_record_ownership.md), [Durable Execution And Control Store](20261019-durable_execution_and_control_store.md)).
- Core semantic definitions of Workspace, Thread, Turn, Item, Artifact, ApprovalRequest, or AgentSession ([Core Concepts](../core/core-concepts.md), [Protocol](../core/protocol.md), [Work Model](../core/work-model.md), [AgentSession](../core/agent-session.md), [Mediation](../core/mediation.md), [Storage](../core/storage.md), [Contract Evolution](../core/contract-evolution.md)).
- Authoritative `CapabilityCall`, `AuditEvent`, `UsageRecord`, `PermissionDecision`, `VaultUse`, `EvidenceBundle`, `RuntimeEvidence`, or execution-journal records ([Audit, Usage, And Evidence Records](20260703-audit_usage_evidence_records.md), [Durable Execution And Control Store](20261019-durable_execution_and_control_store.md)), which observations may cite via `refs` without creating a competing ledger, receipt/fingerprint store, or supply/catalog availability fan-out ([Agent Environment Package](20260616-agent_environment_package.md)).
- Pending-request gate/resolution/attention semantics ([Pending Requests](20260930-pending_requests.md)), Goal Plan Version lifecycle (where a failed Plan proposal leaves the Goal open and preserves any still-valid active Plan version under [Goal](20261002-goal.md) and [A Failed Plan Revision Keeps The Goal Alive](../decisions/20260921-plan_revision_failure_keeps_goal.md)), SQLite table DDL, ORM layout, indexing, BM25, or vector/semantic search.
- Exclusions: this specification never snapshots unrelated world state, working trees, CRDTs, keyboards, raw audio, or unexposed private state (bytes already exposed in admitted model/tool/native work remain eligible content); never builds a generic resume engine, reopens a terminal Turn, promises exactly-once external effects, adds a second scheduler/state machine or Event Sourcing model, builds a cryptographic signature or prefix-watermark digest chain, or adds data-use consent/training/purpose flags, a `CaptureBatch` owner, a per-Thread coverage changelog/epoch, row-level TTLs, or tombstone/deletion ledgers.

Core: [Storage](../core/storage.md), [Protocol](../core/protocol.md), [Core Concepts](../core/core-concepts.md), [Work Model](../core/work-model.md), [AgentSession](../core/agent-session.md), [Mediation](../core/mediation.md), [Contract Evolution](../core/contract-evolution.md).

## Definitions

- **Two record families on distinct axes**: protocol `Item` records are the user-visible work narrative ordered by their Turn item sequence; observations are environment and system records on a separate append-only axis (`apps/nanocore/src/storage/work-observations.ts`). The two families never share a sequence number or narrative rank, and protocol `Item` records never carry observation envelope fields. While `StatusItem` carries no `actor` field on the narrative `Item` axis, structured interrupter identity (who interrupted or cancelled) MUST be retained on the observation row or an existing owner record.
- **Four observation boundaries (`obs`)**: each observer records only the facts it uniquely knows and MUST NOT self-certify another boundary's facts:
  - `llm-gateway` (Gateway): model request and response payloads when collected, resolved provider/model identity, and token/cost observations; never sandbox-internal execution or self-certified experiment conditions.
  - `nanohost` (NanoHost, outside the sandbox): injected image digest, AEP snapshot, mounted Skill/MCP versions, resource configuration, and container lifecycle; never in-sandbox tool detail.
  - `worker-shim` (Sandbox sidecar, inside the untrusted sandbox boundary): actual tool execution and return, process events, and harness-internal state; never authorization or identity authority.
  - `nanocore` (Core): actor, authorization decisions, approvals, product acceptance, and directly observed internal-loop and mediated call facts; never unobserved external runtime internals.
- **Direct observation versus inference (`cert`) and delivery uncertainty**: direct observations omit `cert`; writer inference or model/ASR generation MUST set `cert: 'inferred'`. Recorded outbound or prepared content proves what was observed locally, never that a third party received or executed it. Cross-source `ts` timestamps are observer-local declarations without synchronized clocks, so network-reordered tool calls across sources are preserved as observed.
- **Uncertainty, external-effect risk, and Turn terminals**: uncertainty is expressed in three places, none of which is `Turn.status`: (1) observation `cert: 'inferred'`, (2) observation `outcome: 'unknown'` on external-effect terminal rows, and (3) `CapabilityCall` `status: 'unknown'` and recovery-owner state ([Mediation](../core/mediation.md)). Interruption or the absence of a matching `CapabilityCall` MUST NOT infer that an external effect did not happen or that no effect risk exists; aggregating only `status === 'unknown'` on effect records is insufficient because other non-confirmed statuses do not prove absence of effect. Under the existing effect, recovery, and completion owners, cancellation of a Turn by itself does not require human attention, whereas unresolved unconfirmed calls on that Turn still do; an unresolved unknown effect is evidence surfaced to the person before accepting completion and does not by itself write the completion disposition, while effect-specific duplicate-effect and replay checks remain with their owners. `Turn.status` has the four terminal values defined by `TurnStatusSchema` in `packages/protocol/src/models/turn.ts`, where `cancelled` means authorization to continue that Turn was withdrawn (including workflow supersession, with the specific reason recorded as an `Item`).
- **Thread boundary, Runtime Epoch boundary, and content-addressing digests**: a Thread holds actions and typed references while entities live in their owning stores; Thread identity (`threadId`, `owner`, `visibility`, lineage) is protocol-owned and carries no environment snapshot. Retaining historical runtime evidence on the observation axis (such as copied image digests at bind time) MUST NOT be implemented as NanoCore addressing or storing Runtime Epoch identity as a scheduler, placement, capacity, readiness, or `AgentSession` key; Runtime Epoch identity remains NanoHost-private under [Runtime Scheduling And Scale](20260703-durable_scheduler_design.md#scale-limits) (`NanoHost Boundary`). Content digests (`sha256:`) verify byte matching and addressing, never provenance, Workspace membership, source identity, or access authority. Native-log byte caps bound collection per Turn, never work outcomes or retention duration.

## Capture Coverage

- **Effective resolution and default**: Capture Coverage resolves `server -> workspace -> task` to `'on'` or `'off'` (`policy.workDataCapture` in `@openkit/config-schema` and `apps/nanocore/src/config/runtime-config.ts`). The accepted server default is `'on'`, with explicit `'off'` overrides permitted at server, Workspace, or Task scope, recording `{scope, value}` and configuration provenance. `off` excludes full restricted request/response/transcript bodies while still requiring every `Collect` metadata cell in the [First-Release Capture Matrix](#first-release-capture-matrix); `on` additionally requires full model I/O and native runtime originals (`Unsupported` cells remain empty under both settings).
- **Immutable Turn admission binding**: the resolved `{scope, value}` pair MUST commit with Turn admission as immutable `captureCoverage` on `control_turns` in the owning SQLite transaction before any governed work starts (`apps/nanocore/src/storage/control-store-admission.ts`). Changing the Capture Coverage switch MUST NOT interrupt an already-started bound Turn (security revocation of routes remains governed separately by [AgentSession Continuity](20260704-agent_session_continuity.md)). The binding remains unchanged across provider retries, pending requests, proved reconnects, and AgentSession release, and restart never recomputes it from current config; a later Turn or new attempt re-resolves current policy (where a Task override selects the policy source and the Turn stores the resolved pair without creating a Thread coverage generation). Historical Turns without a recorded binding remain `unknown` (never assumed `'off'` or backfilled when default-on or a new collector lands).

### Collection Responsibility

- **Calls without a Turn, managed-backend gaps, and staging expectations**: a Gateway call with Workspace attribution but no Turn binds effective `server -> workspace` coverage in that Workspace's existing control/Storage scope without fabricating a Thread or Turn; an unattributed call binds server-only coverage under `server/` Storage and control roots (`owner: {kind: 'server'}`), and a call without the Core database retains its declared blind gap with request-local selection only rather than inventing a new store. Managed backends that admit neither sidecar nor Gateway MUST declare an explicit coverage gap so evaluation cannot mix them with self-hosted runs. Across all Gateway and sidecar collectors, the capture owner MUST declare expected content before transfer; a chunk receipt proves staging only, missing chunks leave expected-but-unpublished coverage (never a complete root or publication edge), and a stopped collector is never treated as complete collection.
- **Native runtime log budget and authority**: when capture is `on`, native `stderr`/`stdout-log` collection is bounded by a combined Turn budget of `16 MiB` (`16,777,216` bytes, `current default`), configurable as a positive safe integer via `policy.workDataCapture.nativeLogMaxBytes` and pinned once into the admitted AEP's `observability.evidence.nativeLogMaxBytes` (`packages/config-schema/src/server.ts`, `apps/nanocore/src/runtime/agent-environment.ts`). Native admission reads that exact immutable named AEP snapshot rather than current configuration; missing or invalid historical native authority refuses native content rather than inventing a bound, and the implementation MUST NOT add a Turn budget member, duplicate the budget in `captureCoverage`, create a counter ledger, or renew the allowance through another package.
- **Four independent coverage evidences and state distinctions**: for each material, capture family, and attempt, readers distinguish (1) *intent* (solely from the bound effective `captureCoverage`), (2) *submission* (solely from an owner-committed `edge: 'publication'` reference), (3) *collection failure* (from `capture.unavailable` or the collector owner's failure record), and (4) *lawful reclamation* (from the target owner's disposal semantics in scope). None of the four may be derived from another, and every collection class (and native exchange index) preserves bound intent, actual producer availability, expected/publication evidence, partial/truncated/excluded ranges, and disposal facts, distinguishing historical uncollected/off, missing binding, unsupported producer, collector failure, open/interrupted/complete prefix, explicit truncation, silence/no source, valid empty/no-token response, and lawful reclamation from non-occurrence. On outward UI projections (`ThreadDashboard`), `contentCapture` projects `off`, `on`, or `unknown` from the immutable binding while structural `collecting`/`partial` states never alter `Turn.status`, and incremental runtime capture never implies optional `worker.runtime-provenance.v1` full provenance.

## Retained Records

- **Two-family discrimination, location, and join**: in line-oriented representations (`observations.jsonl` versus `items.jsonl`), an observation line carries required `v` (`1`) while a protocol `Item` line is naked protocol JSON without `v` (and always requires `turnId`, so no Thread-level `items.jsonl` exists and runtime-private traces are never promoted to `Item` records without an owning design). Multiple observations under one `Item` or `turnId` follow ingest append order (`seq` contiguous from `1` per Turn in `control_work_observations`). When an event appears on both families, the observation anchors to the `Item` with `parent: itemId` (pointer direction is observation -> `Item` only; `corr` MUST NOT be used as an `Item` anchor, and Gateway `openkit.gateway/routeLineage` lives on `CapabilityCall` rather than an observation type or `ext`). When no corresponding `Item` exists on a Turn, the observation sets `turnId` and omits `parent` (never inventing a surrogate `Item` parent). The `Item` narrative remains reconstructible without reading observations.
- **Observation split-envelope header (`draftSchema` and `recordSchema` in `apps/nanocore/src/storage/work-observations.ts`)**:
  - `draftSchema` and `recordSchema` own the header field set. Only the known types registered in `work-observations.ts` and reserved `config.model` are processed. `ts` is an observer-local RFC 3339 UTC timestamp with millisecond precision; the reader that accepts a timestamp without that precision remains an Implementation Gap. Historical observer aliases `core`, `gateway`, and `sidecar` are refused. `payload` is type-owned `B′` and never carries raw restricted or time-bounded bodies. An omitted `ret` uses the type's write-rule default class. `parent` is one observation or `Item` ID, never an array. One `corr` identifies a logical call across route attempts, and individual attempts hang off `parent`. `outcome` records the external-effect terminal. `cert` is present only when the observation is inferred. `turnId` is present on Turn-associated rows and conditional for Workspace-only and server-only calls; that no-Turn target remains accepted, and its missing producer remains an Implementation Gap. Withdrawn fields `perc`, `span`, and `aud` are forbidden. `ownerScope`, lineage defaults, and `requiredFeatures` (`openkit.work-observations.v1`) live on the scope or Turn control record or manifest rather than repeating per line.
  - Under [Schema Evolution And Record Envelope](20260703-schema_evolution_record_envelope.md) (`Reader Contract`), readers MUST NOT treat unknown canonical `type` values as processed, and any writer introducing authority-bearing new `type` behavior MUST gate it on `requiredFeatures` (while product UI consumers MUST provide a generic fallback renderer so a closed type switch cannot crash on a new kind). Because `obs` identifies the observer rather than a verifier, remote payloads MUST distinguish source claims and evidence basis from independent verification.
- **Retention basis `B′`, transient `work-capture` admission, and content placement**: placement follows content kind regardless of byte size (no `16 KiB` inline threshold). Observation rows carry only long-term `B′` main facts (identifiers, timestamps, quantities, results, configuration identity, and `refs`, where `payload` placeholders may name `{kind, id, digest, bytes, mediaType}` with logical IDs and open IANA media types). Restricted originals, model I/O, tool `stdout`/`stderr`, and diffs live externally in `@openkit/storage` (`knowledgeBaseId: null`, real Server or Workspace owner, `backend-evidence` mount, `<scope>/evidence/backend/sha256/<digest>`, while Knowledge references require a real `knowledgeBaseId` and media bytes belong to Artifact/Source owners). `work-capture` admission is a transient trusted-caller basis, not a retained grant, Knowledge authority, or permission inferred from a digest: the existing capture owner authorizes each operation and consumes sealed staged bytes (`packages/storage/src/contract.ts`, `apps/nanocore/src/storage/immutable-content.ts`) before publishing its references, and Storage itself never publishes observation records. Raw body bytes never enter `CapabilityCall`, `AuditEvent`, receipt rows, or a parallel `EvidenceBundle` byte store.
- **Self-describing `refs` (`referenceSchema` and `bodyDescriptorSchema` in `apps/nanocore/src/storage/work-observations.ts`) and per-owner scope**: each `referenceSchema` entry is written at citation time and preserves unresolved source identity. `referenceSchema` and `bodyDescriptorSchema` own their field sets. Only `content.published` may carry `edge: 'publication'`. A `bodyDescriptorSchema` descriptor uses `sha256` (64 lowercase hex), distinct from the enclosing `referenceSchema` `digest`. Successful resolution yields `resolved-and-verified`, `absent`, or `mismatch` (where `mismatch` is never treated as success). Per-owner `scope` requirements: AEP snapshot requires `workspaceId` (plus `agentSessionId` for direct file locators); Artifact, Knowledge Source, `RuntimeEvidence`, `UsageRecord`, and `CapabilityCall` require `workspaceId`; `EvidenceBundle` requires `workspaceId` and path class (`bundles` or `backend`); Goal task requires Thread + Goal; `AuditEvent` requires home (`core`, `workspace`, `app`, `user`) + `workspaceId` when Workspace-scoped; `PermissionDecision` and `VaultUse` require `ownerScope` + `workspaceId` when Workspace-scoped; and MCP tool-schema snapshot requires `workspaceId` + catalog entry + source.

### Environment Binding And Cause

Worker environment prompts, harnesses, Skills, and MCP tools are owned by AEP snapshots (`packageSnapshotId`) and MCP schema snapshots and cited via `refs` rather than duplicated. Internal agents have no AEP and record `env.bound` before model dispatch. On `conversation.submit` Assistant Turns, `env.bound.payload.assistantSkillAdmission` records `{catalogRevision, skills: [{skillId, versionId, contentDigest}]}` (`catalogRevision` is a nonnegative integer, or `null` only when `skills` is `[]`; `skills` is sorted by unique `skillId` with `versionId === contentDigest`; an absent field on older/other observations is distinct from `{catalogRevision: null, skills: []}`, and Turn re-entry reuses the original admission without resolving current defaults or pins). Wake-up after idle records the current environment without a changelog; mid-Turn reconfiguration starts a new Turn and AEP under single-flight; and target selection is retained per invocation without rewriting prior `env.bound` rows.

**Lossless model exchanges, content-addressed sequence trees, native runtime capture, context/judgment/journal joins, and UI projections**:
- **Lossless model exchanges and native exchange index**: when capture is `on`, Gateway retains the actual provider-native upstream request and observed response (`upstream.request`, `upstream.response`) with JSON-semantic fidelity (exact field values/types, array order, strings, null-versus-omitted, and provider-specific fields, excluding only OpenKit-held/injected secrets) plus the distinct Worker-facing exchange (`worker.request`, `worker.response`) when protocol translation occurs, and retains unsuccessful route-attempt bodies under the same logical call (`corr`) with attempts anchored by `parent` (`req -> att -> res`). Streaming responses are stored as ordered bounded immutable native chunks with bounded buffering/hashing across split UTF-8/JSON/tool deltas without rewriting the growing response per delta or storing a second normalized final message; the immutable native exchange/chunk index records scope/call/attempt association, native role, protocol/media/encoding/boundary, published body/sequence root (`ref`, `digest`, `length`), observed model/parameters/usage/status, ordered chunk entries (source sequence, byte ranges/counts, publication refs), Gateway-observed first-token/completion timing with clock/boundary, and coverage/omission facts.
- **Content-addressed message/part sequence trees**: requests represent messages as an ordered reference sequence hashing versioned RFC 8785 canonical JSON per message/part (retaining unrounded native bytes with an explicit indexing limitation when values exceed canonical JSON bounds), storing system prompts and tool definitions once per exact digest in the authorized Server or Workspace scope (no cross-scope deduplication probe), and using structurally shared immutable sequence trees so each turn appends only new message/part blobs and changed manifest nodes without $O(n)$ full-prefix rewrites.
- **Incremental native transcripts, runtime logs, and secret scanning**: sidecar and runtime collectors reuse the existing authenticated worker-control channel (bounded to `48 KiB` decoded chunks and `16 MiB` content-frame/carry limits in `packages/worker-protocol/src/index.ts`), provenance guards, and pre-launch source watermarks (`packages/worker-shim/src/runtime-capture.ts`, `codex-runtime-capture.ts`) to stream incrementally before sandbox exit using codec `native-content-v1` and `runtime.observed` (`native-transcript` and `runtime-log` with `stderr`/`stdout-log` sources and `application/octet-stream` for arbitrary bytes, keeping runtime-internal children as scoped origin hashes under the outer Turn rather than new Core execution IDs; spawn edges prove parentage, never send/wait receivers or child completion). One shim parser may derive structural facts, but it does not own a second native truth. Known held/injected secrets are scanned across semantic units (up to the `16 MiB` semantic parser ceiling) and across chunk boundaries in raw and escaped forms, refusing any unit containing a secret with an anchored safety gap while retaining all other observed native content verbatim under `restricted-raw`. On log budget overflow (`16 MiB` default), the collector records captured byte ranges/counts, configured limit, source, last position, `limit-exceeded` reason, and measured-or-unknown `omittedBytes`.
- **Context, judgment, journal, and Thread boundaries**: delivered context observations record source/version/digest refs and delivered message/part refs or ranges for Knowledge, Memory, Skills, attachments, Policy/AEP, prompts, and tools (distinguishing original, representation, and delivered digests, reusing model blobs rather than copying Knowledge/world state, and recording runtime-private compaction as an explicit gap). Judgment links connect PendingRequest approvals/denials/answers (deciding actor/time and raising Turn/call), versioned Artifact Reviews/edits/corrections (judged revision/digest/actor and resulting revision or follow-up Turn), provider retries versus user redos, and judge assessments (target, producer, judge model, and rubric version, preserving contradictory/late history without inferring a score). Execution-journal steps ([Durable Execution And Control Store](20261019-durable_execution_and_control_store.md)) own step timing/outcomes and cite retained nested-call bodies without embedding content in spans or telemetry (`Operational Telemetry Standardization`). Thread records exclude Light App databases/schemas, Artifact/Knowledge bodies, catalog changelogs, and world state (recording Agent writes as typed refs, user re-entry messages, and returned Knowledge page refs; idle Threads do not poll world state while still recording valid late approvals/results). Outward `ThreadDashboard` reads enforce current Thread audience before reading bodies, exclude native IDs/raw tools/secrets/reasoning/diagnostics, and cite source observation `seq`.

### Identifiers

Independently generated Thread and Turn IDs use `th` and `tu` UUIDv7 (`allocateEntityId`), while owner-derived Thread, Turn, Item, Artifact, Material, and Review IDs use UUIDv5 over exact UTF-8 RFC 8785 JCS inputs under [Protocol Identifiers And Enums](20261021-protocol_identifiers_and_enums.md#ids), preserving source and projection names, distinct roles/sequences, single request Items, and unchanged content across reopen without replacement effects after partial publication:
- **Chat, handoff, Artifact, Review, and Pending derivations**: Assistant Turn `tu` uses `commandScope` ([Chat Mode Assistant](20260704-chat_mode_assistant.md#unified-command-branch-and-replay)); command handoff Thread `th` uses `[actor, workspaceId, originatingThreadId, requestId]` and first Task Turn `tu` uses `[actor, workspaceId, originatingThreadId, receivingThreadId, requestId]`; outcome handoff Thread `th` and first Task Turn `tu` each use `outcomeScope`; Chat user Item `it` uses `["chat-user", assistantTurnId]` and Chat result/handoff status Item `it` uses `[resultRole, assistantTurnId]` (excluding clarification/approval requests); downstream Task user Item `it` uses `["task-user", downstreamTurnId]`; Artifact introduction Turn `tu` uses `[actor, workspaceId, threadId, "artifact.introduce", requestId]` and communication Item `it` uses `[artifactId, communicatingTurnId]` ([Work Resource Interaction Model](20260713-work_resource_interaction_model.md#artifact-and-item-lineage)); Review follow-up Turn `tu` uses `[workspaceId, artifactId, artifactVersion, decisionRequestId]`; and Pending Request Items `it` use `[requestId, role]` where both clarification and approval request Items use `[requestId, "request"]` ([Pending Requests](20260930-pending_requests.md#deliver)).
- **Worker transcript, simulator, and Material candidate derivations**: Worker transcript Item `it` uses `["worker", producingTurnId, sequence]` (exact numeric Worker sequence); simulator Items `it` use `["assistant", producingTurnId]`, `["reasoning", producingTurnId]`, and `["command", producingTurnId]`, and simulator simple result Artifact `ar` uses `producingTurnId` as a JSON string; Worker Material candidate Artifact `ar` uses `[packageSnapshotId, producingTurnId, submissionRequestId]`.

## Reserved Reader Fields

The following retained reader reservations are landed on `main` (`f1041512f`) for `#732` while their runtime producers remain unimplemented:
- **Continuous-output Thread segmentation (`ThreadSchema` in `packages/protocol/src/models/thread.ts` and `apps/nanocore/src/storage/retained-work-events-v1.ts`)**:
  - `Thread.segment`: optional integer `>= 0` (`0` is a recorded first ordinal; absence means no recorded ordinal and never defaults to `0`; `null`, negative, fractional, or string values fail closed).
  - `Thread.segmentation`: optional object with required positive integers `maxObservationLines` (`> 0`) and `maxBytes` (`> 0`) and literal `boundaryDelayed: true` (unknown descriptive members are stripped; absence means no recorded cap and never defaults; missing inner members, `null`, `false`, nonpositive, or fractional values fail closed). Segmentation evaluates only at Turn boundaries so a running Turn is never split across segments or terminalized for storage reasons, and declaring `boundaryDelayed: true` on the Thread record distinguishes lawful Turn-boundary overflow from file corruption (after boundary delay, `maxBytes` is not a hard byte ceiling). Segment creation, `parentThreadId`, and `segment` use the existing protocol Thread-create lifecycle without adding a second Thread lifecycle; continuous UI concatenates segments via `parentThreadId` rather than treating the continuous view as a single storage object. A continuation is never treated as a new attempt: it copies `parentThreadId` and `segment` without copying the Turn task tuple, coverage binding, or withdrawn audience fields; a Chat that had no pairing key still has none (true missing data), whereas silently losing an existing pairing key at a cap is wrong data/corruption; and missing/inaccessible historical parents remain unresolved without rejecting history reads. `ProductThreadSchema` and `ProductListThreadsResponseSchema` (`packages/app-api-schemas/src/thread-projection.ts` and `thread-operations.ts`) strip `segment` and `segmentation` from public operation responses.
- **Configured-model observation (`payloadSchemas['config.model']` in `apps/nanocore/src/storage/work-observations.ts`)**:
  - `payloadSchemas['config.model']` owns that payload. Observers other than `llm-gateway` fail closed. `sampling` is `modelSamplingSchema` in the same file, and omitted values are not default-filled. `ReasoningEffortSchema` is owned by [Protocol Identifiers And Enums](20261021-protocol_identifiers_and_enums.md#canonical-enums). `cause`, when present, is open vocabulary rather than a closed enum, and related decisions link through `association` refs. The row records configured physical identity at the shared dispatch attempt, never transport-send proof or a provider-reported snapshot.
- **Unproduced capture-time and unsupported slots**: capture-time configuration slots (including per-Skill ID/version and per-MCP ID/version/exposed tool set) remain interpretable when empty without fabricating identities; raw wire-byte digest, `context.evicted`, and Layer-3 runtime-assembled context manifests remain unsupported slots with no producer.

## Retention And Deletion

- **Closed observation `ret` set**: observation `ret` uses only the five observation retention classes in `draftSchema.shape.ret` (`apps/nanocore/src/storage/work-observations.ts`), which is the observation-applicable subset of [Storage](../core/storage.md), and can be classified from the header without parsing `payload`. Observation rows MUST NOT emit `restricted-evidence` (which belongs to Workspace sync quarantine records under their separate owner) and `ret` never applies to protocol `Item` records. A row's `ret` is distinct from a referenced blob's owner class and MUST NOT be rewritten to `workspace-audit` to keep a blob; same `type` rows may carry different `ret` for permitted in-row metadata while bodies stay external under `B′`.
- **Access, shared-blob lifetime, and disposal**: `restricted-raw` is an access class requiring current source/record authorization and audited raw reads, never a capture-eligibility gate or fixed format duration (retention windows are operational parameters passed to the explicit compactor `apps/nanocore/src/evidence-bundles.ts`). Shared content-addressed objects remain live while any retained referring record, required nested-call reference, legal hold, or protected snapshot references them (replay-cache cleanup MUST NOT delete the sole retained copy of required nested-call inputs/results). Deletion and compaction follow the Thread, Workspace, and EvidenceBundle owners, preserving remaining `id`/`digest`/`bytes` and disposal explanations so an `absent` or `expired` blob never implies the event did not occur or that the source was physically deleted; derived reads fail closed after source deletion or revocation, and `legal-hold` blocks compaction/deletion without granting access.

## Export

[Workspace Backup, Export, Import, And Data-Root Migration](20260704-workspace_backup_export_import.md) admits Turn observations (`observations.jsonl` with `openkit.work-observations.v1`) and their reachable Workspace-managed message, prompt, tool-definition, chunk, and manifest blobs into portable Workspace export V3 and operational snapshots (`apps/nanocore/src/storage/workspace-export.ts`), while cold whole-data-root backup copies files without interpreting `openkit.work-observations.v1`. Portable export enforces current Thread audience and body-read authorization (excluding other users' private Threads and system-managed secrets, while carrying `env.bound.payload.assistantSkillAdmission` under that boundary), fails closed on unknown `requiredFeatures`, keeps server-scoped captures and `scope: 'server'` image-digest references unresolved under source identity rather than rebinding on a destination, and scopes `corr` pairing to its owning logical-call group so identical `corr` keys across imported groups never cross-join. Use-time filtering, normalization, and dataset/schema conversions read currently authorized originals without overwriting native roots or retroactively changing capture coverage; a consumer pins its transformation/schema and preserves source `refs` whenever its owning contract requires derived lineage, without introducing a dataset product or export service.

## Failure And Recovery

- **Content-before-publication durability**: verified immutable blob bytes MUST be durable in Storage before the observation record or `content.published` reference commits (`apps/nanocore/src/storage/work-observations.ts`, `immutable-content.ts`). Durable-class `Item` and observation commits require outer `synchronous=FULL` acknowledgement before caches or notifications expose them (`control-store-worker.ts`). In canonical file or portable representations, blob `fsync` (and parent-directory `fsync` on creation) precedes observation-line `fsync`, unendorsed orphan blobs after a crash are ignored on replay, and torn tails after the last `0x0a` LF are dropped rather than repaired into a committed publication. Committed SQL `captureCoverage` governs even if a disposable `turn.json` projection is missing or stale.
- **Idempotent replay, conflict, and fail-closed validation**: same observation `id` and identical canonical meaning replay idempotently (without resurrecting lawfully expired bodies); a changed payload, digest, byte length, source range, or boundary under the same `id`, a header-versus-payload identity mismatch, a non-contiguous interior `seq`, a missing required header field, an unknown canonical `type` or observer/type mismatch, a missing or conflicting Turn `captureCoverage` binding, or a second distinct Thread continuation for the same `(parentThreadId, segment)` fails closed (`recovery_required`), while admission of a new Thread continuation with a missing predecessor Thread ID refuses, inspecting an already-published exact successor after restart is not a conflict (and does not allocate a second successor), and a successor published without its `parentThreadId`/`segment` link is incomplete rather than a new attempt. Permission denial, owner unavailability, or I/O error on a reference returns the owner's refusal/unavailable outcome rather than masquerading as `absent`.
- **Restart source-inspection and collector fault isolation**: after restart, recovery reads committed coverage and exact publication references, preserves the committed incomplete prefix, inspects the same source/transfer identity where its existing owner and current authorization allow, and reports unavailable buffered ranges explicitly; it MUST NOT reconstruct bytes from UI text, current prompts, later native sessions, or a new provider call. A durably recorded Worker or Gateway source/parser fault (`capture.unavailable` or `model.capture-gap`, or a frame exceeding the `16 MiB` semantic parser ceiling) preserves the committed incomplete prefix without changing the actual work outcome, triggering another model call, or discarding retainable raw chunks, whereas failure to persist required observations or failure facts fails closed under the transport/execution owner (never applying disposable telemetry drop rules). Any unit containing known held/injected secret material is refused with an anchored safety gap while preserving other admitted units. UUIDv7 lexicographic order may prefilter time-range scans only when followed by authoritative timestamp verification (UUIDv5 order is never a time prefilter, and fresh UUIDv7 allocation never replaces request-derived `Item` IDs).

## Acceptance

- **Collector, sequence-tree growth, and crash-boundary proof**: verify at the actual collector, storage, and export boundaries (beyond metadata presence or `fsync` call-site inspection) that growing multi-call request sequences scale with appended message/part bytes and bounded/logarithmic changed manifest nodes without $O(n)$ full-prefix rewrites while preserving shared blobs across single-reference deletion; that upstream and translated Worker-facing exchanges preserve unknown provider fields, unrounded large numbers, array order, null-versus-omitted distinctions, and interrupted split UTF-8/JSON/tool-delta streaming prefixes; that Workspace-only and server-only Gateway calls capture without fake Thread/Turn/Workspace IDs; that post-dispatch source edits do not alter reconstructed model inputs; that late judgments/reviews/retries preserve contradictory/late version and actor lineage; that the partial-publication/reopen fault-injection run exercises the Identifiers contract against actual retained storage; and that crash-boundary fault injection proves no committed publication cites unpublished bytes, unendorsed orphan blobs are ignored, missing `captureCoverage` blocks governed collection, and dropping disposable telemetry alters no retained work record.
