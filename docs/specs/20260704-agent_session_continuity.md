# AgentSession Continuity

This specification owns durable AgentSession continuity for one Thread: exact reconnect, later-Turn reuse, and internal successor replacement.

## Scope

Owns:

- One current AgentSession per Thread, exact reconnect of the active attempt, later-Turn reuse, and internal successor replacement.

Does not own:

- Canonical AgentSession meaning. [`docs/core/agent-session.md`](../core/agent-session.md) owns it.
- Attempt deadlines, adapter liveness, and transport. The scheduler, worker-control, and [NanoHost Runtime](20260802-nanohost_runtime_and_transport.md) own them.
- Workspace collection, review, and apply. [Workspace Synchronization](20260703-workspace_synchronization.md) owns them.
- Credential mint and destruction. [Worker Agent Capability](20260703-worker_agent_capability.md) owns them.
- Generic snapshot, restore, rollback, fork, and clone. They have no current owner. Issue #318.

## Persistent Data Is Separate From Native Continuity

The current physical bindings, locator/digest pairs, and retained-storage facts describe NanoHost continuity and retain those meanings. An external harness owns its native session state and transcripts independently of executor placement. Later external references are additive under the [neutrality decision](../decisions/20261020-compute_and_harness_neutrality.md); they do not reinterpret retained Sandbox data or relax current resume proofs.

[Persistent Worker Volumes](20260910-persistent_worker_volumes.md) permits a freshly authorized successor to reattach its own group's complete retained volume after predecessor writers are fenced. Unimported files and opaque retained native data remain available as data, without becoming exact-version input or generic continuation authority. The exact retained native resume reference is the native continuation authority for the successor. Exact handle, immutable mode, Thread identity and sequence checks are unchanged; no `--last`, latest-session discovery, generic restore, transcript replay, hidden process-state inheritance, or active-Turn replay is introduced. A successor receives fresh Turn authority and new session loopback credentials even when it sees the same retained files; their mint belongs to [Worker Agent Capability](20260703-worker_agent_capability.md). `session.open` carries `resume: { locator, digest } | null`. Core stores the locator and the digest; the raw reference stays in retained Sandbox storage.

## Decision

`AgentSessionRecord` is the durable Core-side identity for runtime continuity. It must preserve the Workspace, Thread, the current Turn assignment while a Turn is bound and its absence while the binding is idle, Agent, profile or AEP snapshot, runtime backend kind, current status, creation and close timestamps, and replacement or interruption reason needed for authorized diagnosis. The record's identity outlives any one Turn. Core stores the resume pair with this record: the locator is the record's own `agentSessionId`, and the digest is the `nativeHandleDigest` of the ready proof NanoCore accepted for its binding, recorded when NanoCore accepts that proof, whether or not the Turn later completes, exports, or leaves the binding reusable, and kept after the binding closes. The raw reference stays in retained Sandbox storage, where the Harness stored it under that `agentSessionId` as [Worker Control Protocol](20260703-worker_control_protocol.md#harness-control-operations) defines, and is not a product field. A digest alone is not a resume locator, and a record without an accepted ready proof has no resume pair. A missing reference is not backfilled by scanning native data directories. A successor's predecessor is the Thread's latest-created other AgentSession, because a Thread holds at most one current AgentSession and a successor is created only after its predecessor is terminal; equal creation times along the walk below leave the order unproved and fail admission closed. Any resumed open proves the exact digest of the pair it presented, so the recorded pairs within one uninterrupted Agent/runtime selection identify one native conversation. A predecessor without a recorded pair either failed before it established a conversation or lost its accepted proof; within the same Agent/runtime selection, its successor presents the pair of the nearest earlier AgentSession with a recorded ready proof, or null when none has one, as the engineer decided in [Successor Resume Walks Back To The Nearest Recorded Pair](../decisions/20260930-successor_resume_walks_back.md), which also records the accepted residual risks.

Native resume is bound to the same Agent and runtime. The predecessor walk MUST stop at a different Agent or runtime, even if that predecessor has no accepted ready proof. An explicit switch starts a fresh native conversation with context supplied by OpenKit-owned Thread records through the existing Context Package and capture-completeness rules. Switching back MUST NOT recover a pair from before the intervening switch. Runtime identity comes from the AgentSession's named immutable AEP: its runtime kind and native adapter must match the current selection. A preparation record with neither an AEP nor a native proof establishes no runtime and may be skipped. A recorded proof with unproved runtime identity MUST return `recovery_required`; missing or unreadable required AEP evidence does not authorize a fresh conversation. This selection rule applies to both the native pair and its retained-storage association. Within the same Agent/runtime selection, missing, corrupt or mismatched expected references still fail closed; the switch rule does not relax exact-reference validation.

For retained-volume execution, AgentSessionRecord also preserves a private retainedStorage fact containing the exact storageRef, workSlotRef and positive attachmentGeneration admitted for that binding. The materialization owner supplies this fact from the actual admitted attachment, and Core durably records it before native open. It is immutable within the AgentSession and remains after close, failure, Sandbox deletion and restart. A native ready proof is accepted and recorded only with agreement on that binding's retainedStorage fact; a recording failure prevents dependent work and retains the existing cleanup ownership. An attachment fact without an accepted native digest does not establish a native conversation.

Successor selection takes the native pair and retainedStorage fact from the same proof-producing AgentSession selected by the existing predecessor walk. Missing or contradictory retainedStorage on that selected record is a recovery failure, not permission to skip its accepted pair, infer an association from contributor eligibility, or start fresh. The record does not retain a reusable admission revision: current revision, audience, attachment and target authority remain with WorkerStorageBinding. Persistent Worker Volumes owns deriving the current selected-storage admission from this historical fact.

Existing records remain readable when the attachment fact or its historical generation is absent, without treating absence as fresh-conversation permission. An absent historical generation remains unknown; current binding state, contributor history, a baseline, raw evidence and successor attachments must not supply an inferred value. Historical generation identifies the original attachment for evidence and recovery; it is not a reusable admission revision, and a successor may receive a different currently authorized generation for the same association and work slot. No permanent legacy lookup or second continuity registry is introduced. Recovery of a ready proof still held by an exact surviving runtime binding must preserve its attachment fact before retiring that binding; missing or conflicting proof stays explicit.

For an idle binding proved physically absent by the current fresh, ready and predecessor-fenced Epoch, capacity inspection and whole-Sandbox retirement do not repeat proof handoff when the owning AgentSession already records the exact native digest, retained-storage attachment and original package snapshot. This retirement does not decode or execute the historical AEP and preserves its bytes and recorded proof. Live bindings and missing or conflicting recorded proof keep complete handoff validation; this rule does not relax native resume or current package admission.

Retiring a resident whose Workspace is not admitted uses its exact historical owner for cleanup reads only. Recognize the native AgentSession record first; only when that row is absent may cleanup read the exact retained V1 `session.json` through its existing schema. The accepted digest, AgentSession, Workspace, Thread, original package, physical Epoch, storage association, work slot and known historical attachment generation must agree with the existing binding and provenance checks. This bounded retained-only proof read grants no resume or executable authority and creates no migration, backfill or general legacy lookup. Never invoke a writing proof recorder or update the non-admitted Workspace. Missing, invalid or conflicting proof refuses with a finite safe cause code. Recorded proof does not release storage: the existing physical cleanup proof must precede attachment release. The reason and rejected alternatives are recorded in [Retired Workspace Cleanup Proof](../decisions/20261023-retired_workspace_cleanup_proof.md).

[Protocol](../core/protocol.md#status-values) owns the status vocabulary and terminal-state rule. An AgentSession belongs to exactly one Thread for its whole life. A Thread has zero or more historical AgentSessions and at most one current AgentSession. The protocol's non-terminal statuses identify current continuity; `interrupted`, `failed`, and `closed` are terminal historical states and cannot be reopened. A later Turn in another Thread never reuses it, even when Workspace, Agent, profile, Sandbox, Harness, or native runtime family match.

The baseline has three permitted continuity outcomes:

1. Exact reconnect: the existing scheduler attempt is inside its bounded reconnect window and the original worker proves the exact process key, product and package lineage, next sequence, and attempt compare-and-set. The same AgentSession and Turn continue.
2. Later-Turn reuse: the prior Turn is terminal, the exact Thread-affine AgentSession is idle, its compatibility evidence is current, and every hygiene check succeeds. Idle means no active Turn on that binding. It does not mean the native host has exited. The same binding receives the next Turn with fresh authority and current inputs.
3. Internal successor replacement: exact reconnect or later-Turn reuse is forbidden or unprovable. The predecessor and prior Turn remain unchanged, the predecessor becomes terminal and runtime-fenced, and separately authorized later work uses the sole current successor created from current manifest resolution, policy, credentials, Workspace materialization, and Core-owned Thread history. The successor is a new AgentSession. It reopens the exact retained native conversation within the same Agent/runtime selection, or starts fresh after an explicit switch. Core-owned Thread history remains the product context and does not replace required native resume.

There is no fourth outcome that silently substitutes a compatible worker for the original attempt. This version starts from a new data root and does not read earlier-version data, as [the engineer decided](../decisions/20260930-earlier_version_data_not_carried.md). The same OS process is neither required nor sufficient.

An adapter whose native protocol creates a conversation only with the first prompt, or whose accepted owner explicitly defers native creation until resolved first-Turn setup and route authority are available, MAY open one capacity-holding new AgentSession runtime binding with its native handle pending; a supplied resume reference never permits this pending fallback. The first accepted Turn must establish the exact handle and bind its digest before the AgentSession may return to reusable `idle`; failure, ambiguity, or cleanup uncertainty closes or fences that binding and never substitutes Core history for native continuity. `session.open` carries `resume: { locator, digest } | null`. Null starts a new conversation. The object is the resume pair of the predecessor AgentSession and starts a successor from the retained reference, and the Harness validates the native result before any work. A missing, corrupt, or mismatched reference fails the resume and does not select another session. The Turn receives fresh Turn authority and must prove the same conversation. Ordinary fresh-process launch of a later Turn on the resident binding is not the path. A binding that never had a native conversation, the first binding of a Thread or an explicit Agent or runtime switch, starts a new one. Absence of a reference that the binding expects is a resume failure, and the user continues in a new Thread. `turn.interrupt` cancels that Turn and does not by itself close the binding. `session.close` revokes live authority. Destruction of the session loopback credentials belongs to [Worker Agent Capability](20260703-worker_agent_capability.md). Closing one binding on a shared host does not kill the server or sibling bindings. Dedicated-host close terminates that host. A host restart invalidates every binding that host held. Socket reconnect to a surviving host does not create a new AgentSession.

## Later-Turn Reuse And Successor Replacement

`SandboxCompatibilityKey` decides whether placement may use one shared Sandbox envelope; it neither decides conversation continuity nor permits an existing AgentSession to move between runtime bindings. `HarnessCompatibilityKey` selects one compatible Harness Instance inside that Sandbox and includes the runtime adapter, runtime image and command shape, process-global extensions, hooks, plugin and MCP posture, and process-static credential and configuration requirements. `AgentSessionCompatibilityKey` decides whether a later Turn may reuse the exact existing native conversation continuity in that exact Harness binding. For V1, the AgentSession key must match exactly and includes Agent and profile identity, Thread affinity, native conversation protocol, context and transcript posture, static policy envelope, logical-model admission posture, required features, the selected Harness key, and the exact `SessionCompatibilityKey` owned by the session-static materialization specification. [Session Static Workspace Materialization](20260704-session_static_workspace_materialization.md#sessioncompatibilitykey) owns that Session key and its digest form. The native AgentSession key is plain SHA-256 of canonical JSON over the adapter id, the adapter version, the Harness key, the final Session key, and the Thread id. [Protocol Identifiers And Enums](20261021-protocol_identifiers_and_enums.md) owns that canonical form. [NanoHost Runtime And Transport](20260802-nanohost_runtime_and_transport.md) owns the physical Sandbox key. The accepted physical-key members and the missing-input refusal are Implementation Gaps #735 and #641.

Compatibility evidence is immutable for one effective setup. Every later-Turn admission recomputes desired inputs from current owners and rejects reuse when the key is missing, stale, conflicting, unequal, revoked, or unsupported. Ordinary Turn input revisions do not invalidate compatibility when the current inputs fit the declared slots and the freshness barrier can reconcile them safely. A changed static path, process environment, OS user, logical-model admission posture, network envelope, credential visibility class, required Harness feature, Agent or profile identity, Thread, or incompatible setup generation requires replacement.

Reuse also requires all of these hygiene checks:

- The AgentSession is idle, its prior Turn is terminal, and no open or closing attempt, writer, or command remains. A resident host that is quiescent between Turns is allowed. No live native operation of the prior Turn remains, and that requirement does not mean the runtime process has exited. The next Turn still requires no open or closing attempt and no active Turn.
- Required outputs, transcripts, and evidence from the prior Turn were collected, or their missing or quarantined status was truthfully finalized by their owners. Turn-end collection completes before the next Turn is dispatched. Collection also runs at AgentSession release and before a successor starts on the same work volume. The change-set schema is owned by [Workspace Synchronization](20260703-workspace_synchronization.md). A work volume's chain starts from Core's accepted base for that work slot, and collection returns `recovery_required` when that base is unknown.
- Every Turn-scoped input, output, context, instruction, route, upstream route token, transcript-spool, temporary, and control slot was cleared or replaced. The session loopback credentials are not Turn-scoped. Their drain and destruction belong to [Worker Agent Capability](20260703-worker_agent_capability.md).
- The retained AgentSession baseline has proved identity, can reconcile to the selected current Workspace and source revisions without ambiguous overlap, and contains no unauthorized retained input.
- Current Agent, policy, permission, Vault, provider, sensitivity, isolation, capacity, and revocation checks admit the new Turn and continued placement.
- The native conversation binding, route separation, exact sequence, and AgentSession-local cleanup proof remain current and non-conflicting.

Fresh authority means the retained AgentSession supplies conversation continuity only. Every reused Turn receives one new immutable AEP snapshot, Context Package, upstream route credentials, execution attempt, deadline, sequence scope, current Workspace input snapshot, current source and Knowledge lineage, and current policy, permission, capability, provider, and Vault decisions. No prior package, upstream route token, attempt, route, permission decision, cached authorization, or sibling AgentSession authority is refreshed or carried forward. The same AgentSession's session loopback credentials remain installed until `session.close`. Their mint, attribution, and destruction belong to [Worker Agent Capability](20260703-worker_agent_capability.md).

When any compatibility or hygiene predicate fails, NanoCore closes or fences the predecessor binding through its existing owner and creates a successor only after fresh admission and required cleanup proof. The predecessor must be terminal and non-reusable before the successor atomically becomes current. Authorized operator diagnostics may retain the redacted predecessor, successor, and replacement boundary; ordinary App API and UI expose only the unchanged Thread, prior Turn outcome, current runtime availability, and actions permitted by the owning workflow.

Eviction of an idle AgentSession changes latency and replacement diagnostics only. It does not change Thread history, accepted Items, Workspace truth, evidence, or recovery truth. This contract defines no idle timer. Retry after a denied or failed reuse decision is a new admission decision from current durable truth; it does not retry a prior native operation or reuse the prior Turn request identity.

The decision and its reason are recorded in [a decision record](../decisions/20260930-native_environment_managed_outside_the_sandbox.md).

A changed effective public native environment waits for the next Turn admission and follows existing predecessor close/fence and successor AgentSession creation with the exact retained native reference. No running process is mutated, no active Turn is replayed, no hidden prompt is generated, and no fresh conversation substitutes for a failed required resume. Unproved predecessor cleanup blocks successor effects.

## Setup Generations And Revocation

Desired and effective setup generations are immutable derived identities, not new Core product records. The desired generation derives from current Agent Manifest and profile resolution, Worker Skill and instruction digests, runtime image and adapter identity, policy digests, Workspace layout, provider and plugin posture, and current AEP requirements. The effective generation is what one Sandbox, Harness, and AgentSession binding can prove it materialized.

Every new AgentSession placement and later-Turn reuse decision compares current desired requirements with the exact effective generation. A compatible Turn receives fresh dynamic authority without changing static setup. An AgentSession-local instruction, Skill, provider posture, or other compatibility change marks the AgentSession stale for new Turns. An AgentSession-local supply change that the adapter declares it will list again at the next Turn start does not drain the Harness and does not replace the AgentSession. A supply change the adapter cannot list again, and any other setup change the live binding cannot apply, is a successor AgentSession that resumes the native conversation. Each adapter declares whether it re-lists tools at Turn start, and its slice establishes the answer by probe; this specification does not invent that answer. Codex, Pi, OpenCode, and DeepSeek each declare that they do not re-list mounted supply. A supply change on those bindings requires a successor. [Codex](20260716-codex_worker_adapter.md), [Pi](20260716-pi_worker_adapter.md), [OpenCode](20260716-opencode_worker_adapter.md), and [DeepSeek](20260930-deepseek_worker_adapter.md) own each carrier. This specification does not copy credential configuration and does not add a timer. The setup-change replacement boundary is the AgentSession. A process-global Tool, plugin, native MCP, adapter, or Harness requirement that cannot be isolated to one binding drains and replaces the Harness under its owner. A runtime image, OS user, mount, network, credential-visibility, containment, or Sandbox-policy incompatibility requires Sandbox replacement. The accepted runtime owner decides the exact physical boundary; this specification decides only that a stale generation is never hot-patched and presented as unchanged continuity.

Ordinary non-security updates use rolling replacement: publish the new desired generation, reject new work on incompatible old bindings, admit and prove the replacement at the required boundary, route new AgentSessions and Turns only to the replacement, let already-running non-security-sensitive Turns settle under their pinned immutable authority, and close the old binding after output, evidence, route-revocation, and cleanup barriers complete. Missing or failed replacement dependencies leave new work blocked or unavailable and do not mutate the running generation.

Permission revocation, credential compromise, unsafe visibility, containment uncertainty, or another security-sensitive change is not rolling convenience. Current routes are revoked, affected work follows immediate interruption and the owning cleanup boundary, and no later Turn reuses the old AgentSession. Cleanup does not prove recall of already exposed material.

Restart recomputes desired inputs from current owners and adopts only an exact surviving effective generation and binding. A missing, stale, contradictory, duplicated-current, or unprovable generation rejects adoption or reuse and follows cleanup plus fresh admission; it never selects an approximately compatible generation. Observable acceptance requires a non-security update to pin admitted work and route new work to the proved successor, a security revocation to block reuse immediately, and operator evidence to preserve redacted replacement lineage while ordinary product surfaces remain AgentSession-free. No decision class is not applicable.

## Exact Reconnect Contract

- `awaiting-reconnect` is a NanoHost adapter observation for the same open attempt, not a new AgentSession lifecycle or selection mode.
- A transport loss while NanoCore keeps running MUST NOT mark a reconnect-eligible worker complete, failed, or replaced.
- A NanoCore restart alone MUST NOT mark a reconnect-eligible worker complete, failed, or replaced. A binding that cannot be proved exactly is closed or fenced, and a successor resumes the retained native conversation or fails explicitly. The restart MUST NOT mark the prior Turn complete, and it MUST NOT infer that an effect did not happen.
- Successful adoption, after a transport loss or a NanoCore restart, MUST preserve the same AgentSession id, Turn id, attempt id, package snapshot, worker process, checkpoint, and accepted worker sequence.
- Successful adoption MUST preserve the same backend session and sandbox and MUST NOT create a replacement Runtime Epoch or sandbox.
- A wrong process key, lineage mismatch, stale or conflicting sequence, expired deadline, missing post-launch proof, or lost attempt claim MUST reject adoption.
- Rejected adoption MUST NOT create a successor AgentSession while the reconnect window remains owned by the original attempt.
- After deadline-owned cleanup, the AgentSession becomes non-reusable and the prior Turn retains the truthful result its lifecycle owner determined. Effect uncertainty and any recovery requirement are expressed by the effect owner and the recovery owner respectively, and interruption MUST NOT infer that an effect did not happen.
- NanoHost service, effect-capable member, or execution-server failure interrupts or leaves unknown every affected AgentSession independently. It MUST NOT infer a shared result, migrate an AgentSession, or authorize an automatic replacement, and affected capacity remains unavailable until the NanoHost owner proves fresh-ready recovery.

## Successor Fallback

A fresh successor AgentSession is allowed for a separately authorized attempt only after the predecessor is terminal and runtime-fenced and current manifest resolution, policy, Vault grants, Sandbox requirements, AEP compatibility, Workspace materialization, and scheduler admission succeed.

The successor reads prior product context from Core-owned Thread, Item, Artifact, Knowledge, and evidence records. It may reattach its authorized retained volume as working data, including unimported files and caches, but does not inherit native provider authority or the predecessor's live process. Within the same Agent/runtime selection it inherits the exact retained resume reference and resumes that conversation. An explicit Agent or runtime switch starts fresh from OpenKit-owned Thread context. Guessing a session from the volume stays forbidden.

The fallback preserves the original attempt. It MUST NOT rewrite an interrupted Turn, claim that an uncertain external effect did not happen, or reuse the previous request identity to repeat a side effect.

## Deferred Snapshot Boundary

Exact native resume of the Thread's retained conversation is current scope. Snapshots, generic resume selection, `--last`, serialized-state restore, rollback, fork, and clone have no current Core or specification owner. They are future, deferred, and non-authorizing rather than optional capabilities supplied by this contract. Exact later-Turn reuse under the section above is current scope and does not authorize any of these mechanisms.

Any future activation requires a present backend and workflow need plus an accepted specification that defines credential invalidation, current-policy reattachment, Workspace truth, lineage, failure, cleanup, and user-visible behavior. A future concept does not justify a current `SessionSnapshotRecord`, generic selector, restore workflow, migration, runner, harness, or test matrix.

## Decision Completeness

The definition and exclusions are the exact reconnect, later-Turn reuse, and internal successor outcomes above. An AgentSession is one authorized active execution binding to the Thread's retained native conversation, on one admitted runtime host instance, as [AgentSession](../core/agent-session.md) defines. Sequential Turns use that binding. Turn completion does not close it and does not stop the runtime. Closure releases the binding. Cross-Thread reuse, two current AgentSessions, compatible substitution during one active attempt, snapshot restore, automatic replay, an empty conversation standing in for resume, transcript replay, inherited Turn authority, and ordinary product exposure are excluded. Core-owned AgentSession, Thread, Turn, Item, and evidence records are durable authority, while runtime bindings, native conversations, compatibility keys, and replacement diagnostics are projections that cannot rewrite product history.

Creation, update, termination, retry, and recovery use existing owners: creation requires no current AgentSession, later-Turn reuse re-evaluates immutable compatibility and hygiene without mutating prior authority, Turn termination closes the Turn attempt and releases exclusion after output, evidence, the loopback drain owned by [Worker Agent Capability](20260703-worker_agent_capability.md), route-token revocation, and the Turn-end collection barrier and does not close the AgentSession, AgentSession termination is `session.close`, successor creation atomically retires the predecessor before the successor is current and collection runs before the successor starts on the same work volume, retry is a new authorized request, and a transport loss or a NanoCore restart adopts only the exact active attempt under the existing proof contract or preserves interruption or uncertainty. Missing, stale, conflicting, duplicate-current, revoked, restart-unprovable, or dependency-failed inputs reject execution; an unprovable local cleanup widens the runtime fence and returns no affected capacity until its owner proves readiness. In-flight work on a dead host is not transparently recovered.

Observable acceptance requires two sequential Turns in one Thread to use the same resident binding and the same native conversation, with distinct fresh Turn authority, and the native process still to be the execution instance after the first Turn completes; closing that binding to preserve resumable native context; the next successor to resume that conversation or fail explicitly; cancelling a Turn to leave the binding open; closing one shared-host binding to leave a sibling binding able to run; an incompatible or revoked case to retire the predecessor before one successor becomes current; another Thread never to reuse the first Thread's AgentSession; ordinary product surfaces to expose no AgentSession identity or action; a transport loss or a NanoCore restart either to adopt the exact active attempt or, when proof fails, to close or fence the binding and resume through a successor or fail explicitly, with effect uncertainty and any recovery requirement expressed by those owners. No decision class is not applicable.

### External Influence Continuity

The durable AgentSession record MUST retain the conservative external-influence bit. A set bit survives reconnect, later-Turn reuse, native resume and successor replacement that continues the context. Summaries, retained history and compaction MUST NOT clear it; a missing recorded bit counts as influenced. This fact carries no prior Turn authority. [AgentSession](../core/agent-session.md) owns the semantic state and [Runtime Security](20261109-runtime_security.md) E9 owns its sources and gated effects.

## Acceptance

L1 and L2 cover the predicates in Exact Reconnect Contract, Later-Turn Reuse And Successor Replacement, and Successor Fallback. One deterministic L3 scenario proves transport loss. A separate deterministic L3 scenario proves a NanoCore restart. A higher-layer real-worker check is used only for integration that those levels cannot prove.
