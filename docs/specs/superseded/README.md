# Superseded Specs

This directory keeps `Status: Superseded` specs whose contracts or substantive proposals continue under or were absorbed by named current specs or stable core documents.

Superseded specs are not current guidance. Each spec must use `Implementation: N/A` and include the lifecycle date, current-guidance path, decision evidence, a substantive lifecycle reason, and a distinct retention reason required by the parent [specification guide](../README.md).

Only an auditor may add a spec to this directory, and the non-authorizing terminal-archive audit record must land in the same change. That record captures the accepted decision, exact source and archive paths, final SHA-256 of every archived file, complete authority-criterion receiver inventory, and every inbound current-guidance link disposition.

Files already archived here are immutable. Do not edit metadata, prose, links, spelling, formatting, or paths, and do not delete a file; record later observations in a new audit record and continue renewed work in the named current guidance, linking the terminal-archive audit only when one exists.

Do not backfill terminal-archive audits for files that predate the auditor-owned rule. The bytes committed by the rule-adoption change are the frozen archive.

Use the named replacement as the current entry point. Link to files in this directory only when historical evidence is explicitly needed.
