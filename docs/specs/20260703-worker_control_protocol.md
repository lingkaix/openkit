# Worker Control Protocol

This specification owns `openkit-worker-control-v2`, the end-to-end worker-control wire protocol between governed worker containers and NanoCore, including upward worker-to-NanoCore control routes, downward private Harness control operations, directional reader and emitter validation, and incremental native work observation envelopes.

## Scope

Owns:

- The worker-visible `/worker-control/*` protocol between Sandbox Integration and NanoCore, including authentication, lineage, monotonic sequencing, idempotency, bounded outage retry, and canonical verification.
- Upward worker-to-NanoCore `heartbeat`, `artifact_notice`, `event_append`, `final_status`, `supply_refresh_ack`, and `capability_summary` routes, plus the cancellation-only first-final exception and transcript Item exact-value replacement.
- The seven private Harness control operations (`session.open`, `session.inspect`, `turn.start`, `turn.steer`, `turn.interrupt`, `session.close`, and `harness.drain`) and the Integration-initiated `POST /worker-control/harness/poll` and `POST /worker-control/harness/result` protocol.
- Directional descriptive-reader and exact-emitter validation rules and `native-content-v1` incremental work observation chunk admission.

Does not own:

- The shared container communication model, internal execution backend port, NanoHost adapter liveness, and resident runtime adapter base contract: [Worker Runtime Communication Model](20260629-worker_runtime_communication_model.md) owns them.
- Agent Capability routes, session loopback credential minting, attribution, drain, and destruction, and built-in MCP tool supply: [Worker Agent Capability](20260703-worker_agent_capability.md) and [Worker MCP Tool Supply](20260704-worker_mcp_tool_supply.md) own them.
- NanoHost transport, Runtime Epoch lifecycle, stock OpenShell supervision, RelayStream and HTTP/2 carriage, and predecessor connection fencing: [NanoHost Runtime And Transport](20260802-nanohost_runtime_and_transport.md) owns them.
- Durable scheduling, AgentSession continuity records, Task live-steer public lifecycle, and Turn stop-reason canonicalization: [Durable Scheduler Design](20260703-durable_scheduler_design.md), [AgentSession Continuity](20260704-agent_session_continuity.md), [Task Mode Worker Delegation](20260704-task_mode_worker_delegation.md), and [Worker Turn Reliability Envelope](20260531-worker_turn_reliability_envelope.md) own them.
- Workspace snapshot chains and staging, AEP and manifest resolution, and retained work data storage layout: [Workspace Synchronization](20260703-workspace_synchronization.md), [Agent Environment Package](20260616-agent_environment_package.md), [Agent Manifest And AEP Resolution](20260703-agent_manifest_aep_resolution.md), and [Work Data Retention Format](20260921-work_data_retention_format.md) own them.

Core: [Communication](../core/communication.md), [Runtime Model](../core/runtime-model.md), [AgentSession](../core/agent-session.md), [Work Model](../core/work-model.md), [Mediation](../core/mediation.md), [Evidence](../core/evidence.md), [Contract Evolution](../core/contract-evolution.md).

## Endpoint

The worker-visible target endpoint is one sandbox-local Integration binding whose route namespace is `/worker-control/*`. The AEP supplies only the non-secret local binding and worker-control token reference, and Sandbox Integration binds it to the standard HTTP/2 session carried by the sandbox's one stock RelayStream under [NanoHost Runtime And Transport](20260802-nanohost_runtime_and_transport.md). The worker never receives a NanoCore address, NanoHost credential, remote Gateway address, SSH target, transport credential, or alternate control endpoint.

Sandbox Integration maps each worker-visible operation-specific request into `/worker-control/*` without changing its envelope. On NanoCore, the accepted upward routes are `/api/worker-control/heartbeat`, `/api/worker-control/artifacts`, `/api/worker-control/events/append`, `/api/worker-control/final-status`, `/api/worker-control/supply-refresh-ack`, and `/api/worker-control/capability-summary`. For per-Turn requests, NanoHost, RelayStream, Gateway, the HTTP/2 session, and the Integration outer adapter are byte-transparent transport intermediaries that MUST NOT inspect, authorize, synthesize, reorder, retry, reinterpret, or terminalize a message. `/inference/*`, `/capabilities/*`, Gateway forwards, direct NanoCore reachability, and transcript sinks are never control paths.

Two exact paths inside `/worker-control/*` are Integration-private Harness carriage rather than worker-visible routes:

```text
POST /worker-control/harness/poll
POST /worker-control/harness/result
```

Only the long-lived Sandbox Integration supervisor may issue them; a native Agent child, App API caller, worker-control client, sibling route, or arbitrary path MUST NOT issue a Harness operation. NanoHost binds those two requests to the current exclusive Integration-client nested HTTP/2 connection and Sandbox Integration as defined by [NanoHost Runtime And Transport](20260802-nanohost_runtime_and_transport.md), and NanoCore selects the exact private Harness instance for each delivered operation. A separate bound Harness subscription-login exchange carrier exists under [Vault Secret Injection](20260703-vault_secret_injection.md) without adding a worker-visible route or general control operation.

## Authentication

Every worker-visible `/worker-control/*` request MUST authenticate with a worker-control token minted for one AEP snapshot and exact current attempt lineage. Each route token is a 43-character unpadded base64url encoding of an independently generated 32-byte CSPRNG value.

The two private Harness paths (`POST /worker-control/harness/poll` and `POST /worker-control/harness/result`) run before or outside a Turn and MUST NOT accept a worker-control, inference, capability, NanoHost, Gateway, Provider, Vault, User, or server-admin bearer credential. Their authentication is the conjunction of the current exclusive Integration-client nested HTTP/2 connection, its NanoHost-owned bridge and Sandbox Integration binding, the current authoritative outer NanoHost connection, and NanoCore verification of the exact current private `sandboxIntegrationBindingRef`. Integration sends no `Authorization` header and cannot supply the binding reference or a Harness selector. NanoHost rejects client-supplied `authorization`, `x-openkit-integration-binding`, or `x-openkit-harness-binding` headers and injects exactly one `x-openkit-integration-binding` value from its private bridge context on the outer request; NanoCore accepts that header only from the authenticated authoritative NanoHost transport and rejects it on synthetic, public, direct, stale, predecessor, wrong-Integration, or ordinary worker-control requests. The reference is opaque non-secret routing metadata, not a credential, AgentSession identity, independent grant, or fallback token. NanoCore places one exact private `harnessInstanceId` in each command response only after matching it to the admitted Integration descriptor set.

The worker-control token is accepted only by `/worker-control/*`. Two distinct independently generated 43-character tokens authenticate `/inference/*` and the AEP-enabled `/capabilities/*` routes respectively; none is derived from or equal to `sandboxBindingRef` or another route token, and each route family MUST reject the other two token families. Shared RelayStream, HTTP/2, NanoHost transport, process, host placement, or restart MUST NOT create token reuse or shared authority.

The worker-control token is scoped to Workspace ID, Thread ID when applicable, Turn ID, AgentSession ID, package snapshot ID, backend session ID or redacted backend session binding, and expiration time. NanoCore MUST reject token reuse across lineage.

Each active Turn's three raw upstream route tokens remain in live memory only in NanoCore, in NanoHost while carrying that exact admitted Turn operation, and at the AgentSession-local `turn.start` route boundary inside Integration. Harness bootstrap, Harness-global argv and environment, Sandbox-wide files, and the native runtime environment contain none of them. `session.open` delivers the two session loopback credentials, whose mint, attribution, drain, and destruction belong to [Worker Agent Capability](20260703-worker_agent_capability.md). Raw upstream tokens MUST NOT enter SQLite, the AEP, the Context Package, retained command or result bytes, native configuration or argv, diagnostics, stdout, stderr, transcripts, evidence, logs, or sibling AgentSession routes; only their lowercase SHA-256 hashes over the 32 decoded bytes persist on the execution attempt, while the two session loopback credentials use the separate 43-encoded-byte SHA-256 domain under [Workspace Synchronization](20260703-workspace_synchronization.md#snapshot-chain). This separation provides conversation-context isolation and route-authority separation, not security isolation from a compromised shared Harness.

Before the readiness exchange, the shim generates one random 32-byte process key in memory and encodes it as 43 unpadded base64url characters. The sequence-`0` `starting` heartbeat carries the unpadded base64url SHA-256 digest of those key bytes, which NanoCore immutably binds to the attempt before the native worker child starts. Sequence `1` is the first durable proof that post-launch recovery is enabled and child execution has begun; restart recovery never arms a sequence-`0`-only supervisor. The raw process key stays in shim supervisor memory only and may appear on the wire only as the request-only `reconnectKey` on an exact-next recovery heartbeat alongside the existing bearer token and exact lineage.

The accepted `schemaVersion` literal for worker-control requests, responses, and private Harness outer envelopes is `2` (`openkit-worker-control-v2`), while canonical transcript, event, Artifact, provenance, workspace-change, and inner capability-summary records retain schema version `1` (`packages/worker-protocol/src/index.ts`). No protocol-version negotiation, accepted-version set, build compatibility registry, legacy adapter, or version-1 control-envelope fallback is permitted.

## Envelope

The canonical control request envelope is `WorkerControlRequestEnvelopeSchema` in `packages/worker-protocol/src/index.ts`. `lineage` includes the workspace, thread, turn, AgentSession, package snapshot, backend session binding when applicable, and token scope needed to bind the request to one governed worker execution.

Every `turn.start` binds a fresh immutable per-Turn Agent Environment Package snapshot and Context Package to the exact Workspace, Thread, Turn, AgentSession, actor, request, Agent, profile, runtime, provider, policy, route credentials, Vault grants, resource limits, observability, and package digest admitted by their owners. A shared Sandbox or Harness MUST NOT receive one Sandbox-wide authorization package or credential that authorizes resident AgentSessions collectively. Static compatibility descriptors are placement evidence only and MUST NOT authorize a Turn, effect, retry, or publication.

An idle or resumed native conversation contributes continuity only. Idle supplies no authority. Refusal of a loopback request with no Turn bound belongs to [Worker Agent Capability](20260703-worker_agent_capability.md). A resumed conversation supplies native continuity only. The newly bound Turn's authority is what a request receives. It MUST NOT supply stale authority or replace current Core context, and old immutable package snapshots remain evidence rather than authority for later Turns.

The envelope does not duplicate an actor. NanoCore resolves the immutable runtime actor only from the exact Turn and AEP snapshot named by that lineage; `AEP.scope.triggerActor` remains the sole runtime actor authority, and a worker-supplied actor or responsible-user field is invalid rather than an override.

Worker-control liveness and terminal records may remain non-authorizing transport evidence after responsible-user authority is lost, but no candidate event, artifact notice, knowledge proposal, capability summary, or collected output may be promoted into canonical Workspace content without the current-authority predicate required by the owning effect. The first worker-control or NanoCore boundary that observes lost authority interrupts the worker, revokes its route authority, terminates the affected sandbox, invalidates the complete Runtime Epoch if the NanoHost cannot prove sandbox deletion completed, and rejects later publication; it adds no control operation, command kind, durable state, quarantine, settlement, or recovery workflow. An already-submitted worker-native external request remains subject to the bounded compromise in the multi-user specification.

`sequence` is monotonic per AgentSession and package snapshot for the relevant control stream. Live append may skip sequence numbers. Exact retries with the same sequence and identical canonical payload are idempotent. The same sequence with different content must fail closed. A lower sequence after a higher accepted sequence fails closed. Ordinary post-launch heartbeats may skip sequence numbers. Each newly accepted higher heartbeat sequence renews liveness, and an exact replay does not renew it.

A control envelope is at most 64 KiB (current default). One live event payload is at most 256 KiB (current default). Larger material moves through the data plane as an artifact, evidence bundle, manifest, or collected file reference, with a typed oversized-payload refusal.

The canonical control response envelope is `WorkerControlResponseEnvelopeSchema` in `packages/worker-protocol/src/index.ts`.

HTTP route-specific projections may put lineage and payload fields directly in route bodies, but they must preserve the same semantics: bounded payload, bearer token, lineage binding, monotonic sequence where the operation is sequenced, and NanoCore-owned verification.

Restart adoption uses the ordinary heartbeat envelope plus request-only `reconnectKey`. NanoCore decodes and hashes the key, then authorizes adoption only when the hash equals the immutable attempt binding, the complete durable lineage is exact, the attempt is open and the NanoHost adapter holds its `awaiting-reconnect` observation before the preserved deadline, and the heartbeat sequence is exactly the next sequence after the last accepted heartbeat. The adoption compare-and-set advances the sequence and restores the same open attempt to ordinary control; rollback, gaps, conflicting replay, a wrong key, or an expired window fail closed. The raw key is excluded from the canonical heartbeat fingerprint, access logs, diagnostics, and durable records.

There is no application-layer challenge, asymmetric signature, recovery listener, or recovery session state machine. The reconnect request relies on the authenticated confidential NanoHost transport and route-separated Integration carriage that protects the Sandbox bearer token. That separation supports conversation-context isolation and does not provide security and adjudication isolation from a compromised shared Harness. A party that can observe both the bearer token and process key on that path could race the original worker; transport confidentiality and predecessor fencing are therefore explicit boundaries of this V2 compromise rather than a second worker-control cryptographic protocol.

If exact adoption does not complete inside the bounded window, worker control authorizes no compatible replacement and makes no completion claim. The scheduler terminates the old attempt authority, while the NanoHost owns definite sandbox deletion or whole-epoch invalidation when cleanup is uncertain. The owning Turn retains the truthful result its lifecycle owner determined until a new request is authorized. Effect uncertainty and any recovery requirement are expressed by the effect owner and the recovery owner respectively, and interruption MUST NOT infer that an effect did not happen.

## Descriptive Readers And Exact Emitters

Worker-to-NanoCore reports, canonical transcript candidates, observation metadata and chunks, runtime provenance manifests and indexes, capability summaries, acknowledgements, diagnostics and error envelopes are descriptive. Readers MUST strip unknown descriptive keys before fingerprinting, canonical persistence, forwarding or display. Generic control-envelope admission MUST be followed by the operation-specific body reader before any use of that body. Unsupported declared requirements, unknown versions, operations, event kinds, statuses and missing required fields remain failures; sequence, attribution, lineage, process-key proofs, content admission, digest checks and secret exclusions remain binding.

Lineage bindings and Turn capture-coverage admission carry authority and remain exact. Worker-supplied actor or responsible-user fields remain invalid rather than supplying authority. Effect instructions, including private Harness command bodies, remain exact under [Contract Evolution](../core/contract-evolution.md#closed-core-open-extension). Emitters and known-core fixtures MUST retain exact assertions that catch an unknown emitted key, including when all required fields are present.

Runtime provenance readers MUST verify digests over the original stored bytes before parsing a stripped view. Retained raw streams and index files keep their original bytes. Ordinary portable Workspace import is absent and does not remint a normalized index. Export retains the normalized index and does not recompute an import digest. This creates no compatibility reader, migration, dual write or new lifecycle.

## Worker-To-NanoCore Messages

Control operation names are `WorkerControlOperationSchema` in `packages/worker-protocol/src/index.ts`, listed once under [Canonical Enums](20261021-protocol_identifiers_and_enums.md#canonical-enums).

`heartbeat` reports worker liveness and coarse lifecycle state. It must not carry transcript content.

`event_append` carries small schema-conformant candidate event records only. Large transcript files remain in the exact admitted `/openkit/threads/<threadId>/<harness>/capture/<turnId>/` capture and are collected through the data plane. NanoCore validation and commit, not append acceptance alone, makes product state canonical.

`artifact_notice` announces an artifact path, title, media type, digest when available, and collection hint. It does not upload artifact bytes.

`final_status` records one Turn's final status and evidence manifest digests. Its `status` and product-safe `stopReason` string are worker-control transport facts rather than Core `StopReason` authority. The sole durable owner is the existing immutable server-scope `worker_control_records` row with `operation=final_status`, keyed by AgentSession, package snapshot, operation, and decimal sequence record key and validated against the row's exact Workspace, Thread, Turn, nullable request, attempt, AgentSession, package snapshot, sequence, and canonical terminal-event lineage. The row stores the complete accepted wire payload plus `acceptedAt`; exact fingerprint replay reuses it and changed same-sequence input conflicts. It survives restart, is not Workspace-portable product history, and MUST NOT be copied into a checkpoint, evidence row, or recovery lifecycle. NanoCore then applies the one closed canonicalization table owned by the Worker Turn Reliability Envelope before mode closeout. An unknown or incompatible pair remains durable and yields `recovery_required`; NanoCore does not infer a Core reason from the product Turn projection or adapter-private vocabulary.

`supply_refresh_ack` acknowledges one explicit NanoCore-issued source-to-target supply refresh request only when the resolved AEP declares support proved by the selected image and shared shim. It does not grant execution authority or extend the absolute attempt deadline.

`capability_summary` reports control-plane liveness and summary ids for capability activity. Authoritative capability call records belong to Agent Capability.

## NanoCore-To-Worker Commands

Private Harness `turn.interrupt` is the only interrupt. The accepted design has no separate worker `interrupt` command. A backend push channel may be added later only if it preserves the same authorization, lineage, sequence, and delivery semantics.

Private `turn.interrupt` is the sole interrupt-delivery owner. NanoCore MUST NOT enqueue, deliver, acknowledge, translate, mirror, retry, or fall back to a second worker `interrupt` command for that Turn. Process-group kill of a resident shared server is not the cancel proof. Cancellation alone does not close the AgentSession.

The existing Turn and attempt terminal compare-and-set is the sole race owner. If an accepted terminal transition wins first, no interrupt delivery record or Harness operation is created and the existing already-terminal result is returned. If interrupt authorization wins first, exactly one delivery is admitted; a later terminal report remains evidence for the Worker Turn Reliability Envelope and cannot create a second interrupt or let an operation result directly terminalize product state. A second non-identical interrupt is a conflict and produces zero additional signal. Delivery uncertainty follows dispatched-command non-redelivery and unknown-cleanup widening. There is no second fallback path.

The private `turn.interrupt` command takes no steer-or-abandon parameter and has no sibling cancel command. With `purpose: interrupt` it is the abandon command for a product interruption: continuing after that stop is a new Turn under the rule that new input without an active Turn starts one, never a revival of the stopped Turn ([decision](../decisions/20260921-turn_interrupt_is_abandon.md)). The purpose value is exactly `interrupt`. A pending approval or user-input request does not use this operation to pause the Turn; that request is owned by [Pending Requests](20260930-pending_requests.md). Missing, unknown, malformed, or extra purpose input fails before any signal, and purpose is never inferred from free text. One Core transaction verifies the binding's current Turn and execution-attempt identity, the complete current active scheduler attempt lineage, absence of an accepted final status for that lineage, and the free Harness-operation slot while queuing the operation. The caller waits only for durable enqueue. Existing asynchronous operation settlement owns dispatch, exact result, non-redelivery, restart uncertainty, and cleanup, and terminal cleanup waits for that settlement before `session.inspect`, including when the accepted terminal status arrives before the admitted interrupt result. A cancel result reports the actual cancellation outcome. `session.inspect` after a Turn cancel still shows the binding open.

## Harness Control Operations

Sandbox Integration exposes exactly these fixed typed operations to its declared Harness adapter:

- `session.open` creates one private adapter binding for one already-admitted Core AgentSession and either binds its exact native conversation or records the adapter-authorized pending state until the first Turn. For a new empty work slot, first initialization completes during this operation before that AgentSession's native runtime starts, as [Session Static Workspace Materialization](20260704-session_static_workspace_materialization.md) defines. After successful `session.open` returns, NanoCore requests baseline collection and withholds the first `turn.start` until [Workspace Synchronization](20260703-workspace_synchronization.md) records durable baseline acceptance. A retained slot is never re-baselined and continues from its chain head under those owners. The decision and its reason are recorded in [a decision record](../decisions/20260930-first_accepted_base_by_baseline_scan.md);
- `session.inspect` returns bounded product-safe identity, liveness, capability, and cleanup proof for exact verification;
- `turn.start` starts one already-authorized Turn in one exact AgentSession with its per-Turn package, Context Package, attempt, route bindings, and sequence;
- `turn.interrupt` requests interruption of one exact active Turn and AgentSession;
- `turn.steer` delivers bounded additional user text to one exact active Task Turn and binding under [Task live steer](20260704-task_mode_worker_delegation.md#live-steer);
- `session.close` revokes the exact native continuation authority and removes only disposable AgentSession control/request slots after collection, preserving retained native and working data;
- `harness.drain` refuses new `session.open` and `turn.start` operations while admitted work and cleanup settle.

This specification is the unique protocol owner for those operation meanings and exclusions. The NanoHost runtime specification owns placement and Harness lifecycle, Sandbox Integration owns local routing and supervision, NanoCore owns selection and authorization, and the Harness owns only execution of the selected native-runtime operation. The names are private protocol vocabulary and create no App API, product command, public schema, shell gateway, or generic runtime API.

### Harness Pull And Result Envelopes

Sandbox Integration uses one serial Harness-control poll loop for all its live Harness instances. It polls only when no command handling or result acknowledgement is in flight. Each poll emits `{ "schemaVersion": 2, "releaseIdentity": { "sourceCommit": "<40 lowercase hex>", "releaseTag": null }, "harnesses": [{ "harnessInstanceId": "...", "nextSequence": 0 }] }`, reporting each live Harness instance's next unreceived sequence without selecting a command. The reader requires version 2 and a known exact Worker build identity, validates present progress entries and rejects duplicates, while ignoring inert additions. Core compares the required identity with its immutable boot identity on every bound private poll, before command selection, material callbacks and either the initial or idle readiness response. Missing, malformed, wholly unknown or unequal identities return typed `409 worker_release_incompatible`; two unknown identities never match. Tagged identities compare both source commit and tag; matching known untagged source builds are valid. The Worker reads an at-most-4096-byte root-owned `/usr/local/lib/openkit/release-identity.json` envelope; runtime environment variables cannot override it. Native immutable-image inspection independently carries the OCI revision/version provenance, checked at the existing post-native-admission barrier before storage attachment or Worker material delivery, including restored resident reuse. Existing capacity/retirement and physical-Epoch authority ordering stays unchanged. This is compatibility admission, not authentication, authority or a negotiated fallback. Unknown image provenance is preserved as unknown and refused, never inferred from a schema version, SDK version, image digest alone or a prior resident. An older shim without the field cannot earn readiness or receive a command. An older Worker may omit `harnesses`; omission provides no delivery proof. The loop advances `nextSequence` only after result acknowledgement. Both response headers and body collection use the remaining original 300-second request outage allowance for poll and result exchanges. A fresh one-second header timer MUST NOT cancel admitted command carriage. Retries consume that same monotonic allowance without renewal; caller cancellation and allowance expiry still abandon the exchange before parsing or execution. This does not extend the Core operation's own allowance or change its uncertain-delivery fence. The reason is recorded in the [Harness carriage deadline decision](../decisions/20261020-harness_carriage_deadline.md). After NanoCore returns no work, polling start-to-start remains at least 250 ms apart. While a Turn is active, the 1000 ms start-to-start maximum applies only between polls while no command handling or result acknowledgement is in flight. An in-flight operation on any Harness delays the next poll up to that operation's existing request allowance. NanoCore returns empty `204` when no operation is available or emits one `200` command. The command envelope is `HarnessCommandEnvelopeSchema` in `packages/worker-protocol/src/harness-control.ts`, and `HarnessCommandEnvelopeReaderSchema` strips inert additions while its effect-bearing body remains exact. `harnessInstanceId` is the exact NanoCore-selected private Harness identity. `sequence` is that Harness record's next expected non-negative safe integer. `operation` is one `HarnessOperationSchema` literal.

`operationId` is the untagged lowercase SHA-256 of the Harness binding reference, per-Harness operation sequence, operation literal, and canonical redacted body identity. The shared canonical form is owned by [Protocol Identifiers And Enums](20261021-protocol_identifiers_and_enums.md#ids). This identity uses the retained Harness serializer instead: it hashes the named object, sorts object keys by UTF-16 code unit and recurses through non-array objects, retains array order including objects inside arrays, and does not treat numeric-index enumeration as object-key sorting, then applies `JSON.stringify`. That retained serializer exception also covers result identity. The stored-byte check hashes the exact retained result bytes. The consumer-facing result fingerprint excludes `consumerContext` and hashes the remaining object with that same serializer. The stored-byte check runs before a stripped view is parsed. A read does not recompute a retained record or replace the encoder. Exact stored-byte native-handle digests and exact UTF-8 steer-input digests stay their own byte-input forms. The decoded route-token hash domain and the encoded loopback hash domain stay separate. The Harness binding reference uniquely identifies the admitted Harness Instance within its Sandbox Integration. The existing NanoCore runtime owner derives this identity. For `turn.start`, the redacted identity contains the three durable route-token hashes rather than any raw token. For `session.open`, the redacted identity contains the durable hashes of both `inferenceLoopbackCredential` and `capabilityLoopbackCredential`, includes the canonical public `nativeEnvironment` identity, and omits raw `runtimeEnvironment` values, rather than any raw credential. NanoHost and Integration cannot select the Harness, id, or sequence. NanoCore permits exactly one queued or dispatched operation per Harness, stores that state with the private `HarnessInstanceRecord`, and advances that Harness sequence only after one exact result settles. Different Harnesses may each have one unsettled operation and progress independently. A queued operation stores only admitted non-secret lineage and body references. At `turn.start` dispatch, one checked transaction mints the three mutually distinct raw route tokens, persists their separate hashes on the exact attempt, derives `operationId`, and marks the command dispatched before returning the one response containing those raw values; a Core crash after that commit loses the private wire bytes and is uncertain delivery, with no regeneration or restart replay. While Core and the same Integration remain live, a subsequent serial poll with the exact Harness identity and `nextSequence == sequence` proves non-receipt and permits redelivery of only the original operation id, sequence and private wire bytes. Core observes every peer reset, including after local write completion. If the command-carrying poll supplied no matching progress, the reset becomes unknown immediately; otherwise Core waits at most 1,250 ms from the reset for that proof, then becomes unknown. A late proof cannot revive a fenced operation or completed Turn. This short bound is independent of the result timer, and a changed Integration, missing private bytes or conflicting progress never authorizes redelivery. Other operation identities are fixed no later than dispatch by the same record transition. This is not the worker `interrupt` queue, a NanoHost effect, an App command, a general command table, or an offline backlog.

Command bodies are `HarnessCommandBodySchemas` in `packages/worker-protocol/src/harness-control.ts`. They instruct effects and MUST refuse unknown fields under Contract Evolution. Unknown operations, invalid core values, and unsupported required or authority-bearing semantics fail before any Harness effect. Shared private identity uses `HarnessIdentitySchema`, `HarnessSha256HexSchema`, and `HarnessRouteCredentialSchema` in that module. Those artifacts supply the identity bounds and character rules. Exact command bodies and descriptive result readers stay separate.

The three `turn.start` tokens are mutually distinct 43-character raw values delivered only in that live dispatch response after their hashes and exact Turn lineage are durable. NanoCore's private Harness operation record and durable command identity contain only their hashes; the raw values remain only in the response-producing live scope. NanoHost forwards them without retention; Sandbox Integration binds them only to the named AgentSession and active Turn and clears them at the Turn barrier. Every `*Ref` is an already-materialized fixed sandbox-local reference selected by its owner, not a caller path, URL, credential, or content carrier. Missing required core fields, malformed or oversized core values, sibling or stale lineage, conflicting core values, and unsupported required or authority-bearing semantics fail before a Harness effect.

`inferenceLoopbackCredential` and `capabilityLoopbackCredential` are mutually distinct 43-character unpadded base64url encodings of independently generated 32-byte CSPRNG values, delivered only in the live `session.open` dispatch response after their hashes are durable. NanoCore persists only the SHA-256 digest of each session loopback credential that `session.open` delivered, with the binding, and retains raw values only in a process-local response-wire slot for at most 300 seconds after dispatch, releasing them earlier on observed exact settlement or unknown cleanup. Durable loss of the exact dispatched owner prevents redelivery immediately, even before the bounded live slot is released. There is no durable raw value or restart reconstruction. The collection check compares those digests as [Snapshot Chain](20260703-workspace_synchronization.md#snapshot-chain) defines. NanoHost forwards them without retention. Sandbox Integration binds them to that AgentSession and destroys them at `session.close`. Mint, attribution, drain, and that destruction belong to [Worker Agent Capability](20260703-worker_agent_capability.md). Both loopback credential fields are required for every worker `session.open`, including when the manifest selects no additional MCP server. Optional private `runtimeEnvironment` follows the bounded-exception rules in [Session-Static Vault Runtime Environment](20260802-nanohost_runtime_and_transport.md#session-static-vault-runtime-environment). Absence of either loopback credential is a missing-field failure; absence of optional `runtimeEnvironment` is a defined body.

The decision and its reason are recorded in [a decision record](../decisions/20260930-native_environment_managed_outside_the_sandbox.md).

`session.open.maxActiveTurns` carries the authored Harness operating bound from [Runtime Scheduling Scale](20260703-durable_scheduler_design.md#scale-limits), with an initial default of 20. Omission uses the current Harness declaration; later opens cannot change it while that Harness is resident. The success result must prove the exact admitted bound. The resident-session bound is the greater of its initial default of eight and the active-Turn bound; it must not introduce a lower active-Turn convenience cap. Each Thread and AgentSession still has at most one active Turn. Known `busy` refusals name the actual exhausted bound with `HarnessExhaustedBoundSchema` in `packages/worker-protocol/src/harness-control.ts`. Native spawn or dependency failures do not invent CPU or memory exhaustion.

`session.open` additionally carries the NanoCore-resolved non-secret `nativeEnvironment` string map, whose name/value/aggregate limits are owned by Agent Manifest And AEP Resolution. An absent public map denotes no public settings only for an input whose owning admitted package permits that absence; an environment-aware package cannot silently omit its resolved delivery. The public map's canonical identity participates in the durable operation identity; raw private `runtimeEnvironment` values remain excluded. No other operation accepts an environment mutation. Environment-variable names in this map are consumed settings, not ignorable additive metadata; the manifest owner's open identifier namespace, bounds and protected-name checks apply.

Native environment comes only from the exact current resolved package and binding, not caller-supplied shell text, a worker request or an arbitrary management map sent to the Harness. Before a Turn performs native work, the Harness requires equality with its session-static public projection and independently requires the Vault name set to match that Turn's credential declarations. A conflict refuses; it never patches the active child.

Integration emits one result admitted by `HarnessResultEnvelopeSchema` in `packages/worker-protocol/src/harness-control.ts`. Success bodies are `HarnessSuccessBodySchemas`. A refusal uses `HarnessRefusalReasonSchema`. A `turn.start` refusal for dependency failure may additionally contain the closed `startupFailure` diagnostic. A `session.open` refusal with that same reason may also contain it for first work-slot initialization, with `startupFailure.stage="workspace_materialization"`. Its stage, reason, and optional Git fetch `explanation` remain owned by [Worker Turn Reliability Envelope](20260531-worker_turn_reliability_envelope.md#durable-git-fetch-failure-explanation) ([decision](../decisions/20260930-closed_core_open_extension.md)). No other refusal admits this diagnostic. An unknown result uses reason `outcome_unknown`. Host liveness is not cancellation proof, and a shared host may remain running after one session closes. `harness.drain` reports the open-session and active-Turn counts. Descriptive result readers are `HarnessResultEnvelopeReaderSchema`.

`turn.start` settles when the resident binding has accepted the Turn and its Turn-local route bindings are installed inside Integration. It does not wait for a child to exit. A first Turn may return `nativeHandleState="pending"` with a null digest when the runtime creates the conversation with the first prompt, which leaves the next Harness sequence available for `turn.interrupt`. Exact handle proof is required before the binding is reusable: after the first Turn reaches its terminal barrier, `session.inspect` must return `ready` with the same digest before NanoCore marks that binding reusable and idle. Process exit is not that proof. If the first Turn did not reach `completed`, or inspection cannot prove one exact handle, the binding is non-reusable and proceeds to exact `session.close` or the existing wider cleanup fence. The raw upstream `turn.start` tokens are not forwarded into the native environment. NanoCore delivers the session loopback credentials in `session.open`. When a binding reports `nativeHandleState="ready"`, its Harness has stored the adapter's restricted handle in retained Sandbox storage under that binding's `agentSessionId`, outside the disposable control root, and `nativeHandleDigest` is the SHA-256 of exactly those stored bytes. The resume locator is that `agentSessionId`, and the resume digest is that `nativeHandleDigest`. Core records the digest on that AgentSession's record when it accepts the ready proof, as [AgentSession Continuity](20260704-agent_session_continuity.md) defines; the raw reference stays in retained Sandbox storage. `resume: null` starts a new conversation. A `{ locator, digest }` value is the pair recorded for the predecessor AgentSession that this binding succeeds. It starts by resume: the Harness reads only the reference stored under that locator, requires its SHA-256 to equal the carried digest, and validates the native result before any work. A missing or mismatched resume reference fails the open. When the successor's own handle becomes ready, its Harness stores the reference under the successor's `agentSessionId`.

Harness result readers strip inert additions from the envelope, disposition-specific body, startup diagnostic, nested Git explanation and new-checkout baseline before canonical identity, persistence, forwarding or display. Required fields, closed values, diagnostic applicability, native-handle relationships and the admitted `maxActiveTurns` proof remain mandatory. First receipt and replay use the same parsed known core; changed core results conflict, including while a successor is queued. A retained result fingerprint is verified against its stored representation before parsing a view, and retained raw bytes are never rewritten by reading. Exact producer assertions remain mandatory.

Integration records the accepted `harnessInstanceId`, `operationId`, sequence, canonical command fingerprint, and then the exact result in bounded per-Harness memory before any retry; it retains only the current or immediately settled operation for each declared Harness and no general queue or history. Exact result replay with the same Harness, identity, sequence, and canonical body is idempotent across outer-session or bridge reconnect. Changed same-identity result, stale or future per-Harness sequence, a Harness outside the admitted descriptor set, or another operation for the same Harness while one is unsettled fails closed without blocking a compatible sibling Harness. NanoCore marks a command dispatched before returning its body. Only the exact live serial non-receipt proof defined in the Harness envelope permits original-command redelivery; no received effect is re-executed. An incomplete delivery without that proof inside the short reset bound, missing result after the existing outage bound, or lost per-Harness memory becomes `unknown`, stops admission to the affected Harness, and widens cleanup without blind replay. A queued command not yet dispatched survives a transport loss or a NanoCore restart through the private Harness record because it contains no raw route token, and after a NanoCore restart a dispatched command survives only as waiting-for-exact-result truth and never regains raw `turn.start` tokens or execution authority. While the original Core process and Integration remain live, only the envelope's non-receipt proof permits original-wire redelivery. Either event may adopt the exact surviving binding under the NanoHost and AgentSession proof contracts. A binding that cannot be proved exactly is closed or fenced, and a successor resumes natively.

The Sandbox Integration supervisor may retry only the same immutable poll or result request under the existing bounded route-outage budget. NanoHost and the Integration transport adapter do not retry it. After a predecessor-fenced bridge successor binds the same current Integration, each surviving Harness resumes at its exact unsettled sequence, first replays a retained result when one exists, and otherwise polls; a new or restarted Integration or Harness cannot adopt the old binding and requires drain, cleanup, and fresh admission.

### Operation-Specific Lifecycle

The Harness control boundary MUST NOT accept or derive caller-supplied arbitrary executable command text, executable, `argv`, `cwd`, environment, executable shell text, host path, provider endpoint, raw credential, working directory, runtime installation, or operation name outside the fixed set. A typed operation carries the bounded core fields its owner admits and refuses unknown fields under Contract Evolution. An unknown operation or extra executable field fails closed before any Harness effect.

The existing private `turn.start`, `turn.interrupt`, and `turn.steer` correlation member `leaseId` carries the Core execution-attempt identity through the NanoHost adapter. Its wire spelling creates no SessionLease record, renewal, or second grant and does not rename NanoHost Rust or native Harness operation types.

Within each Harness, AgentSession lifecycle is `session.open`, zero or more sequential `turn.start` operations with optional exact `turn.steer` and `turn.interrupt`, then `session.close`; `session.inspect` is read-only proof and `harness.drain` is a per-Harness admission fence. `session.open` creates one AgentSession-private adapter control binding and selects a separately retained native data root only when the bound Thread has no other current resident AgentSession. When the pinned native protocol creates its conversation only with the first prompt, or the accepted adapter owner explicitly defers native creation until resolved first-Turn setup and route authority are available, a new open may carry `nativeHandleState=pending`. Its first start reports pending or ready according to actual durable handle proof. The first successful Turn plus subsequent exact `session.inspect` must bind and prove that handle before the AgentSession becomes reusable; pending is never a fallback for a failed resume. A later Turn submits on the resident binding. A successor AgentSession receives the retained resume reference. It does not inherit the predecessor's live process or Turn credentials. Another AgentSession belongs to another Thread and has its own control binding, admitted working and native data slot, handle, route credentials, and cleanup proof. A Turn starts only after fresh admission and consumes one active-Turn attempt. It ends through final status, output, evidence, the loopback drain owned by [Worker Agent Capability](20260703-worker_agent_capability.md), route-token revocation, and Turn-end collection before another Turn may use that AgentSession. Child absence is not that barrier. Different Threads may run concurrently within the admitted Harness and Sandbox aggregate bounds. One AgentSession and one Thread still have at most one active Turn. Each command remains exact and sequential per Harness; settling `turn.start` does not serialize the native work that it accepted. Each Turn writes its own sealed capture under the Thread/runtime layout in [Runtime Provenance](20260711-worker_runtime_subagent_provenance.md#2-runtime-provenance-capture). On a shared host, `session.close` detaches that conversation and leaves the server. On a dedicated host, `session.close` ends that host. Inspect distinguishes a surviving instance from a replacement or an unknown one. The next Turn on that AgentSession is not dispatched until Turn-end collection completes.

Exact replay is permitted only where the owning operation defines an idempotent identity and proves that the prior effect is the same; an uncertain `session.open`, `turn.start`, `turn.steer`, `turn.interrupt`, or `session.close` MUST NOT be retried as a new operation or redirected to a compatible AgentSession. Missing, stale, conflicting, unsupported, or dependency-failed input returns a typed refusal without fallback. A transport loss or a NanoCore restart adopts only an exact surviving binding and sequence under the NanoHost and AgentSession proof contracts. A binding that cannot be proved exactly is closed or fenced, and a successor resumes natively. Otherwise the Harness drains, cleanup widens as required, and later work begins through fresh NanoCore admission. A host restart invalidates the bindings it hosted. This version starts from a new data root and does not read earlier-version data, as [the engineer decided](../decisions/20260930-earlier_version_data_not_carried.md).

Failure of an AgentSession-local operation affects only that AgentSession when the Harness proves native context, child process, route, and file cleanup local. If that proof is absent, the Harness drains and the NanoHost owner fences the Harness, Sandbox, or Runtime Epoch boundary whose complete effect domain can be proved. No sibling result, terminal state, or successful cleanup is inferred.

Observable conformance requires AgentSessions for two distinct Threads to open through the fixed operations, two sequential Turns in each to receive distinct per-Turn packages and route credentials, a second current binding for one Thread to be rejected, an exact interrupt or close to target only its named AgentSession when local cleanup is proved, an unknown operation or executable field to cause zero Harness effect, and cleanup uncertainty to widen the fence before capacity returns.

### Live-Steer Operation Boundary

`turn.steer` is the private delivery projection of [Task live steer](20260704-task_mode_worker_delegation.md#live-steer), whose owner holds the public actors, Item, completed receipt, full lifecycle, failures, and acceptance predicates. Live steer is qualified for Codex 0.166.0 and Pi 1.4.0 against the Runtime qualification row in [Task live steer](20260704-task_mode_worker_delegation.md#observable-acceptance). OpenCode 2.2.5 and DeepSeek 0.2.1-rc.5 remain unsupported. The Task owner's public receipt retention and private slot-reuse fence still apply. The [Task Live-Steer Rulings](../decisions/20261008-task_live_steer_rulings.md) record why this operation is separate from interruption. It grants no authority, starts no Turn, changes no setup, and answers no Pending Request. Bounded `input` is typed user content and is never interpreted by the control boundary as an executable instruction or shell command.

Preconditions are the exact current Integration and Harness binding, AgentSession runtime binding, Workspace, Thread, running Turn, package snapshot, execution attempt carried as `leaseId`, and Turn sequence. `inputItemId` names the already durable ordinary user-message Item; `inputDigest` is SHA-256 of its exact UTF-8 text. NanoCore stores its reference in the queued operation and materializes that bounded text only at authenticated dispatch. The Harness requires the digest and exact active native-work correlation before invoking one qualified adapter mapping. Unknown fields, missing or stale lineage, unsupported required semantics, mismatched text identity, or unqualified support cause a typed refusal before native effect.

`state="accepted"` proves native admission for processing during the addressed active Turn, not model consumption, obedience, completion, or terminal proof. A write to the native pipe or Core receipt of text is insufficient. The adapter must supply exact native acceptance evidence under its own owner; an inability to prove the same-Turn boundary uses disposition `refused` with `reasonCode="unsupported"`, definite non-delivery is `refused`, and possible dispatch without proof is `unknown`. Native identifiers and bodies remain private. The shared result retains exact public Turn, input Item and digest correlation.

The existing per-Harness sequence, single unsettled slot, exact result replay, the Harness envelope's exact live non-receipt-proof exception with no blind effect re-execution, bounded control-call discipline, and cleanup widening apply. NanoCore persists the Task owner's public disposition before allowing the retained private result to be replaced; absence of that proof fences slot reuse. No additional queue, timer, control route, operation-result terminalization, or recovery runner is added. A slow or failed steer cannot wait for consumption or indefinitely occupy the slot, and qualification must prove the existing interrupt-delivery guarantee remains satisfied through bounded unknown/cleanup handling. Interrupt authorization winning before steer dispatch suppresses that dispatch; already-dispatched input retains its own truthful result separately from the Turn terminal. Terminal cleanup observes the retained steer result and public disposition ordering before another operation displaces it. Detailed race, revocation, restart, and successor-spill behavior remains with Task Mode.

### Interrupt Delivery Poll Cadence

Under pull-only delivery the dominant term in command-delivery latency is how long an enqueued command waits for the next poll, not transport time. The cadence is therefore a protocol requirement here rather than an implementation detail.

While a worker Turn is running and polling is not paused by a retryable outage, the private Harness interrupt poll MUST meet the 1000 ms start-to-start maximum only between polls while no command handling or result acknowledgement is in flight. Measure the interval at Sandbox Integration from the issue of one poll request to the issue of the next. An in-flight operation on any Harness delays the next poll up to that operation's existing request allowance. That poll is the only interrupt poll. The start-to-start anchor is normative because it is the only reading under which the cadence bounds an interrupt's wait: a delay measured from response receipt lets round-trip time silently extend the effective interval.

Within that cadence coverage, jitter MAY only reduce the interval. Positive jitter, adaptive backoff, or any scheme that can exceed the maximum is invalid, because the maximum is exactly half of the end-to-end interrupt-delivery bound and has no headroom above it.

That bound is owned by `docs/specs/20260802-nanohost_runtime_and_transport.md` and is measured from the committed product interrupt authorization and enqueue of private `turn.interrupt` to observation of the cancellation outcome; within that cadence coverage, the half not consumed by this cadence is what remains for transport under load. The transport owner MUST NOT raise its bound in a way that this cadence cannot satisfy, and this cadence MUST NOT be relaxed without that owner restating its bound.

A poll paused by a retryable outage does not violate the cadence; resumption restarts the interval. A paused interval still consumes the single bounded outage budget owned by the retry rules in Final Status, and the cadence creates no additional retry authority, no second poll stream, and no offline command queue.

The cadence governs only the private Harness interrupt poll. That poll has its exact separate body and never carries a heartbeat. The NanoHost adapter heartbeat interval owned by [Worker Runtime Communication Model](20260629-worker_runtime_communication_model.md#nanohost-adapter-liveness) is not this cadence. That interval is a maximum staleness bound, not a target rate: heartbeating more often than it is permitted and heartbeating less often than this cadence is permitted when decoupled.

If a backend push channel is ever added, it MUST deliver no slower than this cadence would, and it MUST return to this specification and the transport owner first, because pull-only delivery is what makes Sandbox Integration the transport client and a push path would invert that role assignment.

Private `turn.interrupt` reports the actual cancellation outcome. It returns `succeeded` when the Turn's work is cancelled, `refused` when the terminal owner already won, and `unknown` when the outcome cannot be proved. It does not require process-group absence of a resident shared server, and it does not close the AgentSession. No native graceful-yield hook, free-text inference, double signal, or operation-result terminal state is part of the contract. An interrupt whose purpose is not `interrupt` is rejected before any signal.

After the readiness exchange, a retryable outage pauses the private Harness interrupt poll and starting queued interrupts. Private Harness interrupt operations follow the Harness envelope's exact result replay and bounded live non-receipt-proof rules; a transport outage alone grants no command redelivery authority. The shim retains bounded raw replay data in memory for the current process and records only product-safe identity and digest evidence locally. An unknown repeated command or the same command or operation id with a different canonical payload fails closed; no general offline outbound queue is introduced.

A future supply refresh command may only be used when the resolved AEP declares support proved by the selected image and shared shim. V2 issues no live refresh request. No supply-refresh acknowledgement gates execution admission, and no stepped renewal remains. An incompatible supply change the adapter declares it will list at the next Turn does not replace the binding. A change it cannot list, or whose declaration is absent, is a successor AgentSession with native resume after the current Turn settles. Each adapter declares whether it re-lists tools, and its slice establishes the answer by probe; this specification does not invent that answer.

`shutdown`, `collect-and-stop`, and `health-check` remain future command families until they have a concrete protocol schema and implementation.

## Final Status

The shim must send one `final_status` for each Turn. That record is not coextensive with a process lifetime.

`final_status` uses `WorkerControlRequestEnvelopeSchema` in `packages/worker-protocol/src/index.ts`. Its producer body is `WorkerCanonicalTerminalEventDataEmissionSchema`. Its receiver body is `WorkerCanonicalTerminalEventDataReaderSchema`. `status` is `WorkerCanonicalTerminalStatusSchema`, listed once under [Canonical Enums](20261021-protocol_identifiers_and_enums.md#canonical-enums). `stopReason` stays a product-safe transport value. The final worker sequence is the control sequence. `evidenceManifestDigests` is an optional descriptive map, open for extension; empty means not reported. The admitted diagnostics contract is the optional `diagnostics` member of the emission artifact. Capability summary ids, audit summary ids, and an error summary are not members of that body. `capability_summary` owns capability summary ids. Audit summaries and error summaries stay with their own owners.

Manifest digests are Worker-reported description, never coverage, proof or acceptance. The two mandatory transcript/artifact digest requirements are retired by the [reserved audit ruling](../decisions/20261031-reserved_audit_question_rulings.md#decision). An omitted evidence-manifest digest map defaults to an empty map. No additional manifest producer is required.

NanoCore derives the canonical Core `StopReason` and Turn status through the Worker Turn Reliability Envelope after evidence collection; it does not rename the wire field or treat the transport value as product-state authority.

`final_status` is the worker's last durable-output barrier for that Turn. Before sending it, the shim MUST seal the terminal transcript and the runtime-provenance records it owns. It does not publish the workspace change set by an in-Sandbox capture. Workspace head, base, digest, and acceptance evidence are the separate `workspace.collect` result owned by [Workspace Synchronization](20260703-workspace_synchronization.md#snapshot-chain). After NanoCore accepts `final_status`, that shim MUST NOT publish more transcript, provenance, or artifact output for the Turn. The next Turn waits until the outside collection owned by [Workspace Synchronization](20260703-workspace_synchronization.md) completes.

Accepted `final_status` is necessary but insufficient for the Turn barrier. Process-group absence is not that gate: a resident host is still running at Turn end. The retained bootstrap monitor is a separate Sandbox-wide Harness-lifetime proof. It remains live across Turns and must observe exactly one correlated Exit followed by clean response completion only when the Harness ends. A per-Turn export MUST NOT wait for or consume that monitor. Missing or duplicate bootstrap-monitor Exit, unclean monitor completion, or monitor loss at Harness end follows the separate Sandbox-lifecycle failure contract. Response loss, relay or member loss, or ambiguous cleanup blocks the barrier and follows sandbox-delete and uncertain-delete epoch-fence truth. Closing or cancelling either interactive direction or either H2 connection is never termination proof.

NanoCore may accept `final_status` before it has collected all data-plane evidence. Acceptance means the worker has finished publishing its durable output, not that NanoCore has imported or approved it. The canonical turn cannot close until NanoCore has collected or intentionally marked missing required evidence.

After readiness and admission of the resident host, a lost `final_status` response is retried only with the same logical operation identity, sequence, canonical payload, and remaining shared outage budget. Budget expiry does not start a best-effort final-status grace period; the shim writes its local terminal record and lets durable recovery project the interrupted outcome. Budget expiry fails the affected Turn. It does not kill a shared host or its sibling bindings. Dedicated-host death ends that binding.

### Cancellation-Only First Final On Closing Lineage

A closing lineage may accept one first `final_status` only when Core's existing attempt owner records cancellation for that exact Turn and execution binding. The request must present the exact worker-control token and admitted Workspace, Thread, Turn, AgentSession, package, and attempt lineage. Its cancellation/interruption disposition, logical operation identity, final sequence, schema, and digests must satisfy the existing final-status and sequence checks. A completed or unrelated failure final is not admitted by this exception ([#179 ruling](../decisions/20261015-worker_failure_final_and_chat_call_rulings.md)).

An ordinary event-append refusal on that cancellation-closing lineage does not consume the final operation or revoke its exact worker-control binding solely because the lineage is closing. It grants no inference, capability, event, Artifact, or other output admission. Explicit revocation, fencing, wrong binding/token, deadline expiry, and contradictory cancellation evidence still fail closed.

Before this first final, the shim seals its local terminal transcript and owned provenance under the ordinary final barrier. Acceptance atomically records the existing final identity and fingerprint, seals remote output admission, and permits only exact replay thereafter. A changed sequence, payload, token, operation, or lineage cannot become a second final. Reconnect and restart recover that disposition through existing attempt/control records; they do not reset the one-time exception. This adds no terminal state, credential family, record, or recovery loop.

Acceptance covers cancellation with a refused ordinary append followed by the one valid first final, exact duplicate replay, restart after acceptance, and changed-payload/sequence conflict. It rejects non-cancellation closing, completed finals, stale or wrong tokens/bindings, fenced or revoked attempts, and any new output after sealing. Final acceptance still proves neither cleanup nor canonical Turn completion.

## End-To-End Control And Evidence Collection

The protocol supports end-to-end live append plus turn-end collection from the exact admitted `/openkit/threads/<threadId>/<harness>/capture/<turnId>/*.jsonl` capture. Transcript collection is evidence and deduplication input, not a fallback control mode. Control is fail-fast until the complete readiness exchange succeeds and the resident host is admitted. After that admission, a retryable route outage enters one shared five-minute monotonic outage budget. The worker-control client inside Sandbox Integration keeps the resident host alive, pauses new private Harness polling, and retries only the same immutable logical request every 250 ms within that budget. The Integration outer adapter, NanoHost transport, and other route families do not replay it. Exponential backoff, jitter, and `Retry-After` handling are not part of this contract. The outage budget fails the affected Turn. It does not kill a shared host or its sibling bindings. Dedicated-host death ends that binding.

A NanoCore restart or a short network loss does not cancel a locally accepted OpenShell operation and does not recreate the Sandbox. When the NanoHost transport returns, a successor connection first fences its predecessor, then worker control continues the same AgentSession, attempt, package snapshot, backend session, process key, and exact next sequence. A binding that cannot be proved exactly is closed or fenced, and a successor resumes natively. A late predecessor message is rejected and cannot advance control state.

HTTP 408, 425, 429, 500-599, request timeout, connection refusal/reset, broken pipe, temporary DNS, and temporary TLS/socket failures are retryable after readiness. Schema failure, 401, 403, 404, 409, 413, 422, any other non-retryable 4xx, invalid 2xx JSON, and an invalid success envelope are terminal authority or contract failures and stop the children immediately. String matching is not a normal classifier.

Local transcript append and remote live delivery are separate queues. A remote outage MUST NOT poison local append or prevent one terminal record from being sealed. Exact raw terminal output needed for a same-process retry may remain bounded in shim memory; the durable transcript stores only operation identity, canonical digest, and product-safe summary. Shim restart remains non-recoverable.

## Outage Tolerance Is Two Separate Guarantees

The bounded outage budget above is a worker-control guarantee and nothing more. It is routinely read as "a NanoCore outage does not disturb a running worker", which is false, and the two guarantees that actually exist have different values and must be stated separately.

**Control-plane tolerance** is the single bounded outage budget: a worker survives a NanoCore outage shorter than that budget without losing its attempt, its sequence, or its process, and the execution runtime keeps its local state and its worker process alive for the duration.

**Inference availability during a NanoCore outage is zero.** Inference is routed through NanoCore to the provider, so a NanoCore outage of any duration makes `/inference/*` unavailable for exactly that duration. A worker that needs a model call during the outage stalls; it does not continue. "Local execution survives" therefore means the process, attempt, and sequence survive, not that the agent makes progress.

Neither guarantee may be widened by moving authority downward. The execution runtime MUST NOT open a direct provider path, substitute a provider, serve a cached inference response, or otherwise make an inference effect happen while NanoCore is unreachable, because provider selection, policy, usage attribution, and audit are NanoCore-owned and an unattributed effect is worse than a stalled one.

A worker that exhausts its budget fails through the existing owners. The runtime MUST NOT extend the budget or the attempt deadline to conceal an outage; the attempt's submit-time absolute deadline is immutable, and the NanoHost adapter's existing outage and liveness rules remain additional bounds.

NanoCore verifies:

- token
- lineage
- package snapshot id
- message schema
- worker sequence
- idempotency key or sequence fingerprint
- payload digest when provided
- artifact and workspace path boundaries

## Durable Worker-Control State

Every Core-mediated worker-control, inference, and capability route validates its exact attempt, credential family, current policy, explicit revocation, and absolute submit-time deadline. The [NanoHost adapter liveness rule](20260629-worker_runtime_communication_model.md#nanohost-adapter-liveness) additionally retains startup and heartbeat refusal, stale needs-evidence exclusion, exact duplicate non-renewal, and route refusal until exact process-key adoption. That rule is adapter policy, not generic scheduler liveness authority.

A product-safe active-AgentSession control summary resolves through the exact persisted AEP snapshot and complete current lineage. Absent live state or incomplete lineage yields no summary. The read borrows neither an older package nor an AgentSession-only lookup. The projection is not a new state owner, and a general gateway helper stays available to consumers that can use it.

Worker-control state MUST survive NanoCore restart. Process-local gateway state is a bootstrapping projection only; the durable contract is:

- Token bindings are resolved through the durable execution attempt records owned by `docs/specs/20260703-durable_scheduler_design.md`. That existing owner stores exactly three nullable lowercase SHA-256 projections, one each for the worker-control, inference, and capability tokens, and never a raw value. A family authenticator hashes the presented token and compares it to the exact current open attempt/lineage binding; adapter-stale or fenced lineage, and closed lineage outside exact accepted `final_status` replay, fails authentication and revokes all three through the existing attempt status owner. A `closing` lineage admits only [the cancellation-only first final](#cancellation-only-first-final-on-closing-lineage) or exact accepted `final_status` replay; refusal of an ordinary append solely for that cancellation-closing state must not revoke the final binding. This discharges restart durability through the scheduler's records instead of a parallel credential store.
- The accepted-event high-watermark (last accepted worker sequence and its fingerprint) is durably recorded per AgentSession and package snapshot, so duplicate replay idempotency, stale-sequence rejection, and same-sequence conflict rejection hold across NanoCore restarts, not only within one process run.
- Accepted artifact notices are durable rows; heartbeat state is not separately persisted because the NanoHost adapter's existing heartbeat observations associated with the exact attempt own liveness truth.
- On restart, the worker-control, inference, and capability gateways rebuild their family-specific serving state from the three attempt-owned token hashes, current AEP and lineage, and high-watermark rows during the boot phase defined by `docs/specs/20260704-nanocore_bootstrap_readiness.md`. The surviving NanoHost and exact AgentSession-local route boundary retain the same raw values, so successor carriage performs no token reissuance, Harness Start, Sandbox or AgentSession creation, or already-current bridge open. A request whose attempt cannot be found or re-adopted is untracked execution and MUST be refused under the scheduler's exact ownership and cleanup rules.
- An open attempt with adapter-owned `awaiting-reconnect` may use only one exact-next heartbeat carrying its memory-only process key. Every other operation remains unauthorized until adoption commits. An adopted session immediately regains ordinary control even when another attempt remains pending.
- After adoption commits, replay of the exact same sequence and fingerprint is ordinary idempotent success; rollback, gap, wrong-key replay, or same-sequence payload conflict is terminal.
- Interrupt settlement and replay use the private Harness result owner in Harness Pull And Result Envelopes. Integration retains only the current or immediately settled operation for each declared Harness, and exact result replay under that contract is idempotent.

### Adapter Identity Is Part Of Verification

A candidate record is shaped inside the sandbox by the runtime adapter, which is the least-trusted component in the path. NanoCore MUST therefore verify the exact adapter identity named by the resolved package snapshot alongside lineage, sequence, schema, and digest, and MUST reject a candidate whose adapter identity does not match. The candidate's own claim about its adapter is not evidence; the package snapshot is.

The three-job separation this realizes — carriage, normalization, acceptance — is owned by `docs/specs/20260629-worker_runtime_communication_model.md` under the Core substrate doctrine in `docs/core/runtime-model.md`. This specification adds only the verification obligation on the operations it owns.

### Exact-Value Protection At Transcript Item Admission

Before creating an Item from worker transcript content, NanoCore MUST apply the shared exact injected-value comparison rule owned by [Worker Runtime Communication Model](20260629-worker_runtime_communication_model.md#workspace-and-artifact-plane-projections), including that owner's distinct route-token and loopback hash domains and permitted restart reconstruction. Each matched byte range MUST be replaced with the fixed marker `[redacted]` before canonical creation. A match still creates the Item and does not reject the reply. Overlapping matches MUST leave none of the matched bytes in the admitted text.

The covered Item fields are the `assistant-message` body, supplied as `text` or assembled by concatenating its text `parts`, and the `artifact-reference` title derived from a worker Artifact declaration. When `text` is present it is the admitted body; otherwise all text parts are concatenated before checking, so a value split across parts is caught. The Artifact reference MUST mirror the guarded canonical Artifact title rather than retaining a second unguarded copy. Tool-call arguments and results are not accepted transcript Item kinds and gain no new admission path through this rule. NanoCore owns the resulting canonical Items; worker files remain candidates. Matched original bytes and comparison values MUST NOT be persisted or logged by canonical admission. This is exact-value protection, not generic DLP: credential-looking strings outside the injected set remain unchanged, and encoded, transformed, derived, or non-literal material is outside this check. The decision and reason are recorded in [Transcript Item Exact-Value Guard](../decisions/20261005-transcript_item_exact_value_guard.md).

The check runs before any transcript Item write, including restart closeout and exact replay, using complete evidence for the original materialization under the communication model's reconstruction and association rule; current-value substitution and skipped checks are forbidden. Only genuinely unavailable or contradictory required evidence after that permitted reconstruction makes transcript import return `recovery_required` with product-safe diagnostics and zero transcript Item, Artifact, or Review writes, after the existing backend cleanup lifecycle. It MUST NOT silently publish unchecked text. Recovery follows the existing closeout and replay owners once the exact comparison evidence is available; this rule adds no durable record, automatic retry, update lifecycle, or termination lifecycle. Acceptance is an Item containing the fixed marker and no matched value, an unchanged body when no exact match exists, or the zero-write recovery result when evidence is unavailable.

## Relationship To Agent Capability

Capability calls do not flow through the control plane.

The control plane may carry `capability_summary` notifications so NanoCore can update liveness or progress displays, but the authoritative capability call record belongs to Agent Capability.

Only `event_append` may create item-visible progress by default, and only after NanoCore validates and commits the candidate event record. Heartbeats, artifact notices, final status, and capability summaries are control records until NanoCore explicitly imports or projects them into product state.

## Relationship To Data Plane

The data plane moves:

- artifacts
- workspace snapshots
- patches
- changed-file manifests
- raw transcripts
- raw logs
- backend evidence

The control plane only announces readiness, digests, and collection hints.

## Incremental Work Observations

Native content uses the single `native-content-v1` codec. It fixes RFC 8785 interpretation for canonical JSON content without converting native transcript or log bytes into JSON. `native-transcript` and `runtime-log` are truthful fact kinds, not additional coverage families; actual log source classes are `stderr` and `stdout-log`, never protocol/RPC stdout. Native bodies admit `application/octet-stream` as well as the existing text and JSON media. Source facts retain actual harness and separately authored/measured version identities, admitted image/source, pre-launch watermark, source/Turn association, native ranges, measured observed and retained counts, nullable unknown omissions and observed end/coverage. Existing origin/source/sequence and byte identity members are reused; transport chunk offsets do not become native source offsets. Unknown codec/core values or inconsistent ranges/counts fail closed. Metadata alone never proves native collection or completion.

For native expected content, the existing `content.boundary` member is exactly `native-content-v1`; do not add another codec/version tag. Native facts reuse `coverage` and its existing `reason` domain. Their required `native` object has the following source facts; none supplies execution or Policy authority. Source and origin association remain the existing outer `sourceRef`, `sourceSequence`, `runtimeOriginRef` and authenticated event lineage, not copied owner IDs.

| Native member | Meaning |
| --- | --- |
| `harness` | Actual native harness kind, checked against the named AEP's `agent.runtimeKind`. |
| `authoredVersion` | The exact author label from that AEP's `agent.runtimeVersion`, not measured-version proof. |
| `measuredVersion` | Independently observed native binary version string, or explicit `null` when unknown. |
| `imageDigest` | Worker-reported digest, or explicit `null` when unknown. Core compares a non-null claim with the existing unique NanoHost backend binding for the exact Workspace/Thread/Turn/AgentSession/package: the immutable reference digest or NanoHost build-result digest. With no unique bound digest, the claim remains unverified descriptive data, never authority, and is not refused on that claim alone. A tag or author label cannot become a measured digest. |
| `format` | Actual source's native format name, or `null` when unobserved; not a normalized message schema or another version taxonomy. |
| `preLaunchWatermark` | Measured native source byte position before launch, or `null` when unobserved; it is not a control-plane high-watermark. |
| `range` | `{start,end}` half-open native byte interval for this unit, or `null` with no retained bytes; safe nonnegative integers, end not before start and start not before a known watermark. |
| `observedBytes`, `retainedBytes` | Measured byte counts for this source unit; observed bytes may be `null` when unmeasured. Retained bytes equal the interval length and cannot exceed known observed bytes. Expected content requires known format, watermark, interval and observed count, and body length equals retained bytes. Publication, not these producer counts, proves Core adoption. |
| `omittedBytes` | Measured omitted bytes, or explicit `null` when unmeasured. A known value cannot exceed observed bytes minus retained bytes; do not infer it from an incomplete source. |
| `sourceEnded` | Whether this source's end was actually observed; it does not prove Turn completion, remote stop or complete retention. |
| `logSource` | Required only for `runtime-log`: exactly `stderr` or `stdout-log`. It is absent for `native-transcript`; protocol/RPC stdout is not a log source. |

Core cites the selected bound through its existing AEP association reference (`kind: aep-snapshot`, same authenticated snapshot ID and Workspace). The Worker supplies no new budget reference or grant. An admitted AEP contains the selected numeric `observability.evidence.nativeLogMaxBytes`; source facts cite that immutable record, never duplicate its authority.

`policy.workDataCapture.nativeLogMaxBytes` is a positive safe integer with a combined 16 MiB per-Turn default for native logs. NanoCore selects it once into `observability.evidence.nativeLogMaxBytes` when admitting the AEP. Native log admission reads the exact authenticated named snapshot and existing retained source/publication facts; it does not reread live policy, add a Turn budget or duplicate that value in `captureCoverage`. Missing or invalid historical native authority refuses native content rather than guessing a bound. All sources and packages in the Turn share the same allowance; exact replay cannot recharge it and another package cannot renew it. Transcripts are not charged to the log budget. OFF retains required structure without bytes, and absent source, silence, collector failure and truncation stay distinct. The receiver preserves current byte limits, publication/receipt boundaries and anchored gaps, without a counter table, new writer or cross-domain atomicity. This prerequisite enables no native producer, runtime capability or default; existing ON/OFF bindings and defaults remain unchanged.

The existing canonical event append accepts strict observation.recorded metadata and observation.content.chunk records under its existing outer lineage, revocation, sequence and replay checks. AEP projects the admitted Turn capture binding. Metadata is an observation-family fact, never an Item or child execution command. Chunks are canonical base64 with a maximum 48 KiB decoded length and validated index/offset; complete body length and digest are verified before publication. Metadata declares expected content first; each chunk ACK proves restricted staging, and a separate publication observation follows durable complete-body adoption. An unavailability record for already-declared content carries its exact expected observation identity; Core validates the earlier expected record within the same authenticated package and resolves that identity to the observation parent. A call reference alone is not an anchor because arguments, results and multiple events may share it. Receipt/fingerprint state contains only safe descriptors and digests, never content bytes. The acceptance/replay path must reconcile an interrupted publication before reporting its success. Full body admission, exclusions and failures follow 20260921-work_data_retention_format.md; there is no second transport, execution high-watermark or child-management API.

## Acceptance

Cadence qualification runs under saturating permitted inference load during an active Turn and includes the existing end-to-end interrupt bound. One Sandbox holds at least two compatibility-distinct Harnesses, each with an independent private control handle and a Thread-retained root. Transport-loss adoption and Core-restart adoption and fencing both reuse the scheduler's deterministic NanoCore kill and restart scenario. No second recovery runner is added.
