# Server-Shared MCP Administration

## Intent Revision 1

Source: L-GA P22, recommended #203 Server Vault authority and shared projection, and the engineer's explicit vertical ownership ruling on 2026-10-16. Extend the existing catalog owner to Server scope additively, preserving retained Workspace data, behavior and digests. Deliver current-administrator Server MCP lifecycle, restricted shared-MCP Vault references/grants and exact Gateway cross-scope checks with fake-upstream proof. Put Server administration, Vault and Gateway integration in their existing modules and keep catalog edits minimal. Add no second catalog, credential store, runtime, maintenance runner, Server process-data directory or cross-store transaction.

## Owners And Accepted Route

[MCP Catalog Management](../../specs/20260907-mcp_catalog_management.md#server-scope-and-workspace-projection) owns explicit scope, additive normalization, lifecycle, collision/disablement and command receipt recovery. [Worker MCP Tool Supply](../../specs/20260704-worker_mcp_tool_supply.md#shared-server-origin-and-vault-use) owns current canonical origin, exact effect checks and consuming-Workspace connections. [Vault Backend Implementation](../../specs/20260704-vault_backend_implementation.md#server-shared-mcp-secret-administration) and [Vault Secret Injection](../../specs/20260703-vault_secret_injection.md#server-shared-mcp-projection) own restricted Server references, existing grant lifecycle and cross-scope evidence. [Storage Layout](../../specs/20260703-storage_layout_record_ownership.md#installed-agent-resource-storage) already defines one catalog file per Server or Workspace scope and Workspace-only mutable MCP data.

An independent Astra Consultant inspected source intent, actual owners and current code and returned Continue. Omitted scope is legacy Workspace meaning only under its trusted Workspace path; new CAS writes make it explicit without read-side mutation. Server reads require explicit Server scope. Any local entry, including a tombstone, suppresses a colliding shared id so disabling local supply cannot silently activate shared credentials. The Workspace catalog owns exact disabled Server ids. Re-derive current origin and canonical binding before credential resolution and dispatch, including after asynchronous discovery; failed runtime reload cannot retain revoked canonical catalog authority. Keep Workspace effective digests unchanged and bind Server origin only into shared-entry digests. Sessions and process data remain partitioned by consuming Workspace with distinct stable binding keys.

Restrict Server secret management to the shared-MCP reference classification, excluding Provider, subscription and bootstrap lifecycles. Server VaultUse belongs to Core with null Workspace ownership; linked Audit retains consuming Workspace, actor and call. Reuse the command ledger and existing append-only Audit unknown fence; an absent receipt never permits inferred success or redispatch. Replay reads the identified current resource and immutable version where applicable, not an old mutable state or reload result. No Admin Thread or Artifact is created merely to carry a receipt.
