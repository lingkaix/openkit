# Owned Internal Agent Runtime And Resource Integration

## Intent Epoch 1

Source: the engineer's 2026-09-09 request accepts retaining OpenKit's own minimal internal Agent Runtime, requests continued Pi Agent Core research and implementation-ready MCP, Skill and Generative UI design, requires the primary to write documents, and authorizes an independent Claude Code consultant plus independent reviewers and auditors. Architectural clarity, clean boundaries, maintainability and reliable agent operation decide; development workload and cost do not. Commit all pre-existing changes, including the engineer's sub-agent model edits, before beginning. Product Vision and production implementation are excluded.

## Intent Epoch 2

Source: the engineer's follow-up during design review clarifies that the internal runtime must not become a full-feature heavy Worker harness. Its purpose is OpenKit's own internal capabilities: primarily Generative Kernel/UI, later channel information reads/writes such as Slack, WhatsApp and Email, Skill-guided creation or modification of Skills, and basic retrieval/reads of existing NanoCore Artifacts or configuration. The earlier broad external-Tool selection design must therefore be narrowed to owned internal capability contracts. MCP is an implementation transport, not permission to expose arbitrary server functions. Reading a Skill does not authorize shell execution, workspace manipulation or unrestricted file access. This appends scope clarification without changing the accepted owned-runtime direction or authorizing production implementation.
