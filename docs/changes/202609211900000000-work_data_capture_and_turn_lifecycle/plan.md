## Work Items

These items are not a schedule, queue, or package sequence. Each names a change, the owner that must decide it, and what is still missing before implementation may start.

### 1. Turn terminal publication boundary

After a Turn is terminal, `updateTurn`, `createItem`, and `emitTurnEvent` admit only completion of an already-decided publication: the write is admitted when it carries the same identity and the same content as the decision already recorded, and time since terminalization is not the test. Two different behaviours hide under that description and must not be merged: exact repair of an already-decided publication, which worker transcript replay at `apps/nanocore/src/runtime/worker-transcript.ts:247-254` enforces by deep equality; and a named field-limited display refresh, which `apps/nanocore/src/mode-entry-routes.ts:269-280` performs by returning the Item unchanged when `level`, `title` and `summary` match and updating only those three fields when they differ. A single shared predicate would break one of them. The three guards are one rule applied three times. The existing shape is the presence-keyed idempotent repair at `apps/nanocore/src/runtime/worker-turn-failure.ts:115-152`. A sweep of ten call sites established that a blanket "no writes after terminal" rule would break legitimate paths that must be named here rather than left as a count: `terminalizeGovernedWorkerTurn` emitting its own terminal event and performing idempotent repair; the MCP boot backfill of missing Items; approval-projection repair; and the Task-to-Goal explanation Item. A fifth case, configuration apply, is coupled to the delayed-user-input rebinding line and MUST be resolved with that owner before any guard that would reject its present behaviour is enabled. The admitted exception therefore has to state, per path, what an identical outcome, a missing outcome and a conflicting outcome each do, and whether the rule covers events as well as Items; "judged by identity" alone is a slogan that has already been implemented wrongly once. [`docs/core/protocol.md`](../../core/protocol.md) owns terminal immutability and "MUST NOT be reopened or rewritten"; it does not yet state the identity-keyed publication exception. Missing before start: that exception admitted by the Turn-lifecycle owner, plus a focused regression covering legitimate post-terminal completion of already-decided publication versus rejected new writes.

### 2. Goal revision failure handling

The engineer ruled that a planner failure during plan revision preserves the scene and lets the user decide, keeping the Goal alive so work can continue on the same goal path. `reviseGoalPlan` currently sets the Goal to `planning` with a null `planItemId` (`apps/nanocore/src/runtime/goal-plan-approval.ts:292-299`), and `goal.plan` admits exactly that state (`apps/nanocore/src/goal-routes.ts:3162`), so after a failure the user can retry planning but cannot approve the old plan or issue a fresh revision instruction. [`docs/specs/20260704-goal_mode_coordination.md`](../../specs/20260704-goal_mode_coordination.md) owns Goal admission, plan approval, and the active-plan pointer. Missing before start: a coherent Goal admission and active-plan-pointer transition under that owner, plus a focused regression covering revise, planner failure, fresh planning retry, fresh revision instruction, and old-plan approval.

### 3. Measured harness identity

Stop treating the authored `runtimeVersion` on the Agent Environment Package as a measured harness version. Reference the measured `sandbox_runtime_records.image_digest` instead, captured at binding time for both new and reused bindings, because the row is deleted on cleanup. [`docs/specs/20260616-agent_environment_package.md`](../../specs/20260616-agent_environment_package.md) owns the authored package; [`docs/specs/20260802-nanohost_runtime_and_transport.md`](../../specs/20260802-nanohost_runtime_and_transport.md) owns sandbox runtime records and binding. Missing before start: those owners stating that measured harness identity is the binding-time digest rather than authored `runtimeVersion`, and capture on both new and reused bindings.

### 4. System prompt digest capture

Declare one semantic boundary — the prompt before adapter conversion — and account for the actual conversion paths rather than promising a single existing hook: Chat calls reach it through one converter while Codex and bridged Responses reach it through another (`apps/nanocore/src/llm/pi-ai-client.ts:284-300`). The grouping is not injective: an absent prompt and an explicit default literal produce different pre-adapter digests and identical outgoing instructions. [`docs/specs/20260921-work_data_retention_format.md`](../../specs/20260921-work_data_retention_format.md) owns the slot this digest occupies and the semantic boundary it must be taken at, and requires the slot to exist even when no producer does. What is still missing is the producer and its owner: no accepted owner states who computes the digest, on which conversion paths, and how the non-injective grouping is reported. The LLM conversion paths are implementation fact under the existing pi-ai client. Missing before start: an accepted owner for the producer, without requiring a single hook.

### 5. Coverage binding

The resolved effective retention setting is fixed at Turn admission and written into `turn.json`, which is already rewritten on every persist, so this adds no new file. A setting change takes effect at the next Turn; an already-started Turn is never interrupted. The switch defaults to off. [`docs/core/protocol.md`](../../core/protocol.md) owns Turn admission and when the effective setting is fixed; [`docs/specs/20260703-storage_layout_record_ownership.md`](../../specs/20260703-storage_layout_record_ownership.md) owns what `turn.json` carries. The engineer decided the binding point, the next-Turn effect and the default-off switch; [`docs/specs/20260921-work_data_retention_format.md`](../../specs/20260921-work_data_retention_format.md) holds the contract. Missing before start: the admission-time field on `turn.json` and the default-off switch under those owners, without a mid-Turn interrupt path.

### 6. Turn terminal predicates derived from one named set

Now that `cancelled` is a live Turn terminal in both the schema and production, the predicates that ask "is this Turn finished" are split. The waiter defect half is done: `isTerminalTurnStatus` at `apps/nanocore/src/goal-routes.ts:2326-2333` answers `completed`, `failed`, `interrupted`, `cancelled`, or `awaiting_human`, which is the settled-for-waiters set in [`docs/core/protocol.md`](../../core/protocol.md) (`:204-207`; terminal list `:191-196`). `waitForWorkerTurnTerminalState` (`:2269`, used at `:3972`) therefore settles a cancelled Turn instead of waiting out `WORKER_TURN_AWAIT_TIMEOUT_MS` (`:2259`). That restoration is what protocol already decided, so it needed no new owner under `[AUTH-001]`. `apps/nanocore/src/goal-worker-turn-wait.test.ts` is the regression: it covers the already-cancelled Turn, a Turn cancelled while the waiter is subscribed, and a still-running Turn that must not settle. Named execution output with the fix reverted: tests 1 and 2 fail with `expected Symbol(still-waiting) not to be Symbol(still-waiting)` and test 3 passes; with the fix applied all three pass, and `src/goal-plan-read.test.ts`, `src/goal-steering-authority.test.ts` and `src/thread-goal-summary.test.ts` run 53 tests with 0 failures alongside it. A second function of the same name at `apps/nanocore/src/runtime/worker-turn-failure.ts:319` answers `completed`, `failed`, `interrupted` or `cancelled` and omits `awaiting_human`, so the two same-named predicates still disagree; that is the refactor half, still blocked. The design the discussion settled on is four named sets rather than one: the sealed terminals `completed | interrupted | cancelled | failed`; settled-for-waiters, which adds `awaiting_human` because that state does not advance on its own but can still be moved by an outside actor and therefore must not be read as "the system guarantees no further writes"; checkpoint-collectable, which removes `interrupted` because the recovery path may still own those Turns; and recovery-rewritable, which is only `pending | running`. Deriving remaining predicates from the named set is the refactor. The derivation must be mechanically enforced: adding a value to `TurnStatusSchema` today fails nothing, because `['a','b'].includes(status)`, `new Set<Turn['status']>([...])` (the present shape at `apps/nanocore/src/app-dashboard.ts:38-39`) and `as const satisfies readonly TurnStatus[]` all accept a missing value silently. Only an exhaustive `Record<TurnStatus, …>` or a `switch` with a `never` default fails compilation. Product-side predicates that are allowed to differ from the sealed set must either import it or declare the difference explicitly and list it; the sites to reconcile include `apps/nanocore/src/runtime/stop-after-turn.ts`, `apps/web/src/screens/chat/ThreadStream.tsx` and `apps/web/src/screens/chat/ThreadScreen.tsx`. Missing before start of the refactor half: an accepted statement of where the single derivation lives and which product projections may diverge.
