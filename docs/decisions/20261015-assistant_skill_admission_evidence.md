# Assistant Skill Admission Evidence

## Decision

Use Route B for the selected-Skills family: canonical `env.bound.payload.assistantSkillAdmission` in the existing Core observation. The Work Data Retention Format owner defines its minimal tuple, collection boundary, immutable publication and retention. Resource Integration defines assembly from that same fixed selection before model dispatch. Work Observation Portability preserves source admission metadata without turning it into a target selection or authority.

The field is optional for retained observations and other internal-agent observations. The new command-initiated #144 producer requires it before model dispatch, including explicit empty selection. Absence does not mean empty selection. Keep Worker AEP, pending-outcome continuation and standalone Quick Chat boundaries unchanged. No envelope exception, additional evidence owner, public projection field, backfill, retained-row migration, reset or new lifecycle is accepted.

## Reason

Source: the coordinator's 2026-10-15 20:06Z admission-evidence entry in later-routing.md and independent Astra Consultant 5db1f92a's AGREED WITH CONDITIONS verdict in consultant-144-evidence.md, both in the backlog-20261015 working record. The coordinator accepted Route B with all eleven conditions. Conditions 2 through 5 supply the exact owner text; the remaining conditions assign implementation, tests and integration. This accepts bounded owner placement under the delegated first-resource-family decision; it does not accept implementation.

Core already owns internal-agent environment evidence because those agents have no Worker AEP. Retaining admission with the prompt and Tool digests proves the fixed selection before the first model dispatch, including runs that never read a Skill. The tuple contains historical configuration identity rather than content or authority. Its nested collection belongs to that observation and is not a separately persisted selection array. Import must distinguish historical source metadata from live Workspace catalog selectors.

## Rejected Alternatives

- Optional `ext` as the sole evidence would contradict the required product decision and envelope contract.
- A later capability call cannot prove the complete selection before model dispatch or when no Skill is read.
- Worker AEP does not own an internal Assistant's environment.
- A persisted prompt or separate selection record would duplicate the existing evidence owner.
- Bare-ID catalog resolution on import would confuse source history with target authority.

## Revisit When

Return for a governing decision before making optional extensions the sole required evidence, granting imported tuples execution authority, adding a store or lifecycle, or broadening admission. Keep the complete #144 delivery unit held for integrated acceptance, including P04 capture as a prerequisite. Module completion does not prove family acceptance.
