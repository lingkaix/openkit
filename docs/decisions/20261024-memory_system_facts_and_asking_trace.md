# Memory System Facts And Asking Trace

## Decision

Normalize generated tell lifecycle and Core clock facts before the exact candidate and Review digest are frozen. New tell pages are active/stable; existing pages retain lifecycle and creation time. Only actual normalized content changes update the content clock. Keep native review attribution and publish only through the existing exact approval or delegation.

Admit the actual trusted private asking Thread's retrieval evidence when no asking Turn exists. Preserve exact scope, actor, source, audience and current-access checks, and keep the bounded loop failure code. Add only a finite eligibility sub-reason from existing predicates.

## Reason

Accepted DIAG-KM16 reproduced two separate failures: an exactly accepted generated fact remained draft and was excluded by state, while legitimate thread-scoped query evidence was refused by a turn-only compaction inventory. Core already owns review attribution; the diagnosis did not establish model self-approval. Model-authored clocks are not Core event facts. An empty retrieval must still permit an honest uncertainty answer.

## Rejected Alternatives

- Promote or change clocks at acceptance: the user reviewed different frozen bytes.
- Rely on prompt compliance: system lifecycle and clocks remain dependent on model output.
- Promote every accepted draft: deliberate existing or non-tell drafts remain legitimate.
- Omit evidence checks or use the Knowledge Manager Turn as asker: either widens authority or invents lineage.
- Add a new trace family, retry or budget: existing owners already represent the legitimate query.

## Revisit When

An accepted Memory lifecycle or review change needs different native intent. Retained candidates remain exact; this decision grants no repair of old reviewed bytes.
