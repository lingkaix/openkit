# Explicit Task Delegation

## Decision

Direct `task.start` and an authorized explicit Assistant Task handoff select bounded delegation. A structurally valid nonempty instruction authorizes one bounded worker attempt. Natural-language vocabulary, question form, or inferred size does not veto that mode. Core retains every structural, authorization, eligibility, capability, readiness, identity, replay, scheduler, safety, and recovery check. Task selection grants no governed effect and creates no Goal from prompt keywords. Existing Task-to-Goal receipts remain readable and replay without recreating a Goal. Ordinary undecided Chat keeps conversational classification.

The mode service supplies trusted entry intent from the operation or accepted handoff. Explicit delegation uses the deterministic Coordinator only to select eligible supply and compose the exact request. The worker interprets the instruction and may raise a pending user-input request. No semantic preflight service, durable record, provider pass, or compatibility path is added.

Source: the coordinator's engineer queue entry "Explicit Task selection authorizes one bounded worker attempt", dated 2026-10-04, and the Consultant report `temp/interface-unification/reports/task-delegation-consult/consult-report.md`. ## Reason

The Round 21 instruction "Read issue 110 of lingkaix/openkit with the github MCP tools and reply with its title." was refused as quick Chat before worker selection. Explicit mode selection already expresses authority for a bounded attempt. A language heuristic cannot reliably establish that authority from vocabulary. The Consultant's forty-instruction differential probe rejected a verb-list expansion because it still missed equivalent requests and newly admitted negations, narration, and quoted examples in ordinary Chat.

The accepted price is that an explicit Task saying only "Help." may spend one bounded worker Turn and return clarification instead of immediate refusal. The worker's interpretation does not widen effect authorization.

## Rejected Alternatives

- Expand the keyword lists. The observed expansion missed equivalent retrieval instructions and changed ordinary Chat negative controls.
- Retain semantic pre-admission refusal and repair bounded retrieval recognition. This retains recurring language-recognition costs and the redundant semantic veto despite an explicit mode choice.
- Add a model-backed Task preflight Coordinator. It adds provider availability, latency, usage, and failure handling without a demonstrated need.
- Make all conversation explicit Task delegation. Ordinary Chat has a separate semantic routing boundary and must retain its current behavior in this change.

## Revisit When

The engineer decides that spending a bounded worker Turn on clarification is unacceptable; restore the pre-admission clarification rule. A proposed implementation requiring a new semantic preflight service, durable record, or weakened effect control leaves this decision and requires renewed scrutiny.
