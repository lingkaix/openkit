# Issues Track Remaining Work

## Decision

Keep the Product Vision as the statement of direction. Track remaining work in GitHub issues and remove the separate roadmap document. Each deferred Web projection links to the open issue for its delivery. Core and accepted specifications continue to define product behavior and its acceptance criteria.

## Reason

The roadmap had fallen behind the released product. An issue gives each gap one place to record its scope, evidence and release target.

## Rejected Alternatives

A second release queue in a repository document would require maintainers to reconcile two lists on every release.

## Revisit When

Revisit the need for a separate document if issues can no longer communicate the remaining work against the Product Vision.

## Affected Owners

- [Documentation Model](../documentation-model.md) defines the intent documents.
- [Web Product Surface Projection](../specs/20260628-web_product_surface_projection.md) defines how an unpublished operation identifies its remaining work.
