# Shared Worker Image Build

This directory owns the published `worker-common` base and the build of the one deployment image. Today's Dockerfile still exposes three leaf targets. The accepted design replaces them with the deployment target `worker-runtimes`.

Today's `Dockerfile` still exposes the published target `worker-common` and the final targets `worker-codex`, `worker-opencode`, and `worker-pi`. The accepted design replaces those three leaves with one deployment target `worker-runtimes`. The common stage installs the generic OpenKit worker shim, Node.js and immutable Python development toolchains, mise, source-control and build tools, editors, and network diagnostics; its declared runtime set is empty, it contains no Codex, OpenCode, Pi, DeepSeek, or `pi-mcp-adapter`, and it contains no credential or baked OpenShell policy. The accepted deployment target's Pi supply is the built SDK host and patched native MCP/tool-search production dependency closure owned by [Worker Execution Environment Images](../../docs/specs/20260721-worker_execution_environment_images.md); it does not install `pi-mcp-adapter`. The common stage declares inherited `/workspace` and `/sandbox` OCI volumes, runs as numeric `1000:1000`, uses the writable ephemeral `/tmp/openkit-bootstrap` OCI WorkingDir, and keeps ephemeral control paths in a real `/openkit` directory outside the volumes.

`openkit-worker-shim` is the shared sanitized zero-argument launcher. It rejects every argument with a value-free diagnostic and starts the long-lived Worker Harness without reading a Turn credential from argv, stdin, or the environment; it forces `TEMP`, `TMP`, and `TMPDIR` to the admitted `/tmp/openkit-bootstrap` root. Upstream inference and capability tokens staying inside Integration, and the native child receiving two session-local loopback credentials instead of `OPENKIT_WORKER_INFERENCE_TOKEN` or `OPENKIT_WORKER_CAPABILITY_TOKEN`, are the accepted replacement. They are not a property of the installed shim. Worker control stays in the shim control client. The installed shim owns the fixed `127.0.0.1:17891` Sandbox Integration binding and authenticated `starting` latch before releasing one native child, and no direct NanoCore control URL enters the sanitized environment. `openkit-file-effect` is the fixed Node.js standard-library helper for bounded `reference.import` into canonical read-only workspace slots, AgentSession-private package config and context beneath `/openkit/sessions/<agent-session-id>/`, and `file.export` from canonical writable workspace slots. A main-worktree export uses the fixed `/workspace/worktrees` parent and requires the admitted safe work-slot identity as its first relative component. Package config and context imports are no-overwrite and accept only the closed `<agent-session-id>/config/package.json` and `<agent-session-id>/context/<file>` relative shapes. The closed runtime-credential transport slot rejects every resolved target beneath retained `/sandbox` or `/workspace`; the current image defines no supported credential-file sink. The helper also rejects linked, non-regular, OpenKit-managed, or escaping targets and reports only an explicitly optional final-leaf absence as exit `2` with empty output. It has no configurable input root or command. `smoke-common.sh` verifies both fixed executables, the common non-root execution environment, the fixed zero-argument launcher contract, and the fixed Integration export before each runtime-specific smoke script verifies its catalog-declared runtime set. `openkit-worker-common-base-smoke.sh` reuses those common checks and proves that none of the Codex, OpenCode, Pi, or DeepSeek CLIs is present. Deployment smoke then checks the declared set of four.

Deriving from `worker-common` confers the tool and filesystem baseline and confers no network, credential, or filesystem authority. A derived Dockerfile must regain `USER root` and then return to `USER 1000:1000`; it inherits the volume, WorkingDir, and descriptive storage-family labels unless it deliberately declares a different layout. `test-env` is not that derivation. Build through `scripts/docker/build-image.sh <image-id>` so `containers/images.json` selects the correct target.

## User Native Configuration

User images may add runtime-native configuration and resources without a new OpenKit profile format. Follow the selected adapter's documented, qualified default-source convention: native layering when available, otherwise an image-designated native tree used only for a fresh private home. Do not bake internal Thread hashes into your Dockerfile or replace the fixed worker launcher to copy settings at startup.

Keep image-owned tools/default resources outside retained mounts and return the Dockerfile to USER 1000:1000 after installation. Existing retained native homes keep their authored values and unknown files; changing the image does not overwrite or synchronize them. Configure an existing home explicitly through its native conventions when you want different retained settings. A declared source that cannot be loaded fails visibly rather than silently launching without it.

Native local configuration is honored according to the pinned runtime's qualified precedence. Current model/Gateway, managed MCP, capability credentials and exact conversation remain protected adapter bindings; local files grant no external network or platform credential authority. Use the existing AgentManifest for those declarations. Non-secret environment settings follow their separate NanoCore/AEP mechanism; this guide adds no alternative environment carrier or built-in-agent modification tool.

Qualification must show one actual native resource loaded by each selected adapter, both fresh-home and populated-home behavior, a protected-conflict failure that preserves files, and exact successor continuity. Merely installing a CLI or copying a config file is not evidence of discovery. Consult the four adapter specifications and Persistent Worker Volumes for lifecycle and failure semantics; implementation guides publish native paths/options only after real-pin proof.

The owning design is `docs/specs/20260721-worker_execution_environment_images.md`.

The shim build copies and builds `@openkit/protocol` before `@openkit/worker-protocol` so the deployed production dependency closure includes the shared product-safe failure schema. This adds no runtime network or credential authority. The copy must not gain `@earendil-works/pi-coding-agent`.
