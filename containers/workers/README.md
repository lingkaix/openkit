# Shared Worker Image Build

This directory owns the published `worker-common` base plus the three independently published Worker Agent deployment images.

`Dockerfile` exposes the published target `worker-common` and the final targets `worker-codex`, `worker-opencode`, and `worker-pi`. The common stage installs the generic OpenKit worker shim, Node.js and immutable Python development toolchains, mise, source-control and build tools, editors, and network diagnostics; its declared runtime set is empty, and it contains no credential or baked OpenShell policy. It declares inherited `/workspace` and `/sandbox` OCI volumes, runs as numeric `1000:1000`, uses the writable ephemeral `/tmp/openkit-bootstrap` OCI WorkingDir, and keeps ephemeral control paths in a real `/openkit` directory outside the volumes.

`openkit-worker-shim` is the shared sanitized zero-argument launcher. It rejects every argument with a value-free diagnostic and starts the long-lived Worker Harness without reading a Turn credential from argv, stdin, or the environment; it forces `TEMP`, `TMP`, and `TMPDIR` to the admitted `/tmp/openkit-bootstrap` root. The private `turn.start` operation later binds three distinct AgentSession-local route tokens inside the Harness, and only its sanitized native child receives the inference and selected-capability tokens. The installed shim owns the fixed `127.0.0.1:17891` Sandbox Integration binding and authenticated `starting` latch before releasing one native child, and no direct NanoCore control URL enters the sanitized environment. `openkit-file-effect` is the fixed Node.js standard-library helper for bounded `reference.import` into canonical read-only workspace slots, AgentSession-private package config and context beneath `/openkit/sessions/<agent-session-id>/`, and `file.export` from canonical writable workspace slots. A main-worktree export uses the fixed `/workspace/worktrees` parent and requires the admitted safe work-slot identity as its first relative component. Package config and context imports are no-overwrite and accept only the closed `<agent-session-id>/config/package.json` and `<agent-session-id>/context/<file>` relative shapes. The closed runtime-credential transport slot rejects every resolved target beneath retained `/sandbox` or `/workspace`; the current image defines no supported credential-file sink. The helper also rejects linked, non-regular, OpenKit-managed, or escaping targets and reports only an explicitly optional final-leaf absence as exit `2` with empty output. It has no configurable input root or command. `smoke-common.sh` verifies both fixed executables, the common non-root execution environment, the fixed zero-argument launcher contract, and the fixed Integration export before each runtime-specific smoke script verifies its catalog-declared runtime set. `openkit-worker-common-base-smoke.sh` reuses those common checks and proves no first-party Agent CLI is present.

Deriving from `worker-common` confers the tool and filesystem baseline and confers no network, credential, or filesystem authority. A derived Dockerfile must regain `USER root` and then return to `USER 1000:1000`; it inherits the volume, WorkingDir, and descriptive storage-family labels unless it deliberately declares a different layout. `test-env` is not that derivation. Build through `scripts/docker/build-image.sh <image-id>` so `containers/images.json` selects the correct target.

The owning design is `docs/specs/20260721-worker_execution_environment_images.md`.
