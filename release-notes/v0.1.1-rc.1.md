## Changes since the previous candidate

### In-place update

v0.1.1 is migration-free when updating from v0.1.0. Keep the existing Data Root and use the in-platform App update with the installed helper. Verify a backup and check that the running App is idle. With the new helper, run `--stage-target` on the deployment host to stage the exact published App digest before prepare. If the running App reports `app_update_preflight_unsupported`, stop and obtain the first-upgrade decision. [Update NanoCore and Web](https://github.com/lingkaix/openkit/blob/v0.1.1-rc.1/skills/openkit-ops/references/nanocore-operations.en.md#update-nanocore-and-web)

This release adds no Discord Reports Core tables. Group Reports stay off. Existing Discord DM commands work as before.

### Verify Workers after the update

Once the new App is running and verified, acquire and activate the same-release Worker Runtimes image and match its active platform digest before the first Worker Turn. An incompatible image is refused before Worker effects with `worker_release_incompatible`. [Operator procedure](https://github.com/lingkaix/openkit/blob/v0.1.1-rc.1/skills/openkit-ops/references/nanocore-operations.en.md#verify-workers-after-an-app-update)

### Remote MCP

The remote MCP endpoint at `/mcp` offers a single operation catalog. Tool discovery lists native tools for promoted operations and provides search and describe for other eligible remote MCP operations. Use `openkit_search` to find Skills in a Workspace and `catalog_skill-content-read` to read the Skill document and required files at its exact digest. Use `openkit_guide` to learn how to save results or hand work off to a Worker. [Remote MCP interface](https://github.com/lingkaix/openkit/blob/v0.1.1-rc.1/docs/specs/20261002-remote_mcp_interface.md)

**Upgrade for MCP clients and Workers.** Refresh the available tool list before making calls on the updated App. Switch promoted operations to their listed native tools: `workspace_list`, `thread_list`, `thread_read`, `turn_read`, `task_start`, `material_create`, and `catalog_skill-content-read`. For other remote-MCP-eligible operations, use `openkit_read` for reads and `openkit_call` for mutations. Use `openkit_describe` for the exact fallback input. Promoted operation IDs are accepted only by the native tools. There are no compatibility aliases. [Tool routing and names](https://github.com/lingkaix/openkit/blob/v0.1.1-rc.1/docs/specs/20261002-operation_definition.md#remote-mcp-projection)

### Other changes

- NanoHost recovers an idle App replacement across the expected transport interruption. Before the first Worker Turn, verify authenticated readiness for the same NanoHost identity and deployment, a fenced predecessor and a higher connection generation. [#934](https://github.com/lingkaix/openkit/issues/934)
- Stable promotion gives the anonymous Worker Common lookup its own Docker configuration. The provenance verifier retains its registry authentication. [#937](https://github.com/lingkaix/openkit/issues/937)
- App update verification compares readiness with the previous boot. The candidate must accept product work and cannot add a readiness block or a newly failed subsystem. [#904](https://github.com/lingkaix/openkit/issues/904)
- After a reload fences NanoHost transport admission, the restart reason remains visible until a fresh App process starts. [#891](https://github.com/lingkaix/openkit/issues/891)
- DuckDB can initialize in the stock Worker Sandbox on cgroup v2 hosts. [#930](https://github.com/lingkaix/openkit/issues/930)
- Doctor reports installed Skill compatibility and App-update availability from published stable releases when the required access and release information are available. [#240](https://github.com/lingkaix/openkit/issues/240)
- App update status reports an absent receipt as absent. After a disconnect, use the known receipt ID to read status. [#905](https://github.com/lingkaix/openkit/issues/905)
- Safe reload validates and publishes the model catalog, Provider registry and Gateway configuration together. If a Provider change requires a restart, safe reload retains the active Provider and Gateway configuration and reports the held edits. The old configuration also stays live if native activation is refused or a lost receipt leaves activation unconfirmed. The App publishes the new configuration only after confirmed activation. [#892](https://github.com/lingkaix/openkit/issues/892)
- Workspace MCP create, select, remove and bind report the saved revision and whether it activated. `catalog.mcp-stage-version` only stages a version. If activation fails, the revision is saved and the Audit is confirmed. Fix the Gateway, then run safe reload in the same App process to apply that saved revision without resubmitting the catalog change. Reload cleans up idle sessions of the replaced entry, and in-flight calls can finish. [#891](https://github.com/lingkaix/openkit/issues/891)
- Provider and Gateway configuration saves perform disk writes off the App’s main loop. An unknown save result returns HTTP 409 `config_file_write_unknown`. A durability or receipt failure after file replacement returns HTTP 409 `recovery_required`. In either case, read back the file and revision before deciding whether to retry. [#892](https://github.com/lingkaix/openkit/issues/892)
- A Gateway Responses stream retains its completed outcome when the client disconnects after the completion frame has passed delivery checks. An already released `response.failed` stays failed. A disconnect records cancellation only if neither terminal frame was released. [#938](https://github.com/lingkaix/openkit/issues/938) · [#915](https://github.com/lingkaix/openkit/issues/915)
- Validation and reload report that an App restart is required after a valid certificate chain changes. An unreadable TLS file or a certificate that does not match its key fails validation. Reload refuses to publish the new configuration, and running listeners keep their current certificate. [#891](https://github.com/lingkaix/openkit/issues/891)
- Reload and Setup report the configured NanoHost active Turn limit and the current effective limit. An increase beyond the resident limit is deferred while that resident remains in use. [#891](https://github.com/lingkaix/openkit/issues/891)
- A timed-out Workspace Knowledge intake identifies its retained Source when no Notebook submission took effect or remains unresolved. Select that Source in a new maintenance request to continue. [#920](https://github.com/lingkaix/openkit/issues/920)
- At startup, the App marks orphaned Assistant Turns interrupted before admitting new work. A definite refusal to save an Assistant reply can settle the original Turn as failed. If both the answer save and the failure-state write are definitely refused, the command-initiated Turn still shows as running. After storage recovers, Stop or a new submission marks that original Turn failed without repeating the Provider call. An uncertain outcome remains inspect-only until boot recovery. [#940](https://github.com/lingkaix/openkit/issues/940)
- A reconnecting Worker can confirm that its last heartbeat committed before an App restart, then send one fresh heartbeat to restore control. [#933](https://github.com/lingkaix/openkit/issues/933)
- The App-update helper compares the running and target migration journals before replacement. It refuses a target that needs a migration. [#944](https://github.com/lingkaix/openkit/issues/944)
- Each Gateway call keeps its admitted Provider registry through retry and failover. Each attempt still checks current credentials and caller authority. [#892](https://github.com/lingkaix/openkit/issues/892)
- Goal Plan execution recognizes a delivered approval from its original published decision. Missing, conflicting or damaged decision evidence closes the grant and requires a new approval. [#929](https://github.com/lingkaix/openkit/issues/929)
- Scheduler maintenance releases stalled Worker preparation after the attempt deadline once it confirms no submission occurred. A late preparation result cannot submit the expired attempt. [#941](https://github.com/lingkaix/openkit/issues/941)
- A Pi Worker reports a temporary busy result when steered during MCP setup. Stop remains available. A Codex Worker reports a definite steer refusal only for the exact native request. A mismatched request ID leaves the outcome uncertain and prevents a resend. [#942](https://github.com/lingkaix/openkit/issues/942)
- NanoCore keeps its Data Root lock until the listeners and native writers finish shutting down. If shutdown fails or reaches its deadline, lock ownership ends with the process. [#945](https://github.com/lingkaix/openkit/issues/945)
- Pi lets the host-managed Knowledge ask and tell tools finish within the default Knowledge Manager deadline plus time for admission and settlement. These calls honor both call and session cancellation. Worker Runtimes ships matching integrity digests for the Pi patch and all three MCP files it changes. [#918](https://github.com/lingkaix/openkit/issues/918)
- Knowledge Proposal previews show each candidate page’s proposed lifecycle: active, draft, archived, superseded, invalid or deleted. Workspace intake stages complete pages for ordinary use as active and preserves deliberate drafts, which stay out of ordinary retrieval. [#917](https://github.com/lingkaix/openkit/issues/917)
- Reopening an OpenCode Worker session checks for retained suspended or queued work before starting the host. Confirmed suspended or queued work stays available for inspection, and the reopen is refused. If the session database cannot be read, the host refuses the reopen before starting stdio. [#943](https://github.com/lingkaix/openkit/issues/943)
- A recurring run that could not publish its original Turn because the Thread was busy can continue when the Thread clears and the run is still eligible. Deferred publication has a 30-second deadline to post the write. If a posted write remains unconfirmed, inspect `publicationUncertainSince` in automation history with `includePublicationDiagnostics: true` and wait for the original write to settle. Other schedules can continue. Once the write settles, retry a schedule definition change that it previously blocked. [#939](https://github.com/lingkaix/openkit/issues/939) · [#946](https://github.com/lingkaix/openkit/issues/946)

### Qualification and documentation

- The storage test for new file permissions now checks the mode under the active umask. [#928](https://github.com/lingkaix/openkit/issues/928)

## Known issues

These disclosures apply to the v0.1.1 build.

### Current limitations and qualification

- Keep the original v0.1.0 Getting Started container. Its Data Root backups are stored in the container’s writable layer and removal deletes them. Use the one-time `--convert-getting-started` procedure on the current image to copy and verify existing backups and retain the stopped original. After conversion, verify the backup and continue with the [in-platform App update](#in-place-update). [Operator procedure](https://github.com/lingkaix/openkit/blob/v0.1.1-rc.1/skills/openkit-ops/references/nanocore-operations.en.md#getting-started-bridge-settings) [#902](https://github.com/lingkaix/openkit/issues/902)
- DeepSeek Worker execution remains disabled (#868). Choose another Worker Agent.
- The acceptance window for the reviewed class C findings in the Debian bookworm base ends at 00:05 UTC on 2026-12-17. Debian trixie evaluation and VEX for unreachable components are 0.1.x follow-ups. The persistence-smoke correction now checks the SQLite-owned Workspace record. [#850](https://github.com/lingkaix/openkit/issues/850) · [#856](https://github.com/lingkaix/openkit/issues/856) · [#866](https://github.com/lingkaix/openkit/issues/866)
- Full verified staging and quarantine remain incomplete (#776). Existing conversation Threads can still admit Knowledge maintenance role Turns (#857).
- Hosted reported-activity latency remains under review (#848). Hosted test-container Docker-socket exposure (#846) and an unjoined image-refusal fixture writer (#847) remain tracked.
- Older recovery refusals can cancel unrelated native barriers (#863); historical no-citation Knowledge Manager Chat receipt replay can change its explanation (#864); attachment-only Composer input can be refused by Chat message publication (#865).
- Candidate CI and a fresh persistent Worker Turn on both architectures are required for this release. Deployment and credential qualification are separate checks on the published release.

These issues are tracked in #177. Release admission also requires the current release-blocker reconciliation; disclosure alone is not a waiver.

- You cannot yet redirect a task while it is running (#121).
- Task users cannot create named Workspace-shared Sandboxes, including from a template, or select one in Composer. [#122](https://github.com/lingkaix/openkit/issues/122)
- A reported Pi stop before finishing has not been reproduced, and the available records do not establish its cause or timing (#130).
- After a Goal's Plan is approved, its Coordinator may not start any Task; letting the Coordinator discover eligible Worker Agents remains open (#142).
- Worker runtime identities across the four runtimes have not yet been qualified for general work (#191).
- Chat can answer an execution request instead of handing off the work; start execution work as a Task (#192).
- The ordinary Assistant's planned Core Tool and Skill resource integration remains deferred (#144).
- Internal Agent runs, including Goal coordination, cannot shorten their context and continue once they reach the configured context limit (#125).
- After an unsupported Gateway feature error, choose a compatible route and start the Task in a new Thread if you need a fresh native conversation (#129).
- An older recovery checkpoint can remain marked as requiring recovery after later work reuses the same AgentSession and changes its environment package (#132).
- The conversation target catalog lists only Workspace-pinned Agents, so a globally configured Agent can be absent from the starter choices (#134).
- A Worker can write a report outside its permitted output folder and then be unable to publish it; use the eligible folders listed in the Artifact submission tool's description (#140).
- A review Worker cannot yet receive selected Artifacts from a prior Task through a general cross-Task delivery path (#141).
- A Worker can read permitted peers in the same Sandbox but cannot yet send a peer a question (#150).

- Large streamed tool arguments can incur repeated parsing cost (#167).
- If the first native conversation's resume proof is not retained, later work can start a new native conversation (#168).
- After the system clock moves backward, continuation can consider successor session history in the wrong order (#169).

- Some internal model calls fail before output with only an unknown transport failure in the log (#207).
- Under concurrent load on four Workspaces, a transient storage commit stall of about two seconds can refuse progress Items (#703).

### Tools and GitHub

- When Codex must shorten a conversation to fit the context limit, a failure may be reported without identifying that step as the cause (#123).
- Provider acceptance of past tool calls during conversation shortening remains unproved (#124).
- Upstream MCP integrations that require NanoCore-managed OAuth are not yet supported; current credential delivery uses static raw or bearer credentials (#146).
- MCP server configuration does not yet support an explicit map of ordinary non-secret HTTP query parameters (#147).
- Agents cannot yet withdraw a pending tool request themselves (#149).
- Available vendor MCP tools do not prove that access is limited to the intended repository (#170).

### Host and deployment

- Provider credential or subscription binding changes can still require an App restart. The same applies when restoring a configuration that changes startup-owned fields. Verify the effective configuration after restart. [#891](https://github.com/lingkaix/openkit/issues/891)
- The v0.1.0 release record contains the first exact-product Worker readiness verdict. For later NanoHost runtime-target changes, the release record states the new verdict. [#120](https://github.com/lingkaix/openkit/issues/120)
- Worker runtime-file credential delivery is unavailable on stock boot and fails closed. Use gateway-only grants for MCP credentials. [#926](https://github.com/lingkaix/openkit/issues/926)
- A runtime-file delivery refusal can leave a non-secret preparation plan, environment snapshot and empty mountpoint. [#927](https://github.com/lingkaix/openkit/issues/927)
- Runtime-file credentials for persistent Worker images (#480) and the managed User-scoped credential lifecycle (#578) remain open until live qualification passes (#604).
- Package downloads can be refused when processes sharing one socket have different policy identities (#135).
- A package download can fail before an HTTP event without diagnostics that connect the failure to the affected request (#136).
- Idle backend bindings are not automatically evicted to make room for other work (#157).
- Workspace backup, restore and move cover one Workspace at a time. A Core Data Root backup omits NanoHost execution volumes. Preserve the volumes separately when recovery needs them. [#158](https://github.com/lingkaix/openkit/issues/158)
- This release supports one execution backend and cannot place work across mixed backends (#171).
- Execution quotas are not yet implemented (#172).
- Queued work uses first-in-first-out admission; fairness and aging policies are deferred (#173).
- Dynamic fleet selection and placement affinity are not yet supported (#175).
- Multi-process NanoCore scheduling, high availability and hot failover are not supported (#176).
- NanoCore does not yet emit every Turn-chain span that the telemetry specification targets (#219).
- Server operations shows cleanup work from its supported sources. The view is bounded and can report missing, stale or unavailable observations. [#226](https://github.com/lingkaix/openkit/issues/226)

### Setup

- Existing npm access rules need the documented administrator update for scoped package downloads (#126).
- Repository tool setup may be blocked by download permissions even when npm access is allowed (#131).
- A Codex subscription can appear connected despite rejected credentials, and a stuck login can block login or deletion (#108).
- Remote MCP does not yet provide browser OAuth login; use the supported static bearer route (#145).
- External Agent clients use the user's authorization rather than independent Agent identities (#152).
- Permission-based blocking of selected operations through the Policy Kernel is not yet implemented (#153).
- The equal-member Workspace lifecycle cutover is not complete, so some Workspace lifecycle actions still apply owner-only checks (#159).
- The Web interface does not yet provide the complete Workspace membership, invitation and lifecycle experience (#160).
