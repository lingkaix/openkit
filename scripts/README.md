# Repository Scripts

Root `package.json` owns the command surface and `docs/toolchain.md` owns setup and execution placement. These scripts implement those commands; they do not supply design authority.

`validate-test-governance.mjs --run -- <command>` retains command failures and rejects undeclared TAP skips. It also rejects positive unnamed skipped counts from Vitest and Node's default and spec reporters because those summaries cannot prove file-bound skip authorization. It removes ANSI decoration for skip parsing and retains the original output for display.

## Release Inputs And Verification

`release-ci-reuse.mjs --repository <owner/repo> --workflow ci.yml --sha <full sha> --job <exact job name>` reads GitHub Actions with the job-scoped `GITHUB_TOKEN` and reports the run, latest attempt, and successful job identity for one completed exact-commit workflow-dispatch run or main-push release-gate run. Reuse remains per job, never across commits or from another branch. It paginates runs and attempt jobs, rechecks the selected attempt, and exits 1 when no job qualifies or 2 on usage/API errors. Complete L0-L2 shard steps can reuse exact-source evidence on main and tag pushes; NanoCore e2e reuses it on tag pushes. Either failure result runs the normal tests, and the host aggregate requires every successful shard. Fixtures inject HTTP responses without network access. See the [release cookbook](../docs/cookbooks/release.md#cadence-commands) for preparation, admission, pre-merge and local smoke commands.

`release-notes.mjs` checks `release-notes/<tag>.md` and the tag workflow fails before image promotion when that file is missing or malformed. The verify job compares the published release body through `--compare-body`.

`release-preflight.mjs` validates the selected release inputs and the schema-version-2 NanoHost capability profile. `package-release-assets.mjs` reads checkout-owned inputs from the selected Git revision and produces the controlled release archives. NanoHost packaging selects `linux/amd64` and `linux/arm64` from the distribution table in `lib/nanohost-elf.mjs`; it bundles exact `host-manifest.json` bytes, profile id and digest, product commit, and libc symbol-version requirements derived from both ELF executables. `verify-nanohost-release.mjs` checks the archive tree, checksums, checkout-owned bytes, provenance, ELF and derived requirements, then performs a contained staging install.

Run `pnpm release:preflight -- --tag <tag>` and `pnpm release:package -- --tag <tag>` through the release cookbook. Release and pre-release tag CI runs target-native real-host qualification before publication under the release and NanoHost specifications; pull-request and manual gates do not run it.

For a complete NanoHost release, supply `--nanohost-amd64-binary`, `--nanohost-arm64-binary`, `--openshell-amd64-gateway-archive`, `--openshell-arm64-gateway-archive`, `--openshell-license`, and `--openshell-notices` to the existing packager. Gateway archive and extracted executable identities come from `gateway.targets["linux/<architecture>"]` in the schema-version-2 OpenShell release pin. The shared checksum covers the operations Skill and both NanoHost archives. Tag packaging installs checkout dependencies before invoking the packager and downloads the accepted inputs with the test image's built-in Node fetch. Post-publication asset inspection also installs checkout dependencies inside that image; its Node 24 verifier runs operations discovery from the extracted envelope outside the checkout while Docker and GitHub Release access remain on the host.

## NanoHost Static Checks

After checking the outer archive checksum, extract the NanoHost archive beside its original `.tar.gz`, then run the bundled `./install.sh --check-host`. The checker reads only bundled checksum-verified inputs and verifies that the adjacent archive contains those exact bytes. Checking and installation, including staging verification, require Python 3.8 or later with its standard library at `/usr/bin/python3`, with isolated imports and bytecode writes disabled. It is not a NanoHost service runtime dependency; missing or unusable inspection returns one bounded `cannot-check` result and blocks installation. Every static probe has a deadline, and no checker mode provisions packages or invokes a service lifecycle command.

Each installer invocation bounds interpreter execution and result collection together in the existing POSIX shell and verifies bundled inputs once through that path; no shell checksum prepass runs before it. The checker emits one JSON object and a newline with a hard verdict and separate combined-deployment resource recommendation. `./install.sh --check` and live installation consume the same result while retaining their installation-disposition output. `DESTDIR=/new/canonical/path ./install.sh` verifies bundled inputs and stages only the three fixed payloads, with the existing host-check exemption.

See [Deployment Host Requirements](../docs/specs/20260909-deployment_host_requirements.md), [NanoHost Runtime And Transport](../docs/specs/20260802-nanohost_runtime_and_transport.md), and the [Release Cookbook](../docs/cookbooks/release.md) for the owners and qualification boundary.

`release-record.mjs` generates offline manifests, reviewed drafts and private compact closeout projections. It imports the existing exported notes functions; `release-notes.mjs` remains byte-identical to the proved publication baseline. `tests/release-manifest.test.mjs` checks its raw bytes against the pinned SHA-256 from baseline commit `23f3e2dc`, without requiring Git history in CI. `release-safety.mjs` owns shared credential-safe evidence, canonical identities and single-shot effect retention for the scripts and qualification kit. The kit pins that script-side dependency as part of its instrument digest.

`release-publication-check.mjs EVIDENCE.json` reads immutable Git objects at exact P and `baseline.sha`. Its proof includes publication jobs, moved candidate jobs, the matrix and read-only registry admission. Native App publication also includes its index loader, both native smoke legs and promotion. It follows invoked scripts and their static relative-import and literal-file dependencies, including the native missing-setter fixture. Trailing-slash directory URLs locate a working directory and are not file inputs. Missing or changed file inputs refuse even if supplied hashes agree. The proof retains each input blob identity and the aggregate fingerprint.

`release-observe.mjs` collects baseline workflow, tag-push and job provenance from current GitHub API responses. It resolves lightweight or annotated tags to the actual commit and rechecks the tag and completed run after job collection. Missing or mismatched job run, attempt or source identities refuse collection; authored baseline fields cannot fill them.

## Retrieval Build Supply

`retrieval-cargo.sh` verifies the repository's pinned IPADIC archive with `retrieval-dictionary.py` before Cargo uses its fixed build cache. It forwards the requested Cargo operation without another build runner. `retrieval-notices.py` retains SPDX metadata and notices supplied by the locked Cargo packages, verifies the vendored missing-crate notice provenance, and includes explicit unresolved gaps. The App image copies this output beside the target-native executable; the CI development image seeds the same archive. `release-tests.mjs` builds the kernel before the NanoCore real stdio seam tests are collected. These scripts add no publication effect or Sandbox installation.

`release-record.mjs --publication-assets DIR` joins the committed `release-notes/<tag>.manifest.json` compatibility facts with the exact source and image records, writes the fifth attachment and appends its checksum. `--verify-publication-assets DIR` independently reconstructs the manifest and checks the downloaded archive bytes. The authored assessment cannot override source or App identity. Missing, negative or unassessed facts refuse.

`release-promotion.mjs` supplies the bounded tag-only synthetic stable rehearsal in `notrucked/openkit`. It verifies the current successful source attempt, notes, indexes, manifest and archive bytes before assigning scratch stable tags, then repeats published verification and anonymous worker-base inspection. It contains no build or package operation. Stable assets keep their prerelease names, provenance and bytes. `--check-only` reads and verifies without publishing; an existing stable identity requires complete matching version tags and Latest. The CLI refuses production, and no synthetic result grants production stable eligibility.

`ci-l0-l2.mjs --matrix` derives all deterministic execution partitions, and `--coverage-matrix` derives the required whole-owner coverage merges. NanoCore and Worker Shim use eight Vitest file partitions each. Every partition compares unit and covered case inventories and retains its execution report, inventory and blob. `--merge-coverage <owner>` refuses incomplete or overlapping file and case unions, then merges coverage under the unchanged package configuration. `--join <directory>` requires all execution and merged-coverage observations, including the existing exactly-once root inventory. Parallel static checks and individual native/catalog suites retain every previous command. Exact-commit reuse must download the cited run-attempt artifact; an absent artifact fails closed.
