# Worker Update Orchestration

This directory composes the existing Worker environment operations for an administrator-run release update. [Release Management](../../docs/specs/20260829-release_management.md#bounded-test-deployment-update) owns the bounded deployment grant and component order. [Persistent Worker Volumes](../../docs/specs/20260910-persistent_worker_volumes.md#planned-environment-replacement) owns preparation, confirmation, drain, fencing, activation, retained bytes, and result-only recovery. [NanoHost Runtime And Transport](../../docs/specs/20260802-nanohost_runtime_and_transport.md) owns physical Epoch and authenticated readiness evidence. [Deployment Host Requirements](../../docs/specs/20260909-deployment_host_requirements.md) owns the machine identity digest.

Worker environment operations remain in NanoCore. P07 owns their implementation during rc.8 wave 1. P02 owns live coordinator inspection and process-handle measurement under the accepted [Live Operator Inspection contract](https://github.com/lingkaix/openkit/blob/08b252dc477e27548d458f82e4e6ceb73e1baf22/docs/specs/20260802-nanohost_runtime_and_transport.md#live-operator-inspection). P12 owns public schemas and the stored physicalEpoch projection. Integration order: **P02 before P29**. The concrete command adapter targets the reviewed P02 producer at `aee009245860b4da721f2df4d12caddfd8f57556`. P12 must also supply the stored physicalEpoch projection before live admission. This directory supplies no operator transport or CLI and cannot admit the current public runtime-target response, which omits physicalEpoch. Real-host effects and the identifier reset require their separate authorization.

## Worker Stage

`update-worker-environment.mjs` exports `updateWorkerEnvironment(target, params, evidenceDir, io)`. The caller supplies one explicit HTTPS origin, an already verified release manifest, the platform, the exact existing preparation input without its image declaration, separate prepare and activation request IDs, the bounded grant, the expected preceding NanoHost stage reference, and the asserted previous physical Epoch witness. The script derives a registry reference from the manifest's `worker-runtimes` index digest and compares the prepared image with the platform digest.

The administrator caller supplies independent `deploymentRecord()`, `currentGrant()`, `replacementObservation(target)` and `archiveAttribution()` readers, `runOperator(target, invocation)` through the independently authenticated operator channel, and `call(operation, input)` for the existing public operations. Adapters must bound transport duration and reject timeout or incomplete output; rejection stops the attempt. A manifest or caller parameter snapshot cannot replace an independent reader. The retained deployment binding supplies `machineIdentityDigest`, the SHA-256 of the exact platform installation-identifier bytes. Raw machine identifiers are not accepted as identity evidence or retained.

The replacement reader independently reads the preceding accepted NanoHost component evidence for this invocation. It supplies its reference, explicit target, grant reference, outcome, release tag/commit, and qualified before/after host observations. Its accepted successor effective unit digest is the configuration baseline. A missing, failed, unknown, stale or differently bound stage stops before preparation. The previous Epoch parameter is an assertion checked against that evidence. This script never authors a passed NanoHost result.

A successful preparation requires a different physical Epoch and fresh-empty evidence, plus a greater connection generation than its predecessor. The script retains the complete prepared candidate and impact, rechecks current grant, deployment, host and idle preflight before activation, then checks host identity and readiness again after activation. Every phase requires a new operator challenge. Any connection generation or coordinator/Gateway process change across this attempt stops; a consistent new join alone cannot silently refresh an earlier admission. Existing activation owns drain, fencing and replacement. Configuration-only activation proves pinned configuration, not a mounted Worker or qualification Turn.

## Operator Observation And Archive Attribution

`host-observation.mjs` exports `observeOperatorHost(target, {binding, archiveAttribution, effectiveStateDigest}, io)`. It reads `nanohost.runtime-target`, sends exactly one unpredictable 64-hex nonce through fixed read-only `inspectHost`, and rereads runtime-target. Both stored observations must be ready, fresh-empty and predecessor-fenced. All three observations must match exact identity, deployment, connection generation and physical Epoch. The server field is a stored witness; it does not measure the host. Missing/null Epoch, wrong nonce, unavailable/unknown output, process replacement, mismatch or transport loss stops without retry or rejoin.

The accepted P02 inspection response binds the nonce, machine digest, physical Epoch and native connection tuple to coordinator, NanoHost and Gateway process incarnations (boot UUID, PID, start ticks), measured running executable hashes, installed unit hash and effective unit digest. P02 must pin/recheck the actual processes and connection while measuring, prove Gateway membership and signal replacement. Its reported generation comes from the existing authenticated readiness callback after the complete acknowledgement. Connection or authority loss clears inspection availability; a connection transition during measurement invalidates the sample. P29 checks the returned evidence and exact archive/unit baseline. The independent operator transport authenticates the retained host binding. This trusts that transport and the host OS; it does not prove hardware attestation or resist malicious host root. Each qualified sample retains its stripped inspection, runtimeTargetBefore and runtimeTarget. The Worker result retains the separate hostBeforeActivation sample. Unknown descriptive annotations are stripped at every retained observation level.

`attributeNanoHostArchive({archive, checksumFile, repoRoot, destdir, tag, sourceCommit, platform, archiveSha256})` supplies a concrete archive reader. The caller provides the selected published checksum, retained source checkout and a new staging directory under private operator storage. The helper snapshots archive/checksum bytes privately, invokes the existing release verifier, checks selected source/tag/platform/checksum, and measures its staged NanoHost, Gateway and unit payloads. The existing installer runs only with a staging DESTDIR. The archive attribution is `{archiveSha256, tag, sourceCommit, platform, payloads:{nanohostSha256, gatewaySha256, unitFileSha256}}`. It contains no local paths or new install receipt. Verification failure can leave a staging directory for inspection; never reuse it automatically.

The archive checksum proves supply attribution. The three corresponding live payload measurements must match verified staged payload hashes. Effective unit state must also match the independently accepted replacement baseline, because the archive unit hash cannot approve overrides. The earlier provisional `machineId`, `sourceCommit` and `distributionSha256` host fields have no fallback. The public API gains only nullable physicalEpoch; machine/process/archive facts remain private operator evidence. P02 defines effectiveStateDigest as lowercase SHA-256 of compact UTF-8 JSON without a newline, with 40 sorted property names and string values. The owner defines the exact property set and normalization, including execution fields and credential references, and excludes secrets and runtime counters. P29 compares this opaque digest with accepted evidence; it does not request, hash or retain raw effective-unit properties. The owner semantics and P02 implementation are accepted; its producer must precede this consumer in the train, and the P12 projection remains pending.

`invokeNanoHostInspection(target, {nonce}, runOperator)` invokes only `['/usr/lib/openkit/nanohost', 'inspect']` with compact nonce-only stdin JSON. The already authenticated external operator executor receives `{command, stdin, timeoutMs:10000, maxStdoutBytes:16384, maxStderrBytes:256, signal}` and returns `{exitCode, signal, timedOut, stdout, stderr}`. It must bound collection, reject overflow rather than truncate, and honor cancellation. No local-host or SSH executor is supplied. `observeOperatorHost` always uses this concrete command boundary; a caller cannot substitute a pre-parsed inspection response.

P02 bounds the input to 256 UTF-8 bytes and the response to 16 KiB, including framing whitespace, under one absolute 10-second monotonic CLI deadline. P29 adds its whole-invocation deadline and abort signal, checks process completion and empty stderr, decodes strict UTF-8 and one unambiguous JSON envelope, then checks the nonce and closed producer shape. A non-zero exit, timeout, malformed/oversized/ambiguous output or unknown core stops without another attempt or raw diagnostic retention. P02 owns local root-peer admission and coordinator/process measurement. This directory supplies no alternate command, process/path selector or transport fallback.

## Evidence And Verification

Evidence uses the existing private release `save` and single-shot `once` helpers. A new evidence directory is required. Reentry, interruption, unknown or partial activation, stale candidate, changed target, busy work or missing evidence stops the composition. Inspect the saved operation IDs and owner records; there is no automatic recover, retry, rollback, reset, image fallback or NanoHost restart. Component outcomes remain separate. An App update result cannot stand for a NanoHost or Worker result, and a Worker activation cannot accept retained-data or runtime qualification.

Run `node --test --test-concurrency=1 scripts/host-worker-update/*.test.mjs` with the pinned Node toolchain and built App API schema dependencies. During the shared builder round, use the dispatch brief's `run-slot.sh` wrapper. Independent command/probe cases use doubles matching the accepted P02 owner and pending P12 projection; archive cases exercise the real packager, verifier and staging installer in isolated fixtures. These checks prove orchestration, fixture process measurement and archive attribution. They do not establish installed-host measurements, operator-channel authentication, registry acquisition, writer termination, retained-byte continuity or selected-host qualification. Shared gate inclusion belongs to the release cadence v2 owner and is requested through the coordinator. Builders do not start branch CI. Main is green; the coordinator owns merge-train review and CI.


`native-inspection.test.mjs` composes the unchanged P02 inspection module through its existing test-only entry, UID and file hooks, real IPC and process-image measurement. It compiles a verification-only Rust fixture with P02's existing dependency declarations and lockfile in private temporary storage; no producer file is written. The fixture keeps its coordinator and own sleep child alive while the P29 join runs. Expected image, machine, unit and normalized digest values are independently derived. Success, same-Epoch reconnect and process replacement cross the real producer/consumer boundary. The fixture installs its synthetic current connection through P02's test hook; it does not prove the native readiness acknowledgement. Stored runtime-target reads remain doubles until P12 arrives. These checks do not prove real systemd, operator authentication or published-host qualification.

The native test requires Linux, the NanoHost-pinned Rust toolchain and its cached Cargo dependencies. It fails clearly when P02 source is absent. Before train assembly, `P29_TEST_PRODUCER_ROOT=/absolute/read-only/P02-checkout` may select that exact source root for this test only; production has no source or endpoint override. For example, run `P29_TEST_PRODUCER_ROOT=/path/to/P02 node --test --test-concurrency=1 scripts/host-worker-update/*.test.mjs` through the slot wrapper. The assembled train uses repository source paths without this test override. Temporary Cargo metadata, artifacts and fixture children are removed after the suite.
