# Worker Update Orchestration

This directory composes the existing App update, stopped NanoHost replacement and Worker environment operations for an administrator-run release update. [Release Management](../../docs/specs/20260829-release_management.md#bounded-test-deployment-update) owns the bounded deployment grant and component order. [Persistent Worker Volumes](../../docs/specs/20260910-persistent_worker_volumes.md#planned-environment-replacement) owns preparation, confirmation, drain, fencing, activation, retained bytes, and result-only recovery. [NanoHost Runtime And Transport](../../docs/specs/20260802-nanohost_runtime_and_transport.md) owns physical Epoch and authenticated readiness evidence. [Deployment Host Requirements](../../docs/specs/20260909-deployment_host_requirements.md) owns the machine identity digest.

Worker preparation and activation remain in NanoCore. The concrete host observation uses the current NanoHost `inspect` producer and the public nullable `physicalEpoch` witness. It admits no older response, asserted success or alternate runtime host-control route. Real selected-host effects and release qualification require their own existing authorization.

## External Operator Command

`operator-cli.mjs` runs `updateComponents` in the fixed App, NanoHost, Worker order. Run it from the reviewed checkout with pinned Node 24 and built workspace dependencies. Select one canonical HTTPS origin, an existing protected deployment record and current grant, private invocation parameters and verified old/target archive selection, and a new evidence directory. The administrator API uses the existing endpoint-scoped credential store; the independent operator channel uses the retained `a1` SSH binding and normal host-key verification. It has no default target or new login mechanism.

```sh
node scripts/host-worker-update/operator-cli.mjs --target "$UPDATE_TARGET" --params "$UPDATE_PARAMS" --deployment-record "$UPDATE_DEPLOYMENT" --grant "$UPDATE_GRANT" --artifacts "$UPDATE_ARTIFACTS" --evidence-dir "$UPDATE_EVIDENCE"
```

The parameters contain `{manifest, platform, grant, invocationReference, app, nanoHost, worker}`. `app` supplies the existing App stage's expected current image, verified target helper checksum, selected retained reads and finite status-poll bounds. The target helper must already be installed through its own operator procedure. `nanoHost` supplies one new replacement UUID and the accepted old effective-unit digest. `worker` supplies the existing exact preparation input without a declaration and a distinct activation request ID. The composition derives release/image declarations, prior-component references and predecessor Epoch from actual observations; nested caller assertions cannot supply them. The protected current grant must independently repeat the exact positive `app-first` transitional-pair assessment and authorize all three components. Manifest assertions alone grant no effect.

The artifacts file selects independent `old` and `target` archive inputs accepted by `attributeNanoHostArchive`. Each names its archive, published checksum file, exact retained source checkout, tag, source commit, platform and archive checksum. The source checkout is part of verification, not a runtime selector. Protected invocation files are bounded regular mode-0600 files owned by the invoking operator; symlinks, duplicate authority fields and changed inputs refuse. These are external operator inputs, not product configuration or a new deployment registry.

The first automated host posture is the canonical installed Linux/systemd service on unified cgroup v2, with a tmpfs `/run`, no applicable foreign exact-name, prefix or type-wide service drop-in, no pending service job or external trigger, and the actual manager search roots admitted. The NanoHost environment file uses the documented plain unquoted assignments, protected input files and unchanged declared slots. Other valid environment syntax or activation configurations use the manual procedure. Missing tools, contradictory ownership, unknown host facts or unqualified inhibition stop before interruption.

The fixed privileged program carries only its checkout-owned source set and verified target archive into exclusive private custody beneath the existing installed payload directory. It checks the retained machine and actual App container, preserves old differing payloads, runs the unchanged target host checker and installer, checks complete target files and retained inputs, and starts once. A persistent operation-owned condition requires a volatile permit. The service consumes it before NanoHost execution and `Restart=no` prevents automatic retry. An exclusive durable attempted-start artifact survives interruption. Public pending-readiness observation precedes one privileged native sample for the canonical controlled-unit baseline. The composition then makes its separate nonce-bound native/server join against that baseline before finalization. Finalization likewise measures the restored baseline before the final join. Each sample runs once; any unavailable sample stops before the next sample or effect. Finalization removes only this operation's guard, restores stock supervision and measures the same ready process again before Worker admission.

App image attribution compares the exact selected OCI child manifest's `config.digest` with the actual Docker image ID. Web release attribution is accepted only after a fresh helper-owned tree digest equals the successful exact receipt's staged digest. Those tree and OCI digests have different meanings. The raw installation identifier is used only in memory for the retained host join; evidence contains the installation-byte digest and selected image attribution.

Each component has its own private evidence subdirectory. The parent result distinguishes passed, unknown and unrun stages. A lost command or response stops dependent work without another start, retry, payload restoration, reset or automatic resume. Retain the exact App and Worker request IDs, persistent guard/attempt artifacts, old payload custody and private archive custody for explicit inspection. A new invocation or existing artifact supplies no recovery authority. Successful orchestration proves configuration and activation, not a Worker Turn, retained-work continuation or release qualification.


Fixtures that cross the shared App API use canonical per-kind Core identifiers for Deployment, Workspace, Thread, Artifact and Worker storage records. Native machine, process, runtime-target and harness selectors remain opaque. The native inspection fixture binds the same canonical Deployment ID in the measured producer and the stored consumer witness.

## Worker Stage

`update-worker-environment.mjs` exports `updateWorkerEnvironment(target, params, evidenceDir, io)`. The caller supplies one explicit HTTPS origin, an already verified release manifest, the platform, the exact existing preparation input without its image declaration, separate prepare and activation request IDs, the bounded grant, the expected preceding NanoHost stage reference, and the asserted previous physical Epoch witness. The script derives a registry reference from the manifest's `worker-runtimes` index digest and compares the prepared image with the platform digest.

The administrator caller supplies independent `deploymentRecord()`, `currentGrant()`, `replacementObservation(target)` and `archiveAttribution()` readers, `runOperator(target, invocation)` through the independently authenticated operator channel, and `call(operation, input)` for the existing public operations. Adapters must bound transport duration and reject timeout or incomplete output; rejection stops the attempt. A manifest or caller parameter snapshot cannot replace an independent reader. The retained deployment binding supplies `machineIdentityDigest`, the SHA-256 of the exact platform installation-identifier bytes. Raw machine identifiers are not accepted as identity evidence or retained.

The replacement reader independently reads the preceding accepted NanoHost component evidence for this invocation. It supplies its reference, explicit target, grant reference, outcome, release tag/commit, and qualified before/after host observations. Its accepted successor effective unit digest is the configuration baseline. A missing, failed, unknown, stale or differently bound stage stops before preparation. The previous Epoch parameter is an assertion checked against that evidence. This script never authors a passed NanoHost result.

A successful preparation requires a different physical Epoch and fresh-empty evidence, plus a greater connection generation than its predecessor. The script retains the complete prepared candidate and impact, rechecks current grant, deployment, host and idle preflight before activation, then checks host identity and readiness again after activation. Every phase requires a new operator challenge. Any connection generation or coordinator/Gateway process change across this attempt stops; a consistent new join alone cannot silently refresh an earlier admission. Existing activation owns drain, fencing and replacement. Configuration-only activation proves pinned configuration, not a mounted Worker or qualification Turn.

## Operator Observation And Archive Attribution

`host-observation.mjs` exports `observeOperatorHost(target, {binding, archiveAttribution, effectiveStateDigest}, io)`. It reads `nanohost.runtime-target`, sends exactly one unpredictable 64-hex nonce through fixed read-only `inspectHost`, and rereads runtime-target. Both stored observations must be ready, fresh-empty and predecessor-fenced. All three observations must match exact identity, deployment, connection generation and physical Epoch. The server field is a stored witness; it does not measure the host. Missing/null Epoch, wrong nonce, unavailable/unknown output, process replacement, mismatch or transport loss stops without retry or rejoin.

The accepted P02 inspection response binds the nonce, machine digest, physical Epoch and native connection tuple to coordinator, NanoHost and Gateway process incarnations (boot UUID, PID, start ticks), measured running executable hashes, installed unit hash and effective unit digest. P02 must pin/recheck the actual processes and connection while measuring, prove Gateway membership and signal replacement. Its reported generation comes from the existing authenticated readiness callback after the complete acknowledgement. Connection or authority loss clears inspection availability; a connection transition during measurement invalidates the sample. P29 checks the returned evidence and exact archive/unit baseline. The independent operator transport authenticates the retained host binding. This trusts that transport and the host OS; it does not prove hardware attestation or resist malicious host root. Each qualified sample retains its stripped inspection, runtimeTargetBefore and runtimeTarget. The Worker result retains the separate hostBeforeActivation sample. Unknown descriptive annotations are stripped at every retained observation level.

`attributeNanoHostArchive({archive, checksumFile, repoRoot, destdir, tag, sourceCommit, platform, archiveSha256})` supplies a concrete archive reader. The caller provides the selected published checksum, retained source checkout and a new staging directory under private operator storage. The helper snapshots archive/checksum bytes privately, invokes the existing release verifier, checks selected source/tag/platform/checksum, and measures its staged NanoHost, Gateway and unit payloads. The existing installer runs only with a staging DESTDIR. The archive attribution is `{archiveSha256, tag, sourceCommit, platform, payloads:{nanohostSha256, gatewaySha256, unitFileSha256}}`. It contains no local paths or new install receipt. Verification failure can leave a staging directory for inspection; never reuse it automatically.

The archive checksum proves supply attribution. The three corresponding live payload measurements must match verified staged payload hashes. Effective unit state must also match the independently accepted replacement baseline, because the archive unit hash cannot approve overrides. The earlier provisional `machineId`, `sourceCommit` and `distributionSha256` host fields have no fallback. The public API gains only nullable physicalEpoch; machine/process/archive facts remain private operator evidence. P02 defines effectiveStateDigest as lowercase SHA-256 of compact UTF-8 JSON without a newline, with 40 sorted property names and string values. The owner defines the exact property set and normalization, including execution fields and credential references, and excludes secrets and runtime counters. P29 compares this opaque digest with accepted evidence; it does not request, hash or retain raw effective-unit properties. The owner semantics and P02 implementation are accepted; both producer and stored projection are present in the current repository.

`invokeNanoHostInspection(target, {nonce}, runOperator)` invokes only `['/usr/lib/openkit/nanohost', 'inspect']` with compact nonce-only stdin JSON. The already authenticated external operator executor receives `{command, stdin, timeoutMs:10000, maxStdoutBytes:16384, maxStderrBytes:256, signal}` and returns `{exitCode, signal, timedOut, stdout, stderr}`. It must bound collection, reject overflow rather than truncate, and honor cancellation. `operator-transport.mjs` supplies the fixed independently bound SSH inspection executor; it admits no local-host fallback. `observeOperatorHost` always uses this concrete command boundary; a caller cannot substitute a pre-parsed inspection response.

P02 bounds the input to 256 UTF-8 bytes and the response to 16 KiB, including framing whitespace, under one absolute 10-second monotonic CLI deadline. P29 adds its whole-invocation deadline and abort signal, checks process completion and empty stderr, decodes strict UTF-8 and one unambiguous JSON envelope, then checks the nonce and closed producer shape. A non-zero exit, timeout, malformed/oversized/ambiguous output or unknown core stops without another attempt or raw diagnostic retention. P02 owns local root-peer admission and coordinator/process measurement. This directory supplies no alternate command, process/path selector or transport fallback.

## Evidence And Verification

Reentry, interruption, unknown or partial activation, stale candidate, changed target, busy work or missing evidence stops the composition. ## Host Procedure Modules

`nanohost-replacement.py` supplies fixed-payload custody. It verifies the entire known old set and reserved installer temporaries, refreshes complete fencing and inhibition before each vacancy, and durably retains only differing old payloads in exclusive sibling custody. Exact target files remain in place. Existing custody refuses; it grants no resume. Hard links rely on the owner's exclusive operator and fenced-writer precondition and do not protect against later privileged in-place mutation.

`nanohost-systemd.py` supplies the read-only guard and stopped-domain predicate and bounded command collection. It checks exact guard bytes and ownership, absent permit, the typed loaded condition, stopped service facts and every descendant of the fixed v2 failure domain. Limits are 256 directories including the domain root, depth 16 and 4096 bytes per kernel fact. It refreshes kernel facts after the final manager query. Unknown, unreadable or overflowing facts never mean empty.

`nanohost-maintenance.py` adds actual manager search-path and activation admission, durable guard establishment, whole-domain stop, one attempted start and same-process finalization. `host-procedure.py` joins it to archive custody, fresh target checking, unchanged installer disposition checks, retained-input comparison and the canonical native inspection. The source and archive custody are temporary operator evidence, not a resident helper or product update record.

`bounded-process.mjs` limits the existing SSH and registry child tools by time and bytes. `operator-api.mjs` uses the existing Core Client and administrator credential owner, forbids redirect, bounds complete response collection and never retries. Synchronous Worker preparation has a finite thirty-minute request window for cold image acquisition; other operations have thirty seconds. A deadline leaves any accepted effect unknown and grants no replay or recovery. `operator-live.mjs` and `operator-entry.py` bind those adapters to the fixed procedure. Disconnecting the local SSH process does not prove remote completion.

The ordinary suites exercise real disposable filesystem custody, real bounded child processes and doubled manager/API facts. They do not prove persistent inhibition. Run the explicit host-placed `pnpm test:nanohost-maintenance-live` gate to exercise a rootless private systemd manager, D-Bus and cgroup v2. Missing tools or delegation fail this selected gate; it has no environment bypass or ordinary-suite skip. The suite must demonstrate the actual guard, manager restart with a partial set, permit consumption, finalization and cleanup before this recipe is qualified. A setup failure is unavailable evidence, not a skipped or passed gate. Selected-host release acceptance, retained-work continuation and actual provider inference remain separate.

The `components-result.json` publisher adds retained `schemaVersion: 1` through the shared Protocol marker helper on success and failure. It has no historical product reader; the marker identifies the evidence grammar without changing component effects or granting recovery authority.
